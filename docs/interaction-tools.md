# 交互场景与工具能力指南

适用：2.8.3-dev.53 收口候选。以下描述已接线能力与限制，不保证每次模型都选择工具；实际使用取决于已登录账号、主 Session 绑定、能力开关、模型、预算和独立授权。

## 主人交流入口

| 能力 | 主 Session | B站主人私信 | 好友私信 / 陌生人 / 评论 |
|---|---|---|---|
| 真实经历和长期记忆 | 显式 `dafeiyu_life_recall`、`dafeiyu_memory_recall` | 自主 `memory` 按需读取 | 现有场景范围内；不得跨联系人披露私密经历 |
| 视觉回忆/历史补看 | `visual_query`、`detail_bvid`、`bili_video_revisit_moment` | 按需回忆及核验后的公开历史复访 | 授权好友受限复访；陌生人和评论不获补看权限 |
| 新视频观察 | `bili_watch_video` | `shared_link` / `shared_video`：核验来信分享目标后自主选择 | 授权好友受信分享；其余保持受限 |
| 最近观察清单 | `dafeiyu_recent_observations` | `recent_observations`：主人专属按需菜单 | 不开放 |
| 保存重要事实 | `dafeiyu_remember` | `ownerMemoryProposal`：当前来信原文核验、现有身份记忆额度 | 不新增身份记忆写入能力 |
| 探索建议与待办 | `bili_life_consider_video`、`dafeiyu_todo_list/add/update/execute`（当前账号；延期/放弃） | 原自愿待办建议；`owner_todos` 与 `ownerTodoProposal`（开放待办延期/放弃） | 原受限建议规则；不新增管理权 |
| 公开资料 | 原 `bili_search`、`bili_comments`、`bili_subtitle` 等 | 既有按需公开菜单 | 原场景权限及预算 |
| 图片内容和外发 | `dafeiyu_observation_detail` 核验原图与旧描述，`dafeiyu_share_observation` 独立选择宿主附件 | `observation_detail`、`shareObservation`：当前轮次的真实缓存选择与图片私信 | 不开放 |

主人私信的事实保存是 dev.39 新增的有限写入：必须是当前核验主人来信，模型主动选择，引用当前消息连续原文并经过原身份记忆写入检查；返回真实结果再组织回复。不是任意删除、编辑全部历史记忆的接口，也不是自动记录每条私信。旧聊天及任务保留现有机制。

## 怎样使用

- “你最近看过什么？能说说有哪几张分镜吗？” —— 鱼鱼可以自行选择查看近期观察清单，返回当前账号 12 小时缓存中的视频标识、采样时间和分镜编号（最多四条，私信目前最多三条）。清单不包含图片字节、不确认图片仍可发送。精确选择缓存可核验字节和旧描述，不会重新进行视觉推理；随后可自愿分享。
- “你还记得那只小动物的动作吗？” —— 鱼鱼可选择相似画面回忆，只有仍然有效的实际观察可作为证据。
- “有空看看这个视频吧。” —— 可按已有意愿流程接受、拒绝、延期，或进入受信分享的观察；待办入账不等于已经观看。
- “我更喜欢短视频，你可以记住。” —— 可选择记下当前明确事实，保存成功以实际回执为准。

## 意愿、权限与回执

所有角色自主读取也应经过统一意愿边界。已选主 Session 的实际工具调用、社交模型明确选择的按需菜单作为本轮自愿读取决定；读取前后复核身份、代际与范围。可以不选择、拒绝、延期或缩小范围，不为每次读取额外启动模型投票。读到历史内容不等于必须告诉对方；主人私信实际读取记忆后须独立选择文字披露；未同意的草稿不发送，改以无历史读取上下文重新组织。主 Session 普通文字及其他渠道尚未全面迁移，不能视为语义防泄漏。主动行动及外发仍使用原意愿与授权检查；关闭互动回复不得借工具外发。必要的当前对话、身份线索及系统统计、备份、索引、遗忘维护不属于角色主动工具使用。

自动记忆上下文与待办提示仍提供能力入口，不直接附上完整历史正文。旧的社交全量上下文偏好保留配置，生产模型交互按需展开。后台其他自动唤起与反思路径尚未全面统一；不能把本批声称为所有读取入口均已迁移。

## dev.40 图片与待办

- “如果你愿意，挑一张最近看过的原始分镜发给我看看，不要重新观看。” —— 主人私信可选清单、单图细节、独立图片发送。现有缓存有效且授权就绪时才允许尝试；实际收件人及真实 msg_key 核验成功才记录投递。该轮只发送一张图，不混合文字气泡。不要把旧描述当成本轮新视觉观察。主 Session 需要当前真实已领取主人轮次、支持图像输入的当前模型及宿主附件服务；成功只表示附件准备完成，实际客户端显示需验收。宿主附件可能在聊天历史中保留超过缓存期限。主人变更后重启以同步子进程权限。
- “上次推荐的那个视频先延期两小时吧，如果你还想看的话。” —— 两渠道可自愿读取当前账号待办并延期/放弃开放待办；私信需当前真实版本，不可伪造完成，也不可覆盖运行中或不确定任务。若任务已完成则说明实际状态，不再修改。
- 图片分享不是普通读取，必须独立选择。只允许真实缓存标识与字节，不接受本地路径或远程图片 URL；不同账号、过期、缺失、暂停、授权变化拒绝。平台发送结果不确定时保留原事务，不自动重发。

## 当前限制

dev.40 已接入图片附件及私信图片适配器，实际 DSH Desktop、当前安装的 bilibili-api 和 B站真实投递尚未核验。当前精确图像详情只把旧描述和字节核验回执交给模型；不新增私信图像推理。完整主人渠道工具对等、主 Session 普通文字披露及所有后台读取统一迁移仍未完成。网页完整诊断 ZIP 已接线，Windows 实际收集待验。不得用路径、编号或文字描述代替真实发送。陌生人、好友和评论不获得主人专属图片或待办管理权限。

## dev.42 实机反馈修复

- 主人主动观察的新鲜核验画面可进入现有 12 小时缓存，旧文字记忆不补造图片。清单会排除缺失图片；私信在已选清单后可追加一次分镜详情读取。主 Session 分享必须先在同轮自主读取对应分镜，再独立选择分享。
- 主人私信日常/活跃检查从定向检查开始计时，不从回复生成结束重新等待整段间隔。串行执行、退避及平台限制仍可能延后；检测不等于回复。
- 运行日志页可经本机主人同源明确确认导出完整诊断 ZIP；包含私密业务及记忆，默认省略大型二进制。128 MiB 网页限制，失败或超限用原 BAT。发送给他人前请核对。


## dev.45 · 私信自然工具生命周期（第一批及后续设计）

实际接线：生产按需模型在当前同联系人分享候选中自主选择 `deferredExploration={id,goal}`，与 `futureReadCommitment=false` / `todoDisposition=none` 对应自身兴趣（不是对别人作了承诺）。`read_link` 是未核验的公开 B站链接，`observe_video` 是获准主人/好友的准确视频目标（若已核验元数据，则还须原 Episode 未结束、未观察）。源账本保存有界目标，成功不代表已读取。重复选择相同目标幂等，失败交还同模型修订。陌生人仅可选择自己分享的、原权限允许的公开链接，不新增观察/补看、私密管理或外发授权。无候选可以自然表达不确定、保留线索或沉默。管理页仍查看原生活契机，详细方向可在 duty.log（`Life 自主延期探索已记入原生活契机`）及原分享账本核对；本批未增加独立 UI 或调度器。原冷却、窗口、资源、预算和实际回执继续生效。

### 能力审计：即时、延期、结果续接

| 场景 | 当前入口 | 可自然延后（现状） | 结果/联系边界 |
|---|---|---|---|
| 主人或获准好友分享视频、动态、空间 | `shared_link`，核验后 `shared_original` 或受限 `shared_video` | 本批明确兴趣可记原分享契机，承诺仍走原待办 | 真实元数据/字幕/画面分别核验；不自动发私信 |
| 获准陌生人分享公开链接 | `shared_link` / 平台核验的原动态 | 本批 `read_link`，已有搜索/观看待办建议也保持原权限 | 只读公开内容；不能访问主人观察清单、补看或主动续接 |
| 推荐歌手、作品、公开主题 | `suggestedTodo` 的 `search_videos`、`watch_video` | 已接受只读待办可按原 now/later；纯兴趣的任意搜索目标延期尚未统一 | 搜索回执不等于听歌/看画面；已有社交待办回访仍按独立旧授权 |
| 回忆、查看历史画面 | `memory`、真实获准历史视觉复访 | 当前有界同轮按需读取，不是通用异步回忆队列 | 记忆有效范围、同联系人、独立披露；陌生人不开放补看 |
| 主人查询待办、核验观察、保存事实 | `owner_todos` / `recent_observations` / `observation_detail`；`ownerTodoProposal` / `ownerMemoryProposal` | 保持同轮真实回执，不开放任意延期私密写入 | 主人身份及当前来信重验；已核验原图和发送回执是两个独立事实 |
| 主人点赞、收藏、关注、评论、动态、代发 | 历史 `owner-dm-agent` 有独立权限配置及实现；普通生产 Life 私信路径没有全部自然工具接线 | 不自动将未明确授权的写操作放入 Life | 必须由当前独立能力授权及精确平台目标验证，不能把旧命令解析器等同已接通的自然工具 |

**统一续接目标（历史设计；dev.51 部分接通，见本页末节）：** 使用现有 Life 动态候选和原源账本，工具声明受控可用性、即时/可延期范围、数据作用域、真实执行及回执；模型自己选择即时/延期/不做及兴趣/承诺。对跨轮来源只保存当前账号的受信引用，不保存额外私人正文。执行后根据原目的核对真实回执，资料核验不能结算画面观察目标；记忆仍从活体 Gateway 取证。探索完成后，只有当前真实主人、独立主人主动联系授权、当前可用原会话、联系时段/冷却、真实证据同时满足，才将其作为原 Life 可选交流机会。模型独立决定是否继续交流；执行前再次核验新来信、授权及证据，复用现有发送事务，未知冻结。现有待办回访和主 Session 主动联系不等于该专属主人私信路径已实现；不扩大好友/陌生人主动联系权限。通用只读延期和写操作逐工具审计后才能扩展，不接受任意工具名、路径或模型生成 URL。

## dev.47 · 统一社交只读工具循环与参数化记忆

主人、授权好友、陌生人私信，以及视频/动态评论、被 @ 等进入现有生产互动批处理的场景，使用统一只读工具目录与实时授权菜单。每条互动最多6轮、8次工具调用，每次最多4种；原平台共享预算仍可能更早拒绝。模型可随时结束或根据已取得的证据自主选下一种工具；不因渠道硬编码工具组合。除 memory 外已用种类在当轮隐藏。memory 支持不同有效检索词、时间/类别或历史细节选择的最多3次调用（原权限与参数契约不变）；等价参数重复拒绝，后续模型看到累计证据及每次命中状态。超过四种累计证据不会被误裁剪。分镜需先取得真实清单，写入、披露、外发仍独立决定并复核；未终结的工具请求不能当成回复。不会改变陌生人视觉或主动联系权限。

例如评论中自主读取旧公开经历、当前视频上下文、公开热评、评论者投稿，再决定是否回复。主人私信可选择回忆、真实分享核验、分镜清单及精确详情；自然表达由模型自己生成。无须用户说出工具名。诊断查看既有按需读取统计和真实回执，额外读取模型续推按实际调用计数。

原分享视频延期观察的真实意愿也会进入后台同 Episode 的后续模型，仍可延期、休息或自主结束。

尚待接线：其他工具的通用参数协议（同类多目标）、历史主人写工具自然调用、后台 Planner 的全面统一运行时、跨轮工作流与主人自主回聊。主 Session 保留宿主原生循环，不嵌套重复 Agent；Video Agent 保留专业感知能力。

## dev.48 · 后台 Life 自主回忆工具

在自主生活已启用、允许继续公开探索的时段和原 Episode 子决策中，若当前公开活体记忆能力可用，肥鱼可自行选择 `recall_public_experience`，根据实际结果改换检索词或继续其它已获准动作、延期、休息。最多两次不同有效检索、每次最多三词，计入既有决策额度；历史证据和状态仅在本次续行交回模型，不产生新观看、任务完成或发送权限。无命中不是不存在，账号、权限、遗忘或原目标变化会停止。诊断看原决策轨迹的 `public-recall-found/not-found/unavailable`；不记录查询正文。关闭主 Session 记忆能力或暂停自主生活可撤销该能力。主人专属主动回聊与通用跨轮仍未接通。

## dev.50 · 后台视觉与资源代际保护

Life 当前全局观察及片段补看同样使用原共享读取契约；模型可自由选择或停止，未观察不能提供局部候选，保留原视觉租约和预算。原账号切换/暂停、契机变更或视觉撤销后，旧决策和未交付的工具结果被阻断；同一账号重新登录也不是旧轮次授权。诊断 `life-read-scope-changed`、`account-changed`、`life-resource-account-changed` 或 `life-model-result-scope-changed` 为技术阻断，不是鱼鱼拒绝或真实观看。原已开始 I/O 不保证可取消。主人主动回聊尚未接通，未新增陌生人、评论或写工具权限。

## dev.49 · 社交与后台统一只读执行入口

原社交15种路由与后台 Episode 六种非视觉只读路由共享工具注册描述和执行准入（`registeredLifeRead`、`executeRegisteredLifeRead`）。后台可从当前合法菜单自然选择公开回忆、候选 BV 资料、作者投稿、额外首页、已核验评论者投稿或公开讨论；不要求固定话术或固定先后。相同工具族不互换授权，原参数、目标、预算和专业回执各自保留。原 Life 开关、账号、会话、契机或候选变化后不把在途读取结果写入已改变的契机。决策轨迹 `life-read-scope-changed` 为阻断而非成功，检查原账号、生活设置、候选是否仍有效；切勿为消除阻断而放宽权限。视觉采样、主 Session 原生调用、写工具、通用跨轮与主人主动回聊未迁移。


## dev.51 · 主人分享探索后的自主回聊

首次使用：在现有设置中开启自主生活、主人私信、主 Session 记忆能力及主人主动联系；同时明确开启 `ownerDmSilenceFollowupEnabled`（主人私信沉默续聊）和 `ownerTodoCompletionFollowupEnabled`（主人完成回访）。保守复用原三项联系授权的交集，默认不会新增主动外发。关闭任一项、关闭私信回复或暂停 Life 即撤销该路径。

主人通过 B站私信自然分享一个公开视频；肥鱼若自己选择延期观察，原生活契机保存意愿。实际在后台观察到画面且该记忆仍清晰时，下一次符合原自主生活时段/额度的 Planner 可考虑 `talk_to_owner`，自主决定一条自然私信或保持沉默。无需命令、不会因执行成功自动汇报、不变成待办；仅最近的原主人分享、24小时内、原 Episode 真观察。只读标题或缓存不足以触发。主人后来另发消息、原分享撤销、记忆遗忘、账号/权限变化、联系时段或额度不符时不发；入站复核失败也不发。

诊断：`owner-chat-confirmed` 是真实 B站消息回执；`owner-chat-queued` 仍仅指主 Session 委派；`owner-chat-blocked` / `owner-chat-unknown` 不得视为发出成功。未知事务不自动重试。原日记显示确认的探索分享，不显示私人草稿。仍需真实模型和授权实机验收。普通好友及陌生人不增加主动联系权；任意工具跨轮恢复、全场景统一决策循环和其他写工具尚待接线。


### dev.52 工具注册与权限

dev.52：主 Session 31 个原只读入口（26 个 B站/宿主及5个记忆/待办/观察工具）与社交15、后台 Episode 8共用注册及执行网关；仍由原适配器及绑定范围核验。评论模型选中的热评及评论者投稿不再经过第二次意愿投票，分别复核真实入站来源、当前账号、active、隐私及原平台预算。不扩大任何写入、私密披露或主动联系权限。注册路由不是独立能力数量，宿主循环仍独立。 详见[工具清单](architecture/life-tool-inventory.md)。实际宿主工具发现、权限变更、陌生人与公开评论隔离仍须实机验收。


### dev.53 视频写入注册与门槛

dev.53：共享目录新增后台 Episode 四种既有写路由（点赞、收藏、关注、原创评论），共 54 个只读 + 4 个写路由，非独立能力数。共享语义标识仅用于能力描述，不能跨场景调用别名。仍复用原 Life 意愿、Python 写入桥、平台额度和独立读回；在排队、一次性凭据消费前复核账号代际、原 Episode、视觉证据、权限及额度开关，组合子动作按原凭据和账本顺序。已提交的事务必须结算，旧代际回执不投影为新经历；可信票据绑定准确原 Episode。未迁移宿主手动写工具、社交发送和通用跨轮恢复，未扩大权限。

验收：在隔离夹具中选择单项或同 BV 组合写入；检查原视觉证据、权限/额度为零、换号又切回、契机撤销、写入票据尚未消费与未知结果分别正确结算。真实平台操作必须由维护者在授权测试账号中自愿执行；没有必要启用新权限。
