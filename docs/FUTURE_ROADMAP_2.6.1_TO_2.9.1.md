# 大肥鱼 · 2.6.1～2.9.1 未来发展与验收路线（讨论批准版）

> 更新日期 2026-11-03。**路线是目标和依赖，不等于已实现或已发布。** `2.6.1` 已由用户发布，`2.6.2` 已正式发布；`2.7.0-dev.1` 开始 P6-A/B 合并开发。此前 P6-B 设在 2.7.1 的时间安排已由用户调整，但现有生产端尚未启用 P6 新行为。根 README 不堆砌版本流水账。

## 2026-11-05 补充决议：2.7.1-dev.4 Life Agent（目标架构）

经本轮讨论，`dev.4` 优先采用**事件驱动的单一、平台无关 Life Agent**，而不是保留固定视频轮作为生活主驱动，也不是全天常驻大模型或多个独立生活 Agent。允许重构旧定时刷视频/场景式自动回复的生活决策方式；保留并复用原人格、情绪、人生记忆、兴趣、人物关系、已接受待办、模型路由、平台适配器与 dev.3 安全执行/真实回执。旧的收件轮询仍是感知基础设施，不等于必须触发生活动作。

目标是**真实事件→自主目标→按需工具→证据回馈→可纠错、可遗忘的长期成长**；不允许把模型意愿等同外发授权。优先用事件去重、按需记忆检索、合批和预算上限控制 Token；必须与旧系统实测成本比较，不得凭设计估算宣称更省钱。完整四方案对照、成本算例、迁移和验收门禁见 [dev.4 设计决定](architecture/2.7.1-dev4-life-agent-decision-adr.md) 与 [目标图](architecture/diagrams/2.7.1-dev4-life-agent-target.mmd)。**当前仅记录规划，没有修改运行时或宣布 dev.4 已完成。**

## 0. 产品不变量

1. 鱼鱼是 DSH 中持续存在的数字角色，B站只是可替换的平台生活环境；不以账号 UID 作为角色的内在唯一身份。
2. **自主意愿不是操作许可**。思考/阅读/制作草稿与公开发布/发送私信分别授权。模型不能凭一条评论或私信获得终端、文件系统或外发权限。
3. 事实必须有来源和实际动作回执。读取字幕不等于听到音轨，视频索引不等于完整观看，生成草稿不等于发布。
4. 经历随时间自然淡化；长期的可验证操作技能另存技能知识库，不能把全部技能细节随经历遗忘，也不能因技能索引恢复已经遗忘的私人故事。
5. 主 Session 工作域与 B站生活域共享可信生活状态，但权限不同。鱼鱼对社交可以拒绝或沉默，不影响主人明确授权的普通工作。
6. 各阶段复用同一角色身份、关系索引、人生记忆、模拟情绪、统一待办与自主调度器；禁止每个新插件再建立一套互不相容的人格数据库。

## 2. 2.6.1：本轮实施与发布验收

### 保留 RC2 功能

- 同轮 AI 从主人、好友、普通人私信与评论理解公开只读探索建议；不额外请求意图提取模型，不用关键词替代语义判断。
- 接受/推迟/拒绝、统一待办账本、来源权重、父子连续探索、完成回访诊断；仍遵守真实发送许可和每日预算。
- 关系阶段、熟悉度、关系敏感遗忘、非白名单保守互动印象、情绪与主 Session 的受限双向联动。
- `LifeMemoryGateway` 可衰减真实经历；不得从 `archive` 复活已经遗忘的事实。

### 唯一新增：账号独立性

- 稳定角色身份 UUID 与可变 B站账号 UID 分开存储，私密平台账本按 UID 隔离。
- 扫码先暂存；官方在线验证实际 UID；明确确认后切换；强制重启和复核，禁止旧账号平台任务在新号自动执行。
- 保留鱼鱼现有记忆/长期兴趣/人格和未完成项目；历史待办留存但冻结自动跨号执行。
- 便携业务备份保存角色身份，不保存 Cookie/账号私密运行账本；实际跨设备恢复敏感数据仍需单独设计。

发布门槛：Node/Python/自检、老装置升级、Windows DSH Desktop 实机扫码/取消/切换、旧平台数据冻结/旧号回退、隐私备份与跨 UID 负面测试。发布渠道逐一核验，未授权不推 npm/市场。

## 3. 2.6.2 合并范围 A：请求协调器与轮询稳定性

**问题证据：** 一次私信轮询会读取会话列表并处理多个活跃会话，不能用“每分钟一次”当做整个账号的请求量。默认 1 分钟会话轮询不是一个公开保证安全的 B站配额。

**实现顺序：**
1. 已接入主进程的只读平台请求计数器：按当前登录 UID、接口类别、分钟/小时窗口计数，状态可诊断。外发仍由原来的独立权限/额度控制。
2. 会话列表+会话级更新时间与未读数游标，原有私信账本负责消息 ID 去重；按需读取并定期复查。
3. 有变化的会话优先读、安静会话约半小时安全复查、每轮最多 12 个详细会话；采用分钟/小时预算及有限重试，遇到服务拒绝、验证码/登录异常退避。此处仅覆盖已接入主进程的读接口。
4. 保留 B站真实平台回执，不因重试策略重新发送状态不明的评论/私信。

**验收：** 模拟 0/10/40 个会话，比较请求总量与漏信率；跨窗口、异常 HTTP、进程崩溃恢复、账号切换时游标隔离。若未来官方开放普通账号可用的事件订阅，再单独评审，不预设一定有 Webhook。

## 4. 2.6.2 合并范围 B：原 2.6.3 管理中心视觉与信息架构

- 把「鱼鱼想做的事」升为一级页面，提供已接受任务、长期目标、父子探索、关系权重来源与回访原因。
- 「鱼鱼现在记得什么」改成记忆花园/卡片与搜索筛选：经历/人物/体会/纠错、清晰/模糊/痕迹区分；已经遗忘不透露细节。
- 人格特质卡片采用带图标的统一彩色视觉；展开展示真实证据及“证据不足”而不是虚构成长。
- 统一颜色 Token、响应式网格、深浅主题对比、表单禁用与键盘导航；旧控件 ID/API 不破坏。
- 非白名单的互动印象只用真实行为元数据与允许的交谈证据，不从熟悉度臆断“善良/外向”等性格标签。

**验收：** 1200/768/375px、深浅主题、禁用控件对比度、屏幕阅读器、1000 项分页无卡顿、历史地址/设置兼容。

## 5. 2.7.x：P6 原延期能力（不能混入完成回访）

**2.7.0 P6-A（已并入统一社交架构）**：一轮 AI 决定回复 1～3 个独立短气泡，逐条发送、跨气泡冷却和逐条回执；没必要时只回一条或沉默。主 Session 必须验证宿主能否真正承载多条 assistant 消息，不允许用伪造用户 turn 充当。超时和不确定发送不重放。

**2.7.0 P6-B（原定 2.7.1，现已提前合并）**：会话阶段性“尚未结束”标志；经过合理延迟后鱼鱼自主评估是否补充、结束或沉默。沉默不是不断催促的理由；相同 UID 的退订、安静时段和频率上限独立生效。

**2.7.2 P6-C/D**：生活中的真实新经历和回忆自然产生分享/问候意愿，关系与权限决定渠道选择；全站外发预算、主 Session 与私信避免双重打扰。已完成待办回访属于已有 2.6.1 能力，P6 是**无外部任务也可能主动分享**。

**新增 2.7.0 社交范围：** 私信暗号审批成为默认关闭的可选严格模式，正常聊天由鱼鱼根据统一人格情绪、开放兴趣、关系及连续上下文判断；好友关系可以从简短摘要向有证据、可纠错且可遗忘的人像刻画发展；被 @ 回复不再受用户白名单限制，但主动 @ 他人仍需独立明确授权。详见 [统一自主社交架构](architecture/2.7.0-unified-social-agency-plan.md)。

验收须区分意愿/权限/平台回执，进行跨 UID、跨渠道、冷却、黑名单/退订、双重投递、24 小时稳定性测试。默认关闭未经用户授权的主动外发。

## 6. 2.8.x：开放式学习与感知

**2.8.0 开放目标：**
- 在待办之上增加「长期目标/项目/可验证步骤」模型：鱼鱼决定学什么，任务可跨天暂停、调整方向、恢复，不强迫即时完成所有子任务。
- 添加受控能力目录（工具名、当前可用性、输入输出、费用/时长/风险）；模型能在授权空间中选择研究文档、创建小样、检查结果。
- 实验工作台按项目隔离文件和执行预算，默认禁止联网执行未知代码、安装软件、读私密文件和对外发布。
- 区分“确实完成的实验步骤和作品产物”、“有来源的技能配方”和“有衰减的个人经历”。技能精确知识可修订/验证，不能通过它绕开生活记忆遗忘。
- 示例闭环：自己选择学习 Pillow 绘制、FFmpeg 合成、可选配音 → 预览失败/修正 → 人工验收 → 下次真正复用。

**2.8.1 可选深度感知：** 保留元数据/字幕/评论轻档；新增视觉帧采样和本地音轨的分层证据，接 `video-watch-plus` 适配器；先核验上游版本和许可证。视频下载与授权来源由独立接口负责，不能把没有分析过的音轨写成“听过”；目前它也不等于能识曲/核验真人歌手。

**2.8.2 人文反思：** 借鉴 `dsh-bili-humanism` 的证据手账、可撤回认识、自主提问，不直接复制其独立人格文件成为第二人格真值。反思必须以现存可访问的可信经历为证据，私密对话不得在公开动态中泄露，内容消费不等于参数训练。

## 7. 2.9.x：扩大对外自由但不开放无边界写入

**2.9.0**：研究更开放的私信入口与关系自然成长；独立陌生人准入、额度、频率、拒收和反骚扰。不是自动向陌生人主动发送，更不能因为关系得分升高就绕过白名单特权。

**2.9.1**：自主研究和制作作品、得到真实预览、修正，再在单独发布权限下向外发布。绘图素材、语音、角色立绘必须核对许可与署名（含二创、音色/真人相似性），避免凭模仿未经授权的角色或声音发布。所有公开写入、投稿结果不确定均不得自动重复。

## 8. 跨版本技术债和非承诺项

- **旧 P4/P5：** 统一只读待办、运行前意愿复核、公平调度和真实完成回访主体已在 RC2；自由技能任务和长期目标升级到 2.8.0，不重复建设账本。
- **旧 P6：** 自然连发、沉默续聊、情绪分享、自然朋友回访和跨渠道不重复联系仍延期；已完成待办回访不是未完成项。
- **长视频/音轨：** 当前读取 B站资料不等于完整视觉/声音感知；无法从没有音轨证据的资料推断歌曲的演唱声线。
- **独立研究：** 桌宠、官方事件订阅、音乐作品与演唱者高置信识别、跨设备加密私密数据迁移、多 B站账号同时生活，目前不在确定交付版本中。

## 9. 开发纪律与阶段冻结

每版至少包含：需求/非目标、现有数据兼容分析、权限矩阵、生产调用图、隐私域与证据来源、故障回滚方案、自动化测试及实机验收列表。仍以 `dev` 分支开发，Git Patch 与完整源码对照验证；未经明确许可不打正式 tag、发布 GitHub Release、npm 或 DSHMarket。每版 README 只保留用户理解得了的功能，详细更新留在 CHANGELOG/Release Notes/技术文档。
