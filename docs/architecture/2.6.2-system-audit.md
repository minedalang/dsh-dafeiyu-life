## 一、结论

- **已修复可证实的显示断点：** `panel-life` 记忆花园以前的类别只覆盖 `/main-session/history`（可衰减视频/互动经历）和 `/main-session/memory`（长期身份记忆），没有把已存在的 `life-memory/interests.json` 成熟兴趣和 `social-relationships/relationships.sqlite3` 已核验互动元数据接到顶部花园。现在增加同源、只读 `/main-session/memory/garden`，复用原有存储和资格门槛，绝不凭空补人物/兴趣。
- **新增链接证据防护：** `owner-dm-agent` 的对外 B站视频 URL 必须来自**本轮成功读取的公开 BV 结果**，或主人当前消息明确提供的同一 BV；音乐搜索还须当前主题匹配。上一轮 `lastSearch` 不能成为下一轮聊天里贴链接的授权依据。保留真正的本轮有效搜索链接。
- **已检查现有父子待办 UI：** `management-console.js` 使用 `parentTodoId` 和已知规范化 `sourceKey` 关联，左侧原请求、右侧对应子项，窄屏使用上下布局。代码与回归测试满足结构要求，**尚未进行真实 Windows/安卓 UI 视觉验收**。
- **统一事实事件体系未完成：** `claim-provenance`、`outbound-video-link-evidence` 和任务回执是局部可靠性改进，并非每个评论、动态、反思、私信 Agent 都通过统一的结构化 `EvidenceView/ClaimVerifier`。原设计文档仍是分阶段计划，严禁标成已交付。
- **结论：继续保持开发验收（NO-GO 正式发布）。** 自动化通过不等于真实 B站回执、账号切换、旧配置、设备显示及连续运行全部合格。

### 分类显示的真实口径

1. **经历：** 只由现有 `LifeMemoryGateway` 的当前可衰减副本提供；被遗忘后不从 `archive` 复活。
2. **人物：** 一种来源是长期认识中有明确关系类别的记录，另一种是 SQLite 中 `count > 0` 且 `lastAt > 0` 的真实互动线索。后者只是互动事实，不是人格事实，不给对方额外权限，也不代表双方亲近。
3. **兴趣：** 复用 `interestMemoryRows`；必须是 `life-interest`，已经通过至少三个不同入选 BV、横跨多日等现有成熟条件；主人给的核心兴趣不在这个后天学习列表中。
4. **事实：** 长期身份记忆的稳定资料、事实键、主人手动明确保存的信息；任意 `main-session-ai` 文本不再仅因来源是聊天就被自动归类为稳定事实。

**本轮不迁移、不重算旧资料、不删除用户存储。** 原始兴趣档案本来没满足门槛，或者关系索引尚未写入真实互动时，该分类继续显示 0 是正确结果。最多读取 300 条现有长期记忆及 200 位已进入关系索引的联系人（超出则告警并到关系专页查找），前端本次最多绘制 120 条汇总记录。这些是**显示范围**，不能声称是全历史精确计数。

## 四、审计后仍存在的具体风险（按优先级）

### 发布阻塞 / P1

**P1-1 多入口的事实一致性：** 当前 `claim-provenance.mjs` 用于明确的高风险语言拦截，本轮 `outbound-video-link-evidence.mjs` 仅校验主人私信的 B站视频 URL。`social-intentions`、回访、公开评论和其他外发文本尚未共同读取一份经核验的结构化事件与断言集合。下一步应在原事件协调层之上建立统一只读事实视图：`video_selected`、`metadata_read`、`visual_inspected`、`audio_playback_verified`、`published_verified`、`message_sent_verified`。**不能因为在 B站检索到同一主题就填充尚未发生的“听过/投稿过”事实。**

**P1-2 回访持续 `pending` 需要真实场景验收：** 目前 DEBUG 可重新触发 AI 判断，但不会跳过私信权限、完成回执、静默时段、冷却、每日额度和幂等。即使 DEBUG 结果 `defer`，也不能认定 UI 坏了或“鱼鱼不开心”。应记录同一任务的真实 `modelInvoked`、`lastDecision`、`diagnosticReason`、可用证据和平台回执。在任务已经完成、权限允许、模型成功调用但连续只选择延期的情况下，再评估意愿提示和决策质量，不通过暗改时间或强制发送掩盖问题。

**P1-3 Windows + 真正 B站写操作：** Node/Python 测试不能证明平台侧最终收到、引用的原评论是否正确、账号换号后授权是否正确失效，也不能代替真实私信去重和中断恢复测试。发布前必须在受控账号下做端到端核验。

### 后续优化 / P2

- **音乐搜索只基于元数据：** 标题/作者/分类/描述可以拒绝明显教程，但不能证明已经播放或听到音频。模型可自主选择不执行；没有音频感知回执前只能说“找到/检索到资料”。
- **前端聚合展示上限：** 花园读取的是有界快照（长期 300、联系人 200、可见 120），极大量历史时需做带来源锚点的服务端分页；不能把这一页计数说成绝对全量。
- **父子待办双栏的真实设备：** 已见 `parentTodoId` / `sourceKey` 关联、窄屏 CSS、历史分页，但未验证 DSH Desktop WebView 中滚动、点击后焦点、键盘、窄屏真实视觉及跨页父项不存在时的提示。
- **跨会话纠错：** 主人质疑“你什么时候投稿了”时，需要引用上一条**确认发送**的文字及同一条来源 ID，不能依靠上一轮缓存猜测；目前只有局部短期接话与自然语言拦截，不是完整的可解释事实链。
- **旧安装的兴趣缺口：** `interests.json` 缺失或证据数量不足时，本次不会以封存档案进行“无授权历史回填”；若将来做迁移，只能基于用户仍可回忆、已核验的合法当前副本执行且需明示。

### 建议真实环境验收（必须逐项核对）

1. 先备份当前 `$DSH_HOME/bili-duty/` 数据目录及设置。升级后检查原先的长期记忆条数、已删除/已取代记录状态没有变化。
2. 打开「人生记忆 → 记忆花园」：**人物**应只列出有真实互动的 UID；**兴趣**只列已达到原有证据成熟门槛的主题；**事实**应只展示实际存储的约定与身份事实。没有数据时看资格解释，而不是要求 AI 补造。
3. 按关键词及四个分类交叉搜索；确认没有展示其他陌生人的私信内容，也没有回填已遗忘视频细节。
4. 给鱼鱼一个明确的「请找大肥鱼翻唱歌曲的视频」主人私信；实际完成本轮搜索后才可能出现经过相关性过滤的 URL。然后另发「你什么时候偷偷投稿了？」；不应自动附带上一轮教程或 BV 链接。
5. 打开「自主待办」双栏：选中「听大肥鱼翻唱的歌」父项，应只看到其真实 `parentTodoId` 对应的三个子项。不存在的父项只能提示缺失，不能根据同名标题拼装。
6. 等待模型自主连续考虑：单轮最多三个子项，若额度耗尽、鱼鱼沉默或已延期，应有正确原因；手动再提醒一次可能只执行其中一个是设计允许的结果，而不是强制全部完成。
7. 对真实完成、具有回执和原私信来源的 `pending` 回访使用 **DEBUG 此条**，确认 AI 是否真的成功决策，以及是否发出真实平台回执。不跳过发送硬限制，**不把它当连续试发按钮**。
8. Windows DSH Desktop 及 DSH Mobile 分别核对双栏自适应、深浅色、只读移动端、屏幕阅读器提示、数据备份/恢复与切换 B站账号后的身份隔离。

## 七、后续事实体系实施顺序（不纳入本轮已完成清单）

1. 以现有已核验回执为唯一依据，为 `video_selected / video_metadata_read / todo_read_completed / message_sent_verified` 定义稳定的事件 ID、源域、时间、可证明的主张类型。旧数据无法核验则 `unknown`，不能“追认”。
2. 在 `LifeMemoryGateway`、关系索引及待办回执之外，提供**受限、只读、按 UID/域/遗忘状态过滤的 `EvidenceView`**；事实指针不是永久生活内容记忆。
3. 从主人私信、自主分享、任务回访开始逐一接上结构化主张校验，最终扩至普通评论、动态与反思；严格区分权限门禁和意愿选择。
4. 保留上一条真实已发送消息与来源键的短期受限关联，支持自然承认错误但不能编造新投稿或听歌经历。
5. 做真实旧版数据和外发故障注入验收后，再讨论 `2.6.2` 正式版，不因静态测试成功自动创建 Tag/Release。
