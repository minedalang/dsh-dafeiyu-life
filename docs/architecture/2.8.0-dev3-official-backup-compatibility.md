# 2.8.0-dev.3 · 历代正式版便携备份兼容审计

## 审计范围与原则

按官方 Git 仓库旧版 `lib/data-backup.mjs` 的备份**生成协议**，审阅并在本版实现兼容输入：

| 正式版本范围 | 旧备份格式 | 恢复处理 | 安全边界 |
|---|---|---|---|
| v2.4.99 | `schema: 1`；`dsh-dafeiyu-life-backup` 或 `dsh-bili-scroll-plus-backup`；无 manifest | 无损结构适配后共用现行路径、大小、类型校验，再原样恢复业务文本 | **无原始 SHA-256**；不能宣称文件未被历史篡改；无身份标记须单独确认 |
| v2.5.0–v2.5.4 | `schema: 2`；`manifest.algorithm: sha256` | 验证原始哈希清单后安全恢复 | 旧版可能没有 `character-identity.json`；必须区分身份来源 |
| v2.6.0–v2.6.2 | `schema: 2`；带 SHA-256 清单 | 继续严格比对清单并校验业务文件 | 同上；权限不因升级增加 |
| v2.7.0 | `schema: 2`；带 SHA-256 清单 | 同上 | 同上 |

以上代表对官方源码生成**协议**的兼容，并不意味着已经取得每一个正式 Tag 的完整**真实用户备份归档**；自动测试采用根据旧版生成器源码构造的具有代表性的、含 Unicode 及记忆数据的备份样本。其他历史版本只要采用相同协议，原则上能经共同校验路径导入，但未逐一实测真实文件。被第三方篡改、损坏、超出当前便携白名单或超过安全大小上限的数据不能保证自动导入。

## 当前实现与身份保护

- `lib/data-backup.mjs` 保持新的 `schema:2` 导出不变；`schema:1` 仅作为**输入**兼容，不伪造旧文件具有原始签名。
- 历代 `schema:2` 原始清单仍必须完整通过 SHA-256；`schema:1` 在读取时生成的内部校验结构仅供重用当前严格结构校验器，**不能作为历史真实性证明**。
- `validateRestoreIdentity` 在有角色身份标记时拒绝跨角色覆盖；缺标记的旧备份在管理中心明确提示“身份未校验”，恢复必须独立再次确认。没有真实身份依据时无法自动证明同一账号，用户必须在同一账号资料目录内谨慎恢复。
- 路径白名单、文件类型、大小限制、SQLite 内容、兴趣历史合法阶段、人格/记忆隐私过滤、待补偿记录保护、恢复前快照以及失败回滚不因历史兼容放宽。
- 恢复预览日期转换为**本机时间**；支持原始 UTC ISO 字符串与旧版空日期，并明确创建时间和数据覆盖边界。
- 便携业务备份 / 人生记忆专项备份 **均不等于** `$DSH_HOME/bili-duty/` 停机冷快照。凭证、额外数据库、遗留自定义目录、外部组件文件仍需完整停机快照。
