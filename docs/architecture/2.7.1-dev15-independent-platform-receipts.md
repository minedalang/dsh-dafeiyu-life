# 2.7.1-dev.15 · 视频动作与生活动态独立平台回执（未发布）

## 目的与统一职责归属

延续 dev.14 的 `LifeWillingness → LifeAgentEvents → AutonomousPlanner` 可信完成续行，**不另建 Life 引擎、权限系统、发送器或记忆系统**。原视频 Python 工具仍是写入源，原 `daily-dynamic-publish.py` 仍是唯一生活动态发布源。新增的是**写入后由宿主单独发起的只读状态核验**。查询结果只能证明当前帐号看到的目标状态，不能证明看完视频、喜欢的心理原因或平台最终永久保存。

| 入口 | 写入事实与授权 | 新增独立核验 | Life 接线 |
|---|---|---|---|
| 视频自主点赞 | 原 `bili_video_like` + Life 一次批准 + Python 配额与防重 | `video-action-verify.py` 只读查询当前账号是否点赞目标 BV | 匹配后 `receipt(verified)`，否则保留 `accepted-unverified` |
| 视频自主收藏 | 原 `bili_video_collect` + 原收藏夹及配额门禁 | BV→AID 单视频读取，再查当前账号的收藏状态 | 同上；不把列表数量变化当成收藏成功 |
| 视频自主关注 | 原 `bili_follow_creator` + 真实入选视频作者 + 原关系授权 | BV→作者 UID，再用当前账号查询单目标关注关系 | 同上；不能用历史关注记录代替即时查询 |
| 视频自主取关 | 原 `bili_unfollow_creator` + 原七天及所有权规则 | 只查询指定 UID 当前关系是否为未关注 | 同上；不批量遍历关注名单 |
| 生活动态 | 原 `daily-dynamic-publish.py` 在配额占位后向平台提交 | `daily-dynamic-verify.py` 只读动态详情，检查 ID、作者 UID、完整正文 | `recordVerifiedCompletion(dynamic_post)` → `experience-ready`，不重发 |
| 视频评论、收藏夹删除 | 原工具、原权限、原写入结果 | **本轮尚无足够可靠的单目标独立读回** | 维持 `accepted-unverified`，不谎称 `verified` |

## 信任、数据与恢复

1. Python 视频写入结果里的 `ok=true` 仅表示**进入回查条件**，不是可信完成。Node `life-video-action-bridge.mjs` 在一次性 grant 仍处于有效账号作用域时，调用独立验证进程；查询失败、超时、拒绝、账号切换均不会升级结果。
2. 查询脚本没有写 API 或发布指令，只读单目标 GET；凭证只从当前 `$DSH_HOME/bili-duty/bili_credential.json` 读取，核验帐号 UID；请求禁用环境代理，结果不返回私有凭证、联系人或消息正文。
3. 动态 API `code=0` 与 `dynamic_id` 只是受理，保留原 `published` 兼容状态（页面显示「受理未核验」）；独立 GET 通过后升级为 `confirmed`，并另记 `verifiedAt`。`published` 旧记录仍可列为**等待真实 B站取证的候选 ID**，但不作为已核验发布事实；无账号绑定的旧记录不擅自升级。
4. 动态核验只读失败后不更改发送事务、配额占位或历史受理状态；定时 Life tick 可重新只读核验。`confirmed` 若因为账本不可用未登记 Life 提醒，后续仅补记匿名机会，仍不重新发布。重复回调由原 `LifeAgentEvents` 账户哈希源去重。
5. Life 续行只代表下次可再次考虑自己的生活；不能复发原评论、点赞、关注或动态。评论默认共享每日 1000 条额度、视频工具至少间隔 20 分钟、旧授权和账户隔离未修改。
6. `ownPublishedDynamics` 对旧 `published` ID 保留兼容读取候选功能；下游真实动态评论入口仍需独立核实作者和评论区，不能以这个候选列表为单独事实源。

## 风险和未完成事项

- B站只读端点的字段与认证状态尚未在真实账号上核验；接口反爬／缓存可能导致刚写入的状态尚未可见。采用**查不到即未核验**，绝不自动补发。
- 当前动态只支持**纯文本动态**的严格正文匹配；富文本、转发、图片动态或旧无身份记录可能无法被确认，不能放宽全文校验猜测成功。
- 视频顶层评论和收藏夹删除尚未具备可靠独立回查；未把工具报成功误作平台完成。
- `LifeAgentEvents` 用匿名哈希和时间戳记录继续考虑，不存 UID、BV、原始评论、动态正文或 Cookie。原真实生活时间线只有达到可信结果才会标注完成。
- 新增离线测试包含跨账号切换、伪造回执、读失败、重复、动态文字作者不匹配。Windows、真实 B站、72 小时长期连续生活，仍为正式 RC 阻断项。
