# 2.7.1-dev.12 · 匿名生活契机续行与统一快速设置（未发布）

## 生产接线

`AutonomousPlanner` 在单次普通 Life 思考中读取**当前账号原始可信来源**（熟人双向关系、已接受只读待办、公开观察、兴趣与反思），各类别取有界候选，将 `kind + sourceKey` 摘要写入既有 `LifeAgentEvents` v1 账本。增加 `friend-ready`、`todo-ready`、`public-ready`、`curiosity-ready`、`reflection-ready` 五种匿名唤醒类型，使用原跨进程文件锁、账号独立文件、7 天保留及延期重试状态。

新账本项是**考虑提醒**，不携带 UID、评论/私信内容、待办标题、BVID、模型生成的消息或权限；不建立第二套发送器、第二份记忆或未经验证的持久执行指令。下一轮或重启后，必须重新从原账本获取候选、校验账户作用域、当前意愿、已保存的权限及平台事务。原 `life-willingness-admission` 的跨进程未知批准冻结仍然生效。

- 被选中的候选仅在模型返回的原 `id` 与当前轮实际源 id 匹配、且 `action` 类型相符时结算对应匿名提醒；不相关提醒进入原有 `not-selected` 有界延期。模型主动 `skip` 表示本轮休息，可以结束当前提醒，但不删除原事实或待办。
- 失败调用、结果未知与已尝试外发仍由原重试／未知结果冻结规则处理；不可依据匿名提醒直接重放平台动作。
- 原事件队列只保存有界摘要（每账号最多 60 条、7 天），本轮实现的是**跨渠道机会提醒的第一步**。并非永久任务队列，不承诺所有来源都已接入，也不承诺重启后在没有普通 Life 唤醒时自动连续执行。

## firststart 单流程

管理中心仍保留**顶部横导航**和同一 `/onboarding` 安全接口，将旧的“两块独立区域”整理为：01 B站登录 → 02 Headless 模型验证 → 03 生活/记忆/社交方案卡（直接预览、各自保存） → 04 可选主 Session → 05 完成。顶部五个进度项只读反映已验证、已查看和已完成状态；不会因为进入页面或选择卡片就保存配置。

新老用户首次打开 dev.12 都须查看此页（引导修订号 4），但**不会重置老用户凭据、授权、模型、运行状态**。新用户两项必需验证未完成时仍禁止开展业务及新增主动社交许可；旧用户已完成的业务授权不会因仅展示新版引导而重新被关闭。模型 Provider 等复杂配置仍通过原模型页进行。

## 仍需后续收口

- 跨渠道来源的公平优先级、超过 60 条长期积压、持续唤醒与到期自动重建、账号切换时实时卸载和恢复测试。
- 主动社交在真实 B站上的许可、冷却、未知回执，以及 72 小时完整生命线。
- 本轮不修改评论默认 1000 容量、视频 Agent 20 分钟门禁，也不增加新的平台发送能力。
