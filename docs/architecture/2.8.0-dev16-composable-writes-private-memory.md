# 2.8.0-dev.16 · 兼容视频组合、私信并发与场合隐私（当前增量）

> 当前源码级实现与离线测试说明，**不代表 Windows DSH、真实 B站、真实模型服务商已通过实机验收**。现行总入口见 [Life 当前架构](life-system-current.md)。

## 视频一次决策，多项兼容行动

1. 仅在 `Life Episode` 已取得可信同 BV 资料、单项权限均满足且本轮菜单包含至少两种写入时，提供 `write_bundle`；模型可自由选择单项、组合或不做，组合不是活跃度 KPI。
2. 模型以一次 JSON `actions`（2–4 项、互不重复）形成一个意愿；组合白名单为 `like_video / collect_video / follow_creator / comment_video`。不合并不同 BV、关注与取关、同视频重复主评论、评论回复／私信／休息或需进一步读取的动作。
3. `life-continuation-write.mjs` 再核验当前 BV／公开证据／配置，`life-willingness.mjs` 封存**一个父意愿**和全部精确子动作（类型、BV、评论正文），不会调用第二个 Life 意愿模型。原视频桥对每个子动作独立签发一次性票据，原 Python 写入执行器按原权限、风控、额度和回读结果判定。只有 **verified** 才继续下一项。
4. 父意愿直到最后一项核验成功才完成；单项失败、账号改变、凭据丢失或无法确认时立即停止。已完成的写入不撤销；未知结果冻结整个 Episode，不重发。旧会话恢复时内存意愿失效，也不根据磁盘意愿补发。组合在 Episode 计一个选择步骤，视频平台成功的每个动作由原单项实际回执分别归因，父意愿不能算第二个社交写入。
5. 这不是平台提供的原子事务，不保证多项全部成功，也不能将当前视频作者身份推断成评论者。若实例中途崩溃，保留待离线核查的阻断，而非自动解冻。

## 私信临时缓冲与跨进程协调

- 已核验私信入站和已确认外发按账号、UID、会话顺序暂存；安静约 20 分钟、模型话题结束或累计 14 条／6500 字后安排 AI 批量整理。成品只能写 `private-social` 可衰减记忆，不能直接写长期档案。
- 本地 JSON 的短时读改写由 `private-conversation-buffer.lock` 原子跨进程互斥；提炼前将目标片段标记 `processing`／`claimToken`／PID，AI 请求期间不持锁。另一进程不可重复提炼该片段；只有 PID 被操作系统证实不再运行且认领足够陈旧才安全释放。异常、写账失败退避重试，不将缺失的结果当成「没有值得记忆」。
- 缓冲原文上限 48 小时；成功归档即删除。无锁或损坏的原子锁需人工检查；网络共享盘及用户恶意同时修改文件不在保证范围内。整理时必要脱敏片段将发往已配置模型服务商，正则脱敏不是完整 DLP。

## 完整关系理解与公开表达边界

- 经过可信 UID 核验，公共评论可读取同账号同人的**受限私密关系理解**；这种认知可影响亲密语气，不等于允许公开其来源或私人事实。原文、长期认识、可衰减经历的访问域与联系人发送授权仍严格区分。
- `interaction-privacy.mjs` 增加直接和间接披露风险检测：典型私聊／秘密／私人旧话题暗示、以及当前公开事实没有出现的私下独有短语。命中时该轮拒绝外发或选择沉默，绝不生成固定披露模板。公开来源独立含有相同事实时不机械封杀自然话题。
- 正则无法可靠判别所有委婉透露、关联识别和文化语义；第三方服务商持有输入的影响、公开评论连贯性及朋友隐私都需要实际对抗测试。
