## 安全及迁移设计

- 旧用户已有自定义配置、时段、人物、长期记忆、待办、授权与账号数据不改、不复制、不重置，也不需要新的数据迁移工具。新版代码没有新增存储文件；七天匿名账本对旧缺失字段做只读兼容。
- 旧表单在影子/自主模式可继续保存回访等无冲突设置、未变化的 Planner 参数及原时段；`lifeAgentMode` 切换和模型节奏/额度的修改必须通过新版预览/确认接口。
- 旧版模式下仍可手动调整独立 Planner 的间隔/额度。返回旧版模式必须走新版设置接口；不会自动重启旧 `peakValley` 计时器。
- 旧表单不会自动将 `shadow/active` 改回 `off`，不会把仍在使用的配置键直接从磁盘删除；新界面灰显已迁走的控件，避免误保存。`persistCfg` 原有两个持久化目标未变。
- 读取结果的匿名类别保留最多七天，但只有**48 小时内**且仍属于当前账号的最近三条可以成为下一次模型参考；跨账号、过期、执行失败、没有对应 `action + result` 的输入不能入池。此前旧记录不能推断为成功读取。
- 模型提示将类别解释为仅完成读取，不是完整观看、收听、兴趣改变、个人经历写入记忆或主动联系许可。当前只接 Node 侧原 Planner 自主轮，不篡改主 Session／主人 DM／普通 DM／公开评论的 Life Voice 记忆检索。
- Phase 7c 不通过读取匿名账本重建已遗忘的私人记忆，也没有新增模型调用、订阅、视频启动或社交写入。

## 离线验收与失败处理

`node tools/dev4-phase6c-phase7c-offline-acceptance.mjs` 使用 OS 临时目录和虚构任务/账号：8 个场景、两次假模型决策、零真实调用、零联网、零外发；两轮演示“第一轮成功读取 → 下一轮只见 `todo-read` 类别”；缺少成功回执、跨账号及超过 48h 均不参与。`node --test test/v271-dev4-life-agent-phase6c-phase7c.test.mjs` 验证具体边界。模拟成功**不代表**人格成长和真实模型选择变化。

Windows 实机仍应先通过项目停机冷快照指南做好用户数据保护，然后验证保存无关旧配置不报错、被管理的预算必须通过新版设置调整。无需真实发送任何 B站消息。旧代码物理删除、社交决策排他切换、完整经验因果/人格成长、宿主设置跨版本恢复及 Phase 8 仍未完成。
