# 2.7.1-dev.25 · 统一回忆的时间与意图约束

**当前 dev.25 代码架构记录（开发预览，未正式发布）**

## 问题和边界

dev.24 已有可选本地 Embedding、现有词法检索、真实记忆源和权限复核。不过，若直接对「昨天做过什么」执行语义相似度搜索，上个月的同主题记忆也可能获得很高分数；`createdAt` 是记录被写入的时间，不等于一段经历发生的时间。dev.25 给**明确由 Agent 自主发起的回忆请求**补充结构化时间/意图，不以关键字规则替代回忆决策，不单独增加聊天模型调用。

## 新协议

Agent 原有的首轮模型决策可选择提交 `RecallRequest`，例：

```json
{
  "queries": ["昨天真实做过的事", "昨天的交流和观看经历"],
  "intent": "activity_recall",
  "time": {"relative": "yesterday"},
  "kinds": ["watch", "social", "comment"]
}
```

`lib/recall-request.mjs` 统一验证查询词、意图、事件类型和日期：

- `intent`: `topic_recall`（默认）/ `activity_recall` / `conversation_recall` / `event_recall` / `fact_recall`。
- `time`: 可省略；仅允许 `today`、`yesterday`、`day_before_yesterday`、`day: YYYY-MM-DD` 或闭区间的 `fromDay`/`toDay`（跨度最多 31 个自然日）。拒绝无效日期与未来不支持的表达；**不因解析失败而取消本来要求的时间过滤**。
- `kinds`: 仅允许 `watch`、`social`、`comment`、`private-social`，实际候选必须首先通过原域访问控制。它只能进一步缩小，不得扩展权限。
- 模型不得提供 `uid`、`role`、`domain`、`timeZone`、任意文件路径或时间戳来修改权限或查询时钟；以上值由宿主和真实平台身份决定。
- 时间由宿主使用 `Intl` 及**DSH 所在设备的 IANA 时区**换算为 `[start, end)`。逐个计算相邻两个本地零点，因此正确支持夏令时 23/25 小时的自然日。不由 Embedding 解释「昨天」；也不向量搜索“昨天”的字面文本。

## 一条回忆的处理过程

1. **选择回忆（Agent）**：仍按 dev.23 的机制，由本轮模型理解当前话题，并自主决定是否调用记忆；普通闲聊无需回忆。时间条件来自模型的结构化意图，不产生新的独立 AI 规划步骤。
2. **真实准入（现有账本）**：`MemoryRetriever` 仍只读取当前有效的长期记忆和 `LifeMemoryGateway` 已衰减、仍被允许访问的生活经历；公开评论成功回执继续读取 `recent-comments.mjs` 的独立账本。主人、好友、陌生人的 UID、权限和已遗忘状态按旧权威逻辑过滤。
3. **结构化时间/事件过滤（新增）**：对要求精确日期的事件，仅保留 `stage=clear` 且 `at` 位于用户指定自然日内的经历。对长期认识，只接受显式可靠的 `occurredAt` 作为事件时间，**不能拿 `createdAt` 充当发生时间**。`fuzzy/trace` 不再具有可对外确认的精确发生时间，不可被当成某一天的已证实经历。对 `activity_recall` 默认只取活动类事件；`conversation_recall` 默认只取交流相关事件。
4. **混合候选排序**：如果是宽泛的时间线回顾（如“昨天都做了什么”），直接按真实发生时间排序，不要求主题字面/语义命中。若是明确话题 + 时间的检索，对过滤后的候选执行词法相关度与可选本地 Embedding 相似度融合；模型/向量服务不可用时只保留在相同过滤范围内的本地检索，绝不放开时间条件。
5. **异步实时复核**：每次推理结束后，从目前允许访问的实时记忆记录重新取得仍有效的 ID 与文本；向量库只负责排序，不能授权显示、不能复活已遗忘经历，不能写入事实。
6. **继续回答**：返回的只读证据交还原 Agent，不能触发第二次社交行动选择、私信或评论发送。

## 接线范围（与代码一致）

| 生产入口 | 新增结构化接线 | 说明 |
|---|---|---|
| 主人私信 Agent | `owner-dm-agent.mjs` → `ownerSearchAsync` | 新 `recall` 可携带时间、意图和事件类型；旧 `queries[]` 仍可正常检索。|
| 其他用户私信/评论（compact） | `interaction-batch.mjs` → `social-context-assembler.mjs` → `MemoryRetriever` | 首轮 AI 明确请求 memory 才检索；当前 UID 权限不变。|
| 主 Session / 手动记忆 | `memoryRetriever.retrieve(request, 'chat')` | 提供结构化请求路径；原普通字符串 API 不变。|
| 好友私信私密经历 | `privateContextAsync` | 只在 `bili-dm`/当前 UID 可见的实时记录里按日期筛选。|
| 主人/受信好友公开评论 | `comment-social-ai.mjs` | 模型主动回忆时携带 `recall`；公开回忆不读私密经历。|
| 主人公开评论成功回执 | `recent-comments.mjs` | 依据账本实际日期筛选，并继续实行原账号与 BV/楼层/最晚时间围栏；本地回执不保证目前仍在线可见。|

**仍存在的边界：** `full` 兼容模式及部分专业 Agent 的历史预装配并未全量改成统一协议。不是所有历史长期记忆都保存 `occurredAt`，无法可靠确定事件日期的记录不会凭空补造时间；实际 GGUF 模型召回质量、真实 Windows/B站、账号切换、72 小时运行和跨日 Life 因果仍需实机验收。本轮不声明这些条件已满足。没有为时间检索建立第二数据库或对外写权限。
