# 2.7.1-dev.2 补充：互动真实按需读取与匿名逐轮诊断

> 本轮是 `2.7.1-dev.2` 的增量，没有升级版本号。使用者应先应用以前的精简按需补丁，再应用本补丁。

## 真实实现与没有实现的边界

生产入口为 `index.js` 的 `interactionBatcher`。默认 `interactionContextMode=compact`；`full` 走历史完整行为。`lib/social-context-assembler.mjs` 的 `batch(items,{mode})` 在首轮 compact 只提供经过授权的基础身份、关系与生活状态，不主动执行长期记忆、梗知识或人物画像查询。

如果同一 UID 的互动模型通过 `contextRequests` 要求 `memory / portrait / meme`，`loadRequestedContexts` 才会对该消息、该身份和该渠道调用现有真实查询函数。查询失败会拒绝发送草稿；无查询结果显示 `not-found`，不能推理为“这个人从未说过”。每轮最多四类，最多一次模型续推。`full` 与独立主人私信 Agent、DSH 主 Session 保持原行为。

**尚未优化成完全动态检索的内容：** `todo / recommendation` 在私信的旧接口仍提前生成可信进度 / 候选事实，避免破坏已接受任务的承诺一致性；`video / history` 来源于当前渠道已合法取得的上下文 / 近期聊天记录。接下来若要延后这些来源，必须在最末的承诺和事实检查处保留独立可靠的访问，不能只因模型没有申请就跳过核验。

## 数据边界

- `SocialPolicyGate` 在数据源授权，未认证 UID 不读私密内容；任何请求都不具备写入权限。
- 批处理器按 `kind + UID + privacyGuard` 隔离模型调用。公开评论不检索他人的私信原文。
- 隐私探询执行清空上下文与限制外发；即使模型请求额外字段，也不会恢复敏感资料。
- `availableContexts` 是能力清单，不是已有证据清单；模型续推时附 `retrievalStatus`，区分找到与未找到。
- 继续复用 `assessTodoReply`、视频事实校验、发送授权及真实平台回执。

## 主人验收入口

管理中心 → AI 模型配置 → 后台评论与私信 →「刷新真实调用统计」：新增最近 12 个互动批次，只显示类型、模式、证据请求/命中/无命中和续推状态。**不保存 UID、原文、记忆摘要或模型输出**，重启后清零。没有记录不表示鱼鱼选择沉默，也不代表未使用其他独立 Agent。

建议用测试账号分别进行无待办日常问候、追问已接受待办、询问共同经历，以及切换 full 模式的对照实验。比较 AI 调用次数、响应时间、是否正确答复和是否出现无凭据的承诺。

## 尚未完成

此补丁不能证明“鱼鱼说话更像真人”，真实模型/B站/Windows 端到端 A/B 仍需验证。长时人物认识纠错、兴趣对行为的真实影响及生活契机协调层尚未实现。
