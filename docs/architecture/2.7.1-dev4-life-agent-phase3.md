## 生活时间线的证据分级

管理中心显示：**生活契机（匿名类别） → 自主选择（动作枚举） → 结果状态（执行码或未回执）**；同一意愿的 ID 只保留不可逆摘要，复用既有 `LifeOpportunities` 决策意愿而非第二份长期目标。时间线仅仅是短期**可观测诊断**，不是能够回忆的永久“人生记忆”。真正长期记忆仍只能从可信经历、可衰减的 Life Memory 进入模型；不能因为时间线写了“想探索”就自认已经观看、听到音频、关注、回复或发布。

事件池在账号作用域不可用、发生切号、模型报错或 IO 写入失败时，不得产生另一账号“成功考虑”的伪记录。模型/工具结果不确定时不伪造成功。事件处理和日志从不构成新的社交外发许可。

## 两种备份是不同承诺，不能混用

**A. 现有便携业务备份（管理中心）**：允许在隐私最小化前提下转移指定的记忆、兴趣、已接受待办及显式列出的部分业务文件和 SQLite；旧 schema 2 可恢复。**不会**包括账号 Cookie、部分私密身份/外发运行账本、角色之外的外部插件目录、或这次短期时间线。UI 按此真实范围告知，不能声称“备份了全部数据”。恢复已做角色身份校验和原白名单审查；不靠 portable 恢复外发许可。

**B. 完整本地冷快照（新命令行工具）**：在彻底退出 DSH Desktop/所有读写本运行目录的相关进程后，逐文件复制当前 `$DSH_HOME/bili-duty`，**包含**所有该目录下的旧文件、新未知文件、账号/私密数据、Cookie 和短期日志；不经过通用业务备份的白名单过滤。写入私密目录和 SHA-256 文件清单，复制后再次验证。恢复验证全部文件与原角色身份，再同目录原子切换，旧目录保留在独立的 `*.pre-restore-*` 安全副本中以供人工回退，且新目录会设置 `restore-freeze.json`：**必须重新启动 DSH 并在管理中心以同一 UID 明确复核，才能继续 B站平台操作。** 不能默默恢复旧自动发送。用户应保管好该恢复前目录，不能上传 GitHub/网盘或分享到聊天。

**不在 B 类快照覆盖范围**：宿主 DSH 外部的插件配置库、宿主 secrets、外部 `dsh-fish-memory` 目录（如有）、宿主对话历史、独立安装在数据目录外的素材与模型、操作系统加密密钥。DPAPI 等凭证通常不可跨 Windows 账号/机器直接复用。**完整重构前仍需对这些外部来源另行安全备份，并安排用户实机恢复演练。** 本工具只承诺复制及校验指定数据目录的文件字节，不承诺旧版以外的所有应用一定可直接运行。

### 安全使用（Windows PowerShell，示例）

以实际 DSH Home 为准，不要猜测路径。**彻底关闭 DSH Desktop 和相关服务**后，在项目根目录：

```powershell
$state = Join-Path $env:DSH_HOME 'bili-duty'  # 如 DSH_HOME 未定义，先手动填写实际绝对路径
$save = 'E:\PrivateBackups\dafeiyu-cold-2026-11-05' # 选一个不存在的本地目录，且不能在 $state 内
node .\tools\dev4-cold-state-backup.mjs backup --root "$state" --to "$save" --stopped
node .\tools\dev4-cold-state-backup.mjs verify --snapshot "$save"
```

如确实需要还原，**再次停机**，先确保已经另存当前数据目录，然后执行：

```powershell
node .\tools\dev4-cold-state-backup.mjs restore --snapshot "$save" --root "$state" --stopped --confirm RESTORE_FULL_DSH_STATE
```

恢复工具不会静默合并两只不同鱼鱼的角色 ID，若不一致会拒绝。完整恢复是人为选择将当前数据回滚到快照时间点：会还原当时的私人资料、已删除资料和旧设置，因此**恢复前必须审核是否违反之后提出的遗忘/撤回要求**；需要先确认安全边界，而不是将旧私密归档自动重新灌进模型。恢复后验证生活记忆和待办数量，复核账号和发送权限，再主动解除冻结；不应因为看到快照原有“发送成功”就自动重复发送。脚本也**不能自动检测所有后台进程是否已退出**，`--stopped` 是操作者对停机的明确确认。

## 重构迁移与回滚门禁

1. UI 和固定刷视频主驱动可以替换；首要守住已有数据文件的读写源、字段的语义及已授予权限。新短期时间线不是第二个记忆库。
2. 老用户升级前先做 A 类便携备份 + B 类停机快照（含校验结果），再迁移；升级期间不改写旧版备份格式，也不自动迁移已衰减/已删除的私密认识。
3. 如果发现账号绑定、旧待办、社交回执、隐私数据或回访去重错误，停止迁移，使用冷快照人工恢复，重新复核权限。
4. 任何新的长期存储版本都要同时交付旧版样本回放、恢复可验收路径和可逆性说明；不以“单元测试通过”代替用户的 Windows 存档验收。
