# 2.8.0 — 私信自然对话、跨日记忆与管理端隐私展示审计

> 代码基线：2.8.0-dev.14（已包含本次测试维护修改）。本补丁不更改实际 DM 发送协议或授权边界。

## 多气泡与沉默续聊的真实执行链

- `index.js` 的 `dmP6Enabled` 默认 `true`、`dmP6MaxBubbles` 默认 3。`dmConfig()` 向普通 `dm-autoreply` 提供这两个值；`interaction-batch` 在首次模型调用里提供可选的 `messages`（1–3 条）。`dm-autoreply` 用 `deliverMessageBurst()` 逐条核验发送；每条均需单独的平台回执；新消息到达或授权/限额改变后停止剩余气泡。
- 模型返回单条 `messages` 是合法且自然的选择，并非功能失效。若启用旧版 `dmStrangerOnce` 的单次授权兼容模式，对陌生人的回复强制只允许一条、禁用后续预约；升级到自主多轮陌生人私信需要主人明确的 `dmStrangerAutonomyEnabled` 授权，不能静默扩大。
- 普通 DM 的沉默续聊 P6-B **不是**默认 90 秒发消息。模型仅能在本轮 `reply`、会话确实尚未结束、提出 `idleReconsiderMinutes`（5–360）与合法理由时预约。`social-continuity-ledger` 只保存脱敏意愿，届时重新检查收件箱、账号、权限和节奏，再由模型选择回复或继续沉默。旧授权、拒联、收到新消息或技术失败可能终止此机会。
- 主人 DM 的沉默续聊属于 `owner-dm-agent` 的另一种自然联系：`ownerDmSilenceFollowupEnabled` 与主动联系授权同时成立，达到配置的沉默时长并有真实回复记录、无新消息时才会考虑；本轮单次去重。它与主 Session 的 90 秒短暂停顿不相同。
- 管理中心现有 `/status` 的 `dmAutoReplyStatus.p6LastTurn` 和 `p6` 统计只存类型、数量与预约状态。此次增加了本轮计划/确认条数的清晰文字，不读取私信原文。缺少具体用户真实日志，不能推断“模型每轮都选择了 1 条”的原因。

## 跨日聊天上下文的边界

- 普通 DM：默认最多保留最近 40 条 `user/assistant` 原文（可配 0–80），每条最长保留 14 天；`interaction-batch` 的输入会按长度截断。因超过上限而被挤出的近期**来信**可能保留最多 12 条短摘录（每条 110 字；最长 7 天），不构成永久记忆。
- 主人专属 Agent：对话状态最多保留最近 12 条、14 天内的历史，常规决策通常读取最近 8 条。可选读取主 Session 的上下文（默认关闭），其设置不是普通 DM 的历史条数。
- Life 有私密受限的 `private-social` 人生记忆与按需召回；它只接受经过审核的少量偏好/边界/经验事实，而不是整段对话逐字长期存储。`private-social` 的回忆按当前私信角色/UID 做权限隔离。
- `socialMemoryHalfLifeNewDays` 等按关系分级的半衰期只适用于新产生的公开社交记忆，不直接决定普通私信的原文保留天数，也不能保证每条私信长期可逐字复述。
- 因此跨日话题在 14 天、40 条范围内通常能继续，但超出后能否回忆取决于独立的经核验人生记忆，不能声称“全部记得”。

## 最近私信会话隐私展示

- `lib/management-console.js` 的 `loadDmRecent()` **不再读取或创建包含 `c.recent[].text` 的 DOM 节点**，也不把这些原文放进 `title`、`aria`、隐藏元素或 CSS 模糊层。
- `lib/management-console.html` 使用装饰性的模糊线条与温柔提示；保留联系人、最近确认回复时间、会话数量、保留/过期消息数量等诊断元信息。
- 只修改管理中心「最近私信会话」展示层，不清除底层 DM 历史、发送事实、日志、私密记忆，也不改变 `/dm-recent` 接口。管理员若使用开发者网络工具仍可能直接访问原接口（它仍在本机授权边界内）；本修改不是加密或新的 API 权限限制。

## 测试与尚未覆盖的事项

- 此补丁的新增测试验证：私信原文不进入最近会话视图、现有 API 与记忆设置保持不变、跨日保留、公开关系衰减独立、P6 条件接线不变。
- 在本机 Linux 环境的 Node 定向与核心自动化可以验证协议接口，但不能证明用户的真实 B站账号上产生了某个多气泡或沉默续聊回执。建议在 Windows 管理页读取「后台私信状态」的计划条数、确认条数和待考虑续聊数量，再结合已经存在的脱敏日志区分模型选择、权限、模型超时与平台回执问题。
