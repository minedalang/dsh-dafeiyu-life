## 实际运行契约

1. **生活通道**：按原活动时窗、配置间隔运行。新档位为安静 `120 分钟/12 次`、自然 `30/40`、活跃 `10/100`，是每日自主模型调用**上限**，不是必须触发的任务或平台视频启动次数。手动只读待办、子待办续行和对照探针仍扣生活额度。
2. **社交快速通道**：仅在当前账号和生活开关有效、收件器已经核验来源、匿名事件到期时触发。它可不等待普通生活间隔和日常时窗，但必须拿到同一决策租约，并且模型可选动作仅是 `consider_social` 或 `skip`。如果可撤回的影子上下文授权有效，额外影子判别也消耗同一社交快速额度；**没有**新增真实回复/发送路径。社交快速额度暂固定每天 `24` 次；快速额度用尽后不再进行快速社交模型调用，正常定时生活考虑仍可使用自己的剩余额度（仍遵守正常时窗）。固定值在模型/平台实测后再评估是否配置化。
3. **全局上限**：既有 v1 单文件中的 `runs` 仍是真实累计模型预约数，新增 `lifeRuns`、`socialRuns` 分类计数；原子事务同时判断 `lifeRuns ≤ 配置额度`、`socialRuns ≤ 24`、`runs ≤ min(288, 生活额度 + 24)`。现有 v1 同日账本只有 `runs` 时，历史调用全部归入生活额度，不退款；过日按原规则重置。模型预约数不是提供商实际 token / 金钱成本，**尚没有全插件、所有外部模型请求的货币硬上限**；这仍是 2.7.1 后续研发的发布前缺口。
4. **独立视频门禁**：不修改视频 Agent 的既有限额，每日最多 2 次、最短启动间隔 180 分钟，仍检查原 `runDuty` 的账号、报告和视频每日门禁。`exploration-ready`、`video-round-ended` 继续用原事件账本/成功回执续行，社交通道不能消费模型机会去触发视频。启动和退出只证明进程生命周期，不证明看到了画面或听到了声音。
5. **旧档位兼容**：持久配置 `180/4`、`60/12`、`30/20` 展示为「保留旧安静/自然/活跃」。预览或保存旧档只维持原数值；只有用户明确选择新预设并保存才迁移。纯新建安装的默认配置仍是原 `180/4`，不隐式变为更高额付费档。
6. **错误/恢复**：失败事件有有界退避；已尝试执行但回执不明继续冻结，不自动重复行为。事件/时间线通过每条真实事件 ID 二次散列成 16 位不透明 `ref`；账号隔离、脱敏诊断、七天保留不变。模型可见过证据不等于实际参考或人格成长。

## 已接线与后续缺口

- **已接线**：核验后事件即时通知、闲置分钟轮询兜底、生活与社交只读关注额度、预设/老配置兼容、DEBUG ref、视频自主委派原门禁和后续事件。
- **尚未接线**：正式社交决策/回复所有权、跨全插件模型计费总闸、按联系人真实社交响应节奏、视频 Agent 内视觉和音频的事实证明、完整长期成长因果链。以上不能声称由本包 A 完成。
- **发布门禁**：Windows DSH Desktop、模型服务商真实成本、B站视频元数据/实际视频进程、两个账号切换与冷恢复、真实社交受控测试以及 72 小时/7 天观察。离线单测只是功能证据之一。

## DEBUG / 触发与验收办法

- 启用「鱼鱼的生活」，选择新的活动预设并预览、保存；需要低费用就选择安静或保留旧档。**不会开启 B站新增外发。**
- 核验的新私信／公开评论由原收件器登记后触发同一 Life Planner 的社交快速只读考虑。Life DEBUG 记录 `social` 触发类型、候选数量、原子额度占用、模型枚举选择、失败归因。
- 到「决策全过程 DEBUG」按匿名事件 `ref` 与「真实生活」时间线关联；不展示 UID、聊天正文、可反推的原始 sourceKey；一个无内容的“考虑到私信”不表示真正回复。
- 「鱼鱼的生活」状态和原管理诊断展示生活/社交/全局计数，以及视频独立额度和可能的启动冷却；`modelInputChars` 仍是字符估算，不是 Token 或实际货币成本。
