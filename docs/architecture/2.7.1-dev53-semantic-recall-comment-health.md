## 一、神经回忆场：关键词→向量→线，而非空间距离

- 搜索框位于整个 `.neural-recall-board` 内，故原生全屏与 CSS 全屏均可直接搜索，无需退出全屏。
- 只有用户配置并启动**本地 Embedding**，当前索引就绪，查询完成后才以 `embeddingIndex.search()` 得到原始高维 cosine 分数。先筛选当前允许显示的花园/情节记录，再以 `memoryRetriever.embeddingCorpus()` 的**原索引文本哈希**匹配存储向量；不使用展示标签代替索引文本，不会产生静默错配。
- 后端用 `corpusId → neuralProjectionKey` 映射向量命中到匿名图节点；原始索引 ID、原文、文档向量不通过 API 传入浏览器。查询向量在同一 PCA 坐标基下定位到三维视图；它的屏幕距离仅用于绘制。**连线命中/线宽/亮度使用独立真实高维 cosine**；经过 `minScore=0.30` 的已命中条目最多绘 320 条，若模型停用或当前索引哈希不匹配则明确降级纯词法检索、零语义连线。
- 原本绿色/粉色/灰蓝色“共同来源证据”边照旧只认共享 source reference；语义匹配的青色查询连线不代表两个回忆在现实里有关或产生了兴趣/关系。低显著性节点不冒充遗忘，衰减仍依当前 stage 显示。
- 神经图谱是**动画展示当前回忆检索结果**，不是重现模型隐藏思考。真正的 Life/主 Session 回忆路径：当前场景/意图 → 当前授权及遗忘过滤 → 词法候选 → 可选本地 Embedding 排序/可选低成本模型甄选 → 取真实记录 → 经 Life Voice 自主回应；并不承诺每轮都有此步骤或会调用本地模型。

## 二、长期记忆与“刷 B站学会梗”的现状

- `MemoryRetriever` 支持受场景约束的当前可回忆记录、时序/意图过滤与可选本地 Embedding。向量主要负责**找回有关信息**，不是直接写进系统级表达模式。
- `LifeVoiceContext` 在不同交流入口统一按当前成长风格、人格状态、连续情绪与角色基础人设组织表达，且预算分配可能令固定人设更显眼。实现接口不等于已证明日常聊天的习惯长期发生变化。
- 独立 `meme-learning` 会在跨**至少两个不同 BV** 的现有观察证据积累后提炼谨慎的梗知识；视频 Agent 有专用检索提示。这一知识库**没有作为持久表达习惯自动合并进 Life Voice**，故不能因“有梗库”就称已学会自然地说梗。用户提出的“风格由经历沉淀而成”仍需后续证据丰富后的表达偏好提炼、保守采纳与主 Session 对照实测，且不得无条件模仿单个 UP 主或用未证实的梗。
- 本版没有强行加入主人选择的风格卡片；人格形成应由可信经历和反思影响 Life Voice，主人只掌握交流边界与授权。

## 三、14:30 主评论及生活线索判读

- 上传的匿名决策 JSON（UTC+8）14:30:47：`proposed=1`, `approved=0`, `blocked=0`, `verified=0`，枚举 `proposed-not-approved`。表示本轮一次真实工具提议**没有拿到 Life 写入 grant**；该 JSON 无 `reason`，**无法倒推出 Life 自愿拒绝、权限门禁、网关异常或发送成功**。对应 15:03:56 `no-confirmed-selection` 是另一类：没有本轮新入选，不能要求强制评论。
- 以后对原网关真实 `defer`、Life 明确否决、技术阻断分别留安全计数及 `reason`；网关 `choose()` 抛异常也记录技术故障（不记私密文案）。既有日志不会追溯改写。
- `verified-metadata` 只证实公开视频元数据，绝不等于实际观看视频；`verified-discussion-read` 仅评论区读取。Episode 的 5/5 步满是正常**安全上限**，不是“鱼鱼完全沉淀兴趣”，下次可以选其他线索/新 Episode；看过作者投稿标题也不是播放。没有点赞收藏关注既可能是自主选择，也可能是权限/候选/冷却问题，需要具体 action trace 才能区分。

## 四、Life 每日模型决策与重连健康

- `autonomousPlannerDailyLimit`（1～288）是**Life 生活模型决策额度**，不等于评论、私信、点赞或视频的每日发送次数；它影响获得新生活意愿/行动规划的机会。专业 Agent 仍有各自的模型调用、平台权限、速率和读回门禁，可能受共享额度间接影响。
- 原 `AutonomousPlanner.status()` 暴露 `lifeRuns`、`runs`、`dailyGlobalLimit`、`schedulerPulse`、`nextDecisionAt`。dev.53 的 Life 页面显示这些读数，30 秒可见态刷新或人工点击刷新，均**不调用模型**。上次调度检查距现在超过 150 秒且该调度应运行才告警；“没有产生新的模型决策”本身不告警。
- 系统健康横幅复用 `systemHealthSnapshot()` 的本地快照，额外报告 Life 调度器异常停止/心跳停滞。DNS `ENOTFOUND` 与 B站 `-509` 属于后台监听的网络/DNS/限流退避，不自动断言 Life 自主模型停止；也不保证网络已恢复。用户关闭/暂停 Life 时不发误报。
- 本次上传的决定记录证明 15:19 重启后至少 15:52 手动、15:54 自动仍有 Life 决策。只有决策文件没有完整一分钟心跳历史，不能据此确定 15:33～15:49 的每次 tick 是否运行成功；后台横幅/实时计数用来补足这一证据缺口。

## 质量与限制

- 无新外发动作、授权扩张、新记忆源、平台网络探测、自动重试，也不改变真人/视频事实强度。新的 `embeddingIndex.search()` 查询向量是用户主动搜索引发的本地模型调用，**不是零模型调用**；仅 PCA 图绘制完全只读。
- 需要用真实 Windows DSH、已安装本地 Embedding、实际 1000/10000 节点和网络断联持续复测动画布局、性能、角色表达变化与发评论审批原因；离线测试不能替代这些事实。**`releaseReady:false`；不合并、不发布。**
