# 2.8.1-dev.3b.16：官方 videoshot 雪碧图低清分镜

## 实际问题

`lib/preview_vision.py` 以前有 `_pick_indices` 均匀时间抽帧、`_candidate_indices_from_primary` 同源雪碧图最多12候选、`_select_distinct_previews` 最后最多3张画面。不是弹幕高能图；它已经拆开雪碧图，却最终只把最多3个缩略格送到模型。没有足够的时序覆盖，不适合直接形成动作/剧情结论。

## 修复策略

- 真实视频优先 `adaptive_video.acquire_adaptive_frames`：不能把 `sampler_version=6` 的真实视频解码和本方案混为一谈。
- 只有被适配器明确标为 `fallback=True` 时，才运行官方 videoshot 分镜。`fallback=False`（预算、CDN Range 身份错误、平台风险）继续明确失败。官方图片域名/路径/CDN 白名单不变。
- 使用官方时间索引，不读高能弹幕或 PBP。选择最多6张按视频时间覆盖的原拼图，取其有来源的格子，保留每格的秒数；按画面变化去重，至少保留各源拼图的代表格，最多普通12／深入24或48个时刻；仅重拼原生低清 JPEG，不对缩略图放大宣称高清。
- 最多6张原图，图片总网络读取上限8MiB，若用户剩余读预算更低则优先使用更低上限。超过时显式失败，不伪造时刻。
- 新 `sampler_version=5`、`strategy=videoshot-storyboard-stratified` 或 `focus-videoshot-storyboard-stratified`，记录 `frames_selected`、`storyboard_count`、`sheets_downloaded`、`sprite_bytes`、`low_resolution`、`times`；JS 证据层检查来源、帧数、分镜数量、字节、时间窗。所有成功回执都是 `preview_frames`／`preview_visual_analysis`，不得变为 `decoded_video_frames`、OCR 或原声感知。
- 本地视觉模型收到的每张分镜最多12个带时间码的格子，以独立低清提示词按时间段描述并声明采样缺口。旧 `analyze_preview` 最多3帧调用兼容，新缓存身份与旧缓存隔离。真正 JPEG 只供主人 Debug 的30分钟本机相册；Life 经历只留受控来源与时间的证明。

## 未解决的边界

原始缩略图通常分辨率很低，尤其是商品文字、连续动作与声音不能保证辨认；源图片不足、同画面大量重复时也可能远少于目标格数。暂未对Windows 实机、B站真实 CDN、Qwen3.5/MiniCPM 模型作端到端视觉验收，不声称已经具备连续视频播放能力。
