# 2.7.1-dev.4 · 视频轮结束后的真实反馈与后续自主考虑（开发增量）

> 这是生产代码的 **生命周期反馈修复**，不是新视频调度器、观看/听音证明、真实社交接管或 Windows 实机验收。

## 统一层归属

`Headless 子进程 runDuty → 原 watched/seen 作品账本 + LifeAgentEvents.videoRounds 的匿名进程回执 → video-round-ended 生活唤醒 → 原 AutonomousPlanner → 原 LifeCapabilities / SocialPolicyGate → LifeAgentEvents 决策记录 → 管理中心`。

- **生活决策唯一所有者**：`lib/autonomous-planner.mjs`；主开关、生活开关、影子/主动模式、模型额度、180 分钟间隔、日启动次数不改变。
- **真实视频进程唯一执行者**：`index.js` 的 `runDuty`，继续使用原 Headless 环境及平台门禁。与原手动视频轮共享一套执行路径。
- **真实作品唯一事实源**：原 `seen` 账本；轮次账本只证明子进程启动/退出和原账本中的新增入选数，**不证明视频画面看过、音乐听过、制作或发表作品**。
- **生活事件与匿名轮次唯一状态源**：`lib/life-agent-events.mjs` 中原 v1 账号隔离文件。新增字段全部可选，不迁移、清空或重认领旧记录。
- **能力入口和诊断**：原 `lib/life-capabilities.mjs` 新增只读 `inspect()`，仅公开 allowlist 故障原因，不把平台 UID、原始错误、模型信息或发送权限暴露给 Life。
- **社交入口**：旧私信/评论决策器继续唯一持有生产发送权。不会因为视频完成、兴趣、友好度或生命模式而放宽任何外发许可。

## 已解决的实际断层

### 1. 冷却期不能吞掉真实轮次结束事件

真实视频轮经平台执行器结束并保存可信进程回执时，向既有匿名事件收件箱提供 `video-round-ended`。如果此时没有其他可选行动，视频执行能力因 180 分钟冷却、日启动上限、或另一视频进程忙碌而暂不可用：

- 该结束事件**保留原事件 ID**，不结算成“已经考虑过”；不会每分钟重新产生一个模型请求。
- 手动唤醒与无关空档通知仍按原规则结算；社交信号仍可独立进入 Life Agent 的匿名注意过程。
- 冷却结束后或视频进程空闲后，下一次原有 Life 自动检查可重新让模型作自主选择；并不保证启动视频。
- 日上限仍按原有日额度释放；仅显示预计最早可能考虑时刻，不承诺精确自动执行。
- 旧版本已结算掉的事件不会凭空重建，更不会伪造历史视频行为。

### 2. 可审计的子进程事实，不能冒充感官事实

仅从当前账户 `LifeAgentEvents.status().recentVideoRounds` 中筛选最近 48 小时、最多三条真实结束回执，转换成枚举化 `recentVideoRoundFeedback`：

- `origin`：Life 自主委派或手动启动。
- `outcome`：正常退出、失败退出、退出结果不明。
- `pickedCount`：**只有正常退出且原账本已核实的新增入选数**才可能是非空数字；否则是 `null`。
- `proof`：始终声明只是进程级生命周期，非看过视频/听过音乐。

不向模型提供内部轮次 ID、BV、UID、标题、Cookie、评论原文、模型隐藏推理或私密记忆。时间线上已有真实视频轮次与逐 BV 入选条目仍独立展示。决策记录只增加 `videoRoundFeedbackOffered`（提供过回执），**不能宣称模型实际采纳、情绪改变或人格成长**。

### 3. 可信结束回执才能创建后续唤醒

原 `runDuty` 子进程退出码 `0` **不足以证明回执持久化成功**。只有同账号的 `recordVideoRoundFinish` 实际返回首次 `completed` 回执，才建立 `video-round-ended` 唤醒；失败、账号切换或账本异常不生成成功事件。唤醒以随机轮次 ID 作为内部去重来源，原源值不会写入事件记录。

### 4. 区分临时视频忙碌与永久能力不可用

`LifeCapabilities.inspect()` 只是对已经注册的能力调用原 `available()` 后做脱敏分类；原 `run(id)` 仍在执行前重新核验。已允许的分类：账号未就绪、关闭、视频进程忙、已到视频每日额度、报告关闭后的一轮限制；未知适配器错误仅报告 `adapter-unavailable`。

对于“视频进程忙”的结束反馈，保留待考虑事件，直到原执行器变为空闲；不解除预约、不重复启动、不替代真实平台回执。

## 管理与 Debug 验收

设置 → 大肥鱼 → 鱼鱼的生活 → **重新核查真实状态（零模型调用）**：查看当前账号的后续待考虑数量，以及有明确冷却/日额度时的最早考虑时间。运行诊断会在真实 Life 决策调用模型前出现 `video-round-feedback`（只含是否提供、最新轮次状态与入选数是否已核实）。

离线模拟路径覆盖：正常结束后冷却等待→到期后一次模型选择、日额度、另一个视频 Agent 忙碌→空闲、手动唤醒不抢占视频结束事件、影子模式不执行、跨账号隔离、未知回执与旧 v1 文件兼容、日志及模型提示脱敏。

## 仍未完成

- **社交唯一决策权**：旧 DM/评论回复器仍持有真实发送决策。不存在 Life Agent 的真实社交切换开关。
- **人格因果闭环**：这次提供了匿名子进程证据，不把它自动升级为长期感官记忆、兴趣、关系或人格事实。
