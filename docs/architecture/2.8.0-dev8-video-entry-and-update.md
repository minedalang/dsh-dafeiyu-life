# 2.8.0-dev.8 · 视频只读入口进入 Life 互动续行与更新提示

> 范围：2.8.0-dev.7 → 2.8.0-dev.8；仅开发预览。没有在 Windows DSH 或 B站真实账号上执行点赞、收藏、关注或原创评论。不能视为正式发布验收。

## 缺陷与接线

- **原断点：** 主 Life `inspect_opportunity` 原本核验 BV 元数据并在机会账本记录 `inspect`，却只发匿名 wake，没有可供 `continueLifeRead` 使用的 intention ID。`execute_read` 中 Life 自主完成 `watch_video` 后也未关联一条视频探索 intention，所以完整视频 Agent 之外的只读探索不会收到相同互动选择菜单。
- **修复：** 在原 `life-opportunities` 当前账号账本新增 `beginInspectedOpportunity` 与 `beginCompletedVideoTodo`，分别依赖原机会决策回执，及真实完成的只读待办与同 BV/真实标题回执。保存 `selectedBvid`、`metadataAt`、安全标题和有界步骤，复用原 `continuationMenu`、原模型每日额度和 `life-continuation-write` 原平台写入。每个新来源至多建立一个 Life Episode，`resume_episode` 仍由鱼鱼自由选择。
- **互动资格：** Life 可以自选点赞、收藏、关注视频真实作者或发表原创主评论；不会强制执行，也不把视频元数据当作音画观看。此处为 dev.8 历史设计：当时评论需 `autoComment`、配额、`commentReady` 与平台新证据；**dev.11 已删除 `commentReady` 的简介字数/热评数量门槛**，现依真实 BV/标题/授权提供评论候选，执行器独立核对账号、额度、防重、原 Life 意愿与结果。没有扩大陌生人私信/跨串回复授权。
- **失败安全：** 失败/不匹配/过期/账号切换/未完成都不创建可写 Episode；未知写入冻结。`todo-done` 通用因果记录与本次视频探索意愿是不同用途：同一完成回执不会被当成两次真实视频观看。

## 版本与用户交互

- 原设置页 2.7.1 宣传区删除；首次打开设置页，仅向本机宿主调用 `/update?source=npm`，宿主缓存从 `registry.npmjs.org/dsh-dafeiyu-life/latest` 获取的正式版本号，不把 GitHub 预览版当作 npm 正式版。
- 当 npm 版本高于当前安装版本，顶部显示红色版本提示与升级按钮；点击仍走原宿主 `/upgrade` 安装任务，并需重启 DSH。手动“检查更新”维持 npm / GitHub 两来源旧功能。网络不可用不显示伪造的“已经最新”。版本对比支持数字预发布后缀顺序，例如 dev.8 高于 dev.7，正式版高于同号 dev。
- Life 决策诊断额外记录 `video-delegation-chosen`、`video-offered-other-action`、`video-not-offered` 中的一种脱敏类别，不记录用户或视频 ID 与模型原文。

## 验收入口

- 手动在「大肥鱼设置」查看顶部新版本气泡；无更新或 npm 离线时不应误报；更新操作由原主依赖日志观察结果，**不能将点击等同安装成功**。
- Life 管理中查看选择了 `inspect_opportunity` 或 `execute_read` 的轨迹：观察 `verified-metadata` / `done` 以及可选续行；随后出现的模型意愿、执行器和平台回执必须分开显示。不能仅因出现 `comment_video` 候选就记为平台发评。
- 测试：`node --test test/v280-dev8-video-entry-continuation.test.mjs`、`npm run check:life-architecture`、`npm test`、`npm run test:python`。模拟执行器仅断言接线和阻断，不对 B站发送。
