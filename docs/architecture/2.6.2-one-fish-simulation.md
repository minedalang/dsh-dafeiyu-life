# 2.6.2 dev · “同一条鱼”跨渠道模拟验收

> 本报告基于实际源码和本地离线模型桩（mock），**不是**在用户 Windows DSH Desktop 上调用真实模型或 B站接口。下文的示例对话是预期风格示例，不是模型实际生成的内容；测试通过不代表可以对随机生成模型的每句话作 100% 保证。

## 验收目标与判据

“大肥鱼是同一条鱼”不是所有场景都说相同的话，而是**角色身份、人设底色、成长风格、连续情绪是同一份实时数据**；关系、渠道和当前事实只调整表达与动作许可。

1. **人格一致**：主人配置的核心人设、世界观、认可的成长风格、有效成长人格、当前情绪；角色不会因换私信/评论/回访而成为通用客服。
2. **关系一致且隔离**：相同 UID 的连续消息保留关系；不同 UID、评论和私信不会共用私密上下文，白名单/熟悉度不授予未授权写操作。
3. **事实与意愿分离**：已核验成功回执可在未发送回访时供当前收件人查询；“查过公开视频资料”不能冒充看画面/听音/投稿；“已完成”不意味着一定主动回访。
4. **状态连续但自然**：开心可以更轻快、疲惫可以安静、烦躁不会迁怒。允许沉默，不强制注入固定卖萌口癖。
5. **原请求可辨认**：回访必须准确点明哪一件待办，不能只说“那几个视频”。

## 模拟覆盖

- 全因子提示词装配：**7 个语言场景 × 4 种情绪（开心、低落、疲惫、烦躁） × 3 类关系（主人、熟悉朋友、普通用户） × 3 类任务状态（未提出、待执行、有成功执行回执）= 252 组**。检查统一身份、六类上下文在预算内可见、人格不夹带任务事实。
- 模拟模型调用：用可替换的本地桩截取 `createInteractionBatcher` 最终模型输入；断言私信/评论不同 UID 不被合并、各自的记忆和关系不能串线；同一 UID 连续两条消息可合并并保留关系。
- 专项提示词：检查 `buildTrustedSocialPrompt`、`buildOwnerSocialCommentPrompt` 和 `buildOwnerCommentDraftPrompt` 在**实际最终提示词**中保留完整的六类人格；另验证主人私信主角色上下文配额不被末尾截掉。
- 事实模拟：构造同 UID、成功完成且有完成历史回执的视频待办，验证在未回访时即可被相同 UID 的同渠道读取；其他 UID 与评论渠道不可见；不据此声称真正听完音乐。
- 既有端到端/集成单测还会覆盖自主回访主题、米饭审核、权限、真实发送回执与去重。本报告不将这些单测冒称 B站远端实机测试。

## 本轮发现的五个真实缺口与修复

| 缺口 | 修复 | 审计理由 |
| --- | --- | --- |
| 评论意愿模型只见人格前 180 字 | 完整保留场景预算内的人格 | 180 字可能只有“同一角色核心”，看不到实际成长和情绪 |
| 自主评论模型只见人格前 260 字 | 同上，并让待确认评论草稿继承人格 | 不能只有聊天有个性，轮到公开发表评论就换角色 |
| 批量互动先组装 6,200/7,000 字、再整体砍到 3,000 字 | 改为在角色装配器内按 2,700/2,900 字均衡压缩六部分 | 尾部情绪和关系不能靠模型猜测 |
| 同一 UID 连发两条时不附上其关系上下文 | 在已按 `kind + UID` 隔离的批次中保留同 UID 关系和相关成长检索 | 同一人拆成两条消息不该突然变成陌生关系 |
| 主人私信 7,000 字人格再次被截到 5,500 字 | 在装配阶段按 5,200 字为目标分配，而不是切掉末尾 | 避免成长和关系被挤出模型实际输入 |

关键接口：`lib/life-voice-context.mjs`、`lib/interaction-batch.mjs`、`lib/comment-social-ai.mjs`、`lib/owner-comment-social.mjs`、`lib/owner-comment-draft.mjs` 和 `index.js`。不修改长期记忆格式、不读取 archive、不提高发送权限、不增加真实模型调用。

## 预期对话样例（人工撰写的验收标准，非模型输出）

以下假定同一个主人设定为“略傲娇、好奇、尊重对方”，并在不同场景保留可识别的性格底色，但**不要求每句固定使用这些措辞**。

| 场景 | 应有表达（示例） | 不应出现 |
| --- | --- | --- |
| 主人私信 · 开心 · 已查资料 | “我找到那条视频的资料啦～不过声音我还没真正听到，可不敢跟你装懂！” | “已执行公开元数据检索流程，等待下一步指令” |
| 熟悉朋友私信 · 疲惫 · 刚完成 | “你说的那条我刚去查过了，字幕里提到的事我还没琢磨透。今天先聊到这儿，好不好？” | “我是AI助手，我将继续完成您的请求” |
| 普通用户评论 · 低落 · 内容不足 | “这个我还真没看清，不想乱下结论。” 或选择不回 | 暗示看完画面，或将坏心情怪给对方 |
| 主人评论邀请 · 好奇 | “咦，这个标题有点怪，我先了解一下再决定要不要留言。” | 未经授权擅自发布评论 |
| 私信回访 · 开心 · 三子待办汇总 | “你之前让我找的大肥鱼翻唱那几首，我刚把能查到的资料翻了翻！还没听到音轨，所以先跟你说说进度～” | “前几天查看了数项公开资料”或“那几个视频” |
| 自主分享 · 兴趣强、社交意愿低 | 可以选择沉默；若真想聊，仅基于真实选片说话 | 选中别人视频却说自己投稿被推荐 |
| 生活动态 · 好奇 | “这个标题也太让鱼好奇了……先记住一下，暂时不装看懂。” | 将模拟情绪当作真实经历或泄露私信 |
| 主 Session · 正常 | “我记得我们刚才在说那个翻唱待办，不过我查到的是资料，还没听到歌。” | 切成通用文件助手身份，或把 B站权限当作主 Session 命令 |

## 无法靠离线模拟作出的保证

- 真实 DSH/Headless 模型会不会每次**真正遵循**上下文、口吻是否自然、追问是否具体：需要在 Windows DSH Desktop 以同一套实际 Provider/模型分别发真实对话测试；模型输出有随机性。
- 事实校验目前拦截有明确模式的高风险说法，不是无误的全中文自然语言事实证明器；必须继续审计实际调用工具、证据可用性与具体内容记忆。
- 用户自定义人设可能超过上下文预算，超过长度的文字仍会按权重压缩，不能承诺全文毫无损失；这次保证的是各来源不会被末尾截断**整个消失**。
- “同一条鱼”不等于语气完全相同：私信可能更亲近、评论更短、疲惫时允许不回；这些是同一人格面对不同关系和情境的自然变化。
- `emotionRecall` 当前处于暂停状态；自动对外内容以当前启用的主要发送通道为范围，主人明确授权的手动文本发送并不由模型自动改写。

## 本地运行

```bash
node --test test/v262-one-fish-dialogue-simulation.test.mjs test/v262-life-voice-unified.test.mjs
node --test test/*.test.mjs
python -m unittest discover -s test -p 'test*.py'
node selfcheck.mjs
npm pack --dry-run --json
```

**结论：** 经本轮修复，主要模型入口的角色上下文**结构一致性**和隔离规则可在离线测试中复现；真实生成风格仍无法做到数学意义上的“保证同一人格”。
