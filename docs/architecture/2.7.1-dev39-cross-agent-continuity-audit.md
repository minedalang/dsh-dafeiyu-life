# DSH 2.7.1-dev.39 · Life 各专业入口的自由决策和 Episode 持续性审计

> **开发预览，尚未发布。** 本文区别“真实已实现”“只有候选/有限续行”“尚未实现”；不把共享 Episode 回执误报为每个 Agent 有完整自由行动。基线 dev.38，增量 dev.39。`releaseReady:false`。

## 设计目标与验收口径

1. **专业 Agent 的自主选择**：在真实观察后，模型可以在该专业目前获授权的多种行为中自己选择，也可跳过或暂停。
2. **Agent 内部行动连续性**：实际工具结果进入下一次模型决策，不仅一次性给出 action 字段。
3. **跨轮 Episode 续行**：下次唤醒读取同账号、同对象/任务的可信已发生行为和有效意愿，不是仅凭语义猜测。
4. **跨 Agent 因果交接**：不同专业职责的合法消息和回执能关联同一活动，而不复制私密材料或扩大外发权限。
5. **真实动作证明**：只以原执行器/平台回执作成功事实；冻结未知状态，不利用 Episode 绕开冷却、账号隔离、遗忘和审批。

这五项 **必须分别验证**；只有 Episode 摘要的 Agent 不能判定为完全达标。

## dev.39 实际接线

- `lib/life-subagent-continuity.mjs`：按 `video/dm/comment/owner-dm/todo/social/reflection` 约束 sourceRef、行动 channel 与近期摘要，匿名删去 UID、内容和平台收据；公开反思仅接受 `reflection-public`。现有统一 `Life Episode` 是记录事实的唯一来源；本模块只读，不自动生成新工具权限。
- `lib/owner-dm-agent.mjs` 和 `index.js`：主人私信原四步有限工具选择读取当前主人私信 Episode；确认发送后才通过 `life-action-attribution` 写入 `owner-dm` 已核验回执。没有真实发送收据时不得标记成功。
- `lib/autonomous-planner.mjs`：常规 Life 决策继续拥有摘要；`socialFast` / `todosOnly` 也读取各自匿名 Episode；TODO 的原任务执行/回访现在可读取任务 sourceRef 且继续既有有限行动。
- `lib/life-reflection.mjs`：公开反思只读取新 `reflection-public` 回执通道的匿名动作；旧 `reflection` 通道可能混合私密与公开，无法无歧义区分，故不回填；私密反思不接收这些摘要。模型反思仍只作证据整理。
- dev.38 已有：视频、普通私信、公开评论的局部 Episode Handoff；私信长期可信联系人关注候选有独立授权、意愿重审批和平台读回。dev.39 未把这一候选扩张到其它无授权场景。

## 真实场景边界

- “给多年私信联系人突然想关注”：dev.38 已具独立候选与执行路径，但不能把“想”直接当作批准；原发送成功、可信 UID、账号、显式关注授权、冷却、后续 Life 意愿重审和 B站关系读回必须全部成立。dev.39 不自动扩大名单或开关。
- “看视频 → 自发顶层评论 → 隔天被回复”：原创主评论仍由视频 Agent 决策；接到真实评论后由评论互动 Agent 决策。Episode 可以各自读取脱敏相关信息，但**跨 Agent 同一意愿的自由导航尚无通用事务交接**。
- “回复 A 时想点进评论者 B 的主页 / 顺路回复 C”：目前缺少相应可信评论对象检索和评论跨串授权/工具回路，不能宣称已完成。
- “主人安排任务 → 查资料 → 继续下一步 → 隔天复查”：现有主人 DM 和 TODO 各有有限循环/状态；跨二者完整交接目标、已完成步骤、预算与结果回执仍没有通用协议。
- Episode 摘要不等于现有 Recall Service 的准入许可；长期隐私、遗忘、UID 隔离、账号授权都必须在原服务校验。

## 后续工程缺口（不冒充本轮交付）

1. **能力发现**：各专业 Agent 对工具/动作的枚举仍不一致；缺少基于实时证据、角色权限与来源的通用动态可用候选协议。
2. **子 Agent 全面动作循环**：普通私信、评论、社交、回访不具备“观察→工具→新观察→再决策”的通用有界循环；现有单次回复不可当作自由生活。
3. **跨 Agent 意愿交接**：尚无具有生命周期、去重、取消、原始事实回执的统一委派/领取/完成协议。部分动作只能由原入口完成。
4. **真实环境验收**：尚无 Windows Desktop、模型、B站实际关注/评论/私信、双账号、72h 连续以及跨日成长的真实记录。

建议验收场景：视频自发评论与新回复跨 Agent 交接、私信自主关注同 UID 后真实读回、不同 UID 的 Episode 不能混入、Todo 完成后回访不重复发送、Reflection 不从私信读取身份/内容、切号后不可跨号续行、冷却中不把愿望冒充执行。
