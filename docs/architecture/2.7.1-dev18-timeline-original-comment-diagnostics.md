# 2.7.1-dev.18 · 生活时间线排序与主动视频原创评论诊断

## 用户复现（2026-11-07）

生活时间线先显示 14:44、10:50 视频轮次，再显示 15:33、15:13 等只读，再显示 15:43 反思、15:38/09:18 评论和情绪。跨事件类型没有按时刻倒序；有「回复评论」记录，但没有自主顶层评论记录。两条回复属于后台社交链，不能算视频 Agent 主动在视频下原创发表。

## 实际根因与证据边界

- `buildLifeTimeline()` 构建的 `at` 是整数毫秒，但旧 `sortRows()` 用 `Date.parse(b.at)-Date.parse(a.at)` 比较。对 13 位毫秒整数该表达式产生 `NaN`，标准排序遂保留原数据插入顺序（按事件类型分组）。现改为显式区分毫秒整数与 ISO 字符串，精确时间跨类型倒序。同日只有日期的原 `seen.md` 选片记录继续排在已知时刻之后。
- 自主原创顶层评论的实际发送工具来自视频 Agent 的 Python MCP 白名单，只有 `autoComment=true`、`dmMode!=only` 且公开日额度允许才下发；每轮原提示还遵守 `commentPerRound`。独立后台回复评论不依赖视频 Agent 的这个开关。`bili_ledger_mark`/视频轮次成功不是评论工具调用证据。
- 设置页面「自由互动」仅能选择 `autoComment=true` 等交互权限，**不会同时修改**藏于视频高级设置的 `dmMode`；它可能仍为默认 `only`（「只发报告私信」），实际评论工具会被剔除。这是会令用户误以为评论已经打开的 UI 可见性问题，不代表某个用户当天的配置一定如此。
- 旧提示词在 `dmMode=only` 但找不到私信收件人时自称「降级成只发评论」，与工具白名单不一致，还误暗示扩大对外权限。现在保留 `only`，只说明报告私信被跳过，不提升评论权限。

## 状态契约与不能得出的结论

- 新 API 在原 `/api/bili-duty/life-timeline` 中附加 `commentReadiness`，字段只包括当前 `enabled`、`blockers`、`mode`、额度数、日期、有限样本的 `observedTop` 与 `observedReplies`。当样本正好 200 条时必须标注截断；不可当作全天总数。
- `enabled=true` 只表示配置准入。视频 Agent 仍可自由选择只读、不评论；视频热度阈值、证据、平台风控、异步/未知发送和真实回执依旧独立生效。没有平台写入日志时不得断言「AI 不愿意说话」或「平台故障」。
- UI 的视频互动选项属于尚未保存的编辑预览，生活时间线的诊断属于当前生效配置，不自动同步两者或改变旧设置。
- 真实平台提交 / B站回查、Windows 渲染、跨日生活频率及长期行为因果均未验收。

## 如何验收

1. 打开管理中心 → 「鱼鱼此刻 → 大肥鱼的一天」；相同日期的评论、反思、视频回执和只读行应跨类型按时刻倒序，只有日期的选片记录排在该日末尾。
2. 查看时间线下面「今天原创顶层评论 X，回复别人 Y」以及**当前配置**阻断原因。比较“视频互动 → 自由互动／适度互动”与「报告发送方式」；若只私信，页面应明确说明视频 Agent 不拥有原创评论工具。
3. 若配置允许且本地无顶层回执，查本机原视频进程工具调用日志、实际 `bili_reply` 结果、平台评论状态；仅有“视频 Agent 结束/挑中3条”不证明曾尝试发表评论。
4. 配置修改必须手动点击「保存」，依旧执行原外发授权确认。`dev.18` 不会默认切换到 `both`，也不会强制每轮评论。
