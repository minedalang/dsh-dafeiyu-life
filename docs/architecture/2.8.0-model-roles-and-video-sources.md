# 2.8.0 模型职责与视频来源：统一 Life 下的配置边界

此文档描述本次独立增量，不改变授权、发送额度、发送凭据或主人身份核验。

## AI 模型页面：九类任务、三组职责

- **行为决策模型 (`behaviorDecision`)**：Life 主规划、统一意愿和视频 Episode 自主续行。推荐较强的指令遵循与结构化推理。旧设置未配置该项时继续沿用 **互动模型**；并非迁移成新值。
- **社交互动模型 (`interaction`)**：普通私信、评论回复等高频自然表达。推荐均衡、快速；不是纯粹越便宜越好。
- **主人 Agent 模型 (`ownerDmAgent`)**：主人专属受限 Agent 工具规划。较低频，需较强工具理解和推理。
- **视频 Agent 模型 (`video`)**：只在独立视频探索启动后，判断候选、调用只读视频工具、结合资料分析内容；不能自行决定 Life 是否启动。
- **视觉识别模型 (`vision`)**：仅在需要真实画面时识别取样画面和视觉梗；不同于视频模型对字幕、元数据和评论区的理解。默认复用视频模型，独立视觉需多模态能力。
- **人生反思模型 (`reflection`)**：从有回执的经历中提炼长期认识。低频，更看重推理质量。
- **记忆检索模型 (`memory`)**：对检索候选做相关性判断。高频，优先速度和性价比；本地 Embedding 是另一条检索能力，不是生成模型。
- **生活动态表达模型 (`dailyDynamic`)**：起草可选的生活动态文字，按需、均衡。
- **表情包规则优化模型 (`memeRules`)**：低频管理操作，基础模型即可。

调用次数表示本插件启动的任务数，**不代表真实 API 请求、Token 消耗或费用**。统一默认模型仍可按用户选择应用到各模型，单独配置覆盖对应任务。

## 视频来源：两条明确分开的路径

1. **首页漫游**：Life 选择 `browse_home` 后启动独立首页轮次。仅将 `bili_home_recommendations` 放进候选来源白名单，**没有 `bili_search`**；首页获取失败或没有可用候选时结束，不能静默降级为关键词搜索。
2. **兴趣／生活线索搜索**：兴趣状态、机会核实与主动关键词探索使用 `bili_search`。不将首页推荐混入该轮工具白名单。用户推荐或 Life 待办如已有可信 BV，仍可通过已有的只读核实和 Episode 流程继续探索。

两条来源仍共享真实视频证据、行为授权、去重、Life 意愿和平台回执约束；**来源不同不意味着读到视频后的互动权不同**。不增加评论/点赞/视频启动配额，也不提高发送频率。

## DSH 安全路由

- `headless-life-decision-overlay.yml`：`behaviorDecision`，没有 B站 MCP 或其他文件/终端工具。
- `headless-video-home-overlay.yml`：`home`，只开放首页候选的视频相关工具；校验器拒绝搜索工具进入首页轮次。
- 保留原有 `headless-overlay.yml`（其他视频轮次）和 `headless-dm-overlay.yml`，现有安全隔离及凭据验证保持不变。

## 主 Session 对话支持及明确的边界

`dafeiyu_chat_burst` 已复用主人私信的多气泡上限设置和分条意愿协议，能在主 Session 生成 2～3 条独立 assistant 消息；收到新的主人输入后，未发送的后续气泡取消。它目前是**同一次模型预先规划多个气泡，再分轮送达**；还不能据此宣称已经支持后台私信那种“首条真实送达后再独立生成一条”的渐进式补充。这一细分能力需独立设计和 DSH 实机验收，不能伪造送达回执。

主 Session 右侧足迹页（`conversation.view`）已取消注册；这不会删除后台评论/回执账本及管理中心现有历史页。

## 验收要点

- 旧用户只配置互动模型时，Life 仍使用同一路由，不会被意外重置模型。
- 新配置显式选择行为决策模型时，Life 主决策和 Life 意愿均走同一路由，不新增第二次否决。
- 首页和兴趣搜索各自不能越过来源工具白名单。
- 主 Session 多气泡不应被夸大成真实送达后再生成。
- 无论来源，外发必须经过原凭据与平台验证；此次修改没有 B站实机外发验收。
