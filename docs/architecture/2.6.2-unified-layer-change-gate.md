# 统一层归属与变更门禁（2.6.2 dev）

这是维护者使用的**执行约束**，不是新的运行时“超级 Agent”。业务入口只能提供场景数据，不能复制公共领域的状态来源、提示词装配和发送规则。

## 修改前先做归属分析

| 需求所需信息／判断 | 唯一职责归属 | 场景入口允许增加什么 | 禁止什么 |
| --- | --- | --- | --- |
| 人设、世界观、认可成长、连续情绪、关系表达 | `lib/life-voice-context.mjs` + `index.js` 的 `lifeVoiceContext`；情绪事实由 `lib/emotional-state.mjs` 提供 | 只声明 `scene`、可信 `uid` 和检索主题 | 再拼一份“现在很开心／社交分99分”的独立模型指令，覆盖原人格 |
| 经核验的实际经历与任务完成 | `lib/verified-life-facts.mjs` 和任务成功回执／当前可用只读证据 | 原始请求、任务 ID、可用视频证据 | 将“找到资料”说成“看完／听完”，把回访当作事实入账前提 |
| 当前可回忆的记忆 | `LifeMemoryGateway`、`memoryRetriever` | 当前合法隐私域内的检索问题 | 从永久归档绕过遗忘、跨用户读取 |
| 平台身份、关系 | `SocialContextAssembler`、关系索引和身份策略 | 本轮已核实的发送者／评论串 | 通过昵称猜 UID、把“朋友”当发送授权 |
| 生活意愿／是否交流 | 原有意愿决策与 AI 对话决策 | 原文、同人历史、当前上下文 | 把情绪指标当固定回复概率，按字数强制 SKIP 或强制回复 |
| 对外权限、冷却、去重、真实回执 | `SocialPolicyGate`、现有发送适配器与回执协调 | 本次合法发送目标和渠道 | 绕过检查、自动补发不确定回执、用意愿推导权限 |
| 评论／私信连续话题 | `CommentEngagementContext`、原文取证和会话历史 | 已发送回执、同 UID／同评论串最近互动、原动态正文 | 在场景层重新构建完整角色核心／情绪／事实索引 |

## 每次编码执行顺序

1. **确认唯一信息来源**：对照上表，阅读现有统一层签名和真实生产接线；列出将被影响的所有聊天入口。
2. **明确变更层级**：通用状态由统一层提供；具体内容仅留在场景层。若职责边界不清，先统一接口再写场景代码。
3. **保持数据边界**：事实 ≠ 意愿 ≠ 权限 ≠ 已发送；完成待办不依赖回访；跨 UID 与私密域隔离；记忆遵循衰减。
4. **检查最终模型输入**：不只验证局部函数，要截获调用模型前的完整提示，验证人格／情绪只有一个权威来源，原评论／原动态／任务事实可定位。
5. **跨渠道回归**：至少覆盖主人 DM、普通 DM、评论、自主分享、回访；关系、情绪、权限变化分别验证，不用伪造模型回复代替实机测试。
6. **交付说明**：写清复用层、局部补充、仍未覆盖的入口和实机边界。根 README 不叠加技术流水账。


## 无现有归属时，允许创建新的统一层

**禁止把“优先复用”误解为“绝对不能新增层”。** 新需求不能清晰落入已有层时，先写一个简短设计对照并评审：

1. **现状证据**：列出调用方、现有状态源及不适合承载新职责的原因；确认不是漏看现有 API。
2. **准入条件**：新能力至少跨两个场景可复用，或拥有必须独立治理的数据生命周期／安全边界。单渠道展示逻辑留在场景层。
3. **唯一所有者**：明确谁写入、谁读取、事件 ID 与来源、可信度、隐私域、可回忆期限及错误处理；不得从新层反向复制 Life Voice／事实／记忆／权限功能。
4. **渐进接线**：说明已接入与未接入的渠道、老数据迁移／回滚和开关默认值；不足两条生产入口时需写明后续接入计划与验收条件。
5. **验证契约**：新增跨入口调用测试、权限及故障注入、最终模型输入去重检查。必要时更新运行时接口/图，而不是只创建一个名称。

设计模板：`问题与现有层差距 → 新层职责/非职责 → 数据所有者与信任级别 → 调用入口和失败策略 → 隐私/遗忘/发送边界 → 迁移 → 测试 → 文档与图更新`。

## 架构变更与文档同提交门禁

任何新增／撤销统一层、修改状态源、事件流、记忆路径、模型上下文、对外渠道、权限、持久化或恢复 API，都属于**架构变更**，必须在同一个提交中：

- 更新 [`README.md`](README.md) 的当前职责和入口链接，并修改相应详细技术说明；发现早期文档过时则标为历史，不能让两个文件同时宣称是当前真值。
- 更新可编辑 Mermaid（必要时同步 SVG/PNG），并检查**实际调用图、数据流、权限边界**与源码一致。
- 更新跨渠道覆盖矩阵与契约测试；测试必须包括跨 UID／私密域隔离、真实回执、重复模型提示与恢复／迁移边界。
- 在 Commit 说明中列出本轮改过的架构文档和图。若无架构变化，明确写“架构接线未变”。

单纯修改文案、样式不需要重画架构，但仍要确认没有悄悄改变业务数据流。技术历史写 CHANGELOG／Release Notes，不堆在根 README 与 `AGENTS.md`。

## 新的事实契约与模型提示回归门禁

- 对任意新的感官型事实，必须测试**同 BV + 同感官 + 不超过证据强度**；不允许借用另一个视频或另一种感官的成功回执。模型自己生成的 JSON、文本或标题不构成回执。
- 生产聊天入口修改后，检查最终模型提示：Life Voice 提供一次核心人格、成长、当前情绪；场景层只给话题、已核实任务、真实互动历史与策略参数。
- 对真实外发动作，仍须单独验证授权、额度、去重、回执与跨 UID 隔离；事实层 `ok` 不等于允许发送。
- 持续运行 `test/v262-fact-exact-evidence-contract.test.mjs` 与其他跨入口契约测试，并同步检查两个当前 Mermaid 源及渲染图。

## 本次暴露的重复实现实例

- 动态评论需要“当前情绪”时，应该查询 Life Voice 提供的角色核心，而不在互动连续性模块里再造一份情绪提示；互动模块只应补充同人同评论串已确认回复次数。
- 受信任评论意图提示曾同时接受 `style`（包含 Life Voice 情绪）与 JSON 情绪快照并拼进同一模型文本。本次去除后者的提示插入；保留本地情绪数值参与原有计算和诊断的能力。
- 自主评论邀请曾把 `buildInteractionPersona()` 与 `emotionalState.styleHint()` 同时追加；这一处改为只使用 `buildInteractionPersona()`。
- 私信的旧 `getLifeStateContext()` 曾将当前情绪、成长风格再复制一份到批量提示；生产接线保留兼容回调，但不重复注入，使用统一 Life Voice。

本文件不会机械保证每个模型回答都像一个人；真正的保证来自**明确的数据所有权、生产接线测试和持续检查**。现有其他重复通道应在后续变更时列入审计，不得未经检查宣称全部消除。
