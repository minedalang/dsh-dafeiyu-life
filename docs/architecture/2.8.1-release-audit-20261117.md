## 2. 视频感知完整数据流

1. **真实契机与自主选择**：Life 从可信 B站视频、评论、搜索、待办、分享等读取线索，经账号/授权边界，决定了解/休息/延期。主人只读 Debug 不应写成自主经历。
2. **公开元数据核实**：视频标题、BV、作者与时长等通过平台只读工具取得可信结果；元数据本身不是视觉观看回执。
3. **视频采样与预算**：公开可读范围内按 budget 和 depth 取样。优先使用实际可解码媒体与 FFmpeg；取不到则区分官方 `videoshot` 的低清来源。多帧拼图不是完整视频播放。
4. **字幕/ASR/OCR**：官方字幕保留起止时间；可选 Whisper 在真实无字幕且依赖/用户配置允许时转写；OCR 只从真实同源画面锚点取有限文字。时间上相邻不能自动证明音画语义一致。
5. **视觉模型调用**：DSH 独立 Headless 或用户明确启用的本地 Ollama；无真实 `analyzed/cached + description` 等核验回执不得把画面描述转为可靠已观看事实。
6. **证据汇合**：`video-perception-handoff` 与 bundle 投影原始来源/时刻/窗口/不确定性；只能把有限合规结果进入当前 Life 和可衰减记忆，不持久保存图片、长模型原文或提示词。
7. **下游选择**：Life 可继续了解、复查、休息或考虑有依据的原创评论/点赞。平台写入依原账户、限额、去重和不明回执冻结；视频观察本身不能授予写权限。
8. **可见性与诊断**：行动树区分只读核实/画面观察/低清回退/真实平台外发；用户可以在只读视频 Debug 查看有限临时画面，不代表系统成功建立长记忆。

**当前 P0 实际分叉**：手动图片验收已经把 `vision_dsh.py` 中的 `BILI_VISION_HOST_PORT/TOKEN` 请求导向 `startManualVisionHostExecutor`，由 Node 宿主直接 `spawn` DSH，并已在使用者 Windows 得到 MCP 图片回执、模型回答（最终人为批准状态仍需核对）。但 **生产视频** 的 `ensureOverlay()` 只把 `BILI_VISION_DSH_BRIDGE`、Python 路径及其他常规环境传入独立视频 MCP，没有 host token/port；`vision_dsh.py` 因而仍走原 Python `subprocess.run([node, bridge])`。这两条路线不等价；要将安全宿主能力迁入生产，必须另行设计受限视频读请求、生命周期、模型文本边界和持久化回执，不得复制手动专用固定提示词白名单后放宽成任意命令接口。

## 3. 宿主资源协调（实际范围）

- `lib/life-resource-scheduler.mjs` 提供四类进程内信号量：`model=1`、`biliRead=1`、`video=1`、`vision=1`（默认）；`social / continuation / exploration / background` 有权重与等待时间增长，连续社交优先后有其他 lane 机会。
- `index.js` 实际接线：预算适配器包裹 B站读取、部分模型调用占 `model`、后台视频轮占 `video`、Life 自主视觉占 `vision`；视频同 BV 有局部合并器。
- **不是统一的跨进程调度**：独立 Python MCP 和外部 DSH 的所有读取/模型子调用，并非全都向 Node 资源池申请许可。`tryAcquire` 不抢占执行中的任务；`close` 不能杀死未知外部进程。任务账本、私信可靠续办、平台读取预算与 B站写入互斥是独立的安全组件。
- **禁止营销为“所有 Agent 全局一次排队、精确一次完成”**；平台读限额和模型计费限制不是同一资源槽。账号变更时按账户栅栏拒绝新准入，不等于自动撤销已发生外发。
- 正式发布前实测：长视频/评论/私信同时运行、持续私信积压、模型超时、重启及切号；不应重复外发或把技术等待伪装成 Life 选择沉默。

## 4. DSH Headless 同步与能力管理

**已实现的设计**（`lib/headless-model-sync.mjs` 与 `index.js` `/headless-model/*`）：

1. 读取 Desktop/Web 模型配置和 Host 的真实已注册模型。已注册官方模型只在适配器实时枚举时展示，不按 Provider 名称猜测已存在；该路径不要求复制 YAML。
2. 自定义 Provider：解析真实源/目标 YAML，检查 `llm-pi-ai` 单例与安全字段；全局配置有覆盖优先级。禁止自动复制明文 key、headers、动态表达式、带凭据 URL 或外站明文 HTTP。
3. 显示 **预览差异**、预览 token 后由用户明确同步；只更新受选 Provider、保留其他目标项、先备份再原子替换；配置变动使旧验证失效。
4. `input: image` 与 `reasoningEfforts` 能力向导只编辑 Headless 对应模型的合法声明，不修改 Desktop 来源或凭据；声明不证明模型真实识图。
5. 至少一个 Headless 模型需要真实**文字连接**验证才能解锁首次安装；视频、行为等单独路线若使用独立模型也须分别真实验证。图片仍需固定图片的 MCP nonce 回执、模型回答及用户认可。
6. 验证回执按 Profile、模型和有效配置 fingerprint 绑定。切换实际路由、Provider 配置或目标能力后，必须按现有验证逻辑重新确认。

风险：当前 `hasAnyVerified` 与 GUI 状态有真实 YAML 解析依赖；离线仓库测试在缺失 `yaml` 的环境下会跳过部分同步回归，正式 CI 必须在生产依赖齐全时全部跑过。旧的过时断言不是生产行为的失败，但也必须修正而不是发布时忽略。

**迁移安全原则**：不修改已有账户绑定、主人/好友权限、B站凭证、私信续办、记忆图和未知发送冻结。新版引导只能改变单独的 `quickSetupSeenRevision`，选择能力必须另行显式保存。避免按版本号自动触发 Python 安装、下载模型或启用付费路由。
