# 2.7.1-dev.4 · Life Agent 手动唤醒可观察性修复（Phase 5 后续修正）

> 当前生产行为修正。仍不授予社交接管、关注、私信或评论的新权限；版本号不变。Linux 离线测试不代表 Windows 实机/真实模型验收。

## 问题和根因

管理中心点击「让鱼鱼自主考虑一次」时，即使传入 `force:true`，`AutonomousPlanner.tick()` 在只剩可信兴趣线索的分支依然可能返回 `life-exploration-cooldown`。这是内部 **六小时仅线索自动去重节流**，不同于页面可调整的 20 分钟「普通自主调度最小间隔」；原条件没有排除手动请求。出现此代码说明未进入模型决策，不能解释为模型的意愿。

同时 `life-agent-events` 始终按最旧待处理事件取前四条；当事件积压时手动插入的 `manual-wake` 在队尾，不保证本轮模型能看到。反复点按钮还会追加人工事件，使待考虑计数越来越大。旧代码在账户事件读取出错时可能吞掉异常，回退成只有线索候选，进一步产生误导性的冷却提示。

## 本次实际变更与安全边界

1. 仅自动调度（`force:false`）保留六小时「只有兴趣线索」防重复节流。`force:true` 可以真正再次请求 Life Agent 作一次选择，但仍需有合法候选，且仍受**每日自主模型决策额度**、总开关、账号检查和无写权限的能力边界制约。普通自主调度间隔也仍适用于自动 tick。
2. `manual-wake` 进入 `peek()` 的首个候选位置。旧积压中真实私信、评论、视频事件继续按到达顺序选择，其证据和完成状态不被丢弃；重复手动请求只合并**未处理人工事件**。不将人工点击误写为真实平台经历。
3. 手动模式下若无法读取当前账号的 Life Agent 事件账本，返回明确诊断错误 `life-events-unavailable`，不伪装成「鱼鱼选择延期」。
4. 管理中心对 `quota`、`nothing-to-do`、`busy` 等显示中文说明；阻止单按钮重复并发点击，解释 `shadow` 是**只记录选择，不启动视频**。
5. 独立视频启动的 **180 分钟间隔与每日 2 次限制完全不变**；真实外发、社交回复所有权、冷快照与老用户数据 schema 不变。本次不强制鱼鱼采取行动、不保证模型每次都选择探索。

## 无 B站模拟验收

```powershell
node .\tools\dev4-manual-wake-offline-acceptance.mjs
node --test .\test\v271-dev4-life-agent-manual-wake-hotfix.test.mjs
node .\selfcheck.mjs
```

模拟器只在操作系统临时目录生成 31 条合成评论事件、两次人工唤醒，调用**假模型**选择休息，并确认没有发送动作、网络访问、真实模型费用与正式数据操作。预期模拟器 `ok:true`、`fakeModelCalls:1`、`externalMessagesSent:0`、`realModelCalls:0`、`networkCalls:0`。专项 4/4 通过。

真实管理中心的「让鱼鱼自主考虑一次」**不是**离线模拟器：仍会调用用户配置的模型并消耗当前额度，且如有已授权的只读待办或探索线索，可能联网读取 B站公开资料；若没有候选、配额耗尽或模型主动休息，可能没有后续行动。手动测试请优先用 `shadow`，在时间线中观察动作类别和结果；若显示错误，保留弹窗与当前调度状态作为诊断，不需要私聊陌生人或实际发送 B站消息。
