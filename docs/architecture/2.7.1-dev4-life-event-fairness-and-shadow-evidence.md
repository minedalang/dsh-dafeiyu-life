# 2.7.1-dev.4 · Life Agent 匿名事件公平结算与社交影子证据门禁

> 当前开发接线。**没有**改变旧 DM／评论的生产决策权；没有新增社交外发权限，也没有将短时影子判断当作平台发送回执或人格成长证据。保留现有 Life Agent、原 v1 匿名事件账本、原 Life Voice、当前可信事实／可遗忘记忆与社交安全层，不额外启动模型或调度时钟。

## 统一层归属和调用链

| 入口 | 唯一来源／复用层 | 本次变化 | 仍受约束 |
| --- | --- | --- | --- |
| 核验后的私信／评论事件 | 原 `offerSocialLifeWake` → `life-agent-events` 账号 v1 JSON | 原事件仍匿名／去重；未轮到的事件不再与选中的事件同时误结算为「已考虑」 | 不持久化 UID、正文、BV；不向模型提供无授权的原文 |
| 原手动唤醒／待办／探索 | 原 `AutonomousPlanner` + 模型额度与跨进程 run lease | 独立任务的有效模型选择不再消耗无关匿名社交线索；手动请求仍得到本轮明确回应 | 不新增待办、私信／评论、关注或发送工具 |
| 当前账号匿名事件 | 原 `life-agent-events/<accountTag>.json` | v1 内可选增量字段 `passovers`，状态仍为 `pending/retryable/considered/review/failed`；未选中时 30m → 2h → 6h 有界重考虑，第 3 次后标记 `unselected-after-three-turns` | 技术错误仍单独使用 `failures`，未知执行结果仍冻结，不自动重放 |
| 模型真实读取经验 | 原 `getLifeEventStatus().recentVerifiedReads` | 区分「前轮已核验只读类别被提供给模型」和「模型确实采用」；后者仍无证据，不再写入误导性肯定语 | 不能由这类证据推出观看、听歌、关系发展或人格成长 |
| 社交影子对照 | 原 `life-social-shadow` 十分钟内存审计与旧处理器 `noteLegacy` | 迁移只读检查增加私信／评论成对数、分歧与缺样本状态 | 影子内存不是可持久的切换凭证，检查结果永远不授予接管 |
| 原管理中心／迁移检查 API | `GET /life-agent/transition-readiness` 与原生活状态 | 显示未选中待考虑数、已关注种类、冻结数和影子配对不足／分歧 | GET 不写状态、不调用模型、不修改权限；无自动恢复按钮 |

## 事件结算新语义

一轮生活决策会看到一组最多四条可信**匿名**线索，模型只允许选择菜单里的一个动作。这次增加如下严格区分：

1. **模型调用失败或 JSON 不合法**：所有本轮提供的线索保持既有技术重试（5m、10m、终止），使用 `failures`。不能说鱼鱼拒绝，不能改写真实回执。
2. **模型明确 `skip`／休息**：该轮已经给了鱼鱼选择机会，仍把本轮提供的线索记为已考虑；这不是执行动作或外发。
3. **明确 `consider_social(id)`**：只有命中的社交事件记为 `social-attended`。其他未轮到的事件进入 `not-selected-this-turn`，有界延期后再考虑；`manual-wake` 表示本轮手动触发，得到一次有效选择就正常结束。
4. **选择已有视频能力 `use_capability`**：`quiet-window`、`video-round-ended` 以及本轮手动请求得到明确结算；同时出现但未被选择的私信／评论仍按未选中延期，委派不等于真的看完视频或有外发回执。
5. **选择已接受的只读待办、反思或独立探索**：与该目标无关的匿名线索不得被当作已关注；改记 `not-selected-this-turn`。手动请求仍完成此次「考虑」操作。
6. **执行前失败／执行结果不明**：独立待办／意愿动作失败不计入其他匿名社交线索的 `failures`、`review`；无关线索归为未选中。若选择的是与生活唤醒相关但无法绑定单一事件的委派能力，仍按保守策略处理本轮提供的所有事件，结果不明时冻结，绝不自动重复执行。
7. **未选中重考虑最多三轮**：第一次等待 30 分钟、第二次等待 2 小时、第三次后结束自动轮询并记明「三轮未被选中」，而不是伪称 `skip`、技术失败或完成了任务。原 7 日衰减、同来源去重和账号分区不变。已经处于 `review` 的事件永远不能通过这种方式自动重试。

**注意**：有效的普通生活选择并不意味着模型已经理解了私信／评论正文；`social-attended` 也不等于它已决定回复。真正的社交回复仍走旧处理器，原入站验证、社交权限、退订、发送事务及真实回执不改变。

## 可追溯性与事实强度

原 v1 时间线继续读取历史字段 `priorVerifiedReadReferenced`；旧数据不静默迁移或删除。历史真值只能说明当轮可能收到过可信类别，不能解释为模型真的采纳。新记录使用 `priorVerifiedReadOffered` 代表**提示输入中存在**成功只读类别，并将新写入的 `priorVerifiedReadReferenced` 保持 `false`；如果以后要证明因果，需要单独验收模型结果、真实行动与后续日记的可核实证据链。

新时间线匿名字段：`selectedSocialKind`（仅 `dm-received/comment-received`）、`notSelectedWaiting`（本轮实际被延后再考虑的条数）、`reviewEvents`（需要人工核验的事件数量）。均从**原事件账本结算后的状态**计算；不是模型自述，原始事件 ID、UID、内容、平台凭据不会写入界面。

## 社交移交准备的只读证据

`lifeTransitionReadiness(..., shadow)` 会对两个渠道分别报告十分钟窗口内的 `paired/agreed/disagreed/missingLife/missingLegacy`，并区分 `not-observed`、`insufficient-samples`、`high-disagreement`、`short-window-observed`。至少两渠道各五条配对，且总体分歧率不高于 20% 才显示“短时样本已出现”，但对应检查仍然是 `pending`，`productionHandoffProof:false` 和 `releaseReady:false` 固定；不应该把这一临时阈值当作正式灰度准入标准。

正式取得社交唯一决策权仍需要：长时间可持续的跨账号／多进程样本；真实 DM、评论与 P6 事务的互斥恢复；包括主人私信、主动分享与回访在内的真实发送路由核查；明确的用户授权与撤回；Windows／真实 B站实机测试。**本轮没有实现正式接管。**

## 实际使用验收

- 在生活模式已启用、当前账号通过核验时，让鱼鱼收到两条不同来源的真实社交信号。在菜单中只选一条，则另一条应在状态页展示为「本轮未选中，等待再考虑」，不是技术错误或主动拒绝；无联系权限也不应产生任何新外发。
- 点击「让鱼鱼自主考虑一次」且有真实任务候选时，如果鱼鱼选择任务，手动唤醒按「本轮已选择」结算，但独立社交事件仍等待再考虑；同日模型额度继续由原 planner 使用。
- 如果模型报错、切号、执行器无可信回执，仍必须分别看到技术重试、原账号事件保持待处理或 `review`；不能变成已发送或已观看。
- 「迁移检查」显示两渠道的短期影子审计不足及分歧，不能出现“Life Agent 已接管社交／允许发布”的标记。
