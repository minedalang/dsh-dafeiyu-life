# 2.7.1-dev.42 · 主 Session 自主联系主人（开发预览）

## 唯一职责归属检查

| 入口 | 统一职责 / 唯一事实源 | 本次新增信息 | 安全和隐私 | 回归范围 |
| --- | --- | --- | --- | --- |
| Life 的普通模型决策 | `AutonomousPlanner` / Life Voice、`LifeAgentEvents`、原账号范围 | 新候选 `talk_to_owner`，事件 `experience-ready` 或 `owner-idle` | `skip` 始终可选；无第二人格或强制聊天 | 候选与 ID 验证、帐号复核 |
| 唯一主人主 Session | `MainSessionBridge` 现有 `mainSessionId` / `main-session-memory.json` | 独立 `ownerSpontaneousChatEnabled` 许可，已尝试的来源、时间、排队/未知状态 | 仅已显式绑定且**在线**的 Session；不读取其它会话；不记录聊天原文 | 开关、静默、冷却、重启幂等、未知投递 |
| 宿主 Session | DSH `agent.followup()` / 宿主自身的 Session 压缩 | 非主人命令的 Life 自主交谈契机 | 宿主接收并非微信/Desktop 送达；主 Session 可决定沉默 | 仅注入契约，实机仍待验收 |

影响渠道：本轮只增强 DSH **主 Session** 的唤醒候选；没有修改微信或 B站私信发送接口，B站普通 DM 的 P6-A 是另一条链路。

## 生产接线

1. `AutonomousPlanner` 每次正常 Life 决策读原 `Life Voice`、既有候选及 `getOwnerChatReadiness`。同时提供保守的 `talk_to_owner` 选项：一个当前有效的 `experience-ready` 事件 ID，或者无特定事实来源的 `owner-idle`。不强迫每次聊天，`skip` 不变。
2. 仅明确开启 `ownerSpontaneousChatEnabled` 并且主程序、Life active、主 Session 桥、主 Session ID、在线实例和原账号作用域都有效时才提供候选。
3. 在选中动作并重新核验原账号后，`MainSessionBridge` 检查当地时间 09:00–22:00、8 小时尝试冷却、每日最多 2 次，且同一证据来源不重复尝试。
4. 先持久化 `reserved`，再调用宿主原会话 `agent.followup()`。成功仅表示已进入主 Session 的消息队列；记录 `queued`；异常记 `unknown`，**禁止自动重试**；数据仅包含匿名来源键、时间和状态。
5. 主 Session 根据原 `Life Voice`、现有记忆与情绪，自主选择自然说话或保持沉默。原 `EmotionRecall` 仍暂停；没有新增人格卡片或表达强度控制。

## 人工可验收入口

管理中心 → 主 Session（已有会话绑定）→ 「允许肥鱼自主找主人聊天」（默认关闭）。需要同时启用 Life 自主生活、主 Session 桥并选择当前活跃的原主 Session。保存后，下次正常 Life 考虑时可能出现 `talk_to_owner`，也可能选择休息。状态可从桥状态读取 `ownerChat` 的简化 `enabled/readiness/attempts`，Life 决策记录会显示 `owner-chat-queued`、`owner-chat-unknown`、`owner-chat-blocked` 或 `skip`。

未知状态与冻结、私有会话读取、跨账户隔离、模型调用预算必须实机和跨进程验收；目前不声称实际已经在 Desktop 或微信送达。

## 多个自然气泡的现状与宿主边界

本插件已核对：DSH 宿主的普通 assistant 回复路径只提交一条会话回复，没有插件侧「发送多个独立 assistant 消息」的已核实 API。原 `followup()` 仅唤醒原 Session；模型输出多段文字不等于多个物理气泡。当前**未接通主 Session 一轮 1～3 条独立气泡**，不能说完成或把普通 DM P6-A 的发送测试冒充主 Session 能力。真正实现需要宿主公开多消息输出接口，或在未来明确选定、可验收且有发送回执的微信传输层连接多段输出协议；此轮没有微信集成，也不通过在 Session 里伪造 assistant 历史来达到效果。

## 仍未证明
