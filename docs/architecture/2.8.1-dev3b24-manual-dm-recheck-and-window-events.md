## 单联系人两步核对

1. 管理页先 POST `dm-contact-check`：仅限本机同源；UID 必须是当前账户既有本地 DM 联系人，当前账号已授权，私信已开启。只读取 B站该人的最近50条平台消息（同一共享读预算、账号围栏、退避），不触发模型、不改变 seen/游标、不发送。
2. 状态匹配最近72小时、没有更晚的己方平台消息和本地确认发送、没有旧发送未知/审批排队/拒联/重复手动复核，并经过原 SocialPolicyGate，才返回一个**进程内 HMAC 预览令牌**（不暴露私信内容和消息 ID）。
3. 主人明确二次确认，POST `dm-contact-reconsider`。服务端在原 DM 跨进程锁下重新取得当前平台会话、重新核验账号和同一条来源、先持久化手动尝试占位，再调用原 `generateReply`。回复、沉默、延期全由鱼鱼自主；平台实际发送仍使用原事实核验、额度、冷却、发送回执和不确定结果冻结。模型思考后第一条发送前再查询平台，防止同时有人回复造成重复。
4. 手动复核不会清空 seen 或改后台扫描 cursor。一次来源只有一次人工重新考虑，除非平台出现真实较新的新来信。旧模型技术失败或未知结果不自动重试，以免重复发信；错误须用新日志核对。
5. 平台不足50条、未发现目标或者超出72小时不保证追溯，绝不生成历史重播资格。主人专属 DM Agent 不走普通联系人按钮，不扩大到陌生人不可发送的场景。

## Windows 黑窗事件追踪

- 在 Windows 项目 `tools` 目录运行 `capture-intermittent-window.bat 900`（900秒，最高3600秒），期间等待真正「观察视频画面」发生。Windows 5.1 尝试订阅 `Win32_ProcessStartTrace`；不可用会标为 `process-poll-fallback`，该模式可能错过很短的窗口。
- 结束得到 `dafeiyu-window-event-trace-*.zip`，另运行 `tools\导出B站日志.bat --no-pause` 并上传运行日志 ZIP。事件只记录时间、进程名、PID、父 PID、采集模式，不含窗口截图/标题、命令行、敏感内容。
- 如果没有观察动作或没有对应新进程事件，只能记为这次没有复现，不是已修复证据。

## 实施边界

不得直接恢复/清理 seen、假定平台 unread 等于未回复、绕开 `-509`、跨账号、突破限额或人类要求强制发送。仅做云端增量测试；Windows DSH 和 B站真实验收由使用者执行，本轮未发布 npm。
