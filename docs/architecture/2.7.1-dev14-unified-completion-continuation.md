# 2.7.1-dev.14 · 可信行动统一续行（未发布）

## 目的和职责归属

使独立 Life 行动的**已核验完成回执**有资格触发下一轮自主考虑，而非只让只读待办继续。唯一生命意愿仍是 `life-willingness.mjs` / `autonomous-planner.mjs`；唯一匿名唤醒账本仍是 `life-agent-events.mjs`。没有引入第二套生活决策器、发送器、外发授权、独立记忆或持久任务正文。

| 来源 | 确认依据 | 续行接线 | 不允许发生的事 |
|---|---|---|---|
| 私信、公开评论、推荐私信、完成待办回访 | 原 B站发送事务成功、原渠道真实回执；Life `receipt('verified')` 在入账结算后调用 | `lifeWillingness.onVerifiedAction` → `recordVerifiedCompletion` | 无原始回执、未知结果、重复气泡与发送失败不能伪造完成或自动重试 |
| 熟人主动私信 | 当前账号双向关系与独立授权，原 DM 事务成功，熟人行动账本成功记为 `sent` | Planner 记 `friend-message-sent` → 原 Life 事件账本 | 无视频也可以选择；不能跨账号猜测熟人；不能把未发送或不确定结果当成功 |
| 视频工具里的点赞、收藏、关注、顶层评论等 | 只有已有工具证明成功后才是可信写入 | 与上述 `verified` 回执同入口 | **现有 Python 进程自报成功只是 `accepted-unverified`，不触发完成续行** |
| 视频 Agent 轮次结束 | 原子进程退出码与视频轮次账本 | 沿用 `video-round-ended` 事件 | 退出 0 不代表看完某条 BV 或听到音频；启动 `delegated` 不是完成 |
| 只读待办、公开元数据、公开线索 | Planner 原始成功回执与重新核验事实 | 沿用 `recordDecision` 的 `verifiedReadKind` 续行 | 无效模型输出和只读失败不构成执行成功 |
| 内部反思 | 原反思能力返回成功并且是 active Life 决策 | 同一 `recordDecision` 续行 | 不把反思完成自动写成人格已成长 |
| 动态发布 | 原发布工具只返回 `api_accepted_unverified` | 当前**不触发完成续行**，待增加可独立核实的动态真实发布确认 | 草稿及 API 受理均不能伪称发布成功 |

## 事件契约

- 完成回调只接受已有 `LifeWillingness` 有效账号作用域和 `verified` 状态；`delegated`、`not-sent`、`uncertain` 和 `accepted-unverified` 均拒绝升格。
- 事件账本只写入动作类别、派生哈希和时间戳；不存 UID、BV、私信、评论正文、平台原始回执、模型理由或明文 source key。
- 使用同一跨进程账本原子锁；`kind + sourceRef` 派生稳定匿名键，重启和重复结算均不会插入第二次相同机会。熟人及反思继续通过原 Planner 的已有本地核验回执处理。
- 后续注意力使用现有 `experience-ready`，初始安全延迟 2 分钟；实际是否提前决策仍由安静/自然/活跃档、原 Planner 额度、活动窗口、账号授权和可行动候选控制，**不是两分钟后强制写平台**。
- 时间线读已核验互动和反思的匿名摘要；频道日志和 Life 决策日志相互独立，不代替平台的原始回执。避免重复显示某条评论时应由 UI 使用来源去重，不修改原凭证。

## 错误、恢复和回滚

- 跨进程事件账本不可用时，续行登记失败不改变已确认的社交发送结果，发送事务仍不可重放；输出脱敏的诊断，需排查账本可用性。
- 账号切换后回调不能将旧账号完成写入新账号。内部意愿批准按原跨进程准入管理，未知完成不自动恢复。
- 已结算/未选中提醒由 dev.13 的有界公平调度和到期规则处理。提醒是一次**重新选择**，绝不是自动重新执行原动作。
- 老 `v1` 事件账本保持兼容；没有配置迁移，也不自动增加任意社交权限、日上限或工具调用频率。

## 验收门槛

1. 已核验私信、评论与其他写入结果仅一次触发匿名机会；跨进程重复消息不再创建同源机会；休息、未知、模型自称完成和进程启动均不触发。
2. 熟人主动私信必须等原发送事务确认与原熟人账本结算；纯审核、失败、账号切换不触发。
3. 自然档已确认评论后，在普通 30 分钟考虑间隔到期前可自主考虑其他独立真实候选，允许选择不行动。
4. 历史只读回执和视频轮次链保持不变。动态发布在独立确认前保持未核验。
5. 真实 Windows、B站账号、并发/崩溃恢复、72 小时连续生活仍是正式发布阻断项。
