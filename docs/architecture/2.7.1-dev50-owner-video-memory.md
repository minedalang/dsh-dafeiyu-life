# dev.50 · 视频节奏、主人 UID、主 Session Schema 与神经节点衰减（开发预览）

基线：**2.7.1-dev.49**。仅改变用户明确要求的设置、错误修复与 UI 表达；不会自动授予 B站对外发送权限，也不会强迫视频 Agent 凑数。

## 视频 Agent

- `videoAgentMinIntervalMinutes`：新版可设 **1～1440 分钟**。原有默认和没有显式改动的旧配置继续是 **20 分钟**；自动和手动视频启动共享真实启动时间门禁，不改变 Life 常规模型考虑间隔。过小可能增加 B站接口压力、模型调用和限流风险。
- `videoAgentReadTargetPerRound`：1～30，默认 8；`videoAgentPickTargetPerRound`：0～12，默认 4。**仅为视频子 Agent 的当轮软参考值，不是强制阅读、入选数量或发表评论次数**。真实可信视频资料、视频热度硬条件、B站读取预算和鱼鱼的自主判断继续有效；不能保证每轮达到目标，更不能保证自动评论。
- 两个值随 Life V2 versioned settings 的 `revision` 参与预览、显式确认和保存。旧入口和 Agent 配置工具不能悄悄改变这几个字段。

## 首次配置主人身份

首次配置页新增独立主人 B站 UID 填写与保存：实际账号 UID 仍是鱼鱼登录的账号，两个身份不可混淆。用户明确确认后，同步 `friendDirectory`、`mentionProfiles` 与 `dmOwnerUid`，利用原 `validateOwnerIdentityChange` 校验。只读页面打开不修改任何权限；设置主人身份不会自动授予公开评论、私信、点赞或关注等行为。

## 主 Session 多气泡 Schema 修复

`dafeiyu_chat_burst.parameters.messages` 不再向 DSH 工具值 Schema DSL 传 `minItems/maxItems`（原报 `unsupported JSON schema`）；`lib/message-burst.mjs` 内已有的至少 2、最多 3 条本地验证保留，保持严格防重复/续发约束。工具**注册阶段的兼容性修复**不等于 Windows 宿主已验证多气泡视觉投递成功。

## 记忆亮度

3D 记忆节点颜色仍区分记忆种类；明暗根据已有 `stage` 来区分：`clear` 明亮、`fuzzy` 中等、`trace` 较淡、未标注保持中性亮度。不以记忆日期或模型推测产生新的衰减评分，不因为 UI 变暗就修改记忆事实。

## 用户 @ 评论日志

上传的 10 份 Life 决策 JSON 显示：一轮社交快速考虑选择 `consider_social`，但 `no-verified-preview` 且 `delivery=not-sent`，不是发出回复。另一次 `comment_reply` 的 `LifeWillingness` 模型判断选择 `skip`，结果 `no-action/not-sent`。记录中仅保留 `reasonProvided=true` 与理由字数，未包含理由原文。因此**不能把「没有回复」认定为评论监听死掉，也不能断言鱼鱼为何拒绝**。若需定位专业 Agent 读取/审核/发送，仍需同时间段评论监听 `duty.log` 与对应回执。

`releaseReady:false`。Windows DSH、B站真实请求、主 Session 实际续泡仍需现场验收，保留历史基线失败。
