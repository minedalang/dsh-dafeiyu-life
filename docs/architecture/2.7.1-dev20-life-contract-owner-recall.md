# dev.20 · Life 统一状态契约与主人近期经历

> 未发布。架构设计与离线实现验证，不代表 Windows、真实 B站、72 小时或长期人格成长验收完成。

## 设计约束与运行契约

**入口 → 统一层 → 原事实源 → 场景 → 边界 → 回归**

- Life Planner：整合多源契机与节奏，读取 `LifeVoiceContext`、可信事件账本与记忆；不强迫视频优先，不因普通社交实时到来而阻断局部回复。
- 专业视频、私信、评论、动态 Agent：使用 `life-voice-context.mjs` 统一人格、情绪、兴趣、记忆和关系语境，在各自原有授权内选择行为；自主分享仍通过 `life-willingness.mjs` 与原发送事务。专业 Agent 不拥有另一份人格账本。
- 所有可信生活事实经原有 VerifiedLifeFacts、发送事务、LifeMemoryGateway、情绪、关系和兴趣写入链回馈。**本轮未新增万能写入接口**，未声称所有跨日因果都已经完成验收。无依据的模型自述不产生经历。
- 主人专属 DM 问“今天发什么评论、挑过什么视频”：只读 `seen.md`/归档的 `recentComments`（必须有发送回执），以及 `parseSeenTable()`（必须实际入选），限定最多各 5 条与近期 3 天；不查询平台热搜，不将选片伪称看完、听过或自己投稿。账号必须经绑定核验，切号后的全局无作用域历史仅在可证明归属时纳入；切号当天仅有日期的视频全部排除。普通聊天不强行插入经历。
- 新分享次数：删除自动分享每天 1 次和同一人 14 天无差别拦截；同一个目标视频/同一好友不能因为模型重试而重发。旧 `socialOutreachDailyLimit` 留作兼容配置字段但没有执行意义，UI 不再编辑。
- 跨渠道节奏：删除默认每人每日 8 次的旧计数拦截；仍执行跨渠道冷却、单独授权、未知发送冻结及各发送渠道本身平台保护。旧 `socialRhythmDailyPerPerson` 配置不再控制发送；UI 已移除。

## 验收与风险边界

1. 已有旧配置 `dailyLimit=1` 或 `dailyPerPerson=8` 不再影响发送额度；新增授权不会因升级自动开启。
2. 连续多条已确认社交互动不被退役的计数拒绝，未核验事务继续阻断。
3. 主人私信拥有真实评论原文和入选视频时能自然举例，没有记录时不能编造；切换账号不能拿旧评论当新经历。
4. 同一视频不能再次向同一人自动分享；没有真实发送回执不得进入生活事实，模型选片不等于完成观看。
5. 全渠道人格状态和长期成长的**真实因果验收仍属未通过项**；Life 主 Planner 与各专业 Agent 目前共享语境，不等于完成单一决策引擎改造。
