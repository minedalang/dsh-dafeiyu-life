## 修正的实际对照语义

旧实现可能让同一条原始消息的第二个匿名唤醒 ID **覆盖来源索引**，从而把旧回复器的分类配到错误事件；同一个事件的后续模型调用也能覆盖最初分类。因此“配对数/分歧数”可能被历史上较晚的结果改写。

本阶段在原有 `capture/noteLife/noteLegacy` 上实行：

1. 相同事件 ID + 相同可信来源保持幂等；**同一个可信来源但不同事件 ID** 返回 `source-already-staged`，不抢占旧索引。
2. 同一方第一次合法分类固定为该短期审计事件的观察结果；相同分类重试是无副作用的幂等，**冲突分类**明确失败。以上不介入实际旧回复器的自主决策。
3. 不同渠道分别展示：**已配对/一致/分歧、仅旧方/仅鱼鱼**。未配对表示缺少一方分类，并**不**等于鱼鱼选择沉默；同类一致也**不**等于平台已发送。
4. 状态永远提供 `socialHandoffReady:false`。这不是基于少量样本给出转交许可；没有配置可启用新 Agent 社交写入。上下文删除、授权撤销和账号切换后不留可复用配对。

## 实际接线、影响范围与回归矩阵

- 原普通好友 DM：入站成功后才暂存，原回复器生成分类可与 Life Agent 影子分类匹配；原 `send` 完全不变。
- 公开评论/@：同一套影子缓存和类别状态；原评论/@ 权限与平台回执保持原样。`dynamic` 来源只接受旧生产入口已核验的原事件。
- 主人 DM、陌生人 DM、主人主动评论/其他外发、动态投稿、回访：本次**没有增加影子原文来源**，没有接管，也没有额外权限。原有功能按独立渠道原样运行。
- 测试覆盖了同来源重复 ID、两方冲突重判、不同渠道未配对、跨账号、撤销、TTL、隐私诊断、生产静态接线，以及 Phase4/5 原有行为。模型提示及发送链本轮未修改。

## 使用者如何验收

1. 先保留备份，在「鱼鱼想做的事 → 自主生活驱动 → Phase 5 社交上下文影子对照」明确开启单独授权（默认关闭）。实际模型可能多一次调用，仍计入原每日额度。
2. 有合法好友私信/公开评论进入原接收入口，且 Life Agent 自己选中 `consider_social` 后，查看同页「影子对照」：不同渠道显示配对、分歧和单侧样本。**刚收到消息、没有二次模型调用或模型额度不足，都可以导致“仅旧方”；这是缺样本而非默认沉默。**
3. 切号、关闭授权或超过十分钟再刷新，应看到旧审计被清空。不要以配对率/一致率判断实际发送效果，不能用它证明鱼鱼愿意对特定联系人发送。
4. 不登录 B站的离线演练：`node tools/dev4-phase6g-social-audit-offline.mjs` 和 `node --test test/v271-dev4-life-agent-phase6g-shadow-audit.test.mjs`。所有 5 个纯模拟场景通过，且外发/网络/模型调用均为 0。
