# 2.7.1-dev.13 · Life 公平候选与真实执行续行（未发布）

## 统一层归属检查

| 入口 | 复用唯一层 | 事实源与作用域 | 新增场景信息 | 权限与恢复边界 |
|---|---|---|---|---|
| 自主 Planner / 普通唤醒 | `AutonomousPlanner` → `LifeAgentEvents` | 当前登录账号 + 原意愿/待办/熟人/兴趣账本 | 轮换候选类别 | 不新增平台写权限；多渠道候选只是一种提示 |
| 可信只读动作结束 | `AutonomousPlanner.recordLifeDecision()` → 原事件账本 | 原只读成功回执、已核验目标 | `experience-ready` 匿名二次考虑 | 失败、影子、未知发送、休息不得生成；不得自动重复原动作 |
| 真实生活时间线 | `LifeAgentEvents.status().timeline` → `buildLifeTimeline` | 当前账号、有效本地只读回执 | `life-read` 可信生活事件 | 不包含 UID、消息正文、模型提示词；不冒充实际观看或外发 |
| 管理中心状态 | 原 Life 诊断及时间线 API | 当前账号作用域 | 分类计数和下一次考虑时间 | 只是可读状态，不授权执行 |

## 当前具体实现

- `LifeAgentEvents` v1 保持账号隔离和跨进程原子写入。`peek(4)` 仍有界，但保留人工、有限社交、独立生活候选和视频轮次结束各自的席位。七种生活候选采用持久 `cueCursor` 轮流首选；读管理界面不会推进游标。
- 账号提醒缓存最多 120 条、保留 7 天。保存时保护最近待核实的审查条目和每类最多 3 个未结算提醒，避免社交高峰直接挤掉全部待办、熟人、兴趣和反思机会。**不是**永久任务库，也不承诺几千条社交事件都在此原样储存；平台原事务/消息账本仍是唯一事实源。
- 同一真实来源连续 3 次“本轮未选中”后不永久消失：只有原始来源在后续扫描中仍然合格，且经过 6 小时退避，才可重新成为待考虑提醒；明确选择休息、模型反复失败或执行结果未知不会被自动复活。
- `recordLifeDecision()` 仅在活跃模式且 `todo-read/done`、`video-metadata/verified-metadata` 或 `public-evidence/public-evidence-reviewed` 拥有有效本地只读回执时生成 `experience-ready`。只存 24 位哈希 ID，不存原任务标题、BVID、私信或模型理由；20 分钟窗口内重复回执去重。最早两分钟后到期，实际再考虑仍受生活节奏、时间窗、模型额度、并发准入及当前账号约束。
- `AutonomousPlanner` 在存在已到期可信续行提醒时，可早于一般生活间隔考虑，但安静／自然／活跃分别保留较长／中等／较短的最短间隔（30/8/2 分钟）；模型可选休息。**这不是视频 Agent 频控**，视频最短 20 分钟门禁和原工具授权保持不变。
- 「大肥鱼的一天」新增 `life-read` 类别：展示已核验的只读待办、公开视频元数据、公开证据读取；成功视频子进程、实际入选作品、评论发送仍从各自的事实账本独立读取。`life-read` 不意味着视频看完、听到音频、发过私信或评论。没有对应真实回执就不显示。

## 失败、恢复与边界

1. 损坏、过大或跨账号事件账本仍安全阻断；后续读取事件不授权外发。跨进程 Life 行动唯一准入及未知发送冻结机制维持 dev.9 契约。
2. `experience-ready` 必须重新读取当下的意愿、实际候选和权限。没有可信候选，记录为无可执行项，不强制创造行为；如果原只读回执本身仍待验证，则绝不发出续行唤醒。
3. 单次模型失败使用原有有限重试；重复回执去重只是一种避免重复**考虑**的机制，不能被当作外发事务去重保证。
4. 当前不覆盖所有入站评论、社交出站、动态创作和视频 Agent 内部每个动作的持久自动续行。实际 Windows Desktop、真实 B站、双账号切换和 72 小时自主生活仍需实机测试。不得发布正式 `2.7.1`。
