# 2.8.0 收口：Life 评论、视频委派与渐进式私信的证据契约

状态：以 **dev.16** 为基线的非正式诊断补丁；无真实 B站外发验收，不构成正式发行。

## 统一原则

同一可信观察可获得等价的行动机会；鱼鱼可选择执行、继续了解、拒绝、延期或休息。能力菜单不等于行动意愿，行动意愿不等于获得执行权限，执行请求不等于已确认平台送达。

## Life 视频 Agent

在 `model-input.menuActions` 包含 `browse_home` 时，证明当次模型看到了可委派的视频入口；只有 `model-choice.action === 'browse_home'` 表示鱼鱼选了它。进一步查看 `delegation-result` 和 `execution-result` 才能判断实际启动及结果。旧独立视频定时器已经退役。

不能用「没有启动」反推网络故障，也不能用「选了 browse_home」冒充已观看视频。

## Life 原创主评论

`model-call` 中 `action === 'life-continuation'`：

- `commentOffered` 代表本轮是否提供原创主评论。
- `commentNotOfferedCode` 只接受白名单诊断枚举，避免把私人材料写进日志。
- 新增的 `model-choice.modelScene === 'life-continuation'` 记录本轮已解析的选项，但绝不记录目标 BV、正文、模型原话。
- 当评论出现在菜单里，`candidate-detail.kind === 'life-original-comment'` 区分 `selected`、`alternative-action-selected` 和 `not-selected-stop-or-invalid`。
- 如果真正选中了 `comment_video`，需要继续检查 `action-result` 的 `write-verified / write-blocked / write-unverified`，以及原平台回执。未选择不代表硬门禁拦截；选择了但执行失败也不能写成「鱼鱼不想评论」。

## 私信渐进表达与快通道

持续使用原本的 Life 意愿凭据、账号隔离、发件人权限、发信门禁及平台回执。

- 普通私信最近回合的 `p6LastTurn.postSendStage`、主人私信 Agent 最近记录的 `postSendStage` 可以为 `not-eligible`、`prewritten-burst`、`after-first-confirmed-reconsidered`、`after-first-confirmed-generated`、`stopped-or-invalid`、`cancelled-new-incoming`、`blocked-by-factual-gate` 或 `post-send-confirmed` 等。阶段标记不存正文或用户 ID。
- 只有 `post-send-confirmed` 且第二条拥有真实回执，才能说观察到了 **首条送达后新增生成、随后得到送达确认**；不能将普通 `2/2` 多气泡一概算成渐进生成。
- `interactionSchedulerStatus.checks.dmFast` 显示定向检查执行情况；`activeDm.checks` 是当前运行进程中的计数。重启前的历史快通道 tick 无法从磁盘恢复。

## 仍待正式验收

Windows PowerShell 5.1 上实际运行增强 BAT；连续采样 DSH 本机状态以核验活跃快通道；观察完整 72 小时的 Life 视频/评论决策和平台回执；分别测试正常、不想说、证据不足、限流、撤权、切号、网络超时、已发未知结果。禁止为了验证而无控制地向 B站发真实评论。
