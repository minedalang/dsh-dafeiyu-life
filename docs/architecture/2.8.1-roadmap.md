## P1：按关系的自然行为矩阵

同一人同时拥有三个互不代替的维度：**自然熟悉度**（new/known/familiar/friend）、**渠道双向互动证据**（公开评论 vs 私信）、**DM Openness / 主人外发授权**。白名单不是关系分数；公开熟悉不直接开放主动私信。

| 场景 | 新人/陌生人 | 公开熟人 | 私信熟人及好友 | 主人 |
| --- | --- | --- | --- | --- |
| 私信回复/评论交流 | 仅各渠道独立授权允许时，自主回复/沉默 | 同左，关系可影响语气 | 真实双向上下文影响语气与续聊 | 主人专属规则及身份核验 |
| 接受视频/音乐推荐 | 只读探索可独立决定现在/以后/不看 | 同左，考虑公开经历 | 同左，合法接纳后可以形成回访意愿 | 同左，主人提出的请求不等同自动公开写入 |
| 对方要求关注自己 | 不能仅凭请求关注 | 可考虑只读作品，外发关注仍需原独立许可 | 需当前关系资格、单独主人授权和同 UID 一次意愿；不能仅因白名单就关注 | 依主人明确操作授权与原平台工具资格 |
| 主动联系/分享视频 | 无默认主动 DM 权利 | 不因评论熟悉自动转私信 | 稳定私人往来、明确授权、非拒联、当前 Life 选择及精确回执均满足才可能发 | 走主 Session/主人专用边界 |
| 关系增长/淡化 | 从可核实互动自然形成 | 按活跃天数、双向和时间跨度演进 | 同时保留公开/私信证据差异及可衰减个人画像 | 主人身份不能由内容自称授予 |

## P1：自主行为范围与真正的结果闭环

- **回应型**：私信/评论/@ 回复、安静不回、择机续聊、跨日自然回访。一次回应意愿，专业 Agent 文案/发送不二次“愿不愿意”。
- **探索型**：别人推荐 BV/歌曲、主动搜视频、浏览首页、看作者空间和公开评论。接受只读任务不等于内容已看过，只有真实工具回执才可记经历。
- **关系型**：认识/记住熟人、关注创作者、回应关注请求、自然联系与分享。严格分离关系与写授权，拒联随时阻断。
- **表达型**：点赞、收藏、关注、取关、原创主评论和生活动态。新的动作允许新意愿，但不能为同一动作层层投票。
- **生活型**：核实线索/契机、处理承诺待办、继续或放弃 Episode、休息与主动找主人。状态需能跨重启正确续接，不因历史记录丢失而冒称完成。
- **成长型**：真实经历→兴趣、记忆、情绪、关系、人格→影响下一次选择；需要跨日因果证据，不能用模拟分数证明真实成长。

## P2：全站管理中心 Vue 响应式（不进入 2.8.0）

- 后端 API、账号隔离、发送事务均不因前端框架迁移改变。
- Vue 3 + Pinia 集中只读视图状态；复用原 SSE 变更提示，按需重新拉取原业务数据。
- 与真实平台写入有关的配置修改/授权必须显式确认、幂等与错误处理，不因组件重新挂载重复触发。
- 优先迁移 Life 面板、树与时间线、回忆场，再迁移社交/后台管理；保留性能、断线重连和旧浏览器降级路径。

## 发布前验证

1. 每一条行为验证“真实来源→单次自主意愿→严格门禁→专业执行→可信回执→成长记忆”，再单独验证应当拒绝/延期/沉默的情形。
2. 使用跨账号、撤权、重启、PID 崩溃、结果未知和多实例竞争用例；已消费的写入不得重复。
3. 旧用户从早期正式版停机快照迁移、恢复、回滚、遗忘/联系人/凭证隔离不能回归。
4. Windows DSH/真实 B站受控环境 + 至少 72 小时统计与完整失败归因；不能拿模拟测试冒充这些结果。
