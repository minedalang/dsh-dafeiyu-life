# 2.7.1-dev.21 · 主人私信主动回忆与自然事实修正

> **历史增量（dev.21），不是最新生产接线总览。** dev.22 的公开评论按需回忆与跨日评论主账本查询见 [`2.7.1-dev22-public-recall-unified.md`](./2.7.1-dev22-public-recall-unified.md)。此页仍记录 dev.21 主人私信原能力；本项目尚未正式发布。

## 问题与证据

dev.20 主人私信使用 `socialContextAssembler.ownerDm()` 预检索记忆，并在提及“今天的视频与评论”时一次性加载少量当前账号公开行动。通用长期记忆的 `mainSessionMemoryEnabled` 开关属于主 Session，默认关闭时主人私信可能拿不到相关记忆。主人私信模型无法按需搜索、展开记忆细节；固定事实校验回退又会把有用内容替换为机械检讨。

## 本轮改造

1. `owner-dm-agent.mjs` 增加 `memory_search`、`memory_detail`、`recent_actions` 三个**只读动作**，最多 4 步，不能使用记忆工具代替写入权限或跨账号查私信。
2. `owner-recall-tools.mjs` 对“妙评／夸过／之前那句”等问题识别并扩展查询。主人明确问自身经历时做一次小规模预检索，小模型仍可主动决定下一步是否继续检索。
3. `memory-retriever.mjs` 新增 `ownerSearch()` 和 `ownerDetail()`：只读取当前可用的长期记忆、历史兼容副本以及仍未遗忘的实时情节副本；本次主人提问不允许作为其自身的“旧回忆”返回。主 Session 记忆总开关不再错误地控制已授权主人私信的只读回忆能力。
4. `index.js` 严格检查当前登录账号、认证主人 UID、主人私信 Agent 开关以及账号冻结状态；调用者的合法记忆 ID 只能来自本轮已返回的结果。记忆查询不会调用 B站写接口。
5. 普通聊天提示词剥离长篇待办细则，提议类消息才加载待办证明规则；主人私信人格压缩到有界上下文。事实校验失败时先给同一模型一次针对性修正机会；修正仍不成立，则基于已核验记录自然回答，不再使用整段固定检讨。

## 主人私信回忆数据流

详见 [`diagrams/2.7.1-dev21-owner-recall.mmd`](diagrams/2.7.1-dev21-owner-recall.mmd)。用户内容与检索结果都是**只读资料**，不能包含工具调用授权、不能改变 owner UID，也不能提升公开私信或评论权限。

## 与既有数据的兼容性

- 不迁移、不清空原长期记忆、记忆花园和旧主人会话文件；不改变可遗忘副本的衰减或恢复遗忘归档的内容。
- 旧 `owner-dm-agent.json` 继续使用 `version:1`，无需升级脚本。
- 主 Session 的 `mainSessionMemoryEnabled` 保持原含义。主人私信中的私有回忆是**单独的已验证主人只读通道**，不会流入普通好友或公开评论。
- 用户切换 B站账号后，读取平台行动记录仍受原账号截断时间约束；历史 UID 记忆只能当作历史资料，不能作为当前账号或发送资格的证明。
- 未修改社交权限、1000 条评论容量、视频最短 20 分钟间隔或模型实际输出配置。

## 验收边界

本地测试验证：主开关关闭时 owner DM 仍可检索，模型分步读回、伪造 ID 无法详情读取、无记录时不编造、修正文风不被固定句覆盖、旧文件仍可读取。**尚未完成**真实 B站私信、Haiku Medium 与更强模型盲评、向量语义检索的相关性评估及长期跨日人格因果验收。当前为本地关键词扩展＋实时情节检索＋证据回查，尚不能声称完整语义向量搜索已经落地。

## 对照方案

- Letta/MemGPT：按需主动回忆工具的交互设计（未引入其数据库或完整运行时）。
- Mem0：混合检索和记忆来源追踪的思想（未照搬向量存储）。
- Graphiti：事实的时间、关联对象及可追溯性（未新增第二份关系图数据库）。

## 后续实机实验

对同一批主人真实问答固定模型：A=dev20、B=dev21，两组比较正确记忆 Recall@5、最终回答相关性、无依据自述、重复检讨比例、延迟与费用；再换更强模型作变量控制。禁止用“单次回答看起来聪明”替代统计与真实证据。
