# dev.4 自主生活可见验收（Phase 6e / 7e 衔接）

## 问题与真实系统边界

此前管理中心仅显示 `active`、日额度与压缩多栏时间线，用户无法确认 Life Agent 是否真正委派视频 Agent，也无法区分安全门禁、模型选择休息和实际视频观看。原执行器只有一个 `bilibili.video-explore` 专业能力，不存在另一套“新视频 Agent”。`off` 允许原旧视频定时器按旧设置运行；`shadow` 允许 Life Agent 观察但绝不通过新生活驱动启动视频 Agent；`active` 则允许 Life Agent 在可信候选、模型自主选择及原授权/限额允许时委派**已有的视频 Agent**。只读待办的元数据读取另按现有授权工作，不能因此声称已观看音视频。

## 当前实现（本轮已落地）

1. `lib/life-experience-readiness.mjs`：纯只读投影，可解释总开关、调度开关、影子模式、每日模型决策额度、账号事件账本状态、当前可用视频能力、每日两次视频委派及180分钟视频委派间隔。它不访问 B站、不调用模型，也不启动视频；仅显示目前门禁是否可用，**不保证下一轮有可信候选或模型会选择探索**。
2. `lib/autonomous-planner.mjs#status`：从当前同账号 Planner 和原 LifeAgentEvents 读取真实状态，调用上述只读投影。使用原来的唯一数据账本，不新增配置或记忆副本。
3. 管理中心新增“真实状态”和“本账号真实委派次数”两项说明，重新核查按钮不会计费；将自主人生决策时间线改为纵向单栏，保留实际回执与历史不可追溯区分。
4. `lib/life-experience-demo.mjs`：通过同一个 `createAutonomousPlanner()` 运行**四个合成场景**（影子想看、自主委派、自主休息、无可用视频能力），只用假模型、假账号、假事件和假视频适配器，临时目录随调用清理。管理中心明确标记“纯模拟”，也可用 `tools/dev4-life-experience-offline-acceptance.mjs` 独立运行；不读取真实账号、不会联网或发送。
5. 管理中心演示入口是独立的 POST `/life-agent/offline-demo`，沿用同源请求保护；真实手动唤醒 `/life-agent/wake` 仍保持原额度、外发权限和安全门禁。

## 统一层归属与安全门禁

- 入口：管理中心真实状态刷新 / 纯模拟验收 → `AutonomousPlanner.status` / `runLifeExperienceOfflineDemo`。
- 复用统一层：已有 Life Agent 决策、账号隔离的 LifeAgentEvents 视频委派回执、LifeCapabilities 可用性判断。
- 唯一事实源：`life-agent-events/<scope>.json` 保存自身的委派开始（并非视频观看完成）；原视频执行器和平台回执仍为真实行动证据源。
- 新场景信息：匿名门禁枚举、计数及演示中可重置的合成事件；不记录 UID、BV、消息正文、token 原文或模型思考。
- 权限和隐私：只读核查不写真实数据、不调模型；模拟的假适配器绝不调用实际视频 Agent；真实 `active` 启动条件未放宽。
- 受影响渠道：仅管理中心验收体验，不改变 B站私信／评论／关注、主人会话、回访及平台外发入口。
- 回归：新增核心专项、dev.4 相邻测试、Node/Python 安全层、插件自检和 npm 打包预检。

## Windows 验收

先运行 `node tools/dev4-life-experience-offline-acceptance.mjs`（期望四个合成场景、0 真实模型/网络/外发）。打开管理中心，观察“当前自主生活是否真的生效”：在 active 模式下确认门禁情况，明确显示是否已存在 Life Agent 视频委派。点击“演示四种选择”，页面须显示“纯模拟”。真实 B站视频观看必须另以原视频 Agent/执行回执核验，不可凭演示或 Life Agent 的委派数字得出结论。
