## 1. 为什么允许推翻既有生活流程

产品目标不是让一个固定定时器驱动「看视频→挑选→评论→下轮再看」，也不是为每种「聊得开心便关注」「喜欢 UP 主便关注」写独立流程。目标是**同一条鱼**在真实世界事件中拥有连续的自我意愿，能主动发现目标、组合已有能力、观察结果、改变看法，也能休息、拒绝或放下。

因此 **不以“保留所有现有场景流程”为约束**。允许替换甚至退役旧的生活驱动链；应尽可能复用过去开发的可靠能力、数据与用户设置，且保留可验证的安全边界。不要把 Life Agent 做成旧「定时刷视频」外面的一层提示词。

### 基本分工

- **Life Agent = 自主生活决策的唯一协调主体**：根据人格、心情、兴趣、关系、当前可回忆的经历、已承诺任务及可用能力，选择目标、步骤、延期、停止或沉默。可以出现设计者没预先列举的行动组合；不是所有情况下都必须行动。
- **平台事件接收器 = 感知设施**：后台轮询、通知游标、定时心跳可以继续存在，用于及时且低成本发现新消息和唤醒 Agent。它们不能再自行定义「鱼必须刷多少视频」「来了评论必回」等生活目标。
- **能力适配器 = 可执行技能**：搜索、读取视频、字幕、评论、主页、关注、发评论、私信等工具及其平台实现；平台本身不负责自主生活策略。
- **确定性执行与安全层 = 不可由模型改写的约束**：账号隔离、用途权限、额度、去重、冷却、同意与退订、反骚扰、事务预约、结果未知冻结、真实回执、可遗忘性与敏感信息隔离。
- **经历与记忆 = 对已核验事实的投影**：读取元数据不等于看过画面，视觉描述不等于听过声音；生成文本不等于已发布。意图可以记录为意图，不可冒充完成事实。

**关键原则：重构决策流，保留经过验证的执行能力。** 旧场景函数允许被拆成工具和事件适配器；旧版独立决策循环在迁移完成后应停用，不能与 Life Agent 同时对同一事件作第二次行动决策。

## 2. 以当前代码为依据：哪些保留、哪些重做

| 当前代码与机制 | dev.4 决策 | 理由及迁移方式 |
|---|---|---|
| `index.js` 里的 `peakValley` / `peakWindows` / `runDuty()` 定时视频轮 | **替换旧生活驱动** | 保留 `runDuty` 内合法只读动作、视频采集/证据接口和资源预算；让 Life Agent 发起按需视频探索，不再由固定时段决定必须刷视频。旧设置迁移为可选生活节奏/可用时窗，而非“完成观看指标”。 |
| `lib/interaction-scheduler.mjs` 的 DM/回复/@ 轮询 | **保留为事件采集** | 平台不一定提供推送，轮询仍负责查新、游标和去重；消息写入事件队列后，由 Life Agent 决定回复、阅读、关注或沉默。快速对话必须有延迟预算和可解释的降级。 |
| `lib/autonomous-planner.mjs`、`lib/life-opportunities.mjs` 的候选与独立定时决策 | **合并／渐进替换决策** | 重用原待办、意愿和事实数据；只保留一个总协调循环，避免同时让旧 Planner 和新 Agent 竞争执行同一动作。 |
| 主人已接受待办、父子待办、回访账本 | **保留作为承诺与义务来源** | 鱼可选择何时处理或解释延期，但不应把已经接受的承诺当成可无痕丢弃的自发好奇；复用原回执与状态转移。 |
| `life-voice-context.mjs`、心情、人格成长、`LifeMemoryGateway`、`life-interests`、关系索引 | **复用唯一生活状态** | 不另建「B站人格」「抖音人格」「第二长期记忆」；每个来源仍按渠道、UID、隐私域和遗忘约束检索。 |
| `lib/read-action-execution-gate.mjs`、Python `read_action_gate.py`、`outbound_action_gate.py`、现有各发送账本 | **复用并巩固** | Life Agent 只能请求动作，不能替自己批准权限、直接写入平台或声称取得未验证回执；不确定发送不得自动重试。 |
| `SocialPolicyGate`、平台账号绑定、B站工具、真实回执、数据备份 | **保留实现，允许接口重组** | 稳定安全与数据能力是重要资产，替换调用入口可以，但先做好回归、迁移和可逆切换。 |
| 原独立社交决策模型（私信、评论、主动分享等） | **可拆可退役** | 迁移为统一 Life Agent 的事件分析、内容生成或工具能力；不能长期保留多套互相矛盾的「鱼想不想」真值。 |

现状举证：`index.js` 当前仍以 60 秒 tick 和固定时窗驱动 `runDuty()`；`interaction-scheduler.mjs` 每 15 秒调度消息轮询；`autonomous-planner.mjs` 每分钟检查独立自主决策。这些是**当前生产接线**，不是 dev.4 的完成状态。

## 3. 目标架构：一个主体，多平台世界

- **触发源**：新消息、公开作品线索、经历／记忆的相关性、承诺到期、资源／生活节奏唤醒、用户明确指令。心跳只负责「是否值得考虑」，不强迫执行指定生活任务。
- **上下文组装**：同一人格与可访问的近期经历；隐私和遗忘在读取前过滤。必须带证据 ID、平台及账号来源、可见范围、置信边界。
- **Life Agent**：提出或延续目标，动态选择来自能力目录的动作；有预算的多步「观察→决定→行动→观察」循环；可 `continue`、`defer`、`abandon`、`reply`、`observe_only`、`idle`。所有步骤可追溯其实际输入与决策结果，不保存不必要的私信正文。
- **统一行动契约**：包含 `intentId`、`actionId`、`platform`、`accountScope`、`capability`、目标引用、证据来源、权限声明、风险层级、尝试序号；跨平台动作必须使用不同账号授权和独立回执。
- **安全执行**：一切写操作仍经当下有效授权与外部反骚扰政策；无身份核验就不跨账号关联；未知回执冻结而不是交给 Agent 猜测重试。
- **真实反馈**：只把 verified / failed / unknown / rejected / deferred 等状态传回 Life Agent；记忆、关系和兴趣系统仅采纳当前许可下的真实证据。

未来接抖音时新增 **抖音平台适配器与能力声明**，不用再建一个鱼鱼或第二套目标规划器；但平台协议、权限、账号、数据归属与真实性证明必须分别实现。dev.4 要用一个模拟第二平台适配器检验内核确实不依赖 `bili_` 工具名，而不是声称已经接入抖音。

## 4. 自主性不是无条件自主外发

- **可自由决定：** 有没有新的好奇心；想认识谁；先调查哪条视频；是否继续、延期、拒绝、沉默；在许可范围内选择多步路径。
- **代码硬边界：** 当前用户授予的精确权限、平台规则、联系人拒绝、冷却/限额、对象身份核验、可见性/隐私、发布内容来源审查、进程中断后的未知回执冻结。
- **能力可用但权限未给：** Agent 可以在不泄密的本地意愿记录中保留目标或放下，不能自行开权限或将未授权计划偷偷变成写入动作。
- **关注不是自动奖励：** 聊得愉快、看了作品只是可能的行动原因，不是固定阈值或必须关注的触发器。反复未获回应、拒绝联系时应自觉保持距离。
- **真实互动体验：** 消息接收无需模型 24 小时高频运行；对方来信可以被及时感知，再决定回应或沉默。显式已承诺回应不可被「自由」当作无限拖延借口。

## 5. 目标循环与故障边界

1. 事件进入持久、按来源隔离的待感知区；游标与事件 ID 防重复。系统唤醒时可因没有值得做的事而立即结束，**不以每次必须产出行动为评价指标**。
2. 获取当下允许访问的记忆、关系、兴趣、情绪及未完成承诺；不存在的证据不得由 Agent 自行补造。
3. 同一 Life Agent 作一次有界决策，或者提出由模型继续探索的目标。能力目录动态提供当前平台实际可用的工具，模型不能凭文字新建未知能力。
4. 每一步通过能力注册表、策略、配额与确定性执行层；查询返回实际回执，超时/不明结果必须单独上报与冻结。
5. Agent 可根据结果改目标、继续、暂缓、求助或结束；单轮步数、时间、模型调用和读预算受上限约束，跨天恢复由真实状态驱动。
6. 人生记忆和关系只在可信回执与合法访问下发生相应变化；错误行为应该允许纠正叙述，但不得伪造历史成功。

失败必须可观察：`no_event`、`chose_idle`、`model_unavailable`、`not_authorized`、`receipt_unknown`、`rate_limited`、`platform_error`、`account_changed`、`deferred`。其中 `receipt_unknown` 永远不能被下一轮视作成功或自动重试。

## 6. 分段迁移：先替换生活驱动，再逐步退役旧决策

| 里程碑 | 开发内容 | 退出条件 |
|---|---|---|
| D4-A：盘点与契约 | 列出全部场景触发器、定时器、状态写入者和工具所有权；建立 `LifeEvent` / `LifeIntent` / `Capability` / `ActionReceipt` 的最小契约以及第二平台假适配器 | 事件与工具来源可追踪、同事件不会产生双负责人；旧数据读取兼容 |
| D4-B：影子决策 | Agent 用真实脱敏事件作只读 `dry-run`，不执行写入；对比固定刷视频与 Agent 的目标选择、成本、是否能选择休息 | Agent 可独立选择完全不同的探索路径、可选择不刷；不凭空认定观看或听歌 |
| D4-C：**生活驱动权切换** | 经明确开关和可逆迁移，关闭旧时窗 `runDuty` 自动目标驱动与旧独立 Planner 决策；由 Life Agent 按事件/节奏主动选择已注册只读技能 | 同一动作仅一个执行者；无固定视频配额驱动；原有承诺、备份与用户设置可读 |
| D4-D：社交与关系统一 | DM/评论/@ 保留轮询采集，由 Agent 统一判断是否互动或进一步认识；社交写入只在原政策允许且有真实回执时执行；自主关注成为**行为验证案例**，不是新增硬编码场景 | 同一消息不由两个 Agent 重复回复；陌生人拒联、权限关闭、未知回执及账号切换测试通过 |
| D4-E：反馈与退役 | 行动证据反哺意愿、兴趣、关系、人格；撤出重复决策代码，保留可迁移历史状态和降级支持 | 真实长时间运行无重复打扰/无假经历；用户能看到“为何想做、做了什么、为何停止” |

**切换纪律：** 阶段性可以保留旧实现作对照，但**同一账号同一事件不能同时启用新旧自主决策器**。切换须有明确版本化标记、原状态备份、回滚办法；回滚不得解除未知回执冻结，不得偷偷恢复已撤销权限。不能将影子测试等同于生产上线。

## 7. 可证伪的验收：鱼鱼是否真正更自由

1. **无固定刷视频驱动**：关闭旧时窗后，Agent 仍能从不同来源的真实经历提出探索；也能在有空闲窗口时选择完全不刷。不会强迫达到每日观看指标。
2. **未知路径组合**：同样从真实评论或视频开始，至少演示两种不同工具顺序，以及明确 `idle/abandon`；无需为每种组合增写场景函数。
3. **自主关注**：可以因对话或作品产生意愿，也可能不关注；有独立现时授权才进入写入安全闸，平台回执确认才成为已关注事实。
4. **持续性**：跨次唤醒可恢复真实未完目标，也能主动放弃自发兴趣；已接受主人的待办不可被无痕丢弃。
5. **跨平台可扩展**：接入假第二平台，证明核心决策不需要增加平台分支代码；未经证明的跨平台人物身份不得自动合并。
6. **安全不可回退**：无权限、退订、冷却、错误账号、未知发送状态、进程崩溃、隐私与遗忘边界的负面测试保持有效。
7. **用户可观察**：管理中心应解释“真实事件→自主选择→行动/不行动→平台结果→后续改变”，不把“没运行模型”和“鱼鱼主动沉默”混成一个状态。
8. **Windows 实机与真实平台**：先无真实外发的只读场景；再由使用者明确指定可控的外发对象和范围；不得将 Linux 离线通过冒充真实平台验收。
