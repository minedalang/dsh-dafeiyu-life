# 2.7.1-dev.7 · RC 主人互动与待办回访外发门禁收口

> 状态：离线集成，**未完成 Life 社交所有权交接**；`socialDecisionOwner` 仍为 `legacy`，不得把本次门禁加固写成正式 RC 发布。
>
> Patch 基线是 `DSH-2.7.1-dev7-RC-social-feed-full-source.zip`（包含最新社交兴趣和视频分享事务修复）。

## 1. 为什么需要补这一步

原有普通私信/评论、视频兴趣推荐发送已进入旧社交归属复核，但还有主人私信 Agent、主人指令回执、即时只读待办回执、待办完成回访和主人命令调用的手动写入工具等生产入口。若新 Life 将来接管，只检查普通聊天入口不足以避免旧处理器在旁路发送。

## 2. 当前真实执行路径

- **统一所有权：**`legacySocialWrite(channel)` 先查 `socialDecisionOwnership.route`，再预约 `SocialHandoffFence` 的旧执行槽，平台写入前再次确认 owner。账号不匹配/所有权变化时返回拒绝，不发送。
- **主人私信 Agent：**使用原核验过的首条消息 ID（`owner-agent:${id}`）标记一轮真实回复，`legacyDmWithReceipt` 进入已有 `SocialSendTransaction`。同一账号、渠道、来源只会有一个事务。重启、重轮询或失败都不可自动重发。
- **主人意愿拒绝与操作回执：**分别使用原平台消息 ID、待办 ID 作为稳定来源；原接受/拒绝、权限和事实核验保持不变。
- **待办回访：**由原 `OwnerTodoFollowup` 传递已受理待办的持久键；评论回访和私信回访共享相同的账号范围与跨进程事务，不增加新的回访权限。为避免历史复合键过长，事务标识只保存 SHA-256 摘要。
- **真实回执：**私信必须有 `extractBiliDmReceiptId()` 提供的发送 ID，评论必须有可信的非零 `rpid`。缺失、超时、异常均置 `uncertain`，同来源之后不可自动重试；`success:true` 不是完成证明。
- **主人命令写入待办：**以 `bili_send_message_manual` / `bili_reply_manual` 为既有受权限与回执控制的写入适配器，本次将这些主人指令路径纳入 `legacySocialWrite`。该手动适配器本身的回执逻辑仍归原工具负责，**并不等同于上面自动回执的共享事务**。
- **直接由使用者在主 Session 明确调用的独立工具**与后台自动决策是两种授权边界，不因为本轮主人私信链路改动而放权；以后接管仍需逐入口审阅。

## 3. 不变与有意保留的系统

保留原 `OwnerDmAgent`、`OwnerTodoFollowup`、`SocialHandoffFence`、`SocialSendTransaction`、平台写入适配器、权限/频控、人生记忆、兴趣与人格协调器。既不新增第二套发送账本，也不把调试证据当作可外发许可。运行中可能已经送达的事务不能自动解除冻结。
