# 2.7.1-dev.48：专业 Agent 可选读取由 Life 决定；神经回忆与运行健康

> 开发预览，`releaseReady:false`。dev.47 完整源码为唯一补丁基线。

## 真实调用关系

- 原 `lib/interaction-batch.mjs` 仍负责相同 UID/渠道的生成上下文，评论子 Agent 在精简上下文模式提出 `contextRequests`。新增 `hot_comments` 和原先的 `public_person` 是**可选、只读的补充证据**，不是每条评论默认读取。
- `index.js` 中的 `authorizeContextRead` 把来自**已核验当前评论**的请求转换成可选 `social_read` 候选，交原 `lib/life-willingness.mjs` 自行 `act / skip / defer`。一次只能批准模型选中的具体一项，不能因为选择了查看热评就顺便查看评论者主页。`lib/interaction-batch.mjs` 再次对批准清单取交集；未获批准时让专业 Agent 无该资料重新考虑回复。
- 原 `readVerifiedCommenterPublicVideos()` 的 `commentPublicProfileReadEnabled`、B站读取预算、评论来源与账号门禁继续有效。这里的设置仅为外部访问范围授权。旧用户的 `false` 不自动开启。`lib/comment-video-context.mjs` 的 `forHotComments()` 使用原守门工具 `getHot` 和已有 2 分钟缓存；未选择时不发请求。
- **未完成**：原评论处理入口的可信原视频元数据/楼层读取、@ 场景必要热评、专业 Agent 发送回复及视频 Agent 的全部多步行为尚未统一改为 Life 每步自由菜单。Life 的日常自动考虑间隔不直接挡住现有私信、评论专业回复；专业模型与 LifeWillingness 的额外意愿调用可能增加延迟。不把本轮修改描述为无限开放式行动代理。

## 神经回忆场（正式管理中心，真实数据）

- 原 `memoryGardenSnapshot` 和 `lifeMemory.recall` 仍是唯一召回来源。`GET /main-session/memory/neural` 使用既有同源鉴权，只允许主人本地页面查看，返回由 `lib/memory-neural-projection.mjs` 投影的节点与证据边，不写新数据库。
- 检索支持关键词与经历 / 人物互动 / 后天兴趣 / 长期认识分类。动画是实际检索完成后的信号展开，**不是模型隐藏思维链**。
- 只有两份记忆携带同一个经过保存的来源事件引用时才产生关联边。相同关键词或语义相似不构成“兴趣已发展”“情感联动”的证据。只有 `emotionObservation.sourceEventId` 确实对应记忆来源的记录才显示**当时**情绪回声，不把当前模拟情绪倒灌到历史。
- 被删除、封存和已遗忘记录不得重新出现在图中；来源 token 在服务端关联后不会传给网页。界面可按用户减少动画偏好停用过渡。语义模型与词法图谱可能出现不同召回集合，需标示真实召回类别，不凭空补命中。

## 技术故障显眼提示

- `GET /life-agent/system-health` 只投影原 Life 模型退避/错误、B站共享读取冷却、网络监听退避和不确定外发，不进行新一次联网探测。
- 事件分类为“模型不可用 / 超时”“B站读取冷却”“后台网络监听退避”“结果不确定”，显示下一次计划尝试时间；技术失败不可改写为 `voluntary-rest`。
- 主人主动关闭的监听不视为系统故障。未知发送结果不自动重发；显示本地诊断不证明平台真实连通。

## 保留安全约束与验收限制

一个 Life，多个专业执行器；原主 Session 唯一。评论原始来源、账号一致性、B站访问次数限制、回复授权与写操作平台回执均保持原防线。私信正文、模型隐藏思维和平台凭证不进入图谱/健康诊断。真实 Windows DSH、B站请求、模型中断恢复及 72 小时验收未完成。
