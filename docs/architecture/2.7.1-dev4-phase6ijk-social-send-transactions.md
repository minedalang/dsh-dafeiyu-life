# 2.7.1-dev.4 Phase 6i/6j/6k 安全基础：逐消息持久外发事务（Legacy 生产接线）

> **实际接入：** 后台普通 DM 及公开评论/@ 的原有发送适配器前增加逐消息持久写入屏障；**没有**打开 Life Agent 社交决策、社交发送或灰度权限。旧 `SocialPolicyGate`、原本的收件/评论游标、冷却和平台回执仍是唯一权威。Linux 合成测试不代替 Windows/B站验收。

## 统一层归属检查与新增理由

`已核实入站来源 → 旧回复器决定 → 旧权限/额度复核 → SocialDecisionOwnership.route + Phase 6h 渠道级预交接隔离 → cadenceSend → 新 SocialSendTransaction.execute → 原 MCP 发送工具 → 严格平台回执 → 记录匿名 confirmed/uncertain → 原业务状态/关系投影`。

已有 `dm-autoreply` 的发送前占位和 `comment-interact` 的发送尝试表是各自进程的状态，并不是 DM 与评论共用的跨进程幂等写入边界；Phase 6h 的 `SocialHandoffFence` 则是**渠道级交接冻结**，不是逐来源发送事务（不能拿它的 `releaseDecisionOnly` 解除真实发送）。因此新建独立生命周期的 `social-send-transaction.mjs`，由两个生产发送入口共用，不创建第二个发送器、不复制人格/事实/权限/回执、也不引入模型调用。

## 行为与存储契约

- 在 `$DSH_HOME/bili-duty/social-send-transactions/<accountHash>/<dm|comment>/<eventHash>/state.json` 保存最小状态；目录名和 receiptHash 均是 SHA256 派生，不存 UID、事件明文、私信、回复正文、平台回执原值或账号原值。账号哈希仅用于隔离，不等于加密。状态随本地完整冷快照保留，便携备份清单不隐式扩大。
- `execute` 只接受登录账号可信标签和稳定来源键：普通 DM 使用收件事件 ID 与气泡序号，评论使用 BV／动态 ID + 原评论 rpid + 回复用途 + 气泡序号。**不以模型生成的文字做事件标识**。缺少稳定来源/账号、目录不安全时发送失败，不走降级外发。
- 原子创建事件目录；落盘 `prepared` 后再持久落盘 `attempted`，只有持久写入确认才调用平台发送适配器。得到有效 `msg_key`（DM）或 `rpid`（评论）后记录 `confirmed`；回执不可信、MCP 异常、断线、重启或写回执失败均保留为 `uncertain`/`attempted`/不完整目录，阻止同一来源的下一次发送。
- **成功的事务也不作为下一次发送的许可证**：重复来源会被拦截，即使是另一进程。旧回复器仍负责决定是否回应和继续下一气泡，以及对外授权、跨渠道节奏和接收者状态。
- `reviewNoAttempt` 仅供离线维护：确实停机、旧进程 PID 已退出、记录仍是 `prepared`、运维明确确认从未进入平台发送时才允许清理。`attempted`、`uncertain`、`confirmed`、内容异常/残缺记录**一律不可由此 API 清除**。当前不提供管理页一键恢复；必须人工核查平台和原业务账本，不能把“没看到回执”当成没发送。
- 管理中心 Life Agent 的「社交回复所有权」追加本账号 DM/评论的匿名事务状态汇总，无 UID、正文、发送对象、明文 eventKey；保持 `socialHandoffEnabled=false` 和 Life Agent 未接管。
- 这层约束只保护当前**旧 DM/评论发送回调**；主人独立 DM Agent、主动分享、定期回访、点赞/关注/动态发布等其他外部写入口未迁入，不可声称已全局覆盖。

## 当前缺口及正式接管门槛

1. 当前 `route()` 仍是**检查式**，不能证明“旧模型开始决策之后，Life Agent 的未来新决策者无法抢先插队”。Phase 6h 的渠道预约尚未在发送全程持有，因此**跨 owner 的原子交接尚未完成**。
2. 新增事务的原始来源 ID 必须来自旧流程的已核验事件；原线程与收件游标、实际平台回执仍保留在旧模块。跨流程同一用户不同事件不会被误当成同一条，但其他外发入口可能产生独立动作；后续必须统一审计。
3. 崩溃恢复采用**不自动重发**，不声称能自动判断 B站已经发出还是没发出。当前没有自动远端二次核验/恢复 UI，也不自动丢弃长期确认记录（可能持续占用磁盘）。运营人员不得手动删目录来强制重发。
4. Phase 6k 只具备**安全灰度前提的可见性与永久关闭**：没有启用社交 Life owner 的配置、按钮或外发路径。真正灰度需要确认专用测试对象、明确授权、单消息原子 owner 租约、异步回执核验、停止/撤回和 Windows/真实 B站测试。
