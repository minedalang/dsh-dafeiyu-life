> 更新：2026-11-14。源码基线：用户上传的 `dsh-bili-scroll-plus2.zip`（`package.json` 为 2.8.0）。本开发批次是**2.8.1 开发增量**，没有改动正式包版本号，也没有发布 npm、执行真实 B站外发。本文是项目内实施事实源，不以历史 dev.1 费用测试作为进入条件。

## 用户确认的范围

- **跳过原 dev.1**：GPT-6-Luna 识图能力已经由使用者确认；不再安排识图资格验证，也不把图片 Token/费用实测纳入开发任务，费用由使用者自行测试。
- 保留 `DSH` 现有模型识图路径；可选的本地模型候选：**MiniCPM-V 4.7 1B**、**Qwen3.5 4B**。后续要求像现有本地 Embedding 一样在管理中心提供**选择型号 → 一键下载安装 → 进度/取消/校验/状态/删除**，而非手工命令作为唯一安装方案。**这一批尚未实现安装器或本地推理路由。**

## 当前实现（dev.2a）

新增 `lib/video-evidence-bundle.mjs`，定义 `life-video-evidence/v1` 的**无原始内容、只读**证据出处与时间锚点；由 `bili_watch_video` 的实际读取回执构建，并纳入 `buildVideoExplorationEvent` 的记忆证据标志。新增 `test/v281-dev2a-video-evidence-bundle.test.mjs`。

统一支持的当前来源：

| evidence kind | 上游 | 能说明什么 | 不可声称 |
|---|---|---|---|
| `metadata` | `bili_video_info` | 读到当前 BV 的标题及元数据 | 看过视频画面 |
| `subtitle` | `bili_subtitle` | 读到字幕文本 | 听到原始声音 |
| `asr_transcript` | `bili_transcribe_safe` 已返回文本（`source:local-asr`） | 本地转写结果 | 已听过/理解音色情绪 |
| `preview_frames` | `bili_preview_vision` 的 `times` + 匹配 BV | 抽取了哪些低清预览时点 | 分析已经成功、全片观看 |
| `preview_visual_analysis` | 有效 `analyzed/cached` 与非空描述 | 模型已分析的有限预览帧 | 完整视频视听体验 |
| `public_comments`、`danmaku` | 评论与弹幕读取 | 第三方讨论及数量 | 对视频本身的直接观察 |

### 接口约束

```js
buildVideoEvidenceBundle({bvid, info, subtitle, visual, comments, danmaku, at})
// => {schema:'life-video-evidence/v1',bvid,at,sources:[{kind,origin,status,coverage,
//        timePointsMs?:number[],spans?:{startMs,endMs}[],count?:number}],
//      observedVideoPlayback:false,analyzedOriginalAudio:false,verifiedContent:boolean,limits:string[]}
```

- 只接受可信 BV 格式、成功元数据及有效标题。上游携带异 BV 时不将其提升为本次证据；失败、占位符不作为识图成功。
- 时间锚点统一毫秒：预览 `times[]` 原本按秒；字幕/ASR 只接受明确的 `startSeconds/endSeconds` 或 `start_seconds/end_seconds`，没有单位时不猜测。
- `preview_only` 可以有抽样画面时点，但绝不可因此声称模型识图成功；缓存描述若未保存时间点仅标 `timeAnchor:unavailable`。
- 结构中不携带字幕正文、评论原话、UID、图片字节、文件路径、Key 或任意 URL；记忆只使用经过核对的证据类别，保持原有衰减、遗忘与隐私约束。
- 已有 `experience.subtitle` 继续表示实际字幕；本地 ASR 独立为 `experience.asr`，记忆以“取得过本地语音转写文本”描述，不再把 ASR 写成字幕。
- 该对象只影响只读展示和记忆的证据分层，**不参与授权、额度、写入凭据或模型是否愿意行动的二次投票**；同一 BV 的视频互动仍走 2.8.0 `Life Action Protocol`。

### 接入现状与保留事项

- 已接入主 Session/社交推荐共用的 `executeWatchVideo()` 的返回值 `videoEvidence`；Life 观察记忆使用同一 Builder 派生证据标志。
- 现有视频 Agent 自己的多轮选片、搜索、评论、待办的其他读取链路尚未统一调用 Builder（下一阶段扩展）；不能声称全入口已完成。
- 当前 Python `preview_vision.py` 仍最多三张低清预览，不会自动采集高帧率完整视频；尚未引入下载视频/抽样文件的新增网络能力。

### 本地视觉模型一键安装的规格（**计划，不是 dev.2a 已实现**）

- UI：在视频感知设置提供两张可选模型卡片，**MiniCPM-V 4.7 1B（轻量）**、**Qwen3.5 4B（增强）**。保留“不安装本地模型，使用现有 DSH 模型”的默认选择。模型切换不能自动启用云端上传。
- 参照 `lib/embedding-runtime-manager.mjs` 安全下载：**固定来源和版本、固定制品 SHA-256、大小限制、断点续传、取消、独立数据目录、文件校验、端口仅本机、进程停启与删除**。先核实目标模型精确发布修订、许可证、推理 runtime 的实际多模态能力和预处理器相容性，再固化 manifest；绝不先编造哈希或文件大小。
- 显卡能力、Windows/Linux/macOS 支持各按实际 runtime 返回；模型体积与运行显存应分别显示。无法满足配置时应保留文字/字幕方案，不绕过校验或静默下载不可用构建。
- 安装和模型删除不触及原 `embedding-runtime`、人生记忆、视频经历、账号登录、平台外发授权。
- 路由优先使用明确选择和能力检测结果，不以模型名称猜视觉支持。视觉模型只输出观察，不决定 Life 的行动意愿；无插件可安全降级。第三方 DSH Skill 不得绕开独立视觉子会话的只读隔离。
