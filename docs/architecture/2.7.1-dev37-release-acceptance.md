# 2.7.1-dev.37（S0/S1 同版维护） · S0/S1 发布前修复及现场验收规程

> 当前结论：**代码故障修复已实现；真实 Windows、真实 B站、跨账号、真实 GGUF 与连续运行未在 Linux 开发环境验收。** `releaseReady:false`，不得把本规程自动测试当作正式 RC 批准。

## A. 本轮已在代码中完成

1. 管理中心「现在让鱼鱼考虑一次」不再引用另一个回调中的局部变量 `sched`。`life-agent/wake` API 不变，Life 仍可自己休息。
2. 旧社交归属的投影与真实交接账本一致：当前账号未知、渠道未接管、在途待复核都会阻止旧社交退役被误报为通过。不会修改真实发送权限。
3. Life 高级诊断新增 **「导出 S0/S1 匿名验收快照（只读）」**。只允许当前管理中心使用已有认证 GET 接口；导出只包含固定类别、数量、当前配置门禁和未知发送风险。**不保存模型内容、UID、BV、rpid、私信正文、凭据。**
4. 评论诊断区分 `model-review-not-observed`、`model-chose-not-comment`、`wanted-but-not-proposed`、`life-declined`、`platform-unverified` 等阶段。它们是取自真实记录的分类，不是强迫发表评论。

## B. S0 验收：必须在维护者 Windows / B站账号上执行

1. **安全准备**：关闭 DSH，记录当前运行版本，使用原 `tools/dev4-cold-state-backup.mjs backup --root <业务目录> --to <另一个受限目录> --stopped` 冷备份，运行 `verify --snapshot <备份目录>`；完整备份**含密钥**，不得上传到工单、聊天或公共仓库。先在隔离副本上尝试恢复，不覆盖真实数据。记录恢复前后重要对象数量、配置授权和遗忘状态（只记数量）。
2. **Windows 首次安装、升级及重启**：在测试机器上全新安装一次、使用旧用户备份副本升级一次；运行仓库 `run-tests.bat`；检查管理中心、Python/MCP、B站登录、模型/设置保存与读取；重启复测。旧设置不能意外自动授权公开评论。
3. **唤醒回归**：设置 Life 为 `active`（确认已有授权），点击「现在让鱼鱼考虑一次」并导出匿名快照。要在页面得到实际返回 `traceId` 或解释性的 `skipped`，绝不能再有 `sched is not defined`、无故异常或强制评论。切换 `shadow/off` 时分别确认不会启动非授权视频/外发。
4. **Episode 连续性**：至少观察首页与非视频首步各一轮。确认可执行的原意愿被真正加入候选、模型会自主续行或明确停下；若首步卡住，通过 `firstStepOnly/staleFirstStep/firstStepWithoutEligibleSource/eligibleToResume` 与决策 DEBUG 查是权限、缺失来源、额度、冷却还是模型决定。不能把“一步完成”天然判为故障。
5. **评论、私信与原评论回复**：使用本人明确许可的测试账号/视频和可核实评论，在真实平台上分别核对模型 `consideration → proposal → Life → transaction → readback`。评论不需每日定额；没有评论时必须准确归因。不可在未知结果后自动重发、不可跨渠道绕过原审批，也不可因为获得同意而认为平台已完成。
6. **双账号与崩溃恢复**：分别使用两个测试账号切换并触发只读、受控写入/未知结果；检查用户隔离、权限、Episode 和记忆，旧账号回执不可归给新账号。在网络超时和重启情况下，原始发送账本有未知应冻结，绝不重新发。
7. **72 小时真实运行**：连续保存分时段匿名快照和 DEBUG。重点统计可执行续行候选是否展示、模型选择、真实工具回执、空转与重试、打扰率及异常重启。任何未知发送不得自动补发；出现连续空转或账号错乱即暂停验收。

## C. S1 验收：实际成长、语义模型与新旧授权

1. **跨日因果**：找一条真实发生、当前尚未遗忘的事件及可信原平台回执，证明其进入兴趣/记忆/关系上下文；隔日新 Life 决策明确引用同一个合法来源，并实际选择或拒绝相应行动。仅有向量命中、语气改变或两个相邻事件不能证明成长。
2. **本地 GGUF**：Windows 管理中心显式同意安装或离线导入后检查运行时、真实 639 MB 级模型权重、一次语义查询的返回，关闭语义服务后词法召回仍可用；重启、删除索引、重建、模型缺失降级分别验收。不下载模型、不推理的离线测试不能标为通过。
3. **真实授权**：全新安装和旧数据升级分别核对 `autoComment`、每天上限（当前默认最高 1000）、每轮上限、社交外发、模型额度及确认提示。**快照里 currentConfig 仅代表当前有效设置，不证明用户当时已确认授权**。若默认过于激进，应在发布前由维护者明确调整或修改上架文案。
4. **发布门禁**：在管理中心导出 S0/S1 匿名验收快照。每项 S0/S1 仍标为 `requires-real-acceptance`；使用可保护隐私的人工验收记录附真实环境、时间、版本、运行结果、原平台已核实状态。只有维护者验收完毕才可以考虑 RC，不能更改源码 `releaseReady` 绕过验收。
