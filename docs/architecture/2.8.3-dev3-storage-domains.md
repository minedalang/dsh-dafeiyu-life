# 2.8.3-dev.3｜自由存储、安全迁移与 Life 数据边界

> **状态：源码开发候选；Linux/Node 定向测试完成，Windows 真实磁盘、DSH、ASR 和 Ollama 尚待实机验收。** `dev.4` 负责视频补看与深浅记忆生产闭环，`dev.5` 负责联合收口。

## dev.3 最终收口：历史 Life 外置目录只允许显式清理

从 Life 外置分区回迁默认目录时，助手以**外置当前生效文件**为来源，复制、复核 SHA-256，并在路径指针发布之前留下该旧外置目录的文件数、字节数及全树 SHA-256 快照。离线助手另留独立的回迁凭据 `.dafeiyu-life-return-evidence-v1.json`，避免后续模型／Python 迁移覆盖共享任务记录后丢失旧 D 盘的清理依据。回迁后的旧 D 盘仍然保留，默认 C 盘的旧文件隔离为 `.dafeiyu-return-old-*`。二者均**不是**自动可删除的临时文件。

若用户随后希望再迁至同一 D 盘路径，所有非空目标仍必须拒绝，不得因为目标有同实例分区标记，就隐式覆盖、移动或复用其中的文件。管理中心提供分开的「检查旧 D 盘 Life 分区能否安全删除」和「预约停机删除旧 D 盘 Life 分区」操作：前者只读检查当前 C 盘 Life、默认目录归属、原回迁记录、旧分区身份、全树 SHA-256；后者还需要主人独立确认，并由脱离 DSH 的助手在完全停机后复查文件数、指纹、相关进程，**只有全部满足才允许清理旧 D 盘**。成功后旧 D 盘目录不存在/为空，下一次迁移仍走普通空目录预检。

当原回迁任务已有快照指纹时，D 盘出现新增、修改、未知顶级文件、符号链接或被更换的标记都必须拒绝清理。对**旧版本没有记录快照指纹**的回迁记录，降级为严格的逐文件规则：旧 D 盘每个文件都必须在当前默认 Life 位置找到相同大小、相同 SHA-256 的文件；不满足就拒绝。此降级证明不能识别某个与 C 盘完全一致的文件是否是后来加入 D 盘，所以仍必须由使用者单独审查和确认；不可称为具备完整历史变更检测。删除过程不使用针对用户文件的递归删除：先将已确认的旧分区同盘隔离，再验证指纹、逐项校验已知文件并移除；出现并发变化、异常文件或重新启动的进程就停机失败，未删文件保留，绝不自动重试。隔离阶段异常可能需要维护者人工恢复，不能宣称具备断电后的自动恢复。

模型验证与历史模型旧副本清理**解耦**：只要当前 Whisper、Embedding 与媒体分区身份有效，管理页便可重新进行实际模型运行测试；删除旧 C 盘模型文件另需严格旧副本一致性条件。管理页只读盘点 `.dafeiyu-return-old-*` 和可识别的历史目录，并显示其非生效状态和大致空间；这些未建立足够清理证据的档案不开放一键删除。当前仍不支持分盘后的完整冷备份，Windows/macOS/Linux 的真实 DSH 运行与全量测试仍为发布门槛。

## dev.3 正式回迁默认目录（增量收口）

原有 `--rollback` 是短时撤销，只允许原/新两份逐文件相同；迁移后数据更新、旧副本清理或 Life 遗忘时绝不能用它来回归 C 盘。新增 `--return-home` 则是向前复制**当前生效数据**，不读 C 盘历史副本作为事实来源。`model`（Whisper、Embedding、影音缓存）整组回迁；`python` 只含 uv/pip 缓存，现役 `.venv`/uv-python 不动；`memory` 包括 Life 记忆、深层详情、遗忘保护和向量索引，仍严格要求完全停机，但可通过管理页预约后由独立助手执行，不再要求普通用户复制命令。

回迁首先复制到默认根内同磁盘暂存区，SHA-256 对比当前源；已有同名旧目录会先移动到业务根**同级**的 `.dafeiyu-return-old-<随机值>`，随后发布新目录，最后原子撤销相应分区指针。外置现役副本一律保留，旧目录隔离归档也不自动清理；失败时指针仍留在原生效数据域，反向尝试恢复目录。若被系统强制断电中止，可能留下待人工核查的暂存/归档目录，但不会自动改用失效的旧记忆。回迁需要原盘足够空间、DSH 全退出，并由 Windows/macOS/Linux 实机分别验收。

管理中心按域提供「迁回默认目录 · 安全预检」。模型与 Python 缓存可一键预约停机助手；Life 记忆也通过管理页一键预约、完全退出 DSH 后自动回迁；CLI 仅作为排障兜底。既有 `--rollback` 保留用于 byte-identical 的安全撤销，不作为长期回迁入口。

分盘后的便携业务导出及 Life 记忆专项导出/恢复通过 `storageDataPath()` 读取当前生效目录，保留撤销记录合并和衰减保护。**完整冷备份 `createColdSnapshot` 目前仍拒绝分盘**（原工具仅支持单根）；业务 JSON 备份排除凭据、部分私密账本、向量索引、模型和缓存。跨分区完整离线快照及恢复是 dev.5 阻断项，不能提前宣称完成。

## dev.3 一键预约停机迁移（本次增量）

管理中心「数据备份 → 存储位置」为 `model`（Whisper + Embedding + 影音/视觉缓存）、`python`（**仅 uv/pip 包下载缓存**）与 `memory`（Life 记忆及遗忘保护）提供「一键预约安全迁移」按钮。点击前须先做只读预检，预约操作只写本地一次性任务，不在 HTTP/DSH 在线进程复制任何文件，也不发送 B站请求。

用户**正常完全退出** DSH Desktop、Headless、Python 与模型相关进程后，独立 Node 助手才会复查父进程是否结束、进程清单能否安全确认、源文件数与字节数有无变化、目标目录是否仍为空。通过后复用原有 `migrateDomainOffline` 的内容复制、SHA-256 与原子路径发布；原始数据始终保留，失败不自动重试。任务状态位于核心业务根的 `.dafeiyu-domain-migration-job-v1.json`，重启后的管理页可看见等待 / 完成 / 失败及说明。启动时检测到任务仍处于 `waiting` 或 `running` 会**安全拒绝插件启动**，避免意外提前重启造成并发写入。若助手异常退出导致 `running` 遗留，必须人工复核后处理，绝不能以超时为理由自动解除保护。已有待执行旧副本清理时拒绝再预约迁移，反之亦然。

**没有在线热迁移：** 插件仍需实际停机，助手不强杀任何系统进程；独立 Node/Python 进程保守扫描可能被无关进程阻断。无法安全确认就拒绝迁移（包括无法列举进程）。用户不再需要复制命令，但 macOS、Linux、Windows 上实际宿主进程名、Electron Node 模式、路径与权限仍须现场验证。

`memory`（Life 经历、深层详情、遗忘保护与索引）复用同一停机预约队列：管理页只创建任务，必须退出 DSH 与相关进程后才由独立助手复制、逐文件校验并切换。回迁时从当前生效数据复制，绝不使用原根目录的过期记忆恢复；原始数据保留、不自动清理。整体业务根仍由维护者使用停机 CLI。本次没有修改 Life 自主行为、视频补看或深浅记忆生产逻辑。

## Python uv/pip 缓存验证与状态口径

`python` 用户迁移组仅包含 `uv-cache/` 与 `pip-cache/`。管理页独立分盘状态只计算这两项，不将保留在旧业务根的 Python 解释器、`.venv`、`.venv-asr`、视觉虚拟环境、`uv-python`、`uv-tools` 算作迁移未完成。Python 分组的占用仅统计当前生效包下载缓存；运行环境的旧目录占用仍由原业务根目录单独统计。

迁移结束后提供「一键验证包管理缓存」，验证当前分区身份、uv/pip 路径解析指向、目标目录可写性，并确认运行环境路径没有被分区切换。写入测试使用 `wx` 创建独立随机探针文件，执行后删除，不下载软件、不安装包、不调整 Python 版本或清理旧副本。缓存为空时可检查已验证分区根目录可写，但明确显示缓存文件尚未生成。此检查验证的是**缓存路径配置与读写能力**，不是从 uv/pip 下载、安装依赖或执行模型推理。

## 迁移后验证与清理闭环（当前 dev.3 补丁）

管理中心「数据备份 → 存储位置 → 迁移后保留的旧模型副本」提供**一键实测迁移结果**。验证动作先逐文件 SHA-256 检查原/新数据匹配，再对当前迁移后的 Whisper 模型执行离线模型加载和静音短音频推理，对 Embedding 执行真实 1024 维向量查询。若视觉已启用，调用现有 DSH Headless 或 Ollama 固定图片验收；识别答案由主人明确认可或否决，不能自动批准。视觉未启用时显示“不适用”，不宣称完成识图测试。缺少依赖、模型、权限、真实推理错误均阻断旧副本清理。

全部通过才出现**清理旧副本（退出后自动执行）**。用户再次确认后管理 HTTP 只写入一次性任务并启动脱离 UI 的本机 Node 清理助手，**运行中的 DSH 进程绝不会执行删除**。助手等待 DSH 父进程结束，保守扫描 Windows/macOS/Linux 的 DSH、Node、Python 与模型相关进程；无法确认全停或超时就留下旧数据，并记录拒绝理由。停机后还要重新校验身份标记、原件与当前生效目标内容、文件数及大小，复用原有 `cleanupRetainedModelCopies()` 临时隔离、审计与故障恢复逻辑。任务结果下次启动后显示；失败不自动重试。Python 环境、Life 记忆、Ollama 外部模型一律不清理。

进程扫描采用保守策略：**其他不相关的 Node/Python 程序也可能阻断自动清理**，宁愿不释放空间也不能冒险边运行边删除。Electron 嵌入 Node 模式以及三平台的实际关闭/辅助进程退出须 Windows/macOS/Linux DSH 实机验收。旧离线 CLI 留作维护者的应急入口，普通用户不再需要复制删除命令。模型、Python 包缓存与 Life 记忆现均可由管理页预约**退出后离线迁移**；整体业务根目录仍需停机 CLI。在线 HTTP 本身从不执行实际搬迁。

## 生效位置与故障保护

`lib/storage-layout.mjs` 的 `storageDataPath()` 根据 `storage-layout-v1.json` 确认当前归属；每个外置目录由 `.dafeiyu-storage-domain-v1.json` 校验原始根、域、目的路径和随机身份 nonce。缺盘、损坏、未知域、嵌套、非法链接均**拒绝回落到默认路径创建空白记忆**。原 Life 账号、遗忘、授权和证据门禁始终有效。

Whisper 的下载/安装列表/删除与健康检查、Embedding 模型路径、Python/uv 启动环境、uv/pip 下载缓存、ASR/视觉缓存、Life 情节/深层附件/长期记忆/遗忘撤销/向量索引，以及便携记忆备份/恢复，都通过相同的分区路径解析。新 Python 缓存迁移只改 `UV_CACHE_DIR` 与 `PIP_CACHE_DIR`；`UV_TOOL_DIR`、`UV_PYTHON_INSTALL_DIR` 及各虚拟环境路径不被新迁移操作修改；历史有效 rebuild 指针仍按原身份兼容读取，避免升级破坏已安装环境。

## 实际停机迁移流程

1. 在 DSH 正常运行时仅查看路径及大小，选择 `domain` 和新的**空本机目录**，执行管理页只读预检。检查磁盘剩余空间、NTFS 访问权限和备份。不要使用网络盘、磁盘根目录或另一个已配置域的内部目录。
2. 完全退出 DSH、Headless、ASR/Python 和写入相关模型与缓存的进程。离线 CLI `--confirm-stopped` 是人工确认，不会替你关闭进程。
3. 逐文件复制到目标盘的临时目录，SHA-256 校验每个文件，复制后进行第二次源对照，完整校验才原子发布新目录及配置。**旧目录始终保留**；中途失败时保留原生效位置。
4. 重新启动并测试模型安装/读取、ASR、语义检索、Life 记忆、账户隔离和遗忘保护。Python 缓存迁移不改变正在使用的环境，也不触发依赖重装。
5. 可再次迁往新的空目录。只有原默认目录与当前有效目录内容完全相同且未发生任何新增写入时，才允许离线 `--rollback`；若记忆发生变化就拒绝自动回滚。

PowerShell 示例（用自己的实际根目录和空目的路径替换；页面可为三组生成命令）：

```powershell
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain model --to "D:\DSHData\bili-duty\modelData"
# 以上仅检查。只有完全关闭 DSH 后，才运行下面命令：
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain model --to "D:\DSHData\bili-duty\modelData" --confirm-stopped
# 保证迁后数据从未变化时才可按需回滚：
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain model --rollback --confirm-stopped
# Python 默认只迁移可再下载缓存：预检
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain python --mode cache --to "D:\DSHData\bili-duty\pythonData"
# 完全退出 DSH 后执行；旧 Python 环境不动
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain python --mode cache --to "D:\DSHData\bili-duty\pythonData" --confirm-stopped
# 已移除高级重建；任何 --mode rebuild 请求都会在预检阶段拒绝，不写磁盘
# Python 回退：原环境从未被移动或删除
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain python --rollback --confirm-stopped
```

## 真实限制与 dev.5 门禁

- 旧 `lib/cold-state-snapshot.mjs` 只支持**未分盘**的业务根；分盘后会明确拒绝制作或恢复该旧式冷备份，避免谎称已备份外置 Life 数据。便携 Life 记忆备份已能随活动 `memory` 分区读取与恢复。跨域**完整**冷备份／恢复仍须 dev.5 提供。因此迁移前先分别离线备份核心根和所有外置目录及其身份标记，验证后保留原件。
- 大小统计是活跃路径的普通文件物理字节数；不等于 C 盘总回收空间，不会统计旧源副本和独立 Ollama 缓存。Windows 重解析点、系统保留空间与磁盘容量须现场核对。
- 必须在**普通和管理员 PowerShell** 分别验证有空格/中文目录、C→D/E 迁移、重启、原路径缺失或目标盘断开、模型安装/删除、Whisper/ASR、Embedding/uv、Life 深层详情与遗忘、账号隔离、迁后写入禁止回滚、Python 重新安装及 Windows full。任何红灯都阻断正式版。
- 存储改变不授予 B站读写权限，不改变 Life 自主选择。`dev.4` 再实现证据不足时有理由的有界补看、可信视频浅层摘要和深层按需记忆；`dev.5` 统一联测与发布。

### dev.3 历史设计记录（已被当前 cache-only 设计取代）

- 早期 dev.3 曾将 Python 迁移分为缓存模式与高级重建，现已取消新建高级重建，**当前仅迁移** `uv-cache` / `pip-cache`，不触碰 `.venv`、`.venv-asr`、`uv-python`、`uv-tools` 等现役环境，因此 Windows `uv-python` 目录联接不会再导致预检失败，也不会影响插件当前 Python 功能。早期高级模式为历史兼容，不再开放新申请；现役运行环境始终保留原位。对 `model` 和 `memory` 的非法链接检查不放宽。
- `model` 三部分在 **同一个迁移事务** 复制到 `modelData` 下仍保留既有相对子路径，完成所有校验之后一次性写入三条兼容的路径指针；其中任何源数据变化、身份不符、目标非空或目标盘消失都拒绝发布。Python 页面只提供缓存迁移，使用 `pythonData` 建议目录；仍独立展示缓存及运行环境的实际位置。
- 合并后单独再迁 `whisper`、`embedding`、`media` 将拒绝，防止拆散同组共享身份。分组回退仅在旧来源与新目标逐文件一致时允许，任何更新都会阻止用旧缓存覆盖现有数据。
- 未在实际 Windows 上验证目录联接、PowerShell 迁移、ASR/Embedding 启动、备份或 DSH 重启；这些仍是开发候选的实机门禁。


## dev.3 迁移后旧副本检查、平台差异（本批新增）

管理页将**原业务根目录物理占用**与**各当前生效分区**分开显示，解释为何模型数据已在新盘生效但原目录的“AI 运行环境”大小尚未下降。新增的旧模型副本卡片只统计最初 `model` 整组迁移留下的默认目录旧副本；页面只读，未经逐文件校验的大小不是“可以删除”的承诺。

验证与清理严格分开：用户可以在管理页对旧模型副本进行只读 SHA-256 比对；实际清理只允许在全部 DSH、Headless、相关 Python/模型进程退出后执行离线 Node CLI。离线清理前必须通过三道**操作员明确确认**：已停机、已实机测试新目录的 Whisper/Embedding/视觉功能、同意永久删除匹配的旧模型副本。CLI 每次重新计算哈希和校验可信目标身份；仅首次整组迁移且三个旧指针皆不存在时开放。二次迁移、旧独立分区、任何源数据变化、危险链接、目标标记异常、重复清理记录均拒绝。清理操作会在原根留下审核记录，不影响分区指针，且**旧模型回滚不再可用**；操作前须另有可信的离线备份。

实际删除只命中原根里的 `.hf-cache/`、`embedding-runtime/`、`tmp/asr/`、`asr-transcript-cache/` 和 `vision-cache/` 五条白名单路径（仅存在的目录），绝不删除 `.venv*`、`uv-*`、`pip-cache`、`life-memory`、`long-term-memory`、`detail-protection`、`embedding-memory-index`、Ollama 外部模型或其他文件。先在原卷暂存白名单目录，暂存失败尝试恢复；进入删除阶段后若因文件锁等原因失败会保留一次性审计记录并拒绝自动重试，要求维护者人工复核。

### 平台矩阵与验收界限

| 平台 | 路径/终端 | 可以使用的模式 | 仍需实机确认 |
|---|---|---|---|
| Windows 10/11 | `C:\...`、`D:\...`；PowerShell；拒绝 UNC、可疑 junction | 模型、Python 缓存、Life；高级 Python 重建依赖既有 Windows 修复入口 | NTFS 重解析点、锁文件、目标盘断开、普通/管理员权限、ASR/视觉/Embedding 真调用 |
| macOS | `/Users/...`、`/Volumes/<实际本地磁盘>/...`；Terminal 的 zsh/sh | 模型、Python **缓存**、Life；高级 Python 重建暂禁 | APFS 大小写差异、外置盘挂载、用户目录隐私权限、实际模型加载和 Life 回忆 |
| Linux | `/home/...`、`/mnt/...`；bash/sh | 模型、Python **缓存**、Life；高级 Python 重建暂禁 | ext4/btrfs 权限、挂载点、symlink、实际模型加载和 Life 回忆 |

macOS/Linux 的目录建议是 `~/DSHData/bili-duty/<分组>` 的**完整绝对路径示例**；它通常位于同一个物理磁盘，**不能被理解为必然释放系统盘空间**。需要分盘时应选择用户实际本地挂载的另一块磁盘。不能可靠地仅凭路径文字区分所有网络/同步盘，因此迁移前需人工确认是受支持的本地文件系统；网络共享与可中断云同步存储不作为推荐目标。Windows/Linux 当前定向自动测试、macOS 的路径/命令生成模拟测试**不能代替真实 macOS/Windows DSH 验收**。

**macOS/Linux 手动只读校验示例**（调整成真实 DSH 根目录；这只检查，不会删除）：

```sh
node '/path/to/dsh-dafeiyu-life/scripts/migrate-bili-duty-domain.mjs' --root "$HOME/.dsh/bili-duty" --inspect-retained-model
```

对应永久清理命令**不能**在未验收模型、未停机时运行；清理只经管理中心产生的带三重确认的离线命令进行。跨平台完整快照仍属于 dev.5 门禁。

## Python 缓存模式（dev.3 后续收口）

管理页将第 2 组命名为「Python 包管理缓存（uv / pip）」，仅有一项迁移操作；`.venv`、`.venv-asr`、视觉环境、uv 管理的 Python/工具仍显示**当前实际位置**，但不作为该组迁移目标。不能把原运行环境占用算作“可清理的包管理缓存”。

API / CLI 均拒绝新增重建；但对以前已发布并验证的 `safe-group-v2` rebuild 指针采取**只读兼容**，不强行改指针（强行改指针可能让已重建用户断开 Python）。早期没有 safe-group-v2 的旧版悬挂 rebuild 标记继续按原机制保护。若用户曾选过高级重建，升级前后须单独核对当前实际运行环境，必要时停机回退；不得盲目删除目标目录。

不同平台的模型、安装和依赖的功能边界见 `docs/architecture/2.8.3-dev3-cross-platform-installer-audit.md`。官方上游支持 != DSH 完成实机验证。
