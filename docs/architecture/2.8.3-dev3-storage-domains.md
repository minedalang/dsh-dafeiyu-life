# 2.8.3-dev.3｜自由存储、安全迁移与 Life 数据边界

> **状态：源码开发候选；Linux/Node 定向测试完成，Windows 真实磁盘、DSH、ASR 和 Ollama 尚待实机验收。** `dev.4` 负责视频补看与深浅记忆生产闭环，`dev.5` 负责联合收口。

## 五个独立数据域

默认路径保持旧版 `bili-duty` 不变；用户明确配置后才启用外置域。管理中心「数据备份」展示当前有效位置、物理占用、只读预检和待执行的离线命令。**运行中的管理页不执行真实迁移。**

| `--domain` | 目录 | 策略 |
|---|---|---|
| `whisper` | `.hf-cache/` | 离线复制、SHA-256 校验；Hugging Face 仓库内可信 blob 链接复制为普通文件 |
| `embedding` | `embedding-runtime/` | 离线复制运行时及本地语义模型，语义索引单独归入记忆域 |
| `python` | `.venv/`, `.venv-asr/`, `.vision-venv/`, `uv-cache/`, `uv-tools/`, `uv-python/` | **只切换目标、重新安装**；旧环境带绝对路径不能安全直接搬运 |
| `media` | `tmp/asr/`, `asr-transcript-cache/`, `vision-cache/` | 影音与视觉可再生缓存离线复制，不能当 Life 记忆自动删除 |
| `memory` | `life-memory/`, `long-term-memory/`, `detail-protection/`, `embedding-memory-index/` | 受控情节、深层详情、撤销标记和向量索引作为一个不可拆的迁移域 |

核心根依然持有身份、权限、业务配置、引导指针、未明确分类的数据库和其他文件。**Ollama 模型、DSH 宿主缓存**由外部软件管理，本插件不会宣称能替它们迁移。未启用分区时，dev.2 的整根停机搬迁仍可用；已分盘后，为免指针与目标身份失配，暂拒绝再次整根搬迁。

## 生效位置与故障保护

`lib/storage-layout.mjs` 的 `storageDataPath()` 根据 `storage-layout-v1.json` 确认当前归属；每个外置目录由 `.dafeiyu-storage-domain-v1.json` 校验原始根、域、目的路径和随机身份 nonce。缺盘、损坏、未知域、嵌套、非法链接均**拒绝回落到默认路径创建空白记忆**。原 Life 账号、遗忘、授权和证据门禁始终有效。

Whisper 的下载/安装列表/删除与健康检查、Embedding 模型路径、Python 和 uv 启动环境、ASR/视觉缓存、Life 情节/深层附件/长期记忆/遗忘撤销/向量索引，以及便携记忆备份/恢复，都通过相同的分区路径解析。

## 实际停机迁移流程

1. 在 DSH 正常运行时仅查看路径及大小，选择 `domain` 和新的**空本机目录**，执行管理页只读预检。检查磁盘剩余空间、NTFS 访问权限和备份。不要使用网络盘、磁盘根目录或另一个已配置域的内部目录。
2. 完全退出 DSH、Headless、ASR/Python 和写入相关模型与缓存的进程。离线 CLI `--confirm-stopped` 是人工确认，不会替你关闭进程。
3. 逐文件复制到目标盘的临时目录，SHA-256 校验每个文件，复制后进行第二次源对照，完整校验才原子发布新目录及配置。**旧目录始终保留**；中途失败时保留原生效位置。
4. 重新启动并测试模型安装/读取、ASR、语义检索、Life 记忆、账户隔离和遗忘保护。需要 Python 时必须在新的目录重建 `.venv` 和 `.venv-asr`。
5. 可再次迁往新的空目录。只有原默认目录与当前有效目录内容完全相同且未发生任何新增写入时，才允许离线 `--rollback`；若记忆发生变化就拒绝自动回滚。

PowerShell 示例（用自己的实际根目录和空目的路径替换）：

```powershell
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain whisper --to "D:\DSH-Data\whisper"
# 以上仅检查。只有完全关闭 DSH 后，才运行下面命令：
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain whisper --to "D:\DSH-Data\whisper" --confirm-stopped
# 保证迁后数据从未变化时才可按需回滚：
node scripts/migrate-bili-duty-domain.mjs --root "$env:USERPROFILE\.dsh\bili-duty" --domain whisper --rollback --confirm-stopped
```

## 真实限制与 dev.5 门禁

- 旧 `lib/cold-state-snapshot.mjs` 只支持**未分盘**的业务根；分盘后会明确拒绝制作或恢复该旧式冷备份，避免谎称已备份外置 Life 数据。便携 Life 记忆备份已能随活动 `memory` 分区读取与恢复。跨域**完整**冷备份／恢复仍须 dev.5 提供。因此迁移前先分别离线备份核心根和所有外置目录及其身份标记，验证后保留原件。
- 大小统计是活跃路径的普通文件物理字节数；不等于 C 盘总回收空间，不会统计旧源副本和独立 Ollama 缓存。Windows 重解析点、系统保留空间与磁盘容量须现场核对。
- 必须在**普通和管理员 PowerShell** 分别验证有空格/中文目录、C→D/E 迁移、重启、原路径缺失或目标盘断开、模型安装/删除、Whisper/ASR、Embedding/uv、Life 深层详情与遗忘、账号隔离、迁后写入禁止回滚、Python 重新安装及 Windows full。任何红灯都阻断正式版。
- 存储改变不授予 B站读写权限，不改变 Life 自主选择。`dev.4` 再实现证据不足时有理由的有界补看、可信视频浅层摘要和深层按需记忆；`dev.5` 统一联测与发布。
