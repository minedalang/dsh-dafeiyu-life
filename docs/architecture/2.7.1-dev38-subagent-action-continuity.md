# 2.7.1-dev.38 · 专业 Agent 动作持续性（第一阶段；未发布）

> 目标：Life 不只选择要运行哪个子 Agent；专业 Agent 也可以在其本来职责内读取安全的近期行动上下文、独立选择后续行动，并在执行前重新获得 Life 意愿、权限与平台核验。**本阶段并未实现全部专业 Agent 的通用开放式工具循环**，不可当作完成实机验收。

## 统一层职责与生产入口

| 入口 / 方向 | 复用的权威信息源 | 新的场景能力 | 当前生产接线 |
| --- | --- | --- | --- |
| 视频 Agent | `UniversalLifeEpisodes`、原视频意愿账本、视频 MCP | 匿名近期视频片段注入 `promptFor()`，保留原工具自主选择；不读取私信 Episode | 已接入；**没有**任意评论者 UID 工具和跨轮完整原目标恢复 |
| 私信 Agent | 原 `dm-autoreply-state.json` 同 UID、`SocialPolicyGate`、`LifeWillingness`、`UniversalLifeEpisodes` | 模型在自然回复的同一决策中，可提出 `follow_dm_contact` 候选 | 只对双方实际多轮交流、可信好友、独立开启自主关注的当前发件人提供；当前回复有真实回执后延时到下次 poll 重新审批；跨轮续行可用 |

## 私信自然关注：真实动作流程

1. `createDmAutoReply` 从经身份校验的单 UID 私信会话读取其原本最近对话（不是对方声称的 UID）。候选源不新建额外联系人数据库。
2. `dmContactFollowCandidates` 只在独立 `dmFollowAutonomyEnabled` 和原 `agentFollowEnabled` 同时开启、关系经现有策略核验为可信好友、真实双向多轮往来且持续至少 24 小时的前提下产生只读候选。
3. `interaction-batch` 依当前 Persona 让**私信 Agent 自己决定** `reply / skip / defer / close`，并可选 `nextAction: follow_dm_contact`。聊天内容本身不授予关注权限，也不得声称已关注。
4. 模型只可提议本轮菜单实际提供的动作；候选由执行器持久化在既有私信状态 `pendingLifeAction`，前提是原 DM 真正发送成功。默认 75 秒后复查，过期后丢弃。
5. 下一次 poll 重新核验同 UID 未退订、好友白名单和账号有效性；先将 pending 置为 `reserved` 防崩溃双发，再由原 `LifeWillingness` **再次自主决定**愿不愿意关注。冷却拒绝可有限延时；主动跳过终止。
6. 获得独立 `dm_follow` proof 且 `SocialPolicyGate` 当前仍为 `friend` 后，host 把**自己核实的 UID**交给独立 MCP `bili_follow_dm_contact`。Python 再验证当前登录账号、平台关注现态、已有关注账本额度、外发预留，并在写入后读取 B站关系状态；不确定时冻结、不自动重发。
7. 只有真正核实关注状态后才写入 Life Episode 和原可衰减行动记忆回执。Episode 只作事实摘要，不能替代权限或反推出对方 UID。

**设置**：管理页「长期私信联系人自主关注」默认关闭，独立于视频作者关注；开启必须有明确确认。MCP 子进程配置指纹包括这个开关，变更后重新建立运行时，以保证新授权实际生效或撤销。

## 现有层与新增层的职责

- `lib/life-subagent-continuity.mjs` 是**只读衔接与候选筛选**，无账户、回忆、权限、平台发送或永久状态写入权。视频、私信、评论共享一套安全投影，独立保留原 Person、Life Voice、Recall 和真实回执所有权。
- 私信 pending 存在原 `dm-autoreply-state.json` 的同 UID 记录内；新增字段可被旧版本安全忽略，关闭自主关注不会影响既有 DM 回复。退出或重启后保留未来意愿，但正在执行的 `reserved` 一律不自动重试，须人工核验平台状态。
- 生命周期：匿名 Episode 原 7 天窗及最多五步分段仍在；pending 最长 24 小时；私信原对话按既有衰减删除；不让新字段保存原文。选择和审批不自动造成功 Episode。
- 当前授权仍需原总开关、账号、DM 白名单与关系策略、`agentFollowEnabled`、独立开关、Life 再决定、Python 每日次数限制及平台读回；本人/陌生人/已退订用户不可因历史聊天自动获得关注候选。

## 仍未覆盖 / 验收风险

1. **尚未完成所有 Agent 的充分动态行为菜单**：评论者主页、跨评论串自发回应、任意评论 UID 关注、主动陌生私信、新待办工具、反思模型续行都还没有形成安全生产闭环。不能宣称肥鱼已具备通用自由社交。
2. 完整 Episode **意愿**（为何开始、未完成目标）尚未统一复原给所有专业 Agent；当前 Handoff 传的是脱敏动作摘要。主 Life 对其他 Agent 仍有部分单步调度限制。
3. 人工/社交角色配置不同于 B站已关注状态：候选仅限本机已经信任且有双向历史的联系人。已有关注／关系不明确时原 MCP 返回不执行。
4. Windows Desktop、真实 B站账号、真实 SDK 关系读回、72 小时跨日运行尚未验证；所有自动测试为源码及隔离模拟，不能代表平台实机成功。
5. **不改变主评论分工**：视频 Agent 负责自主原创顶层评论；评论互动 Agent 负责收到别人的回复与 @，二者的成功回执共享同一 Life 因果层，但并不互相获得外发授权。
