# dev.31 · Life 反思空转、模型失败退避与自主首页闲逛

当前开发源码说明；不是 Windows、模型提供商或真实 B站实机验收结果。依据用户上传的账号脱敏 33 轮决策轨迹，反思连续跳过、主模型连错，以及单次视频写入 `life-context-unavailable` 是三种**不同**现象，不能一概当作鱼鱼主动休息。

## 统一层归属与事实源

| 入口 | 原统一层 | 唯一状态/执行源 | 本轮新增内容 | 边界 |
|---|---|---|---|---|
| 自动/手动 Life | `AutonomousPlanner` | `autonomous-planner.json` 决策预算 | 主模型失败 5/15/30/60 分钟退避，恢复后清零 | 不退模型扣额；自动退避只阻主 Life 轮，社交快速路照原权限；手动可检查但不新增权限 |
| Life 反思 | `LifeReflection` | `life-memory/candidates.json` 与执行服务 | `status().canAutoReflect` / `autoReflectBlockedReason` / `nextAutoReflectAt` 共用候选分组、冷却、配额和重试门禁 | 隐私分域、遗忘、模型调用门槛原样保持；执行时二次检查 |
| 无主题自主闲逛 | `LifeCapabilities` + `AutonomousPlanner` | 原 `runDuty()` 与 B站 `bili_home_recommendations` | `browse_home` 新菜单选项 + video Agent 首页优先语境 | 只复用已授权视频能力；`homeRecommendationsEnabled` 关闭即不可选；首页候选不是观看或评论证据 |
| 视频/私信写入 | `LifeWillingness` + `LifeVideoActionBridge` | 原 Life 意愿 + 平台回执 | 可选公开语境读取失败降级；脱敏标明基础身份失效层 | 基础身份失效或权限不充分仍拒写，结果未知仍冻结；不增加外发权限 |

## 自动生活新版动作

1. 只有通过账号、额度、原始视频能力门禁，才生成静默生活/首页闲逛候选；原自主定时器不变。
2. Life 本次模型调用可选择 `browse_home`、现有 `use_capability`、当前确实可执行的反思、可信兴趣/人物探索或 `skip`。
3. `browse_home` 不新建进程：原视频 Agent 以首页优先语境启动，最多一次 `bili_home_recommendations`；工具仍仅为当前账号的 12 条普通公开视频初筛，不等于挑中、看完或有内容足以发评论。
4. 后续核实内容、评论、点赞、收藏、关注、分享继续使用 dev.27–30 现有执行桥、平台核验及可衰减 Life Memory。
5. 如果模型调用出错，当前轮不当作自主沉默；同一 Life 预算账本保存不包含敏感文本的失败类别、连续次数和下次允许重试时间。`force` 手动测试不隐式授予平台操作权限。

## 诊断与验收

- 自动 Life 轮中 `reflection=0` 是暂不可执行，不意味着永久不能反思；在管理中心「人生记忆 → 鱼鱼怎样整理经历」查看就绪原因（`interval` / `daily-limit` / `not-enough-or-backoff` / `manual`）。
- 模型失败后未到退避时间：应出现 `model-backoff` 跳过且**没有模型额度预约**。下次到期正常考虑动作，模型成功则复位。若 provider 一直不可用，退避不能修好 provider 本身，应排查私有运行日志，不上传秘钥。
- `browse_home` 是模型可选动作，不是每 10 分钟必刷一次。执行结果 `capability-launched` 只证明视频 Agent 成功启动，必须在视频轮次回执、真实选片及主评论诊断里核实后续。
- 单次 `life-context-unavailable` 根因无法仅靠脱敏决策日志判定；dev.31 新增阶段级分类，仍需真实 host 错误记录和部署验证。
- 离线单测不能证明已在用户 Windows Desktop、B站真实推荐接口及真实模型 API 调通；不得据此更新 `releaseReady`。
