# 2.7.1-dev.2 补充 · 好友兴趣自述的时序纠错

> 已实现的**窄范围**纠错；不等于完整的主 Session／Life Memory／多渠道长期人物语义统一重构。

## 归属与生产数据流

`后台普通私信 / 已验证的公开评论` → 现有的 `prepareFriendInterestObservation` → 原有的 `recordPreparedFriendInterest` → 每账号 `friend-interest-observations.json` → `friendInterestSummary`、`learnedFriendContext`、`friendRecommendationGuard` → **原来的**模型上下文和真实发送门禁。

唯一持久化源仍是 `lib/friend-learning.mjs` 的旧版证据账本；没有新数据库、后台 AI 分类器、AI 续推或第二套画像。现有 `SocialPortraitGateway` 仍只保留可撤销的**交流方式/明确边界**，本轮未将兴趣写到该画像里；`Life Voice` 与人生记忆不因偏好纠错发生变化。

## 已修复的问题

- 以前“我以前喜欢古典音乐，但现在不喜欢了”会把**历史**的喜欢误当成**现在**的喜欢；现在只记录同消息中最新的、明确的当前自述。
- “我现在没那么喜欢电子音乐了／不太喜欢”记录为 `uncertain`（兴趣减弱或尚未明确），不偷换为“讨厌”；旧 `like/dislike` 记录保留用于去重与审计，但只投影最新状态。
- 对同一个主题，后续来自同一 UID 的明确自述可以将 `like → dislike → like` 或 `like → uncertain` 修订；同毫秒的真实入账先后也按顺序处理。
- 对主动推荐的保护：明确 `dislike` 时按原规则阻止相同主题；`uncertain` 时谨慎跳过该主题的主动推荐，返回 `friend-interest-needs-reconfirmation`。**不是**关闭普通聊天或代替联系人授权；再次明确表达喜欢后可恢复此主题推荐，但独立的全局退订、拒联与发送授权不会随之恢复。
- 未明确第一人称当前自述、仅提及“过去喜欢”、主题缺失、陌生 UID、被删除白名单成员，不写入当前兴趣；不保存私信正文；事件键沿用原实现，不在此轮改变其存储生命周期。不通过第三方评论、标题或外部资料猜测一个人的喜好。

## 可观察的实际结果

管理中心 → **社交互动 → 好友兴趣变化**（原已有的折叠区块）→ `刷新兴趣观察`：会显示当前每位白名单好友每个主题的最新 `喜欢／不喜欢／兴趣减弱／待确认`、`近期表达有变化` 与证据次数。

例如用测试好友按时间依次发送“我喜欢电子音乐”“我现在没那么喜欢电子音乐了”：刷新后应显示 `兴趣减弱／待确认「电子音乐」`；不应同时出现另一条“喜欢电子音乐”作为当前结论。清除好友兴趣观察仍用原功能；不会对 B站发私信或评论。

**验收边界**：UI 呈现是后台证据投影，不证明模型已经完全理解所有自然语言。该解析器依然是保守的有限表达识别，复杂反讽、隐喻、转述及省略跨消息主题不会强行写入。真正的多次谈话语义纠错、跨日回忆、跨源矛盾处理和真实账号端到端仍未完成。

## 影响范围与验证

| 入口 | 有变化吗 | 约束 |
| --- | --- | --- |
| 普通私信、可信公开评论 | 是：已经调用原好友兴趣采集接口 | 仅白名单 / 真实 UID / 当前账号 |
| 读取好友兴趣、推荐意愿与发送前过滤 | 是：使用最新时序状态 | `uncertain` 只限制主题主动推荐，不授予其它权限 |
| 主人私信独立 Agent、主 Session | 无新增接入 | 不宣称全渠道长时语义一致 |
| Life Memory、人物交流画像、拒联账本 | 不改 | 仍用各自唯一状态源 |
