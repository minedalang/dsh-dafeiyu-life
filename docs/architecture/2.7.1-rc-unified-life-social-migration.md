# 2.7.1-dev.7 · RC6 统一 Life 社交归属、老用户升级与验收边界

> 当前**生产实现**，非发布声明。旧版 RC1–RC5 社交所有权章节属于历史开发阶段；此文为最新权威说明。

## 最终原则

- 新用户、**老用户**使用同一个 Life 社交**生产决策归属**。旧 `legacy` owner 不再作为生产回退。不能因生命周期调度设置为 `off` 就让旧决策器重新发送；生活视频频率和社交回复权限是不同维度。
- 旧代码中一部分 `ownerDmAgent`、`interactionBatcher`、`ownerTodos`、`socialIntentEngine`、Python MCP 仍保留为 **Life 调用的技能／上下文构建器／平台适配器**：这些模块不是独立 owner。完全删除它们会破坏主人命令、消息收取、历史待办、记忆、关系、权限与平台回执。逐步清理旧命名不能等同于删除数据或未经验收重写工具。
- 真实账号原来的私信、评论、@、主动分享授权保持原值；迁移只改所属的 **owner+generation**，不自动开启新的写入能力。旧隐私、记忆遗忘、历史账本和角色 ID 不因升级重算。

## 真实生产链

1. 经 B站登录与 First Start 校验的当前账号建立脱敏作用域；管理页或正常调度触发 `ensureUnifiedLifeOwner`。不可用/数据损坏时拒绝写入。
2. 统一复用 `SocialHandoffFence` 的 DM 和 comment 两个账号隔离通道。先逐条预约两个通道，再核查两侧无旧操作在途且 `SocialSendTransaction` 无 attempted/uncertain/incomplete；双通道满足才写持久 owner=`life-agent`、generation。不是删除本地历史聊天或记忆。
3. 任何半迁移、进程崩溃、未知平台回执、身份切换或归属文件损坏：**冻结**、拒绝旧决策器发送，不自动重发、不自动恢复 legacy。残留预约需要离线核实后由操作员执行原有核查/解锁流程；故障复原不可静默删账本。
4. 普通入站私信、评论和 @：仍复用唯一角色人格、情绪、兴趣、短期上下文、关系记忆与既有生成技能；决策入口与真实发送前分别校验当前账号、Life owner 和 generation；缓存旧稿与旧主人工具不能借到新归属。
5. 主人私信 Agent、主人命令、待办回访在相同 Life 社交归属下调用既有能力。自动回执以来源事件为键，入同一跨进程事务。明确人工操作继续要求原单项权限，不会由 Life owner 自动授权。
6. 自主视频兴趣推荐：既有模块只准备候选；`social-intentions.mjs` 在真正自动发送**前**要求 Life 独立返回可解析的 `send/skip` 决定，再次核验收件关系、全局/单项授权、当前 owner+generation，最后进入匿名幂等发送事务。模型失败即跳过、不发送。主人手动发送仍走旧人工确认。
7. 视频探索按 `AutonomousPlanner` 既有生活节奏、单独视频额度及只读证据继续运行；统一 Life 社交归属本身不等于启用视频探索，不证明看过/听过音画。

## 保留、退役与不扩权

| 内容 | RC6 决定 | 原因 |
|---|---|---|
| `legacy` 作为默认社交生产 owner/发送兜底 | **退役** | 否则新老用户行为不一致、两套决策竞争 |
| DM、comment 原消息收取/平台工具/发送事务 | **复用** | 已有防重、未知回执、真实权限与跨进程约束 |
| 主人 Agent、待办回访、推荐草稿 | **受控技能** | 保留既有能力，不是新独立生产 owner |
| 原始记忆/兴趣/人格/关系/待办账本 | **保留原单一事实源** | 遗忘、私密域、账号隔离与备份稳定性 |
| 独立视频生活模式及视频 Agent | **保留** | 决定何时探索，与社交授权无关 |
| 管理中心旧 owner 历史日志 | **可读不可作为发送授权** | 调试与人工核对需要 |

## 自动升级/失败流程

- 仅在**已经核验的同一账号、无在途旧操作、没有未知发送结果**时原位迁移两个渠道。无需老用户再选择“旧/新决策器”，历史外发权限不扩张。
- 如升级时无法检查可信回执或存在异常，两个渠道都不使用旧 owner 继续工作；显示迁移待确认，并保持待人工核验。软件可继续做不受影响的本地生活/只读工作。
- 中断发生于第一个 owner 文件写入后时，预约不会被无条件释放。恢复以可审计的真实文件状态为准，不宣称磁盘上两个文件物理一次性原子写入。
- 回滚代码包**不等于回滚发送归属**。在新版本尚可能运行时不得直接删 owner 文件/手动设 legacy，避免双发。冷备份/恢复需验证用户配置、账号归属、原记忆、遗忘衰减和原未知发送记录。

## 限制与 RC 上线门槛

1. **代码层面**可用同一 Life owner 路由 DM/评论/主人入口/推荐，并对未知结果 fail-closed；不过生成文本仍由多个保留的技能适配器提供，尚未重写为单个大模型规划函数。`Life` 在此指统一归属、权限/上下文、决策与执行门禁，而不是删除所有旧命名的实现文件。
2. Linux 离线模拟和单元测试**不是** Windows/Conda、真实 B站、真实模型与双账号操作证明。生产上线前需运行 `run-tests.bat`，对两个测试账号做受控入站 DM、评论/@、主人命令、待办回访、视频分享发送/不发送、未知回执模拟、升级和复原。不要在真实主号上先行批量发送。
3. 用冷备份的旧用户目录校验**原始权限逐项一致**、私密及已遗忘人生记忆未复活、关系和待办数量一致、旧外发事务不重试，并验证重启及切号。
4. 72 小时稳定运行 + 7 天观察：按日记录真实回执、失败/跳过、沉默、打扰率、兴趣探索与跨日人格证据，验证后续社交/探索确实受到可信经历影响。只看单次模型提示或匿名计数不算因果验收。
5. 通过前保持 `2.7.1-dev.7`、`releaseReady:false`、不打 RC Tag。RC 标准是**真实安全/自然**而不只是离线测试通过。
