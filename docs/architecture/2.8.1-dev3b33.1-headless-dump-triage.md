# 2.8.1-dev.3b.33.1：DSH Headless 配置合成失败分层诊断

## Windows 18:39 实机证据

`2026-11-16T10:39:10.644Z` 持久化验收为 `headless_config_dump_exit`。独立 Python MCP 图片预检 `ready`；Headless 配置合成 `failed`；DSH 内图片工具 `not_run`、Provider `not_started`，模型没有最终回答。该证据**不能推导为图片模型不支持图片**，也不能证明安全 overlay 真的被 DSH 加载失败。CLI dump 命令未成功结束，旧版本没有保存它的退出码和错误分类。

## 本轮范围

在原固定图片验收中，只有 `--dump-config` 非零退出时才额外测试同一 DSH CLI：

1. 不带视觉 overlay 的 `--dump-default-config`：内置 bundle / CLI 是否能导出；
2. 若第一项成功，测试不带视觉 overlay 的 `--dump-config`：用户 Headless profile / Home 配置层是否可合成；
3. 若两项都成功，首次添加视觉 overlay 后的失败归因于视觉 overlay 层（仍可能是环境/插件版本冲突，不能直接称为模型问题）。

整个检查不请求模型、不读取 B站、不对外发送消息，不保存任何原始 CLI stdout/stderr、配置树、图片、路径或凭据。只记封闭状态、失败层级、CLI 退出码、有限 Node 异常代码和错误类别。失败继续阻止当前图片认可，不能绕过图片工具回执与人工确认。

失败层级字段 `headlessConfigFailureLayer`：
- `cli_or_bundle`：默认配置导出不成功，优先检查 DSH CLI 启动器及安装的 Headless 包；
- `profile_or_home`：默认 bundle 可导出，但现有 Headless profile / Home 配置不能合成；
- `vision_overlay`：未叠视觉 patch 时可导出，添加视觉 patch 后失败；
- `unknown`：不能归因，不猜测。

`headlessConfigFailureKind` 仅分类已知的命令行选项、Node 模块解析、patch 解析、profile 错误，未匹配显示 `unknown`。`headlessConfigDefaultDump`、`headlessConfigBaseDump` 是独立命令状态，不能冒充图片能力。
