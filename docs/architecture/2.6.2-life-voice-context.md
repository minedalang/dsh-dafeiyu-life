# 2.6.2 dev · 大肥鱼统一人格上下文装配（实际接线）

> 开发阶段说明。此处是**对现有模型上下文装配的统一**，不是重置人格、追加永久记忆、改变聊天授权或发布新版本。

## 两条独立原则

1. **事实发生在操作成功时，而不是回访成功后。** `owner-todos` 的成功执行回执是可核对的只读事实来源。`verified-life-facts.mjs` 的收件人隔离视图会在聊天、回访等入口按需读取，回访是否主动发送不改变待办结果。事实视图有时间和渠道边界；视频详情读取仅证明读取资料，不证明看完画面、听过音乐或形成完整感想。
2. **大肥鱼只有一个人格，渠道只决定表达环境和权限。** `lib/life-voice-context.mjs` 统一编排核心人设、角色背景、已批准成长、当前成长人格、模拟情绪和当前对象真实关系；不同入口调用同一装配器。人物设定仅影响**表达**，不能成为记忆证据、发送权限、工具操作授权，也不能免除发前真实事实检查。

## 实际接线矩阵

| 入口 | 接线方式 | 边界 |
| --- | --- | --- |
| 普通 B站私信 | `dmChatPrompt -> lifeVoiceContext(dm)` | 当前 UID 的关系与上下文，不读取其他人的私密经历 |
| 主人私信 | `ownerDmAgent.getPersona -> lifeVoiceContext(owner-dm)` | 不再被原 900/1500 字上限直接截断；动作权限仍由 Agent 独立控制 |
| 评论 / @ / 互动批次 | `buildInteractionPersona -> lifeVoiceContext(comment/dm)` | 评论有独立的短回复约束；多人批次不混入单个人的关系 |
| 完成待办回访 | `ownerTodoFollowup.chooseReply -> lifeVoiceContext(todo-followup)` | 原请求主题、完成时间、成功回执独立于人格；回访意愿与授权不变 |
| 自主分享 | `socialIntentEngine.getVoiceContext -> lifeVoiceContext(social-share)` | 仍需真实选片、草稿检查、好友授权、发送回执 |
| 自主生活动态 | `dailyDynamic.getVoiceContext -> lifeVoiceContext(dynamic)` | 只允许当前可用的公开记忆证据，原草稿审核、自动发送开关不变 |
| 主 Session | `getIdentityPrompt -> lifeVoiceContext(main)` | 与主 Session 原工具权限、私密检索和成长提示分开 |

## 上下文等级

- **同一不变核心**：主人手动设置的人设、角色背景。对长人设按段分配预算，避免其它关键成分完全被挤出，但不保证无限长的人设全文无损注入每一次调用。
- **可变人格**：主人批准的风格及已开启的人格成长，按场景选择当前有效片段。
- **当前情绪**：当前模拟状态与表达节奏，不推断对方造成情绪变化。
- **当前关系**：只有收件人身份确定并允许使用时才装配；关系熟悉度不是发送授权。
- **事实、长期记忆、待办进度**：仍通过原有的 `SocialContextAssembler`、`LifeMemoryGateway`、成功操作回执和权限门禁提供。人格装配器自身不读档、不绕过遗忘、更不读永久 archive。

## 尚未解决的限制 / 验收要求

- 模型仍可能自然语言表达不准确。事实检查目前覆盖既知高风险断言，不能保证对任意复杂句子的全语义正确性。
- 成功读取视频元数据/字幕后，**具体可追问细节**仍须来自当前可用的经历摘要或重新授权检索；本轮没有建立新的完整视频感知和持久内容索引。
- 刚完成的任务可立即被相关聊天读到成功状态，但历史/跨天信息会受到事实视图时间窗及人生记忆衰减约束。不能宣传为每条旧事实永久可被所有人回忆。
- Windows DSH Desktop、真实 B站账号、用户自定义长人设和多 UID 实际对话仍需人工验收；测试通过不等于远端实测成功。
