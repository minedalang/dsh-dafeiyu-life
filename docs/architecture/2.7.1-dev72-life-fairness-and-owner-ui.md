## 正常并发不应变成五分钟技术延期

- `LifeWillingness.decide(...,{queueIfBusy:true})` 将不同轮次真实候选放入同账号进程内等待序列；普通 DM 和评论沿同一队列执行**已经生成好的正文封存授权**，不额外调用模型。
- 同一短期窗口的多项候选仍交由 Life 一次性择一，不强制她执行所有候选；本轮未选中由原 Producer 的延期路径负责，不构造新的跨会话持久化外发任务。
- 每个发送者仍拥有原身份/正文/线程验证、额度、平台真实发送和结果结算；队列不替代这些步骤。
- 内存队列最多 64 项，每项最多等待 90 秒；超时返回 `life-choice-queue-timeout`，交还原 Agent 后续核验重试，不自动重发。跨进程授权依旧由原持久文件串行，未知结果继续人工复核。
- 只有前一笔 proof 实际结算后才能继续放行另一笔。队列本身不代表已发送，且不同账号切换后作废。

## 限流处理

- 保留所有既有本地总频率保护、平台 -509 共享冷却以及每类轮询退避；不调高 B站请求额度。
- 在限流连续发生时，成功读取其他接口不能清除导致 -509 的具体接口所积累的退避层级；该接口实际恢复读取成功后才清零。
- 这不能确保平台解除风控；真实 B站长期运行后再决定是否需要按 endpoint 单独设置更长的读间隔。

## 面向使用者的 UI

- 真实时间线改为单一按日期的列表；原 `continuity` 事实仍由 API 提供，但不再强迫展示从未有可靠关联的空分组。
- 相同心情的连续情绪事件只在第一次变化时形成一张生活卡片；原始事件不删除；真正变化再显示。
- 小型设置搜索框直接索引当前已有选项标签，选中后切换对应页面并展开原设置容器，不复制控件、不绕过保存验证。
- 白名单/唯一授权主人编辑器改为完整宽度卡片和响应式字段组，保持原 UID 唯一性、所有草稿及保存逻辑不变。
- 新安装的 `dmFollowAutonomyEnabled` 默认 `true` 只表示允许 Life **提出关注选择**。既有用户显式关闭继续保持关闭；实际关注仍同时需要 `agentFollowEnabled`、真实双向长交互、Life 另一次明确批准和 B站关注成功回执。

**边界：** 不声称已在 Windows DSH 实机上验证布局、平台实际风控和长期队列公平性。高频模型调用的历史上下文缩短没有在此版盲目改动，避免未经证据删除需要的记忆。
