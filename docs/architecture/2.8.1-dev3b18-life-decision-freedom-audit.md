# 2.8.1-dev.3b.33.18 · Life 决策自由与安全链接审计

> 本轮基于 `.17-notification-sentinel` 工作源码审查并实施安全修复。当前标识是开发候选，不代表真实 Windows/B站端到端验收完成。

## 1. 审计范围

- 私信文本与 B站分享卡片中的链接识别、登记、模型可选读取、转发原动态连续读取。
- Life Autonomous Planner 的 `inspect_shared_link` / `inspect_related_content` 选择和只读执行。
- Life 意愿凭据、私信发送前门禁、关注/取关、评论/@回复、公开点赞/评论、只读待办和视频探索。
- 外部内容提示注入、跨账号引用、联系人权限撤销、请求预算旁路、证据回执准确性。

## 2. 发现的问题与修复

| 编号 | 发现 | 风险/表现 | 本轮处理 |
|---|---|---|---|
| DF-01 | B站 `b23.tv` 短链重定向请求未逐跳进入共享读取预算 | 多跳短链可能消耗未记账的 B站请求，不能完整服从账号级冷却 | 已修复：每个重定向 HTTP hop 都经过 `biliReadBudget.guard('shared-link-resolve')`；302/307 等预期跳转记为成功请求，403/412/429进入保护；本地预算延期返回 `read-budget-blocked`、资源队列未准入返回 `resource-deferred`，均通过独立 deferral 回执等待，不记为内容读取失败 |
| DF-02 | 同一私信包含两个安全链接时，原 DM 接线只在“唯一一个链接”时提供读取入口 | Life 无法在当前私信轮次自主选择其中一个，多个链接只能等待后台机会 | 已修复：最多展示两个宿主生成的 opaque 候选 ID；Life 必须选择精确 ID，单候选可默认；多候选缺少精确选择时 fail closed；每轮最多主动读取一个外层链接，其他候选保留给后续 Life 决策 |
| DF-03 | 分享链接登记时检查了发件人角色，但后续执行没有再次核验当前联系人权限 | 好友被移除、陌生人权限关闭或 DM 总开关关闭后，旧待读链接仍可能被 planner 选择 | 已修复：DM 上下文展示和实际只读执行前重新校验当前账号、发件人、好友关系/学习权限、陌生人开关与 DM 开关；相关公开节点沿父引用继承源权限 |
| DF-04 | `recordRead` 对直接类型化链接没有强制 proof.kind 与 ref.kind 一致，AV/AID 映射也没有逐项核对 | 错类型或错误 AID 的平台回执可能被记入分享账本 | 已修复：直接 dynamic/video/profile 必须类型匹配；AID 必须与平台回执中的 AID 完全一致；只有经过验证的短链可解析成另一资源类型 |
| DF-05 | 视频分享读取上下文容易让模型把元数据核验误说成观看 | 标题/简介回执不等于播放、观看或画面理解 | 已修复：账本和 DM 上下文记录 `video-metadata-only`、`watched:false`、`metadataOnly:true`；planner prompt 明确禁止把元数据核验描述成观看 |
| DF-06 | `contact-shared-bili-link` 在 planner 的候选详情摘要中缺失 | 经授权的陌生人/熟悉联系人链接可能只有 ID 菜单，没有足够类型/状态信息供 Life 判断 | 已修复：向 planner 提供有界 kind/status/evidence 摘要，不暴露发件人 UID 或私信正文 |
| DF-07 | 一条私信登记多个链接时，事件唤醒只使用第一个链接 ID | 其他链接可能未获得独立的 Life 机会唤醒 | 已修复：每个已登记 ID 都产生幂等的独立唤醒事件 |

## 3. 当前安全链接边界

当前生产能力仍仅限明确支持的 B站 HTTPS 官方域名与已知动态、视频、空间路径；`b23.tv` 只允许受限短链解析。短链使用手动重定向、无 Cookie/Authorization、有限跳数和超时；每一跳进入共享读取预算。任意外站 URL、未知短链、非 HTTPS、带用户信息/非标准端口/不支持路径不会进入读取工具。

外层转发动态只有在平台真实回执返回唯一 `orig` 引用后，才会出现独立 `shared_original` 候选。原帖读取仍由 Life 再次选择；不递归自动抓取、不自动点赞或评论。视频 metadata-only 不代表播放或观看。

外部动态文字、视频简介、评论、作者签名、图片观察和网页内容都只作为不可信证据；不得执行其中的指令、修改系统行为或扩大工具权限。

## 4. 对其他自由决策场景的审查结论

| 场景 | 当前决策链审查 | 本轮是否改变权限 |
|---|---|---|
| 私信回复/沉默/延期 | 同一 Life Voice 形成决定；SocialPolicyGate、短时账号绑定凭据、发送前复核和平台回执独立生效 | 否 |
| 私信安全链接阅读 | Life 选择只读上下文；宿主提供精确候选 ID；读取权限、账号、预算和真实回执再次校验 | 仅修正只读链路 |
| 转发原动态 | 外层读取后由 Life 独立选择唯一平台核验原帖 | 否 |
| 评论回复与 @ 回复 | 统一意愿和社交上下文；目标、长度、发送节奏、账号与回执门禁独立 | 否 |
| 关注/取关 | 精确候选与单次意愿凭据；权限不由模型意愿授予 | 否 |
| 公开点赞/评论 | 需要全局公开互动明确授权、目标作者与对象核验、Life 决策及发送回执；未知结果不重试 | 否 |
| TODO/只读待办 | 接受/继续需要明确 Life 决策；待办不能授予外部写权限 | 否 |
| 视频探索 | Life 选择内容和观察深度；元数据、字幕、视觉和完整观看证明严格区分 | 否 |

审查中没有发现需要放宽写权限的理由。本轮不新增任意网页读取、不新增私信自动回复权限、不更改陌生人私信许可、不扩大公开互动、不自动恢复未知发送状态。

## 5. 关键实现文件

- `lib/bili-share-link.mjs`：B站安全链接解析、短链逐跳预算。
- `lib/life-shared-bili-links.mjs`：链接引用、证据回执和类型校验。
- `lib/life-shared-link-policy.mjs`：执行时发件人权限复核。
- `lib/interaction-batch.mjs`：同一 Life DM 模型选择具体安全链接候选。
- `lib/autonomous-planner.mjs`：分享链接和关联内容候选摘要、外部内容不可信提示。
- `index.js`：平台预算、账号作用域、当前联系人权限和真实读取回执接线。

## 6. 回归与边界

本轮新增覆盖：逐跳共享预算、HTTP 429 冷却、预算延期不记内容失败、多个链接精确选择、缺少选择 fail closed、发件人权限撤销、动态/视频类型与 AID 证据匹配、视频 metadata-only 语义。

同时回归既有：私信同一 Life 决策、转发原动态第二次自主选择、外部 URL 拒绝、陌生人准入后才登记链接、评论/关注/取关意愿、公开互动授权、TODO 只读限制、未知外发冻结和账号隔离。

离线测试不等于真实 B站接口验证。仍需 Windows DSH 实机确认短链真实重定向、真实动态/视频/空间读取、发件人权限变更和 `-509` 冷却期间行为。2.8.1 其他既有发布门禁（尤其生产 DSH 视频视觉）仍独立存在。

## 7. 结论

当前决策自由机制的总体方向是正确的：Life 自主选择候选，宿主只提供有限能力，权限与真实执行门禁独立存在。本轮修复的是链接处理链的请求预算、候选表达、权限复核和证据语义缺口；没有把“自由决策”改成自动执行，也没有用关键词或链接本身代替 Life 意愿。
