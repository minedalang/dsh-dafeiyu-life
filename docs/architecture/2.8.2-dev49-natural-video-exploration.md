# 2.8.2-dev.49 · 鱼鱼自然挑选与观看视频（已接线，待 Windows 实机验收）

## 用户体验：一次选片，自由探索

视频 Agent 在**同一轮选片决策**中参考标题、UP、播放/点赞/评论热度、时长与简介，形成选中与否的判断。不会额外启动“先点开详情再选中”的第二次模型决策，也不会在此阶段取得字幕、ASR、分镜描述或评论正文。

**真实入选之后**，模型才可自主选择只读 `bili_watch_video`：一个逻辑观看动作同时发起受控视觉采样与官方字幕读取；官方字幕缺失时仅在主人已开启 ASR 的情况下尝试本地转写。画面和语音文字证据分别验证，分别标注是否成功。即使其中一类失败，另一类有效证据仍可使用；若都不可用，不能声称已完整观看或听到原声。

选中之后，观看、读评论、评论/点赞/收藏（原 Life 意愿和外发权限门禁）、继续换视频或休息**无固定顺序**，评论不以观看为强制条件。Life 当前 Episode 的独立 `observe_video` 等能力不被此视频 Agent 专用分阶段协议替换；2.8.3 的跨轮次按需补看与双层记忆仍属于未来计划。

## 技术归属与可信边界

- **视频 Agent 模型菜单：** Node `index.js` 在该视频子进程注入 `BILI_DUTY_VIDEO_PICK_FLOW=1`，将 `bili_watch_video` 注册为可见工具。原字幕/ASR/视觉函数仍在内部受控调用白名单，但 Python `tool()` 不向此视频 Agent 注册为独立模型工具；其他受权会话不设置该标识，旧入口不变。
- **选中证明：** Python `vendor/bilibili-mcp/mcp_server.py` 检查当前 B站 UID、24 位轮次 ID、真实 `selected_videos` SQLite `挑中` 记录、精确 BV 与当日作用域。评论区阅读同样在选中后开放。不依赖模型自称选中、历史公共 Markdown 或标题相似度。
- **可信阅读：** 继续使用原有 `_guard`、公共读取预算、限流、视觉模型开关/采样上限和字幕/ASR 原工具，聚合只返回有限长度的真实来源结果；未成功不能写已看事实。
- **诊断：** `lib/video-round-funnel.mjs` 只计入匿名轮次/精确 BV 的工具实际回执，统计字幕与画面尝试/成功，不保存评论或模型原文。选中不等于已经理解视频。
- **安全边界：** 该流程不更改社交 Life 意愿、主人授权、B站发送回执/配额或可衰减记忆；无额外账户数据库或后台调度器。
