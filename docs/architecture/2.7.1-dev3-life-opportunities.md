# 2.7.1-dev.3 生活契机协调：多来源接线与第一条真实闭环

## 本轮补充：多来源的真实责任归属

| 来源 | 事实/唯一写入者 | 成为契机的条件 | 模型能做什么 | 不允许做什么 |
|---|---|---|---|---|
| 评论阅读的临时感受 | `video-discussion-diagnostics.mjs` 当前账号真实只读回执 | 同 BV 成功非空评论列表，随后鱼鱼记录非 none 主观反应，最近 7 天 | 对同 BV 调用 `bili_video_info` 只读核实；延期、放下、沉默 | 将评论当事实、人物关系或承诺 |
| 后天兴趣变化 | `LifeInterests` 既有真实自主选片证据，新增可选登录归属标签 | **同账号**不同 BV 至少 3 条、跨至少 2 天，最近 14 天有新证据；阶段 emerging/growing/stable | 可选读取最近真实 BV 元数据，作为后续弱选片线索 | 推断喜欢、自动记录已观看、信任旧无账号历史 |
| 公开交往线索 | `SocialPortraitGateway` 当前账号 runtime 私密库中的**公开评论**条目 | 已准入自然关系或白名单，最近 30 天至少 2 个独立真实公开互动事件、跨 2 天，最近 14 天仍有记录 | 仅复核该账号公开已记录的交流偏好；不提供 UID 或正文给模型 | 读取私信原文、推断亲密、主动私信/@、邀请 |

**来源取舍与安全：** 老的 `life-memory/interests.json` 很多记录不带 B站账号标签，不自动回填到当前登录账号。这些记录不删除，原兴趣页面仍可呈现。事件入账的账号标记发生在原人生记忆协调器/反思环节，不另写一份兴趣账本；延迟超过两天的选片回执不自动赋予当前账号标签。关系索引里若只有互动总数而缺乏评论来源，不可因此产生新的主动联系契机。所有候选按当前登录账号凭据签名隔离，缺失/损坏的数据源只报诊断，不解释成鱼鱼故意不做。

`review_public` 只是对当前可见的公开证据进行本地只读核对，其回执只证明公开交流记录存在，不构成新的心理认识、现实好友授权或联系方式。与某人再次正常交流时，仍由原画像上下文及 `SocialPolicyGate` 判断，不得因生活契机跨过原权限。兴趣 BV 真实元数据可以给下一轮自主视频探索一条**可忽略**的弱提示。

## 统一层归属检查

| 项目 | 实际入口与现有责任 |
|---|---|
| 输入 | 视频 Agent 的 `bili_comments` 非空成功回执 + 同一 BV 后续 `bili_discussion_note` 的临时主观反应 |
| 事实源 | `video-discussion-reads/YYYY-MM-DD.jsonl` 的按账号 HMAC 过滤的成功读取记录；原只读模型反应不是事实 |
| 新的最小统一层 | `lib/life-opportunities.mjs`：从真实回执派生短期候选，保存当前账号的选择与元数据读取回执；**不是待办、记忆或人物关系数据库** |
| 决策与时机 | 复用现有 `lib/autonomous-planner.mjs` 的定时器、每日模型额度、活跃时段、busy 互斥、原只读待办/反思分支 |
| 执行 | 仅允许选择已有候选的 BV，走宿主现有读取预算与账号门禁调用 `bili_video_info`；返回匹配 BV 与真实标题才记录 `verified-metadata` |
| 回馈 | 下一轮 `promptFor` 可以带入最多两条“**已核实视频元数据，但没看过或听过**”的弱线索。鱼鱼可以忽略，不强制继续搜索或发布 |
| 验收 | 「人生记忆 → 生活行动契机」，刷新不触发网络或 AI，手动提醒经过原模型额度；提供本账号候选、选择、延期、失败及核实标题 |

## 真实生命周期

1. **评论来源**：有真实成功且非空的评论区读取，鱼鱼之后对**同一 BV** 自主记录非 `none` 临时反应，两项缺一不可；只筛最近 7 天、当前账号的回执，旧无日期记录不参与。
2. **兴趣来源**：原 `LifeInterests.recordInterestEvents` 在真实事件入账时保留当前登录账号的作用域标签；只有带可靠完整时间戳、入账距事件不超过两天的真实自主选片可以获得该标签。当前账号在滚动 90 天内至少 3 个不同 BV、跨至少 2 天，且最近 14 天有新选片，才形成 emerging/growing/stable 阶段契机；它是选看趋势，不等于喜欢。
3. **人物来源**：从当前账号运行目录的 `SocialPortraitGateway` 读取可撤回的**公开评论**明确偏好，必须有不同公开评论事件跨至少 2 天，最近 14 天仍有效。DM 原文、人物昵称、UID 和主观人格推断均不放进模型候选。
4. `LifeOpportunities.list()` 返回待考虑的只读机会，不读取原文、评论者 UID 或私信。视频标题和临时问题均按不可信数据处理；问题不可能证明评论内容的真假。
5. `AutonomousPlanner.tick()` 仅在原有每日额度、间隔、时段和开启条件满足时才调用模型。模型可选择 `inspect_opportunity`、`defer`、`dismiss`、`skip`；原 `execute_read` 仅针对已经接受的只读待办。手动考虑不会跳过每日限额或首次启动检查。
6. `inspect_opportunity` 后重新查询当前账号仍有资格的同 ID/BV 候选；调用一次既有 B站只读视频元数据接口。匹配 BV/title 才有“已核实元数据”回执；读取失败只保留 `defer`，不得对外声称观看或听歌。
7. `review_public` 对同一个账号的公开偏好候选再次读内存证据后只记录 `public-evidence-reviewed`；不得生成私信或把证据当成亲密关系。每个候选的 skip 至少冷却 24h、defer 至少 48h、完成/放下不再重复考虑。一个账号的记录永远不会被另一个账号的页面展示，也不会跨账号回馈到视频模型。

## 为什么不是空架子

- 至少一个**真实读取**动作是受原平台预算与账号绑定的，结果写入最小回执并参与下一轮视频 Agent 的可选搜索上下文。
- 模型选择离开同样留有回执，而不是没有日志就猜“她不想看”。
- 既有待办受自身账本与意愿/回执约束；新观察不会直接写入已接受待办。
- **不额外开启定时器**；AI 的考虑频次仍沿用 `AutonomousPlanner` 原上限。只有同时存在真实合格候选或已有任务时才可能消耗模型额度。

## 仍未实施的部分

- 兴趣阶段目前只凭真实跨日选片，仍不是可量化的喜欢/不喜欢；公开人物仅验证明确偏好，**没有把私密关系、完整共同经历或长时语义记忆接入调度器**。
- 未提供完全自然的跨多日自主规划或自由联系陌生人，未验证实际 B站/Windows 模型行为。
- 当前元数据只读动作不能说明完整观看、音轨体验、评论区理解或兴趣变化；这些必须由后续真实证据另行证明。

## 使用者验收步骤

1. 确认正在运行 `2.7.1-dev.3` 且 B站账号已登录，独立自主调度已开启并配置了非零 AI 每日额度。
2. 通过「现在跑一轮」让视频 Agent 自己决定是否读取评论；在「运行诊断 → 评论区只读探索」先看到**成功非空评论**与同 BV 的**暂时感受**，否则尚无合格契机。
3. 兴趣来源需要在当前登录账号中跨两天真实自主挑选至少三个不同 BV，并经过人生记忆的正常事件入账；升级前没有账号证据的老数据不会直接变为契机。公开交流来源需要同一人物的不同公开评论多日明确表达，私信互动不计。打开「人生记忆 → 生活行动契机」刷新，确认每条记录的来源、证据次数及日期数；点击「提醒鱼鱼考虑一次」可能调用一次模型，并选择读取元数据、内部公开证据复核、延期、放下或不处理。
4. 如果她决定核实 BV，必须看到真实元数据读取回执与匹配标题；次轮刷视频可以忽略这条弱线索。对公开人物来源，只能出现本地公开证据复核回执，不得触发联系。如果她沉默或延期，要看到相应状态/下次允许考虑时刻；模型和 API 失败不得伪装成功。
5. 切换账号后不能查看上一账号的契机记录；主动考虑不应发送任何评论、私信、关注或额外待办。
