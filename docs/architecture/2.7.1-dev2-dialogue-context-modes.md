# 2.7.1-dev.2 补充：后台互动上下文模式（本轮实际生产接线）

> 本文记录首次交付双模式时的实现。后续 `2.7.1-dev.2` 补充已将长期记忆/画像/梗改成真正按需读取，请以 [真实按需读取更新](./2.7.1-dev2-true-on-demand-retrieval.md) 为当前行为依据；版本号不变。不涉及主 Session 模型管线重写，也不将主人高权限 Agent 偷换成普通社交 Agent。

## 实际问题及现有入口

- `lib/interaction-batch.mjs` 为普通私信与部分后台评论/被 @ 回复提供共用 `reply/skip/defer/close` 决策和结构化只读待办建议。历史 `prompt(batch)` 固定注入完整的待办、推荐和 P6 说明，以及允许范围内的记忆/画像/梗、视频上下文。
- `lib/owner-dm-agent.mjs` 是独立的受限主人私信 Agent，在单轮操作里可以最多进行四步模型与后端白名单工具动作（依据权限）。此入口与后台普通私信的上下文模式 **不共用**。
- 主 Session 由 DSH 宿主的 Agent、会话管理和本插件的记忆桥接工具组成，**不经过** `interaction-batch.mjs`。
- 部分评论存在自己的独立 Agent/草稿路径；新开关只覆盖最终使用 `interactionBatcher.generate` 的后台互动入口。

## 两种可切换模式

配置唯一键：`interactionContextMode`，值为 `compact` / `full`。新安装和旧版未设置该键均默认 `compact`，但底层纯工厂 `createInteractionBatcher` **未显式传入模式**时默认 `full`，用于外部调用者兼容旧接口。生产创建时总是传入运行时配置选择器。

- **精简按需（默认）**：单轮必带 Life Voice、当前可用生活状态、当前 UID 身份/关系的基本资料、最近八条会话与必要的隐私/发送/只读待办承诺底线。其余记忆、对话旧片段、画像、完整推荐/待办回执、梗知识、扩展视频上下文默认不在初次模型请求中。仅将「当前可获取的证据种类」作为模型选项，**不采用本地关键词推断聊天意图**。
- **模型自主请求扩展**：模型先输出指定消息的 `contextRequests: ["todo", "memory", ...]`。同 UID 已授权的 `SocialContextAssembler` 已准备好的内容才会被按请求投放到下一次模型续推；从不把其它 UID、私信域或已遗忘档案拼进来。允许的种类：`todo, recommendation, memory, portrait, meme, video, history`；一次最多四类、只允许一轮续推。不请求时仍只有一次模型调用。
- **完整模式**：复用旧版 `prompt(batch)` 原文与原先的完整上下文装配，保留历史行为及对照测试路径；不会额外产生「请求扩展」步骤。

这里的按需扩展是**已授权检索结果的模型驱动展示**，目前并不是开放 DSH MCP 任意检索工具，也不是跨所有 Agent 的新全局上下文系统。上下文读取/预取仍使用现有统一组件；本轮减少的主要是**首轮模型输入体积**，不保证必然减少本地/平台读取次数或整体 Token 消耗。

## 任何模式都不能绕过的强契约

1. `SocialPolicyGate`、私信已读去重/拒联、跨渠道冷却、P6 授权与真实平台回执照常工作。模式不会授权发送。
2. `assessTodoReply`、`social-todo-intake`、推荐/完成事实冲突等最终校验仍位于模型输出之后。模型在语义上自主接受的只读建议，也只有真实入账后才能对外承诺。
3. 隐私探询在上下文装配 **之后**继续清空历史、长期记忆、画像、待办、推荐与视频背景。模型申请补充不会恢复这些资料。
4. 模型只提出 `contextRequests` 的第一轮**不外发、不创建待办、不更新情绪**。第二轮失败、仍提出请求或缺少最终决定时仅该项安全失败，不能把草稿当最终回复。
5. 同一进程对外提供非正文的聚合统计：精简/完整处理条数、发生扩展的条数、额外模型续推次数和失败次数；不包含 UID、原文、请求的证据内容。重启后重新累计。

## 用户可验收入口

**管理中心 → AI 模型配置 → 后台评论与私信 → B站后台互动 · 对话上下文模式**。选择后点击页面底部「保存全部模型配置」，重启不改变已保存的值。

同区点击「刷新真实调用统计」查看本次插件运行期间的精简/完整条数，以及额外续推次数。无真实消息不应显示伪造计数。可用两个自己控制的 B站账号做以下测试（不要发送真实私人内容）：

- 普通寒暄：精简计数增长，额外续推可保持为 0；但模型可能自主请求记忆，因此**不能保证**每次只调用一次。
- 问上次的真实只读待办：可观察到模型请求扩展或直接根据已知信息回答；需要核验完成状态时不能编造。若真正发生扩展，额外调用计数增长。
- 切回完整模式，用相同的测试场景观察完整条数增长及回复差异；模式不会改变用户是否有发送权限。
- 主人专属 Agent 和主 Session 不进入这两个计数；它们不受此下拉框影响。

## 已知边界与后续验收

没有在真实 DSH Desktop 与 B站账号上完成模型自然语言评测；静态和离线模拟仅验证接线及安全边界。对“精简后语气更自然、成本更低”的判断必须等到相同模型/消息/权限的实际前后 A/B 测试后作出。

代码变更：`index.js`（配置、运行时选路、脱敏状态接口）、`lib/interaction-batch.mjs`（模型请求/二次续推）、`lib/management-console.html` 与 `.js`（唯一设置与计数）、回归测试。只保留一个 Life Voice、原 SocialContextAssembler 和单份外发契约。
