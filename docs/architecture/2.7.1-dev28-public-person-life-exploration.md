# 2.7.1-dev.28 · 真实公开互动对象的自主作品探索

> **开发预览，非 Windows／真实 B站实机验收；`releaseReady:false`。** 以 dev.27 为基线，沿用单一 Life Agent、Life Voice、原事件／机会／意愿账本、原读取工具和写入门禁。此轮不是任意陌生人主页漫游，也不是跨评论串回复功能。

## 统一层归属

| 阶段 | 实际事实源与功能 | 准入与边界 |
|---|---|---|
| 相遇来源 | `social-portrait-gateway.mjs` 现有本账号真实公开评论交互记录 | **必须是当前允许的已认识/好友对象**，跨日 2 次独立公开互动且有对方明确交流偏好；不得从私信、好友白名单存在本身、模型脑补或旧归档生成 |
| 匿名 Life 契机 | `publicOpportunitySignals()` → `life-opportunities` 的 `public-person-observation` | 模型只看 24 位不可逆 `personKey` 对应的 Life 契机 ID、证据次数、日期；不接收 UID／私密原文／对方昵称 |
| 可信人物还原 | 宿主 `resolvePublicOpportunity` 只在当前证据仍有效时返回 UID 给私有平台读取适配器 | 模型不传 UID；关系撤销、当前账号不一致或证据过期立即失败 |
| 查看公开作品 | `readVerifiedPublicPersonPortfolio` → 原 `bili_user_videos` | API 返回 UID 必须与当前新鲜的目标证据**完全相同**，作品 BV+标题通过校验；读取中账号或关联证据改变就拒绝 |
| 独立意愿 | `life-opportunities.beginPublicPersonExploration` | 同一个账号隔离 v1 账本，原子保存匿名来源与最多 5 个真实 BV，不写入 UID、评论原文或新的用户画像；同来源一次，旧契机完成后不可重复开启 |
| 后续生活 | 原 `AutonomousPlanner` / `continuationMenu` / `completeExploration` | Life 可选择视频核实、继续探索、停止；在真实选定 BV 和公开内容足够的前提下，可再按 dev.27 原**单次写入**门禁选评论、点赞、收藏或**该视频作者**的关注 |
| 外部写入 | `life-continuation-write.mjs` + 受控 Python → 原 LifeVideoActionBridge / 原平台回执 | **不新增**评论目标写入、陌生人私信、对评论者 UID 的直接关注权限；未知回执必须冻结，所有已有开关、额度、账号、结果复核仍有效 |

## 风险与实机验证

- `bili_user_videos` 在真实 B站返回的 `uid` 和 `videos` 结构，必须同实机连接验证。代码不把非匹配结果猜成成功。
- 两次跨日公开交流的门槛偏保守，目前仅覆盖既有认识且明确表达偏好的对象；**刚遇到的任意陌生评论者**尚未形成候选，下一轮仍需设计可信评论 ID／作者 UID 来源与单人社交防骚扰规则。
- 查看视频标题、介绍和公开文字不等于实际观看画面或听过音频，不得在评论中宣称自己看过、听过或认识作者。
- `review_public` 的原纯本地只读选择继续存在。`inspect_public_person` 是鱼鱼自愿选项，不会强制每次遇到人都打开主页，也不会把已知好友当作必需联系对象。
- 这次改造没有新的持久 schema、模型服务、发送器或配置授权。登录切换、关联撤销与旧记忆遗忘继续使用实时检查；新公开投稿意愿只包含 BV 和简短标题。
- 需要 Windows DSH、真实登录账号、平台读取、真正写入 GET、72 小时自由行为实机验收后才考虑发布。
