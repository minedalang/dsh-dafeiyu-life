# 2.8.2 视频探索自然感知流程 · 技术评估（待实施）

> 本文是产品方案审查和回归准备，不表示代码已实现。现有 `bili_video_info` 在选择前可返回完整简介，`bili_subtitle`、`bili_preview_vision` 目前亦可在视频 Agent 有权限时各自调用。实施前须完成 Node/Python 工具桥及真实平台端到端验收。

## 用户意图与推荐流程

1. **扫视频列表**：模仿首页/搜索结果，先拿标题、UP、播放/点赞/评论量、时长等确有来源的卡片信息；无视觉模型调用，不提前附上字幕、转写或视觉描述。平台不返回的点赞数不猜测。
2. **点入候选详情／考虑挑中**：通过现有 `bili_video_info` 取得该 BV 的真实简介、标签和更新的热度指标，按已授权的原有门槛决定是否挑中；简介属于创作者自述，不是已经观看的事实。若用户设定的“入选”就是“打开视频页”，状态需在 UI 上统一为真实读回执，而非声称已观看。
3. **挑中后自由选下一动作**：Life/视频 Agent 自主选择观看、看评论区、点赞、收藏、继续搜片、跳过、休息等当前实际有权限的行动；**不强制先观看再评论**。评论、点赞、关注的现行账号授权/外发核验和反重复门禁不改变，不能把挑中解释成外发授权。
4. **选择“看视频”时才接入视频理解**：一次用户可理解的逻辑观看行为，对可用的 B站预览/解码采样帧调用视觉模型，同时读取公开字幕；无字幕时若已启用 ASR 则在原读预算内尝试转写。失败不能自动触发评论。所有视觉/字幕/ASR 均分别存真实回执、时间/范围和错误码，统一生成一个观看尝试经历；画面只是抽样，不声称完整播放。
5. **观看后回到自由选择**：新的实际观察证据进入合法当轮上下文，Life 可继续评论、回复、再选片、看讨论、休息或有目标地聚焦，现有跨轮补看和深浅双层记忆仍由 2.8.3 专项实施。

## 捆绑行为应如何定义

**捆绑的是一次“我要看视频”的自主意愿和动作入口，而不是两个模型结果必须同时成功。** 举例：

- 视觉成功＋字幕成功：两者均可用于理解，分别核验，并在同一事件中展示来源。
- 视觉成功＋视频无字幕且 ASR 未启用/失败：保留可信视觉经历；明确文字/语音信息缺失，不冒充完整内容。
- 视觉失败＋字幕/ASR 成功：记录「尝试观看，实际仅取得文字内容」，可供文字讨论，但不登记已看画面。
- 双方失败：记录观看尝试和真实阻断原因，无成功观看记忆。
- 只有文字模型、无视觉能力：用户/AI 可继续看文字、评论或延期；不能让“捆绑”使整个探索无法使用。

## 执行门禁与测试要求

- 单独新增“候选卡片可读字段／视频详情字段／已选后观看字段”的**工具返回投影或按阶段的实际读许可**。仅靠提示词“不要读字幕”不足以形成可靠的信息边界，且不应该阻断其他已授权 Life/主人上下文中的合法记忆检索。
- 现有 `bili_search`、`bili_home_recommendations` 可能已经夹带简介；需要统一选择阶段展示；`bili_video_info` 仍提供热度门槛但应按阶段投影；字幕与 ASR 不得被借道其他通用工具提前暴露给当前选片任务。
- Life Episode 和视频 Agent 须统一复用现有账号、BV 和读取回执，不以标题相似/时间相近拼接；预算、失败退避、缓存、平台限流和撤销授权沿用现行护栏。
- 原创评论的意愿不以观看成功为前提，不新增“必须证据充分才可以评论”的劝退话术；但任何以视频某个实际片段为依据的陈述不得伪称已看到不存在的画面。外发权限、平台事务和真实证据校验不放宽。
- 回归：候选数据不泄露字幕/视觉、选前视觉调用被拒绝/只读可复用场景、选后观看双渠道结果的所有组合、无字幕、ASR 关闭、视觉模型断连、评论先于观看、账号切换、重复 BV、旧记忆、防注入、诊断回执、Windows DSH/Ollama；完整更新四张现行 Life 架构图后再实施生产接线。

## 权衡

该方案能降低选片阶段的信息“上帝视角”，并且可能使 Life **更有理由自主看视频**，但不会保证观看频率一定提高。选择阶段保留简介有利于合理判断兴趣，也仍可能让某些视频不必观看即可表达对标题/简介的看法。实施时不应以提高识图次数为硬指标，以实际自主选择、证据诚实性、成本和体验为验收依据。
