# 2.7.1-dev.3 · 已接受待办与自主生活的共享只读动作契约

> **当前实现边界**：这是统一自主行动的**第一阶段调度冲突整合**，不是把所有生命周期迁到一个新账本，也不是开启对外自主联系。Windows/真实模型/B站仍需验收。

## 为什么需要重构

此前 `AutonomousPlanner` 一次决策虽同时看到 `readOnlyTodos`、`lifeOpportunities`、`lifeCues`、`lifeIntentions`，但它们分别保留独立的延期、放下与结果状态。模型可能看到同一主题的已接受搜索待办和自主搜索意愿，或者进行中的 BV 探索和一次性 BV 核实契机。仅依靠「每轮只选一个」**无法避免跨轮重复执行**。

**不迁移事实所有权：**

- `owner-todos.json` 仍是唯一已接受承诺的责任源；主人 Session、主人私信、普通私信及公开评论/@ 中**确实核验并接受**的只读任务，依旧由旧 `owner-todos` 入账、执行与确认。没有确认的建议不是待办。
- 当前 B站账号匿名文件 `life-opportunities/<account>.json` 仍保存自愿生活意愿、契机的短期状态；可放下的好奇**不等于**已经答应朋友的事。
- `verified-life-facts` 与各执行适配器的真实回执仍为事实源；读取 BV 元数据绝不充当视频完整观看、成功发表评论或待办履约的回执。
- 私密记忆、人物画像、熟悉度、Life Voice 只提供**合法的决策参考**；本契约不会新增它们的读写存储，也不会开放关注、私信、点赞、评论。

## 新增的唯一职责

`lib/autonomous-action-contract.mjs` 提供**纯函数**只读动作身份与候选协调，不写入新状态文件、不调用 AI、不调用平台：

| 已核验来源 | 动作身份 | 边界 |
| --- | --- | --- |
| 已接受 `search_videos` 待办 | `public-search:<标准化主题>` | 当前账号下未完成的已接受责任优先；含未来才到期、排在模型展示数量之外的责任 |
| 后天兴趣衍生的自发搜索 | 同一个 `public-search:<标准化主题>` | 若已有该搜索待办，则暂缓自发重复搜索，不自动创建／关闭意愿或待办 |
| 自愿评论好奇／生活契机核实 BV | `video-metadata:<BV>` | 仅表示平台元数据读取 |
| 正在接续的生活意愿 | 其可信搜索/作者投稿列表中的 `video-metadata:<BV>` | 同一 BV 的一次性核实契机暂缓；包括已有失败冷却但仍有效的探索 |
| 已接受 `watch_video` 待办 | `video-content:<BV>` | **不同于** `video-metadata`，不得用元数据回执宣称观看完成 |
| 已接受查看创作者作品待办 | `creator-portfolio:<UID>` | 不能通过评论者昵称或模型猜测 UID 形成行动 |
| 公开人物交流证据复核 | 无公网读取身份 | 仍仅内部复核，不和向人发私信／关注建立等价关系 |
| 对外写入类待办／P6 主动联系 | **不参与这个只读身份协议** | 继续通过原唯一发送与幂等/未知发送防重闸门，不能被“生活意愿”授予权限 |

所有跨账本比较只在**已由原账号绑定器和数据源筛选后的当前账号资料**中运行；不创建跨账号索引，不记录主题、UID、BV 或私信正文到去重诊断。原业务账本中的审核数据按原访问权限保留。

## 实际执行顺序

1. `AutonomousPlanner` 仍使用现有冷却、AI 日额、时段和 busy 门禁；从现有 `ownerTodos` 读取**全部未完成且当前账号允许的只读承诺**作为动作保留集，不只看当轮展示给模型的八项，也不能忽略尚未到期的承诺。
2. 从 `LifeOpportunities` 分别读取本轮可考虑线索、进行中的跨轮意愿，和**所有未过期**、尚在冷却期的进行中意愿作为 BV 保留集。后者**不进入模型提示**，只用于避免重复读取。
3. `reconcileAutonomousActions` 对具有**相同操作语义且目标相同**的自愿动作做候选协调：已接受责任优先；进行中的意愿优先于一次性相同 BV 核实；不同强度的事实不合并。模型仍可主动选择其他合法行为、延期或沉默。
4. 如果本轮只剩重合线索，**不调用 AI、不扣额度、不执行工具**；现有 `autonomous-planner.json` 最多每小时记录一条脱敏 `reconciled / held-overlap`，供管理中心查看。此记录不表示鱼鱼自主说了什么，也不表示任何任务已完成。
5. 如果模型明确提出新的同主题自发搜索或一次性 BV 核实，调用平台之前**再次读取最新责任／意愿保留集**。执行期间新增的已接受责任也能阻止竞争性的自发搜索。冲突结果为 `held-by-accepted-todo` 或 `held-by-ongoing-intention`，不会记造成功回执。
6. 原 `owner-todos` 和 `life-opportunities` 依旧各自记录真实完成、失败、延期、放下；任何一个只读回执都不会自动把另一份账本置为已完成。主人取消／更正、主动忘记、账号切换等，继续由原数据所有者的现有安全规则处理。

## 全系统入口与回归边界

| 入口/系统 | 与本轮共享契约的关系 | 权限与事实边界 |
| --- | --- | --- |
| 主 Session、主人专用 DM Agent | 原核验后接受的待办是调度保留集的一部分 | 不改变独立会话、模型或主人写入授权 |
| 普通好友/陌生人 DM、评论/@ | `SocialTodoIntake` 已核验并接受的只读建议仍统一进入 `ownerTodos` | 未接受的建议不得阻塞自主生活；P6、拒联、审批和发送去重不变 |
| 自主视频选择、评论观察和作者只读探索 | 真实证据仍由原平台工具与各生活源记录 | 搜索结果不是观看；评论者不是视频作者；模型不能编 UID |
| Life Memory、好友兴趣、关系指数/画像 | 仅作为现有可信来源及决策上下文 | 不写新关系分或深层画像，不使私密文本成为公开搜索词 |
| 已接受待办自动执行与原完成回访 | 保留原责任链及执行成功/未知状态 | 本轮不重构外部写入；不把去重记录变成履约回执 |
| 生活协调器 `AutonomousPlanner` | **本轮真实接线**；模型前协调、执行前二次核验、匿名回执 | 同一个鱼鱼／Life Voice、同一自主决策预算、无第二定时器 |

## 管理中心验收

在 **「管理中心 → 人生记忆 → 自主生活 · 线索、意愿与真实回执」** 刷新。具备同账号真实生活线索时：

- 已接受的 `search_videos`（包括延期至明天）与鱼鱼想做的同主题自发搜索重合：应出现 `同动作去重，未调用模型或执行`，或在同轮其他实际行为里显示暂缓数量；**不能**同时成功执行第二条自发搜索。
- 进行中的 BV 元数据探索与同 BV 一次性契机重合：一次性只读核实暂缓；已完成的观看/关注等不同动作不应因这个规则被隐藏。
- 若模型输出之后、平台调用之前才新增同主题责任：显示 `held-by-accepted-todo`；没有平台搜索回执也不能写成成功。
- 这几种去重都**不扣除额外 AI 额度**，也不改变已有待办的履约状态。只记录动作类别和暂缓计数；页面不显示由此产生的私人文本或 UID。

## 尚未完成，不能声称已经解决

- 只在**这一台自主调度器**的只读候选与执行前做契约协调；其他独立入口（主人手动运行待办、主人 DM 立即执行、社交主动发送、视频 Agent 内部工具循环）仍依赖各自原有幂等和回执保护。跨进程分布式锁与同时执行的全局去重未实现。
- 两个**不同承诺**虽然可能拥有相同动作身份，仍需分别履约或明确协商，不允许简单合并承诺，也没有在这一版自动复用另一任务的完成回执。
- 不通过关键词语义合并“爵士乐”“Jazz”等相关但不同的主题；仅做明确规范化后的完全相同目标。用户行为自然性／真正减少了多少重复请求还需真实 DSH 运行诊断。
- 真正统一的执行适配、持久跨进程动作租约、双域记忆撤回与自主社交外发权，还需要后续独立设计、测试和实机审计；不得为了尽快上线而跳过。
