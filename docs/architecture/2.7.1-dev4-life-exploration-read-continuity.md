## 实际报告与故障位置

用户在 **2026-11-06 16:53:40–16:53:46** 的手动唤醒调试号 `813a38e1` 中，模型有效选择 `begin_exploration`；候选 `cues=2`、`opportunities=0`，开始 `bili_video_info` 只读读取后，最终出现 `action-preflight-error`。这证明“模型无意愿”不是本轮失败的解释，也不证明视频真的已经观看。

一个可由离线代码复现的断点是：已完成 `inspect` 的**原生活契机**不会再出现在 `opportunities`，但同一个有来源的公开评论主观好奇仍可作为**独立自主探索候选**进入 `cues`。过去探索失败却调用 `recordOpportunityDecision(id,'error')` 修改原契机；该原契机已结算，写入会被拒绝，于是最初的平台读取错误被覆盖为笼统 `action-preflight-error`。用户实机具体的平台底层拒绝原因仍需新回执确定。

## 执行和回执时序

1. 规划器按账号收集当前真实候选：`opportunities` 和 `explorationCues()` **可代表同一个最初证据产生的两种不同选择**。两者不能共用“这次选择的失败结果”。
2. 模型只能从准确动作菜单中选 `begin_exploration`；执行器再次核对原始 BV/账号/状态，调用原受预约保护的只读 `bili_video_info`。
3. 只读执行结果写入脱敏 `read-result`：`verified-metadata` 或 `metadata-rate-limited`、`metadata-account-unavailable`、`metadata-read-busy` 等类别。B站 `-412` 分类为风控/限流，`-101` 为登录态不可用。
4. 若失败，向**原账号同一 v1 账本**的 `cueFailures` 记录独立失败，不覆盖原 `inspect/defer/...` 决定。每条线索最多重试 3 次，间隔约 15 分钟、1 小时、6 小时；三次后停止自行尝试。观察证据过期时不继续请求，失效/切号时不做跨账号迁移。
5. 若成功，只写可信的 `verified-metadata`，**不**写看完视频、听到歌曲、喜欢、关系成长或平台外发。原生活事件回执中可有 `video-metadata` 类别。
6. 成功后通过既有 `LifeAgentEvents.offer({kind:'exploration-ready'})` 给**下一轮**增加可选生活线索，下一轮模型可以选择 `use_capability` 启动原视频 Agent，也可以休息。原视频 Agent 的账号、额度、真实动作权限和视频回执独立生效；启动亦不等于观看完成。
7. 如果本地回执登记失败，`exploration-cue-receipt-failed` / `exploration-intent-receipt-failed` 与 `read-result` 同时显示，便于区分工具层和账本层。未知外部副作用仍依赖原冻结保护，绝不盲重发。

## 实际可验收入口与边界

- **触发**：管理中心「鱼鱼的生活 → 现在让鱼鱼考虑一次」；检查 `active` 模式、B站登录态、原限额和时间窗口。
- **调试**：进入「运行诊断 → 鱼鱼的决策全过程」查看每轮编号、`action-start`、`read-result`、`next-wake`、`event-settlement` 和最后诊断码。平台返回不保存原文；历史旧回执不能反推未保存的拒绝原因。
- **状态**：生活线索区可见“独立线索读取冷却/暂停”数量及分类，不显示 BV/UID。手动点击不绕过限额、账号与平台只读保护。
- **真正视频结果**：需后续可见 `use_capability` 委派及真实视频 Agent 回执；仅 `begin_exploration` 成功不新增“已观看”的真实生活时间线。
- **未实现**：Life Agent 不拥有真实私信、评论决策与发送权；没有真实 B站/Windows 的端到端证据前，不宣称视频已经播放或人生时间线已增长；人设/关系因果成长仍待验证。
