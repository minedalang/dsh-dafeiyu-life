# 2.8.3 llama.cpp 视觉独立技术验证（dev.89–90，非生产能力）

下述 dev.89 段落为历史 CLI 试验方案，dev.90 新增的管理面板见文末。

维护者批准先验证，不变更现有生产视觉 provider、模型默认值、安装流程、存储迁移或 Life 运行。生产仍使用原 Ollama / DSH；本地 Embedding 仍由 `embedding-runtime-manager.mjs` 管理。开放人格留 2.9.x。此实验不进入 npm 普通用户包、不访问 B站、不写任何真实记忆。

## 单一事实源及安全边界

`tools/llama-vision-probe.py`（仅源码维护者运行）以合成形状/颜色采样调用 `preview_vision.py` 的原 `_make_preview_boards`、`_call_local_ollama` 的请求预算/提示与响应验证，以及 `_analyze_local_storyboards` 原批次、补救、时刻绑定及局部回执。显式 Python callable 仅由实验入口提供，不是配置、MCP、Session 或网络可控制参数。以 llama.cpp OpenAI 兼容 `/v1/chat/completions` 接口传入原 JPEG data URL，归一化可见 `message.content`、finish reason、completion token；不把 reasoning 当成描述。服务故障继续使用原受限错误分类以复用停止条件（`ollama_*` 是历史分类名，在本报告中不代表 Ollama 被实际调用）。

显式给定可信本地二进制和配对权重，独立环回端口、随机临时 API key、无 shell、无代理/跳转、请求及响应沿用原限额；仅结束自己创建的子进程。不使用生产配置或账号、也不向原 Embedding 服务发送图像。共享二进制文件可以试验，但不共享模型进程或自动启动服务。进程清理在正常返回及可捕获异常中执行，强制杀死父进程/断电等异常仍须验收。日志只含合成图测试，但可能含本机路径或临时 API key，分享前检查。没有增加用于理解自然语言的规则；技术约束仅为本次获准的独立环回实验，不能作为新的生产授权规则。

## 本机验收与结论判定

见本批 TESTING.md。合成 12/24/48 格仅用于检查图像内容和空间定位的初步能力；`completedBoards`、`structurallyParsedCells` 只反映结构解析，不能代表语义正确。人工逐格核对 `ground-truth.json` 与 report 中原模型描述，记录色彩/形状、漏格、错位、臆测；继而使用合法、脱敏真实分镜做后续实机比较。对照 Ollama 保持相同采样、提示、思考关闭、批次及上下文条件（量化、模板、实际上下文可能不同，须记录）。2B 单图策略保持。记录冷启动和推理时间、CPU/GPU实际卸载、峰值内存/显存、失败后进程退出及并行 Embedding 是否仍能服务。GPU layers 仅请求参数，不是卸载证据。没有真实模型性能或资源数据前，不能宣布比 Ollama 更快或将内置后端设默认。

当前环境无 llama-server/视觉 GGUF/GPU，Hugging Face DNS 失败；实际验证限本机模拟 HTTP 线协议、原解析、子进程清理与原生产回归。所有原发布门禁继续开放。生产架构接线未变，Life 四图不需要新增实验节点。

## dev.90 · 双页面内置 Qwen CPU 试验

新手引导的视觉步骤和 AI 模型页移动同一 `models-vision-shell`，共享 `/llama-vision/status|install|verify|cancel`，原管理身份及同源操作边界；非 Agent 工具。模型来源仅允许固定的 [Qwen3.5 2B](https://huggingface.co/unsloth/Qwen3.5-2B-GGUF/tree/31ea6ac42dacbee2db8a2540a323377b3f652c75) 与 [Qwen3.5 4B](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF/tree/e87f176479d0855a907a41277aca2f8ee7a09523) Q4_K_M、各自 mmproj-F16。具体 Git LFS SHA-256 与字节数固定在 `llama-vision-experiment.mjs`。权重及投影约 1.95 / 3.41 GB，另需共享 Runtime；不提供 MiniCPM 安装，旧 Ollama 历史支持不变。复用原下载、断点和完整性核验，不接受浏览器提供 URL、路径或启动参数。

视觉资产在现有受管 `embedding-runtime/vision-models` 子目录，属于原 Embedding 大模型存储域而非业务记忆；共用 b12110 二进制，独立环回 CPU 进程、临时 key 和固定自检 PNG。任务相斥防止管理操作同时修改共享运行时；已运行 Embedding 继续保留，不承诺实际并行性能。模型测试前再次校验完整性；返回可见完整内容仅进入人工核对状态，重启后不保留回答。取消或结束清理自建进程，未确认退出时阻止新任务。共享 Runtime 删除后需重新安装；视觉权重单独保留。尚无单独视觉资源删除/迁移 UI；停机后如需释放空间，只在确认实际存储目录后删除对应视觉模型子目录，不删除 Embedding 权重。备份恢复和 V2 分盘实机仍待验证。

本轮只开放管理试验，不增加生产 provider、默认推荐、GPU 选项或 Life 观察回执。无需 Ollama，仍须联网下载并人工确认真实图像识别质量。CPU/GPU 真实模型、分镜、并行资源和异常退出尚未实机验收。固定资产及技术试验协议属于维护者批准范围，不新增自然语言规则或角色权限规则。Life 生产接线未变。

### dev.92 本地模型准备阶段

原 Embedding Runtime 管理器是共享运行时及两个独立模型任务的唯一状态源；安装任务按资源隔离，运行时 single-flight 与按消费者取消，视觉测试、删除及导入保持排他。管理中心与向导只投影真实状态，平台向导允许开始下载后继续可选配置，最终必需项回执不变。模型专项冷恢复仅接受完整固定 GGUF/mmproj 对，V2 路径不变。未新增生产视觉路由，原 Ollama/DSH、Life、权限、证据与记忆接线保持不变；内置 CPU 原图试验由维护者报告已通过，尚需正式接线及真实分镜验收。

## dev.93 · 受管内部视频调用

`withVisionRuntime` 使用原 Embedding Runtime 管理器维护排他、固定资产及 V2 解析；`withLlamaVisionRuntime` 管理临时 CPU 进程并确认退出。`callScopedNativeVision` 是可信宿主内部适配器，要求调用方已取得权限及当前账号/路由守卫；仅一致的安装脚本与单工具 MCP 子进程接收临时凭据，不写持久配置。Python `NativeVisionSession` 使用固定环回 OpenAI 兼容端点，复用原全局、局部及逐格核验、读取预约、证据和 provider 隔离缓存。缺租约、错模型、截断及仅思考内容拒绝，旧 Ollama 不自动替换。当前未接入用户侧选择、真实主人诊断、Life/Headless 选路；生产开关保持关闭。CPU 原图由维护者已验，真实分镜、资源协调、GPU、Windows 宿主仍待验。

## dev.94 · 内置视觉生产选路

内置 CPU 视觉正式可选（`independent_native`），正常宿主读走原 `call` 与 `callScopedNativeVision`；旧 Headless 本轮选中 BV 通过短期环回桥接调用同一宿主入口，复核账号、轮次、选择、路由及资源，关闭轮次即撤销。无租约不回退。使用原采样、分镜核验、记忆与意愿保护。首次引导只显示所选本地方式或远程稍后配置，切换不写配置，图片人工认可后明确启用。旧 Ollama/DSH 不自动迁移。GPU、真实 Windows/DSH 分镜、私信、连续推理与迁移后专项原图验收仍开放；迁移核验未通过不删除旧副本。releaseReady:false。
