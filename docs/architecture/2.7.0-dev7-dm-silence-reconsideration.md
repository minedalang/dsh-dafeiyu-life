## 修复对象

原 `dev.6` 只在初次不回复时收到 `defer`，或在回复中得到 `followUpMinutes`（值得补充的新内容）时预约。普通回复后对方持续沉默**没有其他入口**；轮询继续运行也不产生复议任务。因此“有人和鱼鱼聊天，停了一会儿它会主动再想想”并不完整成立。

`dev.7` 在现有模型输出中增加一个**完全可选**的私信字段组合：

- `idleReconsiderMinutes`：5–360 分钟，并受现有主人配置的最短/最长延期约束。
- `idleReconsiderReason`：`open-conversation`（确实未结束的会话）或 `explicit-check-back`（明确约定稍后再联系）。
- 仅 `channel=dm && trigger=incoming && action=reply` 能提出；与 `followUpMinutes` 互斥。`scheduled` 轮次不能再预约自己，防止无休止的追问链。
- 模型不选择此字段时照旧直接结束本轮，不暗中对每位聊天者设置定时器。

到期后重新读取私信；如果有新来信，则旧预约取消，新消息进入正常新一轮。如果模型选择 `skip/close`，或发送资格、已撤回边界、配额、回执不满足，则不发送。

## 只读复核暂时失败与幂等边界

原本到期的定向只读收件箱一旦抛错，就立即将单次意图 `cancelled`；短暂网络/平台读取限额会造成“明明预约了却永远不再考虑”。现在只在**还没有调用远端写入**时，通过 `retryPreflight` 最多安全延期两次（每次五分钟）。满两次仍失败则取消；服务崩溃留下 `claimed` 的条目仍不重放；实际发送失败或回执不确定**绝不进入安全延期**，保持原有停止策略。

## 诊断与隐私

`dm-autoreply.status()` 在当前已确认账号下读取续聊账本的 `dm` 渠道统计（scheduled/claimed/sent/skipped/cancelled/uncertain/expired），显示最早待唤醒时刻和最近聚合结果；没有其他渠道的数值，也不会返回私信内容、对方 UID、线程标识、情绪或模型提示。未登录/账本异常时显示“不可读”，不得伪装为没有任务。管理页位于「后台私信 → 后台私信状态」，与原轮询时间并列。

## 2.7.0/2.7.1 范围

本轮只修复 P6-B 的“现有私信对话内、正常回复后的沉默”场景。未发生真实入站消息的主动找人、关系变深主动关注、跨平台生活行动意向、旧推荐体系重构均属于 **`2.7.1` 或后续阶段**；不会在 2.7.0 封版中悄悄加入。仍需要 Windows/真实 B站端到端观察至少一次**已预约 → 到期 → 自主选择 → 回执**，确认 B站频率限制与账号切换表现。
