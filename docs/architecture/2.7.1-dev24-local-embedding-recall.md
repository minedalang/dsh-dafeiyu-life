# DSH 2.7.1-dev.24 · 本地 Embedding 语义回忆

**开发预览 · 未发布**

## 1. 目标与不做什么

dev.24 在 dev.23 的「模型先判断是否回忆，并给出专用检索词」契约上，增加一个**可选、本地运行的语义候选排序器**，解决“AI 已经提供了合适查询词，但记忆只靠字面匹配仍可能漏掉同义表达”的问题。

它不是新的记忆系统，也不是新的事实源：

- `LifeMemoryGateway` 继续管理可衰减经历、UID/场景访问和遗忘状态。
- `long-term-memory` 继续管理长期事实；公开评论成功回执仍由 `recent-comments.mjs` 唯一账本负责。
- `memoryRetriever` 负责召回编排；Embedding 只根据当前已授权候选的文本生成向量并排序。
- 模型返回的只有候选 ID 与相似度。使用前必须重新从实时账本按 ID 取回并核验，不能直接把向量索引当作可读记忆。
- 现有词法检索保留。模型未安装、索引正在建立、运行时退出或查询失败时，回退原有本地词法召回。

本轮**没有**完成 dev.23 的所有兼容路径收口：传统 `full` 上下文模式、部分专业 Agent 的预装配提示仍保留。只对实际经过 `memoryRetriever` / `SocialContextAssembler` 的入口增加本地语义排序，不宣称所有 Agent 都已统一。

| 推理方式 | `llama-server --embedding --pooling last`，本机 CPU |

查询采用 Qwen3 的 instruction-aware 格式：

```text
Instruct: Given a user query, retrieve relevant personal memories, past experiences, and stable facts that answer the query.
Query:<模型提供的检索词>
```

记忆文档不附加查询指令。模型输出 1024 维向量，使用余弦相似度排序；Embedding 路径不额外调用聊天模型做二次重排。

## 3. 安装与生命周期

默认配置 `mainSessionMemoryEmbeddingEnabled=false`。插件启动时**不会**自动下载模型；只有用户在管理中心点击「启用并下载模型」才启动安装流程。

1. 管理中心请求本机 Runtime Manager，按当前 `platform/arch` 选择固定资产。
2. Runtime Manager 下载并校验 llama.cpp 压缩包，先检查压缩包路径，再解压到私有状态目录。
3. 下载或导入固定 revision 的 GGUF 模型，严格校验文件大小和 SHA-256；网络下载支持 `.part` 断点续传。
4. 启动 `llama-server`：只绑定 `127.0.0.1`、随机端口、随机 API Key、关闭 Web UI；不开放局域网监听。
5. 通过 `/health` 和一条真实 Embedding 自检确认模型已加载。
6. 后台同步当前记忆向量索引。索引未完成期间，所有入口继续使用词法召回。

状态目录位于 `$DSH_HOME/bili-duty/` 下：

- `embedding-runtime/`：GGUF 模型、llama.cpp Runtime、安装清单和下载临时文件。
- `embedding-memory-index/`：`manifest.json` 与 `vectors-<generation>.f32`。

下载式 Runtime 和随安装包附带的 Runtime 都必须提供含 `platform`、`version`、`sha256`、`binary` 的安装清单，重启时校验平台和清单后才允许启动；模型导入先等待现有推理进程完全停止，校验失败不留临时模型。向量索引的清除操作与同步、重建、更新、按 ID 移除使用同一队列，避免删除后被正在进行的重建重新写入。

管理中心支持：

- 启用并下载、取消下载（保留可续传部分文件）。
- 暂停语义回忆：停止本地进程，但保留模型和向量索引。
- 重建索引：重新向量化当前可访问、仍有效的记忆。
- 导入已下载的官方 GGUF：再次校验大小和 SHA-256；导入后仍需下载对应平台的 llama.cpp Runtime。
- 删除模型与向量索引：清除 Runtime、模型和向量文件，但不删除长期记忆、经历、关系、待办或 B站数据。

## 4. 统一记忆召回接线

| 入口 | dev.24 接线 | 允许的候选范围 |
|---|---|---|
| 主 Session / 手动回忆 | `memoryRetriever.retrieve()` | 当前有效长期记忆 + `main-session/owner` 可访问的可衰减经历 |
| 主人私信 | `ownerSearchAsync()`、`localContextAsync()` | 主人授权的长期记忆、主人可读经历与原有公开评论回执工具 |
| 好友/陌生人私信 | `socialContextAsync()` | 公开安全记忆、当前 UID 可读的公开互动/公开视频经历 |
| 好友私信私有补充 | `privateContextAsync()` | 仅 `bili-dm`、当前角色和当前 UID 可访问的私密经历/私有洞察 |
| 普通用户评论 | `socialContextAsync()` | 公开安全记忆、当前 UID 的公开互动；不读取私信或主人私人记忆 |
| 主人公开评论历史 | 原 `public_comments` / `recent-comments.mjs` | 当前账号已确认的公开评论成功回执；仍是独立只读账本，不并入私人记忆向量库 |

检索步骤：

1. Agent 按 dev.23 契约决定是否回忆，并提供最多三组受限查询词。
2. 原有入口先按账号、角色、UID、渠道、公开/私有域、当前衰减阶段与遗忘状态构造候选集合。
3. `EmbeddingMemoryIndex` 只对候选 ID 的文本计算/读取向量，按余弦相似度返回 ID 与分数。
4. `memoryRetriever` 再从实时 `LifeMemoryGateway` / 长期记忆读取器按 ID 复核；异步期间被删除、遗忘、切号或权限变化的记录不会因向量命中复活。
5. 将可信结果交还原 Agent 继续回答或决策。Embedding 不授予评论、私信、关注、点赞或其他外发权限。

## 5. 索引内容与隐私边界

- 向量索引只保存记录 ID、规范化文本 SHA-256 和 1024 维 Float32 向量；不保存原文、查询词、私信正文或模型提示词。
- 原文仅通过本机进程内存传给绑定在 `127.0.0.1` 的 llama-server；不调用云端 Embedding API。模型和 Runtime 下载分别来自固定的 Hugging Face / GitHub HTTPS 资产，并在本地校验摘要。
- 索引目录权限尽量限制为当前用户（目录 `0700`、文件 `0600`）。向量属于由记忆导出的数据，仍按本机私有状态保护，不应分享索引文件。
- Embedding 不可决定可访问范围。公开评论不会把主人私人记忆放入候选；好友私信的私有候选必须带当前 UID；陌生人评论不读取私信；主人公开评论的成功回执账本保持独立。
- 记忆进入 `forgotten` 或从可衰减活动窗口淘汰时，Life Memory Gateway 通知索引移除相应 episode 向量；长期记忆被删除时同步移除其向量。启动同步/手动重建也会移除当前 corpus 已不存在的索引 ID。
- 任何模型输出都不能直接变成事实。相似度高只代表“值得检查”，不代表用户说过、鱼鱼做过、视频已看/已听或平台已发送。

## 6. 配置、API 与代码归属

- 配置：`mainSessionMemoryEmbeddingEnabled`，默认 `false`；安装动作明确置为 `true`，暂停/删除置为 `false`。
- Runtime：`lib/embedding-runtime-manager.mjs`。
- 本地向量索引：`lib/embedding-memory-index.mjs`。
- 统一召回：`lib/memory-retriever.mjs`。
- 权限与经历事实：`lib/life-memory-gateway.mjs`、`lib/life-private-policy.mjs`。
- 跨社交入口：`lib/social-context-assembler.mjs`。
- 管理界面：`lib/management-console.html`、`lib/management-console.js`。
- 管理 API：`GET /api/bili-duty/embedding/status`；同源 POST `install/disable/rebuild/cancel/delete/import-model`。

Runtime 管理 API 的变更操作要求管理中心同源 Origin，并在首次安装门禁完成后开放。Runtime 本身没有公网监听；下载和推理都由 DSH 插件托管。

## 7. 测试与未验收项

本轮新增自动化覆盖：固定模型/Runtime 资产清单、归档路径穿越拒绝、向量索引持久化与增量同步、索引不保存原文、维度校验、记忆删除与遗忘后的向量清理、主 Session/主人私信/普通社交/好友私信的 UID 与权限隔离、异步召回后二次核验。

本轮离线全仓结果：**Node 1992/1992 通过；Python 223 项执行（222 通过、1 跳过）；插件自检与 npm pack 预检查通过**。新增专项共 17/17 通过（含于 Node 全仓结果），包含运行时状态目录重启识别、非法模型导入清理、后台重建与清除竞态。详细记录见本轮交付测试报告。

**仍未验收：**真实下载 639 MB 模型、真实 llama-server 启动和 Embedding 推理质量；Windows DSH Desktop、macOS、Ubuntu 实机性能；真实 B站账号；跨日长期运行和完整 Life 成长因果。CPU 性能、内存占用和不同机器上的首次索引时间必须由用户现场观察。`releaseReady` 继续为 `false`，dev.24 不是 RC，不应正式发布。
