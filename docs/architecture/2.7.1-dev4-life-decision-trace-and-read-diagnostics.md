# Life Agent 决策全过程诊断与平台只读拒绝分类（当前 dev.4 增量）

## 统一层归属门禁

| 项 | 当前生产事实 |
| --- | --- |
| 触发入口 | 普通一分轮询；「鱼鱼的记忆 → 鱼鱼的生活 → 现在让鱼鱼考虑一次」；既有只读待办与契机 |
| 唯一生活决策者 | `lib/autonomous-planner.mjs`（保留原额度、排他租约、生活事件账本） |
| 唯一事件与事实源 | `life-agent-events.mjs`、`life-opportunities.mjs`、`owner-todos.mjs`、既有真实工具回执；新 Trace **不是事实源** |
| 新增的诊断生命周期 | `lib/life-decision-trace.mjs` 只记录本轮调用步骤；`read-action-diagnostics.mjs` 只归类底层工具拒绝 |
| 权限与隐私 | 按当前可信 B站账号伪名隔离，保留最近 7 天最多 60 轮；不保存原始 UID、BV、消息原文、模型提示/答案或工具响应。旧记录不反向导入 |
| 受影响通路 | Life 自动/手动考虑；Node JS 共享只读预约；账号级后台平台只读预算；管理中心运行诊断 |
| 明确**未接管** | 原私信、评论社交唯一决策者仍负责线上回复与外发，Life 只有影子观察；没有修改其发送权限、去重或授权 |

## 本次排查到的具体逻辑

之前 `tool-rejected` 并不是 `ReadActionHeldError`。它意味着共享 JS 门禁取得了 MCP 返回，但返回中 `ok:false` 或 `success:false`；此前没有记录失败类别。Python 工具也可能以 `{"error":"..."}` 形式返回错误字符串。本阶段只记录脱敏的 `account-auth`、`platform-rate-limit`、`platform-permission`、`platform-timeout`、`not-found`、`invalid-argument` 与 `platform-rejected-other`，并按动作／来源／类别汇总重复回执。确切是哪一种，必须看**升级之后的新记录**；旧回执没有保留错误信息，无法补推根因。

Life Agent 过去采用一个布尔 `actionAttempted` 来把所有后续异常升级为未知完成结果，导致只读元数据工具返回后、仅因本地记录写入失败也可能冻结手动事件。现在收紧保护：只读资料核验与本地记录更新异常按 `action-preflight-error` 进入有界技术重试；真正进入可产生副作用的专业能力后，若回执不确定仍为 `action-outcome-unknown`，**没有**自动重做或写入假回执。只读待办若工具返回明确失败，再更新待办记录异常，则不把失败说成平台可能发送成功；成功回执后本地状态保存失败仍保守人工核验。

## 可操作的端到端验收

1. 更新插件并完全重启 DSH Desktop；管理中心按 Ctrl+F5 刷新；确保当前 B站账号已核验、Life 模式已保存且非暂停。
2. 在「鱼鱼的生活」点击「现在让鱼鱼考虑一次」。结果显示一个短调试号；点击“查看本轮决策全过程与错误回执”进入「运行诊断 → 鱼鱼的决策全过程」。查看候选筛选、额度、模型调用、合法决策、执行前门禁、工具开始、动作结果、事件账本结算、最终结果。没有模型调用时不会虚构模型步骤。该页面**不**再次调用模型或 B站。
3. 同一页「平台读取预约与中断核查」刷新，查看 `bili_video_info` / `bili_received_replies` 当前新回执的具体拒绝类别及重复次数。`tool-rejected` 不代表锁中断，不要因此点击解除。真正残留执行锁只出现在“正在执行/待核查”的单独列表，符合原 30 分钟、进程已结束及人工确认条件才可解除。
4. 若出现平台 `account-auth`，先检查登录态；若是 `platform-rate-limit`，等后台冷却结束，不要连续强制重试。具体失败无法分类时保存匿名诊断而不是公开原始私信和 Cookie。
5. 在 Windows 原版 `run-tests.bat` 和真实 B站下分别验收。离线 mock 通过只能证明调用契约，**不能**证明平台实际回复或记忆成长。

## 数据与成本

- 诊断目录：`$DSH_HOME/bili-duty/life-decision-traces/<account-hash>/`。记录受 7 天、60 轮、每轮 48 个步骤及 30 KB 单文件上限约束。不会迁移旧 `autonomous-planner.json`；模型原文仍不进入这个诊断目录。
- 自动一分轮询中被 `cooldown`、`outside-hours`、`nothing-to-do`、暂停或额度拦截的无价值空轮不占用诊断历史；手动被拦截的尝试会显示阻止代码。实际模型调用仍占原每日额度，诊断读取本身不消耗额度。
- 平台只读回执保留原来的账号作用域和最多 240 份文件上限；最近 30 条用于分类汇总。旧 `tool-rejected` 没有保存原因，升级后不会伪造原因。
- 旧“Dev3 运行本地模拟验收” HTTP 按钮/入口退役；对应单元测试迁移至 `test/helpers`，不会被 npm 打包成生产 lib。旧历史临时补丁、无意义文件与不参与生产运行的旧离线测试脚本不进入发布清单（部分保留仓库内以便开发回归）。账号恢复、原安全锁、外发幂等及停机人工复核工具保留。

## 未覆盖与风险

- “完整决策流程”是**每一步因果调用、合规选择和回执的脱敏记录**，而非逐字展示原始推理链、私信原文、完整提示词或模型内部思维；既保护隐私也避免误把模型理由当事实。
- Node 的共享门禁不保证覆盖 Python Headless 直接在工具内部调用的所有 B站请求；Python 独立读取回执需继续查看其既有日志/门禁。它不能用来判定真实平台是否可达。
- 社交 Life Agent 未正式接管，不进行授权扩展或自动外发。发布前仍要检查 Windows、Python、账号切换、平台实际返回与历史恢复。
