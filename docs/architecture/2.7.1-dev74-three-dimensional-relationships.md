## 三维具体语义

- **自然熟悉度（Relationship Familiarity）**：自然发展阶段 `new → known → familiar → friend`，综合现有已验证交往次数、双向和活跃日期，长期不联系逐渐衰减。它是联系人的认知辅助，不是现实亲密程度；不受白名单数字加成。
- **渠道亲密度（Channel Familiarity）**：`public`、`private` 分别为 `none`、`encountered` 或 `ongoing`；每个渠道单独统计，评论区双向很多次也不会增长私人渠道证据。
- **私人联系开放程度（DM Openness）**：`unknown` 表示只有旧历史、当前账号缺乏渠道可核验证据；`not_established` 表示证据不足；`established` 表示满足跨日双向 DM 的最低资格；`restricted` 表示主人/对方拒联优先。资格从不自行打开外发。

本版对“对方明确邀请主动私信”的自然语言表达**不作自动抽取授权**：需要可靠核实邀请对象、范围及撤销语义，避免把评论或模型对文本的猜测直接提升为写权限。只有确有持续双向私信的当前账号关系才进入自动候选。这是有意的谨慎边界，不能将其宣传为支持所有邀请情形。

## 原关系账本迁移策略

- `friend-relationship-observations.json` 和现有 `social-relationships/relationships.sqlite3` 原样保留；老关系分数仍能作为历史认识参考，但旧历史可能混有多个账号/渠道，不能产生 DM 资格。
- 当前账户新 `relationship-channels/evidence.sqlite3` 从新经核验事件开始累积渠道事实；原有 UID 和旧互动不被后台悄悄重算成新的双向 DM 习惯。
- 当前账号受凭据绑定保护；切换账号须按既有账户绑定机制重新运行，无法确认当前账号时返回无候选，不能读取之前账号的私人资格。
- 「清除关系」会同时清理自然索引、对应当前账号的渠道摘要和可清除的肖像证据；已发送消息的原安全事务账本不能因清除关系而删除。

## 使用者能看到什么

管理中心「逐渐熟悉的人」展开某个人，可以看到自然熟悉度、评论区亲密度、私信亲密度与主动私信开放程度（原因单独说明），同时能看到与白名单权限的区分；「自主联系」新增需明确确认的自然私人关系发送授权。

一个可信新 DM 只形成互动证据；达成资格并获得主人授权后，Life 仍可以选择 `review_friend` 或 `skip` 而非发送。无授权、拒联、模型失败、平台写入不确定均不能显示为已发送。

## 当前明确的边界与实机验收

1. 没有 Windows/真实平台或 DSH UI 端到端验证。对两位已授权自然私信好友做双账号、跨日核验、注销/切号/撤权测试，严禁测试脚本真实外发。
2. 不从私信或评论原文自动识别“邀请你私信我”，未来若加入，须通过可信来源核验、对方意愿撤销、独立授权和反打扰机制。
3. 历史无账号/无渠道归属的记录必须渐进积累新证据，不迁移开放资格；原旧友关系展示作为历史辅助，不是第二套活跃发送决策算法。
4. `social-relationship-index.mjs` 的旧每日防刷上限、阶段估计仍是粗略指标，不能当作现实情感亲疏；单一用户短时频繁发消息不应快速刷高熟悉度。
5. 先前 dev.70 尚未完成的历史视频入选后的**跨轮主评论机会恢复**未在本次三维关系补丁中处理；不是已解决状态。
