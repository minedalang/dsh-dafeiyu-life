# 2.6.2 dev · @ 原评论查证与正文恢复

## 用户真实问题

2026-11-03 16:10 的 `Zoroxs` @ 显示 `mention_only_or_text_missing`，但用户确认原评论写了话，且视频可以取得字幕。该旧标签不足以判断对方是否只发了 `@`。视频字幕用于视频内容理解，不能用来证明具体某条 @ 评论正文、作者或楼层。

## 修复的调用链

1. 由 `bili_received_at_and_likes` 读取平台通知（不把 AI 生成文本当来源），`normalizeAtNotifications` 从 `source_id`、`subject_id`、官方网页链接或官方 `bilibili://video/` 跳转定位视频和评论。绝不从评论用户文字或任意外域 URL 猜 BV。
2. 如果 `source_content` 缺失，或紧挨 `@昵称` 的真实文字被清洗到仅剩标点，**保留通知进入后续只读核验**，不立即称为只有 @，也不直接让空正文进入模型。
3. 在已开启的回复权限、24 小时时窗、邀请名单范围内，读取对应 `bili_comment_thread`。对**当前 BV、原评论 rpid、真实作者 UID**三者做精确比对；验证通过才用于互动 Agent 的本轮文本和对话内容。含连续 @ 昵称且边界不明确时保留核验过的原文引述，不把昵称内容当情绪事实。
4. 作者/评论 ID 不匹配是硬拒绝；网络不稳定或原评论尚未找到则在有效时窗内退避重试，不提前冒充“AI 自主不回复”。界面展示原因及下次重试时间。原视频 ID 缺失时无法安全定位，该通知仍拒绝发送；可在诊断看到原文存在状态与缺少定位的具体说明。
5. @ 解析器升级到第 3 版时，先把此前未能识别的旧通知标记为升级基线；它们不会因为重新被识别就在同一轮自动公开回复。
6. 只有成功通过既有权限、额度、意愿和真实发送回执核验后才可能公开评论。历史通知不自动重放、旧发送结果不重试，未开启的自动回复权限不改变。

## 仍需实机验收

本地没有账号的 B站原始通知或平台 Cookie，不能证明 Zoroxs 的 `subject_id`、原评论 `source_id` 和通知 URI 在真实接口里实际如何返回。若通知缺少全部视频定位，即使视频字幕可用，也仍须先获得正确 BV/AID 才能查询原评论；不得凭昵称/主题自行回复其他地方。

实机验收：使用当前账号再收一条新 @（原评论有文字），核对诊断的原始发送时间、识别状态、评论链接、原文恢复状态、AI 决定/失败及真实回执。旧通知的显示理由不会因升级自动变成已回复。
