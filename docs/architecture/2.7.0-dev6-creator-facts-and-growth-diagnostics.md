### 现行状态语义

- `followCurrent`: `following | not-following | restricted-or-unknown | unknown`；只有当前 B站单目标查询成功才是当前态，不保证永久有效。`followHistory` 是操作回执的时间事实，不能推导当前关系；`collectCurrent` 仍为 `not-verified`，因为本轮**没有**实现当前收藏夹成员资格的可靠核验。旧 `collect` 成功回执只能表述“曾收藏过”。
- `creator_encounters` 只在显式入选且 `agentFollowEnabled=true` 的模型主动调用时写入；不因仅看过视频或旧推荐状态推导“喜欢”。只以当前账号 UID 计数，不跨账号混合。单独的只读查询不改变遇见次数。
- `lifeFactsFromCreatorSnapshot` 从可信工具响应提取**受限、短期**的事实视图；平台账号与本地当前绑定账号必须完全一致。成功跟随、取关、收藏的历史事实不等于“永久记忆”，当前状态每次需要新读。不是主 Session 所有回合自动全文注入，只有主动调用工具的回合可用；后续全渠道事实自动装配需单独设计。
- `bili_follow_creator` 仍由鱼鱼自主判断而非达到社交熟悉度阈值强制执行；`bili_unfollow_creator` 仍只对本插件自关注 7 天以上且当前平台确实关注的 UP 提供严格受限操作，不启用定期取关。收藏与关注的授权保持分开。

## 本轮不处理（下一阶段计划）

1. **旧视频推荐与判重重构**：评估旧 `值得看/不值得看` 的主人导向推荐是否应拆离/移除；本轮不迁移旧表、不改掉推荐入口。现有点赞/收藏等旧判断仍可能依赖这些历史状态；后续设计独立的“鱼鱼自主观看/喜欢”意图证据，再决定改动范围。
2. **真正的当前收藏状态**：需要按明确的 BV + 当前账户 + 收藏夹权限可靠验证，未实现前仅呈现已确认历史回执，不能说现在仍收藏。
3. 主 Session 的 `400 prompt_blocked`：服务侧 moderation 拒绝，缺少宿主请求日志与原始调用路径不能归咎为本插件；本轮只给诊断口径，不绕过服务安全策略或暴露隐藏提示。
4. 主 Session 自己与鱼鱼对话不应无凭据计入“B站已核验互动”；如未来要统计主人对话关系，需要独立身份归属和隐私设计，不能直接用 B站 UID 填充。
5. 当前未执行 Windows DSH Desktop / 真实 B站账号 E2E；只做模拟、静态和本地离线回归。

## 失败与迁移边界

- SQLite 表以 `CREATE TABLE IF NOT EXISTS` 在首次有效相遇时懒创建，不触动现有 `actions` / `creator_relations` / `creator_relation_attempts`；新表最近 90 天保留有效相遇，历史关注/收藏原账本不自动删除。数据库文件为符号链接时拒绝访问。
- 平台原视频 `owner.mid` 无效、账号未登录/切换、API 失败、目标关系属性非明确未关注、来源未入选，都不外发关注。状态读取失败时返回 `unknown`，不能回退成未关注，更不能推断取关。
- `AGENTS.md` 的人格单源、出站授权及实体回执规则未变；本轮不增加新的业务统一层，只扩展既有 `VerifiedLifeFacts` 事实种类，按 dev.5 平台身份与已存在数据域隔离。
