# 2.8.3-dev.26 · 分盘完整冷备份、安全修复与隔离灾难救援（候选）

## 第四批：隔离救援后的差异与保护记录审查（只读）

```powershell
node .\tools\dev4-cold-state-backup.mjs plan-rescue-merge --to 'F:\dafeiyu-disaster-rescue'
```

仅读取已经完整核验的救援资料，不读取实际原盘、不写运行目录或资料包。按历史核心布局确定实际记忆域，忽略迁移前核心中的过时记忆副本。报告 `comparisons` 按核心与 Life 分区统计文件和目录的精确一致、差异、类型或名称冲突、仅历史、仅候选以及无候选可比；缺少候选时不会把历史文件误认成已删除。比较依据是清单路径、类型、字节数、哈希和权限位，不以文件时间选择所谓最新版。

`deepRevocations` 检查现役记忆域内两份深层撤销文件的版本、ID 及容量限制，只统计格式合法的已知撤销 ID 并集，不输出 ID。缺少文件、来源不可用、损坏分别显示 `not-recorded` / `source-unavailable` / `invalid`；即便两份合法或相同，`complete:false` 仍明确表示不能证明灾难前所有遗忘都已保全。并集超限不能丢弃旧撤销记录。报告不包含文件名、对象哈希、凭据、记忆正文或角色/账号 ID；所有结果只供离线审查，SHA-256 不提供防恶意伪造的签名。`freshnessProven:false`、`mergeAllowed:false`、`activationAllowed:false` 永远保持；不提供自动合并入口。后续需要单独完成浅层/长期删除、授权、未知外发及任务状态的单调保护契约，才能讨论可运行恢复。

## 第三批：核心 / Life 丢盘后的隔离救援（不激活）

当核心目录、记忆目录丢失、或旧盘损坏，首先抢救能够读取的数据，不把旧快照直接写入运行中的角色。冷快照只能证明拍摄当时的内容，**无法证明快照之后没有遗忘、权限撤回、待办完成或未知外发**。现有深层撤销并集、衰减阶段比较及专用备份各自有保护，但不是覆盖所有业务状态的单调合并协议；长期记忆删除与清空也没有跨盘持久的完整凭据。因此本批不会宣称完成历史业务激活恢复。

先退出 DSH/Headless、Node、Python 等相关进程，原磁盘和快照保持原样，选一个不存在的新隔离目录（父目录须存在、建议独立磁盘）。

```powershell
$save = 'E:\dafeiyu-cold-20261126'
$rescue = 'F:\dafeiyu-disaster-rescue'
node .\tools\dev4-cold-state-backup.mjs plan-disaster-rescue --snapshot "$save" --to "$rescue"
node .\tools\dev4-cold-state-backup.mjs rescue-disaster --snapshot "$save" --to "$rescue" --stopped --confirm RESCUE_DSH_OFFLINE_ONLY
node .\tools\dev4-cold-state-backup.mjs verify-rescue --to "$rescue"
```

预检校验源完整快照，并列出历史核心、外置 Life（如有）的原路径状态：`missing` 原位置缺失，`identity-or-route-mismatch` 不能核验身份/路由，`unreadable` 不能安全读取，`same-identity-unconfirmed-freshness` 身份相符但新鲜度未证明；旧单根 V1 格式没有记录原路径，报告 `original-path-not-recorded`，只保留历史资料。不可读或身份不同的原分区不会被混入。没有读取单个损坏文件的跳过模式：原候选扫描失败就整分区不纳入候选，原盘保留给进一步专业救援。

救援目录由 `offline-rescue-only.json` 和 `objects/` 组成。历史与可读原盘候选分开列出路径、字节数、权限位与 SHA-256，相同内容仅保存一份；原目录结构不展开，不执行其中的任何程序。新目录不与快照或捕获原分区重叠，不覆盖已有目录；预估空间，停机复制、逐对象核验、复核来源后才发布。独立验证根据捕获核心配置检查 Life 分区是否齐全、身份和所有对象；不依赖原盘仍挂载。SHA-256 不是数字签名，无法证明人为重写的整套资料真实性。核心与 Life 全树中原本存在的缓存也随资料保存；独立的模型/Python/影音分区不重复抢救，原完整快照仍保留，V2 模型恢复另走既有流程。

输出 `activationAllowed:false`、`historyMergeRequired:true` 是明确限制；不能将隔离救援目录改名为 bili-duty 启动，宿主会拒绝。不要手动展开对象或改名覆盖运行目录，也不要在原核心已丢失时贸然重新启动 DSH 创建新身份。旧 `restore` 若原业务根不存在也拒绝直接历史激活，可用上述救援保全 V1 快照。已有根的旧格式恢复兼容路径仍在，不等于全部未知业务账本已经得到完整单调保护。救援包和原完整快照均含敏感私有数据、未内置加密；不要上传。Windows 真盘故障、断电持久性、访问控制及正式历史合并仍是后续门禁。



## 第二批：模型盘损坏/更换（保留当前业务）

同一角色、同一模型路由代际及同一核心引导下，核心和现役 Life 分区仍存在并通过身份核验，即使 V2 原模型盘不在，也可使用以前完整快照中的已知 Whisper 模型文件与 Embedding GGUF，在另一个尚不存在的目录恢复。新位置不得与任何当前或捕获的分区、旧引导源、备份目录重叠，父目录须存在；原盘有数据时保持不动。旧快照的核心/业务文件只用于身份与完整性验证，**不写回**；未完成下载、HF token、未知文件及运行时均不导入。快照完整性不等同于实际模型可运行，模型需要重启并完成原有健康验证。

完全退出 DSH/Headless 与相关进程后执行（路径仅示例）：

```powershell
$state = 'C:\Users\YOURNAME\.dsh\bili-duty'
$save = 'E:\dafeiyu-cold-20261126'
$newModel = 'F:\dafeiyu-models-recovered'
node .\tools\dev4-cold-state-backup.mjs plan-model-recovery --root "$state" --snapshot "$save" --to "$newModel"
node .\tools\dev4-cold-state-backup.mjs recover-models --root "$state" --snapshot "$save" --to "$newModel" --stopped --confirm RECOVER_DSH_MODELS_ONLY
```

预检只读，输出可恢复文件数、字节数、旧位置是否存在及未导入文件数量（含重建的身份标记）。恢复写入原核心目录外的同一事务冻结文件，全部模型校验后发布新目录，原子替换核心 V2 路由文件并复用实际 `largeDataStatus` / `storageLayoutStatus`；不写原账号权限、记忆、运行账本，也不清理旧盘。若中断，仍使用下文 `rollback-full`：核对当前路由仅为旧或本次新路由，恢复原指针，保留新目录或暂存。原盘若已经丢失，回退不等于 DSH 可启动，应重新选择新目标完成恢复；不得删除恢复冻结或手工改指针来绕过验证。原盘已不存在时不会自动生成空数据目录。恢复成功后请立即生成一份新全分区快照，旧快照的存储代际不再与当前路由匹配。

本批不是核心或 Life 整盘损失恢复，也不是 V1 业务盘换盘。对后续历史业务恢复，应使用现有记忆/遗忘及授权事实源的严格合并契约，无法证明保护记录完整时保持拒绝。未实现备份加密或完整 GUI 向导。

## 首批功能与仍适用的限制

本轮是开发候选，**不是 2.8.3 正式发布，也不是历史业务灾难恢复完成**。dev.25 引导、常用导航、四场景补看、深浅记忆和在线便携备份保留。备份主体是本机明确停机的维护者，事实源为 `storageLocationStatus`、`storageLayoutStatus`、`largeDataStatus`；不增加 Life 任务、模型、HTTP 写入、权限或第二记忆库。

- 完整快照包含实际生效核心运行目录和 V1/V2 外置分区所有普通文件、目录及现役身份标记；共享分区只保存一次。已退休 V1 模型不再依赖旧盘；核心目录内部遗留副本仍作为原始文件保存，不能恢复为现役路由。旧核心迁移的引导指针对象也保存在清单中，但不会自动改写当前 DSH 引导。
- 所有快照均未加密，包含凭据、私密记忆、数据库及未知业务数据；不要上传、发送给开发者或放入项目仓库。建议使用受 ACL/BitLocker 保护的独立物理磁盘。SHA-256 用于一致性，不是防恶意重写的签名。
- 模型缓存中特定相对 HF 文件链接在目标仍为同模型普通 blob 时物化为普通文件；不跟随目录链接、绝对链接或其他链接。遇到未知文件类型、大小写冲突或不安全路径、缺失现役盘、超出 300000 条文件/目录上限，拒绝生成完整快照，不跳过。硬链接关系、ACL/所有者、时间戳、整个 DSH 宿主配置及插件外的 Ollama/自定义模型库不包含在本快照保证中。Windows 实机的链接和权限行为仍需验收。
- 恢复只支持同一生效根、相同分区身份/拓扑、所有现役盘仍可读。**不可重建业务文件（含记忆、遗忘保护、授权、外发及未知账本）须与快照一致。** 允许修复已知 HF 模型文件、Embedding GGUF 和 Python 包缓存，不回退现有记忆与权限。正常运行一段时间后，历史快照往往会因此拒绝覆盖。这不是完整的历史回退能力。旧单根格式的已有关键保护也加强，但不是新分盘事务协议。
- 后续必须设计及验收跨版本单调保护合并、整盘损失/换盘、独立恢复和原数据不可用时的安全准入；不因候选通过定向测试而跳过。这一限制是为了不复活已遗忘经历或未知外发，不代表这些需求取消。

## 实际操作（维护者）

从管理中心核对**实际生效核心运行区**路径。退出 DSH Desktop、Headless 及相关 Node/Python/模型进程；若进程检查拒绝，请关闭相关程序，不要绕过。使用 Node 22+、本机绝对路径。示例中的盘符只是占位：

```powershell
$state = 'C:\Users\YOURNAME\.dsh\bili-duty'
$save = 'E:\dafeiyu-cold-20261126'
node .\tools\dev4-cold-state-backup.mjs plan-full --root "$state"
node .\tools\dev4-cold-state-backup.mjs backup-full --root "$state" --to "$save" --stopped
node .\tools\dev4-cold-state-backup.mjs verify-full --snapshot "$save"
```

`plan-full` 只解析现役分区身份，不写入、不测容量；`backup-full` 二次停机检查、逐文件哈希及两次来源复核，分区身份和清单独立核验后才发布新目录。目标须不存在，不得与任一现役分区重叠。空间预估包含所有物化数据和目录开销，恢复需要每个盘可保留旧目录并新建完整暂存；估算不等于磁盘预留。备份只读原数据，不删除旧副本，不触发 B站 或模型请求。

**恢复只在隔离测试副本演练。不要在真鱼鱼的状态上先尝试历史回退。** 在同一隔离路径上创建快照，改动可重建模型文件，再执行：

```powershell
node .\tools\dev4-cold-state-backup.mjs restore-full --root "$state" --snapshot "$save" --stopped --confirm RESTORE_FULL_DSH_STATE
```

预期结果 `restored:true`，并返回各 `safeguardPaths`（恢复前原目录）；启动后按既有同 UID 权限复核。当前状态或拓扑不同会安全拒绝。不得通过删除记忆/权限文件来让比较通过。

## 中断与恢复事务

在所有分区旁各自准备完整暂存；核心目录旁创建持久的 `*.cold-restore-pending-v1.json`。真实宿主 `stateDirOf` 在目录创建之前拒绝启动。外置分区先切换，核心最后切换，每步保留原目录 `*.pre-restore-*`；只有全体身份及哈希复核成功后清除事务冻结。成功恢复仍写入原 `restore-freeze.json`，不得绕过 B站 UID 权限复核。

如果进程退出、中途盘失效或原件校验失败，保持停机，不删除事务标记和原件。先接回原盘，使用明确回退：

```powershell
node .\tools\dev4-cold-state-backup.mjs rollback-full --root "$state" --stopped --confirm ROLLBACK_FULL_DSH_STATE
```

只有所有恢复前原件仍能校验才恢复原位置；不能验证时保留冻结并停止，不重复执行恢复。异常阶段保留暂存用于排查，不自动清理。当前保证覆盖正常进程失败/退出和目录切换错误，**不保证物理磁盘损坏、断电写缓存落盘、Windows ACL 或恶意本地进程**。不要手工删除冻结文件；维护者需先核查所有数据及恢复事务。

## 旧工具和门禁

原 `backup / verify / restore` 命令用于旧单根格式，分盘依旧拒绝。新命令不自动执行，不影响 JSON 自动备份、Life 私密备份及原账号绑定。当前实机、历史合并、核心/Life 跨盘重绑定、整盘损失恢复及 dev.27 累积审计未完成；公开 npm dev.14 冻结，正式版 2.8.3 不放行。
