# 2.8.1 · 截断与上下文完整性审计（2026-11-18）

> **范围**：本次修复只读的模型输入和展示检索摘要，不修改事实库、权限参数、账号、平台回执、写入预算或持久原始资料。它不是一次全局删除 `.slice()`：数组上限、哈希、日期、URL/ID、短文本安全校验与数据限流需要保留。

## 已收口的高影响路径

| 调用链 | 旧问题 | 当前处理 | 仍需注意 |
| --- | --- | --- | --- |
| `index.js` 视频字幕 | 超过 12,000 字符只取开头 | 开头／中段／结尾分段，标出未读取区间和原始长度 | **不是全文音画理解**；重要转折可能仍在未读区间，须由 Life 选择补读 |
| `life-willingness` | 视频候选、观察、历史串行 JSON 截成半截 | 有界、可解析的 JSON；证据 ID 与来源键优先保留 | 总预算不足时返回显式 `contextUnavailable`，不能当作已看过/已确认 |
| `life-continuation` | 视觉、评论、Episode 与公开资料 JSON 只取前 N 字符 | 结构化裁剪与缺失说明 | `180` 等极短预算无法容纳多项事实，后续需结合真实工作负载评估预算合理性 |
| `life-voice-context` | 栏目末尾直接截断，易丢近期状态 | 栏目内尽量保留头尾，原有栏目预算保持不变 | 不承诺把全部人生数据注入所有场景 |
| `life-reflection` | 只取早期候选、候选文本首段被截 | 重要片段保留头尾，超额候选跳过并继续后续候选 | 反思选择过程仍有成本限制，不能用压缩文本覆盖原始记忆 |
| `memory-retriever` / `long-term-memory` | 检索摘要末尾丢失、工具输出 JSON 非法 | 检索结果显式缩短，工具输出保持有效 JSON | 私密资料仍由原账号与公开性规则决定是否可见 |
| `interaction-batch` / `owner-dm-agent` | 每轮最近消息、跨天历史和主 Session 摘要只保留前缀 | 头尾保留；带回执的结构化历史使用可解析 JSON | 私信依然默认 `compact`，不会预先灌入所有长期记忆 |
| Video Agent / 主人评论 / 评论区上下文 | 整段观察或评论资料只留开头 | 提示词里的概要优先保留头尾；调用前的可信来源、权限和安全校验不变 | 模型输出仍需通过独立平台权限及发送回执门禁 |

## 长度保护按性质分类

1. **不能取消**：输入长度上限、有效 BV/UID、文件大小限制、单轮工具次数、跨进程读预算、错误日志脱敏、最多 N 个候选等；这是安全或成本边界。
2. **改为语义预算**：`JSON.stringify(...).slice(0,N)`、超长字幕只取前缀、跨日聊天/成长/证据摘要只留开头。此类提示词上下文已在核心通路修订，并由 `npm run check:context-budget` 抓取重新引入的直接 JSON 前缀截断。
3. **仍存在的设计约束**：每类上下文预算、记忆条数、视频采样密度、场景的证据优先级。它们不能保证模型获取所有可能相关的材料。真正的**视频触发角色认知与相关记忆检索**、跨次主动补读、成长/关系证据关联，属于 [2.9.x 未实施方案](2.9.x-character-learning-memory-trigger-plan.md)，本版不偷偷实施。

## 测试与发布门禁

- `test/v281-context-budget-regression.test.mjs` 验证 JSON 可解析、候选 ID 保留、字幕三段与缺失提示，以及静态防回归入口。
- `.github/workflows/ci.yml` 与稳定 Release 检查执行 `npm run check:context-budget`；此检查是回归辅助，**不能替代**模型调用链、实际字幕与 Windows/B站实机行为验收。
- 本审计只统计已知高危调用点，不宣称所有 `.slice()` 都是缺陷，也不声称模型能凭被裁减的证据补出未观察事实。
