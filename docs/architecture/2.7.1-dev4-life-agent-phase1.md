# 2.7.1-dev.4 · Life Agent 第一阶段实际接线：生活唤醒、能力目录与视频驱动权切换

> **状态：代码已接入、离线验证中；不是完整 Life Agent；Windows / 真实模型 / 真实 B站未验收。** 依赖 `2.7.1-dev.3` 后续三阶段统一执行与诊断版本。ADR / 重构总方案仍是目标，不得把目标图冒充当前接线。

## 本阶段解决了什么

固定时间刷视频是旧版“自动生活”的事实主驱动之一。本阶段让**现有 `AutonomousPlanner` 的唯一模型调用**同时看见当前合法的待办、dev.3 的可信意愿和**可选生活事件/能力目录**。鱼鱼可以决定 `use_capability` 启动原视频 Agent，或者 `skip` 休息／转而处理别的事。模型不能创造能力，旧计划器没有改成第二个模型系统，Life Voice 仍只装配一次。

**入口 → 复用统一层 → 唯一事实/状态源 → 新增信息 → 权限和隐私 → 受影响渠道 → 回归**：

| 入口 | 复用的统一层 / 唯一状态源 | 新增的场景信息 | 权限及隐私 | 渠道与测试 |
| --- | --- | --- | --- | --- |
| 轻量定时检查 / 主人显式唤醒 | 原 `AutonomousPlanner` 同一忙碌标记、同一模型计数；Life Voice、owner-todos、LifeOpportunities | 本账号已去重的 `quiet-window`/`manual-wake`；能力目录 | 不存 UID、原文、模型提示，事件仅当前账号可见；模型无发送许可 | 生产：B站视频可选轮；第二平台事件模拟；Node 契约测试 |
| 视频轮结束回调 | 原 `runDuty`、可信视频事实与回执、原权限/写入门禁 | `video-round-ended` 匿名唤醒事件（不代表观看成功） | 不保存 BV、UID 或私密文本；平台错误仅作为事件，不制造事实 | 原 B站 Agent；回归原视频执行与安全测试 |
| 模型选择 `use_capability` | `life-capabilities.mjs` 白名单注册表 → 原 `runDuty` | 精确能力 ID，当前 `bilibili.video-explore` | 执行前二次可用性、账号、模型额度、每日视频启动限制；实际点赞/评论/关注依旧原有独立授权和平台事实门禁 | 单一生活决策器；假平台的纯读技能测试 |
| `lifeAgentMode` 配置 / 管理中心 | `index.js` 原配置正规化、`autonomousPlanner.status()` | `off / shadow / active`、匿名事件摘要、字符统计 | 默认 `off`，旧用户不迁移权限；无自动开启或未知回执重放 | 管理中心「自主待办调度设置」及 `/api/bili-duty/life-agent/wake` |

## 源码和状态归属

- `lib/life-agent-events.mjs` 是**短期事件信号与限频统计**，不是新的生活记忆/人格/兴趣/待办账本。路径 `$DSH_HOME/bili-duty/life-agent-events/<accountTag>.json`（账号伪名由现有可信凭证计算，必须是 16 位 hex；本模块不得自行推断 UID）。只存匿名事件 `kind/platform/at/id/state` 和视频启动时间；7 天过期、最多 60 个事件。来源 key 只用于哈希身份，不落盘。异常文件、无账号、符号链接拒绝；不会默默跨账号获取旧事件。
- `lib/life-capabilities.mjs` 是**确定性能力目录**：平台注册 `id/platform/risk/description/available()/execute()`；模型只能从当前 `list()` 选择，`run()` 再检查 `available`。当前生产仅登记 `bilibili.video-explore`；其它平台没有生产能力或账号绑定。模拟 `mocksite.video-explore` 测试证明不必为第二平台造新的模型决策循环，但不等于已接入抖音。
- `lib/autonomous-planner.mjs` 仍是**唯一后台自主生活模型决策点**：共用 `autonomousPlannerDailyLimit` / `autonomousPlannerMinutes`、忙碌门禁、Life Voice 和 dev.3 机会/意愿；新事件每 3 小时提供一次**可选思考机会**，不是三小时一次“必须刷”。选择 `use_capability` 必须有真实事件和当前已登记的能力；无事件 / 不想做 → 零模型调用或可选跳过；不修改公开写入权限。输入输出总字符数仅作成本观察，**不是实际 Token 计量或费用**。
- `index.js` 既有固定谷时定时器在 `lifeAgentMode==='active'` 时**不启动自动轮**；`runDuty('manual')` 和主人显式手动工具入口保持不变。原视频 Agent 内部及其可选自动点赞/评论/关注仍用原授权、执行和平台回执；本阶段的 `use_capability` 是**委派已有专业 Agent**，不把委派当成平台成功。

## 运行模式、预算和回退

| 模式 | 旧固定谷时触发 | Life Agent 可调用专业视频 Agent | 升级默认值 |
| --- | --- | --- | --- |
| `off` | 如旧配置所设 | 否 | **默认** |
| `shadow` | 如旧配置所设 | 仅记录 `shadow-would-explore`，不执行 | 需主动选择 |
| `active` | **关闭固定谷时的自动启动** | 需要模型主动选择、`masterEnabled` 和 `autonomousPlannerEnabled` 等硬门禁 | 需主动选择 |

Life Agent 的视频启动有本账号**每日最多 2 次、最短间隔 180 分钟**的额外边界，原 `perDay` / `pickPerRound` 和原 `reportLevel=off` 限制仍然生效；主人直接手动启动不受这层“自动生活”额外数量限制，但仍受原限制。自动生活的决策时段和预算取用原 `AutonomousPlanner` 配置；如果将其关闭，`active` 不会退回偷偷执行旧定时视频轮。按模式回到 `off` 可恢复旧谷时调度，保留原运行数据，**不会删除/重试未知外发结果**。

本阶段不是实际 Token 统计：仅累计规划器 prompt/response 字符长度；原视频 Headless Agent 的 Token 应通过独立模型/任务用量日志另行评估。计划 ADR 的“同等活动量 <=1.5x”仍是未来实测目标，不是已经满足的结论。

## 模型输入、实际回执与隐私

- 最终提示词复用 `getLifeVoice()` 一次；新增 `lifeCapabilityOpportunities` 只列可用的 ID、平台、危险级别、描述以及匿名事件类型/相对时间；不传私信正文/联系人 UID/历史遗忘内容。
- `use_capability` 不是“完成观看”“成功关注”，仅可获得 `capability-launched` / `capability-not-started` / `video-explore-blocked` 或 `shadow-would-explore`。真正的账号动作由原专业 Agent 的 B站回执决定。它可以生成自己的子任务，**但不能成为第二人格或第二人生记忆源**。
- 若模型输出非法动作或伪造能力 ID，降级为 `skip`；模型调用失败时保留事件供下次限额内尝试；账号在模型思考中切换时不执行、不会把旧账号事件清算到新账号。
- 在控制台可见：模式、本日模型次数、匿名待处理事件、自动视频启动次数、最近决策和字符数；不显示私信内容、UID 和原始模型提示词。

## 当前未覆盖与接下来的里程碑

1. **当前已接入：** 轻量生活唤醒、事件去重、平台中立能力目录、可选择视频或休息、原自主待办/意愿复用、选择前后账号校验、旧自动视频驱动权可逆切换、页面诊断。
2. **第二阶段已部分接线：** 已核验私信/评论/@ 的匿名唤醒进入统一 Life Agent（见[第二阶段现行图](./2.7.1-dev4-life-agent-phase2-social-wakes.md)）；目前没有私密对话正文的 Life Agent 读取或社交外发接管。下一步仍需为具体入口建立唯一发送决策所有权和原文合法读取协议。
3. **后续：** 同一模型在多个工具间自主规划多步探索、跨轮关系成长与关注意愿，接回原权限与回执，建立实际 Token 基线/计费观测、更多平台适配器、完整生活记忆反向反馈。
4. **仍未声称：** 私信后自动关注、评论者主动结识、任意多步工具调用、全平台统一社交回应；Windows、真实模型和 B站未验收，`dev.3` 实机待验收仍未作废。

## Windows 受控验收（先离线）

应用本阶段源码补丁或使用完整源码后，在项目根目录运行：

```powershell
node --test .\test\v271-dev4-life-agent-events.test.mjs
node --test .\test\v2499-autonomous-planner.test.mjs .\test\master-switch.test.mjs
node selfcheck.mjs
```

管理中心 →「鱼鱼想做的事」→「自主待办调度设置」选择「影子观察」并保存，确保自主调度开启；点「让鱼鱼自主考虑一次」。可观察 `shadow-would-explore` 或 `skip`，**不应启动原视频 Agent**。再在明确知晓原视频 Agent 的独立对外授权的前提下，受控选择「接管自动视频轮」，确认谷时定时轮不再主动启动、Life Agent 在模型愿意时才启动。出现 `capability-launched` 也只代表子进程成功拉起，不是观看/发送成功。完成测试可改回 `off`；`active` 不自动扩大原权限。
