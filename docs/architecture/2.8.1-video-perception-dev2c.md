# 2.8.1-dev.2c：视觉识别两路合一、DSH 图片人工验收与旧 Endpoint 退役

> 2026-11-14 开发增量；基于 dev.2b 的「大肥鱼原图人工验收」替换包。仍保留 package.json 的 2.8.0 版本号，未发布 npm，未进行真实 Windows DSH 验收。

## 用户可见设置

仅两种「识图方式」：

1. **DSH 识图模型**：使用上方视觉模型 Provider、模型 ID、推理强度；不再另列「复用视频模型」或「独立 DSH 模型」。DSH Provider 指向支持图片的模型才可实际识图。
2. **本地 Ollama 视觉模型**：继续由下方一键下载、手动识图、人工认可和启用；仍由本机 Ollama 运行、无需在 DSH 添加 Ollama Provider。

两路都显示同一份 `lib/assets/local-vision-selftest-dafeiyu.png` 原图、真正拿到的模型最终文字回复，以及用户自主的「认可/不满意」选择。测试图不会变成任意图片上传能力。未取得工具图片回执或没有最终回复时不能确认。DSH 测试调用可能产生第三方模型费用，发起前需明确确认。

## 安全生产链路

- `lib/dsh-vision-review.mjs`：按 DSH 路由和一次性 reviewId 绑定人工验收；模型变化/重新识图使旧记录失效。
- `lib/vision_dsh.py --selftest`：受限 headless 子会话，唯一可用 MCP 工具 `bili_vision_selftest`，由 `vendor/bilibili-mcp/mcp_server.py` 返回固定大肥鱼图片和带哈希的本机回执；没有其他 B站读取/写入工具。
- `lib/headless-security.mjs`：分离视频视觉 overlay 和专用自检 overlay，限制工具白名单、DSH profile 和固定图片路径。Python 运行仍有进程超时及响应大小技术保护，**没有专门设置最大生成 Token 数**。
- `index.js`：自检仅可通过管理端同源 POST 发起，DSH 与 Ollama 的用户选择不会绕过原读授权、视觉预算和平台外发门禁。

注意：**DSH 人工图片认可只证明用户接受本轮识图效果**，不是模型万用的视觉能力担保；现阶段不强制将所有既有 DSH 识图用户迁移为“先验收才能继续用”，以免破坏旧有调用链。新的验收状态不是 B站操作授权凭据。

## 旧配置、Endpoint 与兼容策略

- 移除旧 `visionEndpoint` 的表单/保存/启动参数，以及 `lib/preview_vision.py` 的自定义 API 端点和 `lib/vision-secret.ps1` 密钥脚本（不会自动删除用户电脑中的历史个人密钥文件）。
- `auto` / `reuse_video_model` 仅用于判定历史用户配置；历史模式首次读取时自动**关闭** `visionEnabled`，并要求使用者重新明确选择两路方案，避免偷偷切到另一个收费模型。内部只读 DSH MCP 子会话仍使用兼容的图片返回方式，但它不是用户的第三种识图模式。
- 旧文件以保留数据为前提，不做破坏性删除。已有 Ollama 安装、模型缓存、用户认可状态和 B站额度保持各自作用范围。
