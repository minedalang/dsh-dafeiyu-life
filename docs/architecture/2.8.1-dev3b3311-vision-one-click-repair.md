# 2.8.1-dev.3b.33.11 — DSH 图片 Python 环境一键修复

## 背景

Windows 上 UV 管理的 Python 可能在普通权限下对 TEMP / Duty Home 写入返回 PermissionError。用户自行寻找 Conda、输入完整 Python 路径、运行 PowerShell 不是面向 2.8.1 用户的合理安装体验。`dev.3b.33.10` 附带的离线 PS1 无 BOM，在 Windows PowerShell 5.1 中文环境还可能被按系统代码页误读，造成脚本语法错误。

## 新的默认流程

- **正常用户：** 已健康的主 `.venv` 及 MCP 依赖由视觉自动选择器直接使用，无需额外操作。
- **视觉运行时不健康：** 在管理中心「AI 模型 → 视觉识别模型 → 图片识别验收 → 技术诊断」点击「自动修复视觉运行环境」。界面明确要求用户确认可能联网安装第三方 Python 包。
- 宿主只读探测显式路径、主 Python、系统普通安装位置和 Desktop PATH 中已有的解释器，要求 Python 3.10–3.13，且在普通权限下可同时写 TEMP 与 Duty Home。
- 如果已有完整健康解释器，直接验证并保存；否则优先使用健康基础解释器的 `-m venv --copies`；若本机没有可用的系统 Python，则沿用插件已有的经用户确认的 uv 安装能力尝试建立 Python 3.12 环境，仍须通过完全相同的读写检查。正常安装路径会 在 Duty Home 创建新的、带随机后缀的**独立视觉环境**，安装项目自带 `vendor/bilibili-mcp/requirements.txt`，复检 `mcp`、`bilibili_api`、`qrcode`、`PIL` 和文件读写后才自动保存。
- 安装与读写失败不发布未验证路径；原主 `.venv`、原视觉环境与旧设置保持原样。执行器使用 `spawn(shell:false)`，不开 PowerShell，不允许权限放宽或管理员提权。
- 安装结果仅说明 MCP Python 环境可运行。真实 DSH 图片验收仍需要 Headless 配置、MCP nonce 图片回执、模型最终回答和人工认可。

## 实施边界

- 这是仅在用户主动点击后运行的一键修复，不是启动时未经许可就下载组件。
- 如果所有可用 Python 进程都被 Windows 安全策略阻断，不能通过更改 ACL、安全策略或提升权限自动绕过；只能报告明确错误，供用户按本机管理策略处理。
- 当前宿主资源安装器不替代主依赖安装，也不触发 Life、视频或私信发送。
- 离线 `tools/repair-dsh-vision-python.ps1` 与 `tools/repair-dsh-python-runtime.ps1` 已加 UTF-8 BOM，供高级排障时可选使用；普通用户不需要运行。
- 本轮只进行增量自动化及静态测试，Windows 与真实 DSH 图片模型需要实机端到端确认。
