## P6 参数与兼容性

| 配置键（统一配置 API） | 默认值 | 允许范围 | UI 归属与生效位置 |
| --- | --- | --- | --- |
| `commentP6Enabled` | `false` | 布尔 | 最近评论 → 默认折叠的后台评论互动设置；原普通评论授权仍需开启 |
| `commentAtP6Enabled` | `false` | 布尔 | 同上；原收到 @ 回复总开关仍需开启 |
| `dmP6Enabled` | `true` | 布尔 | 后台私信 → 默认折叠的后台私信规则；旧 DM 发送授权不会被升级扩权 |
| `commentP6MaxBubbles` | `2` | 1–3 | 最近评论，普通评论和 @ P6 共用；仍受单条 130 字和全部公开硬额度 |
| `dmP6MaxBubbles` | `3` | 1–3 | 后台私信 P6；单条 450 字，原每轮／小时／日额度仍有效 |
| `socialP6MinDelayMinutes` | `5` | 5–360 | 后台私信 P6 与全渠道节奏；延期最短时长 |
| `socialP6MaxDelayMinutes` | `360` | 5–360 | 同上；延期最长时长；必须不小于最短时长 |
| `socialRhythmCrossChannelMinutes` | `30` | 0–1440 | 同上；同 UID 从 DM 切换到公开评论或 @ 等**不同渠道**的冷却 |
| `socialRhythmDailyPerPerson` | `8` | 1–100 | 同上；跨私信+评论+@ 的同 UID 滚动 24 小时发送尝试额度 |

新安装/旧配置均通过 `index.js` `Schema` 和 `DEFAULTS` 注入安全默认值；管理 UI 使用同一 `/config` 接口读取与保存，不制造第二套配置。运行时每次生成、每条发送、每次 P6 意图预约或节奏预约都重新读取所需限制；变小的配额不会触发旧预约的“强制发送”。模型不保证一定达到最大条数。跨渠道限制不改变已有平台硬上限。

## 恢复、安全与目前范围

- 普通评论与收到 @ 续聊只在用户**另外开启 P6** 时启用；未开启时维持原有单条回复，不能把旧 true 自动升级为公开 P6 true。私信 P6 默认开启只改变允许的回复形式，不会启用陌生人 DM 或放宽 `dmApprovalEnabled`／`dmStrangerAutonomyEnabled`。
- 公开评论同一通知逐条消耗原评论额度；平台回执是具体出站 rpid，不是模型生成文本。延迟后必须确认原评论所属 UID、rpid、视频/动态来源和没有更新的同线程新消息，才允许重新决定是否发送。
- 节奏账本的保留窗口为滚动 48 小时，且为不确定响应保留不可重放的保守状态。账号切换、新 UID 或其他线程不能继承旧身份、权限或待办。
- 原 `SocialConversationContinuity` 是跨渠道共享账本：增加 `channels` 领取过滤而非复制一个新定时器；私信只读 DM 意图，评论只读 comment/at 意图。
- `SocialInteractionRhythm` 当前仅接入**后台自动私信及后台评论/@**，不声称覆盖主人直接命令、主动推荐、动态发布等其他外发入口；后续如扩容须单独验证新的写入权与实际接线。
- Windows DSH Desktop 与真实 B站多气泡发送、失败回执、平台风控与用户选择退订尚未做实机端到端验收；离线 mock 无法证明平台已公开可见。
