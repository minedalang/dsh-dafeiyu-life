# 2.7.1-dev.4 · 统一生活驱动与简单设置（当前开发预览）

> **开发增量，不代表全域 Life Agent 已接管**。本说明记录代码中实际生效的调度入口、配置源与权限界线；真实 Windows、模型及 B站验收仍待完成。

## 用户目标和本轮边界

用户希望鱼鱼的生活由 Life Agent 自主决定，而不是由「谷时刷视频」推动。日常使用者应只设置「生活状态」和「活跃程度」，细项折叠在高级设置。**已实现：旧视频自动时钟退出生产运行；Life Agent 统一本系统自主视频唤醒，保留手动视频工具。** 未实现：私信/评论/回访/主动分享的所有社交意愿与执行统一交给 Life Agent；现有社会监听、回访与记忆维护仍有独立调度。

## 实际生产路径

1. `index.js` **不再注册**旧 `tick()`+`setInterval` 视频谷时轮；`peakValley`/`peakWindows`/`peakIntervalMinutes` 等仅保留原数据格式，`legacyVideoTimerAllowed()` 恒为 false，`assertLegacyVideoPatchCompatible()` 阻止旧接口再次打开它。
2. 既有 `AutonomousPlanner.start()` 每分钟做廉价的是否值得考虑检查；仅在总开关、`autonomousPlannerEnabled`、生活时段、冷却及当日决策次数允许时才可能调用模型。`active` 可按现有能力/额度条件委派原视频 Agent，`shadow` 不能启动视频轮；模型可以跳过/延期/休息，不被强制刷视频。
3. 生活设置 `GET /api/bili-duty/life-agent/settings-v2` 只读投影；`POST` 通过 revision 比对、预览和显式 `APPLY_LIFE_SETTINGS_V2` 保存。`off` 明确保存时关闭 Planner，`active`/`shadow` 明确保存时开启它；历史旧值在保存前不自动迁移。
4. 普通活跃预设：**安静** 180 分钟/4 次，**自然** 60 分钟/12 次，**活跃** 30 分钟/20 次。这里是模型决策尝试上限，**不是视频数/发言次数**；各预设不覆盖已有活跃时段。**自定义**才写入间隔、日决策上限、起止小时。
5. DSH 原生首页不再展示旧定时开关，改为直达统一生活页。旧「待办」页面中 Life Agent 的旧数值控件只读；待办独有配置仍通过原独立页面保存。旧账号、历史待办与外发回执保持原始隔离。

## 旧用户数据与滚动升级

- 初次升级不会自动修改已有配置；如果旧 `peakValley=true`，**旧视频时钟也不会再运行**。旧字段保留在历史备份及配置中，不因 UI 不显示而删除。
- 用户开启时需主动预览/保存并确认总开关已开；关闭时应在统一生活页保存「暂停」，使旧存量 `autonomousPlannerEnabled=true` 也被明确关闭。仅将模式显示为暂停，不代表此前所有后台自动社交授权都被撤回。
- `bili_config` 模型工具和 `/config` 通用设置接口不得重新打开旧视频定时器或直接抢占 Life Agent 核心设置；新的用户可编辑节奏入口在统一 Life Agent 页面。
- 回滚至旧插件版本前应备份完整原始配置与业务数据，**旧版本可能重新识别历史 `peakValley`**，需要先检查旧版调度设置；当前补丁不能约束被安装的旧版代码。

## 剩余风险与真实验收

- 当前只收敛 **自动视频驱动**，尚未将评论、私信、@、回访、主动分享及定期记忆整理全部交给同一 Life Agent 作社会选择；所有社交外发继续使用原权限及原决策器。本轮不新增 Life Agent 社交真实发送权。
- 旧已开启 Planner 的用户，首次在页面显示 `off` 时可能仍有旧待办自动考虑；统一页提示需明确保存「暂停」才完全关闭；这是为了避免软件升级静默改变原用户任务数据和调度意愿。
- Windows `run-tests.bat`、DSH Desktop 原生按钮跳转、真实账号登录与模型/视频操作，需要用户在真实环境核验；不能用 Linux 单元测试冒充验收。

## 生活页体验收敛（本次增量）

- 常规页面只展示生活状态、活跃程度、保存及「现在让鱼鱼考虑一次」；**不再要求用户理解 Phase 4/5/6 名称、旧 Scheduler 参数或影子社交对照**。高级设置内保留活动时段与每日模型决策上限；旧页面的只读兼容字段、离线模拟、社交影子授权和时间线统一折入「开发者诊断与旧配置」，默认关闭。
- 本次只调整现有 HTML/JS 视图归属；不会删除原配置字段、旧任务、回执或其他仍实际执行的社交模块。`life-v2-mode` 与 `life-v2-pace` 仍通过原 `lifeSettingsV2` / `planLifeSettingsV2` / `persistCfg()` 保存。单独的待办回访授权继续使用原独立回访配置，不能被生活活跃度偷偷覆盖。
- 模型返回不符合契约时，`AutonomousPlanner` 继续拒绝执行、并消耗原已预留的当轮额度；HTTP 响应只追加固定枚举 `diagnosticCode`（例如 `model-json-invalid` / `model-action-unknown` / `model-target-invalid`）。界面用明确的「决策未通过校验，未执行动作」解释，不再把技术失败混同于鱼鱼主动休息；不回传模型原文、UID 或候选 ID。
- **不会自动向模型重试，也不会为了修复 JSON 错误而放宽 `execute_read`、社交外发或写入门禁。** 如持续失败，需要核验所选模型是否遵守 JSON 契约、当前实际可用候选和后台日志。成功修复前不能宣称鱼鱼自主意愿已被正确识别。
