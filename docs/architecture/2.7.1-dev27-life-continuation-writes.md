## 动作边界

- `like_video` 需原 `autoVideoLike` 和正额度，且必须是当天实际入选视频；未必有喜欢就不点赞。
- `collect_video` 需 `autoVideoCollect`，模型给 2–14 字普通主题；Python 仍使用原受控收藏夹、限额及动作锁，本 Life 续行强制私有新夹。
- `follow_creator` 需 `agentFollowEnabled`；只能关注该 BV 经平台核实的**视频作者**，模型不得提出 UID；对方关系状态、本人账号限制、日限额及已关注等均由原 Python 守卫。
- `comment_video` 需 `autoComment`、每轮/每日配额和有内容的公开资料；只能对此 BV 发表一个 180 字内、不得 @ 的原创顶层评论。仅有标题、无可靠材料时不提供此动作；不能捏造观看、字幕或热评。共享原评论额度及发送核验。

## 实际一次行动的数据流

见 [`diagrams/2.7.1-dev27-life-continuation-writes.mmd`](./diagrams/2.7.1-dev27-life-continuation-writes.mmd)。

1. Life 首轮从已有公开兴趣/评论好奇源自主选择探索，读取并核实 BV；`completeExploration` 记录当前账号可信 `selectedBvid`/`metadataAt`。
2. 下一个续行决定之前，宿主只读再次获取视频详情、真实播放/点赞/评论统计，按**现有配置阈值**过滤，并在必要时补少量公开评论作为文本背景。读取成功不代表观看过画面或听到声音。
3. `continuationMenu` 把仍有效的读动作与 **本轮允许的写入候选**一起交给 Life 模型，模型也可 `stop`。写入文本、原因、BV 和参数必须完全匹配菜单契约。
4. 若选写入，宿主重新校验当前账号、权限、意愿及平台资料，才调用原 `bili_ledger_mark` 记录“挑中”；启动受限 Python 工具进程。Python 仍要取得新的 Life 审批许可、核查原视频入选来源和账号权限后，才能执行一次平台写操作。
5. Python 调用原 Loopback Bridge 结算并等待宿主独立平台 GET；只有 `status=verified` 时当前 Life 轮才记为完成。未知、超时、无结果一律保守冻结同一意愿的此动作（原平台账本的未结事务也保留）。无论执行结果如何，本轮**不再连续发第二条**。

## 当前未覆盖与风险

- 尚未把“回复评论时探索评论者主页、跨评论串发表评论”接入。该需求需要基于评论 ID、作者 UID、原串身份校验与反骚扰门禁设计；不能把当前 BV 的视频作者 UID 当作评论者。
- 现阶段的内容充分性是视频简介/公开评论等**文本资料**，不是完整观看/听音，模型仍可能主动不评论。写入不能伪称视听经历。
- 旧日 `seen.md` 中若此 BV 已记录为跳过，原 Python “当天明确入选”校验依然会阻断写操作。不会为了满足写入而重写历史选择。
- 不新增新的对外权限开关，完全采用原 `autoComment/autoVideoLike/autoVideoCollect/agentFollowEnabled`；没有这些授权的旧用户升级后不会获得写能力。原 `dmMode` 已退役，继续不影响评论。
- 新的 Python 受控写入需要与 DSH Desktop 随包提供的 `mcp`/`bilibili_api` 依赖联调。离线单测用模拟服务器验证协议，但**没有实际调用真实 B站、真实写入或平台 GET**，不可宣称实机通过。
