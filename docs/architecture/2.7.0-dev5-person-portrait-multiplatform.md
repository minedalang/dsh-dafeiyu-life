## 身份契约与多平台扩展

- **人员记录的定位键**：`{platform, platformUserId, personKey, platformLabel, linkStatus:'unverified-unlinked', linkedAccounts:[]}`，`personKey = platform + ':' + platformUserId`。原 B站 `uid` 仍可用于旧关系数据库、白名单和平台回执，因此升级不修改 `relationships.sqlite3` 表结构，也不触发不可逆的数据迁移。
- 现在只有 `platform=bilibili` 接入真实通知、私信与关系索引；其他平台 ID 仅能通过纯身份契约形成不同的 `personKey`，**不会**虚构其他平台的联系人、消息或权限。不能仅凭相同 UID 数字、昵称、头像、互相自称或模型猜测就合并不同平台账号。未来要做账号关联，需要单独的双端验证、明确主人确认、撤销和全渠道隐私审计；本轮不实现关联 API 或合并存储。
- 现有 `evidence-v1.json` 的旧条目没有 `platform` 视为 B站原数据；新条目显式写入 `platform:'bilibili'`。单一证据源和账号目录不变。读写本轮仅允许 B站，不能把其他平台的同名标识塞进 `uid` 字段。

## 分阶段画像规则（只提高**有证据内容**的上限）

| 阶段 | 画像呈现 | 最多进入模型的明确证据 | 允许新建自然联系人证据？ |
| --- | --- | ---: | --- |
| 刚认识 `new` | 最小互动摘要、平台 ID | 0（既有白名单最少保留 2 条兼容） | 否，除已列名的可信好友 |
| 见过几次 `known` | 双向往来、跨日信息、简要明确偏好 | 2 | 是，必须真实已核实入站 |
| 逐渐熟悉 `familiar` | 在已有证据上增加明确偏好和边界 | 5 | 是 |
| 自然好友 `friend` | 更完整的可信交流证据组合 | 8 | 是 |

阶段由 `SocialRelationshipIndex` 已有硬条件计算，不引入第二份关系评分；只有明确说过的安全偏好才会被提炼，**关系分高不意味着“鱼鱼知道他的性格”**。模型只收到有证据的列表和谨慎的关系往来摘要；没有开放式人格判定或长期叙事生成。仍需后续阶段才可探索更丰富且可审核的共同话题摘要。

## 失败与迁移

- 新版正常加载 dev.4 的 B站 `evidence-v1.json`；旧版如回滚可忽略新增字段，但**自然联系人画像与人物页不可视**，仍以老白名单语义读取。回滚前建议保留账号目录备份，避免旧程序误读新数据。
- 当前平台 UID 不合法、跨站来源、未知关系、平台不是 `bilibili` 的画像请求失败；不通过昵称或 404 回退查询另一个人的资料。画像损坏拒绝读写，P6 安全约束仍按既有失败保守逻辑，不自动补发。
- 清除关系会调用 `SocialPortraitGateway.forget` 清除该 B站 UID 的画像，避免失去关系资格后留下隐藏档案；这不清除其他人生记忆、白名单权限或别的平台身份。UI 有明确确认。
- **仍未覆盖**：Windows DSH Desktop 实机交互、真实 B站私信/评论收件箱验证、多平台真实适配器、跨平台同一人关联、开放式个人理解摘要、长周期自动纠错与记忆融合。未推送、发布或向平台写入任何测试消息。
