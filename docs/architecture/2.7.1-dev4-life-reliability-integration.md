## 生产数据流

见 [当前 Mermaid 图](./diagrams/2.7.1-dev4-life-reliability-live.mmd)。

- `life-agent-events` 的 **v1 格式不迁移**：旧 `considered/result=invalid` 读取时按一个失败算作 `retryable`，但需到期才重新进入 `peek`；同源 `offer` 仍去重，不制造新消息。失败来源限于 `invalid/model-error`；有效的主动 `skip` 仍结案。三次失败为 `failed`，不会无限自动运行。
- `autonomous-planner.json` 的 **v1 JSON 保持不变**：`runs` 和 `lastAt` 是所有 B站登录账号共享的模型额度，不能切换账号重置。短时间的同步文件预约序列化额度消费和最终诊断回写；主轮租约覆盖整个异步模型/读取选择过程。已发生但不确定是否调用的模型次数不得退款。
- 新锁目录：`autonomous-planner-ledger.lock/`、`autonomous-planner-run.lock/`、`life-agent-events-ledger.lock/`。文件内只写锁类别、随机 token、进程 PID、时间，不写私信、视频/任务 ID、账号标签或模型推理文本。
- `life-opportunities` 旧错误记录 `action=defer, result=metadata-read-failed` 在**读取时**解释为技术错误（首次失败），缩短最长等待到原失败后 15 分钟；只有下一次真实持久写入才会写出新格式，其他延期不变。新读取失败使用 `action=error`，不被称为鱼鱼主观延期；退避 15 分钟 → 60 分钟 → 6 小时，连续三次则该契机不再自动提供给模型。重新获得成功的同 BV 回执才可关闭为 `inspect`。
- 自主意愿中的连续元数据读取失败也记录枚举 `metadataFailureCode`，计数最多三次，第三次暂停该意愿；已有 24 小时失败延期记录保留原记录，不跨账号猜测归属。不删除成功回执或重新播放视频。

## 保护条件与已知边界

1. `verifyLifePublicMetadata()` 必须匹配**请求的原 BV**和实际**非空的原标题**。支持内置 MCP 常见平面对象以及唯一一层 `{data:{...}}` 封装，但不会把模型输出、搜索摘要、异 BV 或接口错误转为真实观看事实。
2. 失败码只允许有限枚举：`metadata-read-busy`、`metadata-rate-limited`、`metadata-account-unavailable`、`metadata-timeout`、`metadata-response-invalid`、`metadata-bvid-mismatch`、`metadata-title-missing`、`metadata-api-error`。底层平台异常文本**不**写入生活契机/决策时间线，不泄露账号。
3. 账号作用域在调用 `bili_video_info` 前后检查，发生切换就拒绝更新原契机为本账号成功。无可靠登录态不得向 Life Agent 传成功回执。
4. 原来的 `SocialPolicyGate`、逐消息外发事务、主人待办、专业视频 Agent、情绪/人格和人生记忆均没有新的授权、定时器或写入者。**旧普通私信/评论仍是唯一真实社交决策者**；其他社交写入入口未由本轮集中接管。
5. 租约基于**本机文件系统**的原子目录创建，不适用于共享网络盘与多台机器。崩溃后的未知结果必须停机、备份、人工核查，不按时间自动解锁；已预约的模型额度仍然消耗。

## 离线复核 / Windows 维护

```powershell
# 在项目根目录、停止所有 DSH 实例之前，只读检查锁状态：
node .\tools\dev4-life-planner-offline-recovery.mjs --data-dir "<DSH_HOME>\bili-duty" --inspect

# 若出现崩溃锁：先关闭全部 DSH，备份本地状态并人工确认无未完成动作。
# 仅在确认所有实例均已停止后，再执行显式离线恢复：
node .\tools\dev4-life-planner-offline-recovery.mjs --data-dir "<DSH_HOME>\bili-duty" --recover --confirm-all-stopped
```

CLI 仍会拒绝清理进程存活、损坏、符号链接或归属无法核验的锁；绝不建议删库、直接删 lock 文件或强制重试不确定的平台动作。`<DSH_HOME>` 需替换为本机实际路径，恢复工具不会自动发现目录。

## 触发与验收

1. 管理中心「鱼鱼的生活 → 让鱼鱼考虑一次」：存在可信候选且额度允许时，才消耗模型调用；模拟无效 JSON/模型故障会报告技术失败并保留原匿名生活唤醒待重试。真实主动 `skip` 仍显示鱼鱼选择休息。
2. 模型自主选择 `inspect_opportunity` / `inspect_exploration` 但 B站返回异常：显示具体失败分类，不制造成功视频回执。相关契机/意愿退避，最多三次暂停；检查管理中心生活契机与匿名决策时间线。
3. 两个 DSH Node 进程争用模型额度：单日额度为 1 时只能产生 1 次模型调用；异常锁需停机复核。
4. 旧账号、跨账号、网络失败、平台被限流和 BV 不一致均不得把另一账号数据记入当前账号；所有对外写动作仍遵循旧授权，不能由此轮启动。

## 管理中心 HTTP 409 的可读诊断

API 仍将 `metadata-read-failed`、模型输出无效和模型/执行异常作为非成功结果返回（HTTP 409 + `ok:false`）。现有管理中心请求层仅对这三个**明确且可显示的结构化 Life 结果**保留 `result/diagnosticCode`；账号、授权、服务端通用错误依然拒绝，不会把真正的请求失败伪装为成功。页面在「让鱼鱼考虑一次」「立即重新考虑生活契机」及生活线索详情中区别技术失败、退避重试、三次失败暂停与鱼鱼主动延期。
