## 统一层归属与实际变化

| 入口 | 继续使用的唯一状态源 | 新增信息 | 权限/隐私边界 | 实际接线 |
| --- | --- | --- | --- | --- |

`life-agent-events.mjs` 仍是**账号隔离的 7 天短期唤醒池**，不是人格、记忆、对话历史、关系证据或授权的新数据库。事件 ID 由既有 `kind/platform/sourceKey` 摘要生成；`sourceKey` 只在调用时使用、不会落盘。旧版 `version:1` 文件继续兼容；无可信 16 hex 账号作用域、非法类型、异常或符号链接时拒绝。

## 两个重要修正

1. **社交事件不依赖视频额度。** 之前 `getLifeEvents()` 仅在“可启动视频”时调用，导致每日两轮视频额度用完、视频子进程繁忙、视频能力未注册时，收件唤醒也无法进入统一决策。第二阶段先读取同账号生活事件，再独立判断视频能力及额度；零可用视频技能仍可 `consider_social` 或 `skip`。
2. **切号后二次阻断。** Life Agent 模型异步返回后、作任何动作前再次比较原事件账号作用域；不一致直接停止、不清除原号的未处理事件，也不生成“新账号已考虑”的虚假记录。视频第一阶段的切号定向测试因此更新成更严格的失败关闭预期。

## 自主性边界：真正在选择什么

鱼鱼可以面对匿名“收到一条私信 / 公开评论”的真实事件，选择 `consider_social`（我现在愿意注意到有一次交往）、处理已有其他待办、反思有证据的经历，或 `skip`（本轮不考虑）。这是一个**同一 Life Agent 生活优先级选择**，不是第二个社交 Agent。

模型**没有拿到正文或 UID**，所以 `consider_social` 只留下 `social-signal-considered` 的短期决策回执，**绝不代表已阅读消息内容、理解当事人、发送回复、增加朋友关系、写入长期记忆、主动关注或接管社交回复**。原 DM/评论模块仍各自决定对外回复；任何发送继续走既有 `SocialPolicyGate` / 限额 / 事务预留 / 真实平台回执。新路径零额外平台写入。模型伪造 event ID 或 capability 会被拒绝。

生产上沿用原自主规划每日 AI 决策次数、最低间隔、时段和忙碌门禁；入站高频收件只增加轻量事件，不会每条立即调用模型。当前观测仍仅有模型输入/输出字符数，**没有真实 Token 费用测量**；因此架构 ADR 的成本目标尚未验证。

## 默认、迁移、回滚与待办

- `lifeAgentMode=off` 为默认，不入队社交唤醒，旧私信/评论/视频驱动不变。`shadow` 收集/考虑匿名社交事件但不启动新视频轮；`active` 也能考虑社交事件，且允许自主委派视频探索；只有 `active` 会替换旧视频固定启动。**本阶段 `active` 不切换评论/私信的外发所有权。**
- 从第一阶段的 `life-agent-events` 状态文件无损读取；原 `quiet-window`、`video-round-ended`、`manual-wake` 仍有效。旧角色记忆、待办、兴趣、退订、私信游标、回执无迁移写入。
- 人工关回 `off` 可停止进一步观察与决策；已有匿名事件会在原作用域短期保留至 7 天 TTL，绝不会重播旧消息以自动发送。
- **下一阶段才做实际社交决策迁移**：为某一具体回复入口设立单一决策所有者，按 UID/线程/权限域检索真实合法上下文并在同一决策循环中选择答复、延后或沉默；必须先解决旧回复器与新 Agent 的去重和确认协议，才可让 Life Agent 委派真实外发。跨平台身份关联、全工具自由组合及由聊天自然决定关注仍未实现。

## 验收与可观测性

离线：

```powershell
node --test .\test\v271-dev4-life-agent-events.test.mjs .\test\v271-dev4-life-agent-social-wakes.test.mjs
node selfcheck.mjs
```

实机验证应先在管理中心将「Life Agent 自主生活驱动」切至「影子观察」，保留现有私信/评论设置，**在用户允许的测试账号里**收到一条真实私信和一条真实公开评论；确认「待考虑社交」计数变化、账号隔离，以及 Life Agent 可选择注意/沉默而不触发任何第二次发送。之后可选「接管自动视频轮」，验证视频额度用完时仍能考虑社交事件。不要为了测试主动联系陌生人、关闭既有发送保护或尝试未知回执重发。

特别要记录：账号切换、真实 DM/评论的去重、对外发送是否仍由**原入口唯一执行**，以及真实模型调用次数/用量；目前 Linux 单元测试不能替代这些实机证据。
