## 一、P0：Host 错把「窗口最长120秒」当作「视频第120秒之前」

- 修改 `lib/vision-host-owned-executor.mjs` 生产固定提示词二次校验：绝对结束时间 `<=43200`，窗口长度在 `3..120` 秒之间，必须有限数且起点非负。
- Python `lib/preview_vision.py` 的 `_normalize_focus_window()` 原有约束保持不变。
- 真实 Python 生成的 `focus_start_seconds=6000.0, focus_end_seconds=6015.0, perception_source=adaptive, view_depth=deep, network_budget_bytes=52428800` 提示词在 Node 的受限 overlay/固定提示词检查中可通过。网络额度仍严格验证。
- 2分钟以上的合法时间点不再误判；3秒以下、120秒以上、超过12小时、倒序、任意附加命令仍拒绝。

## 二、P1：全片索引截断与下游证据连锁影响

- 移除 `lib/preview_vision.py` 在时间分层**之前**将整片索引截到 `3000` 格的限制，改为接受最多 `len(images)*xlen*ylen` 个有效官方索引。
- `.bin` 的读取仍需验证 B站官方域名/路径/HTTPS，不接受模型给出的 URL；有界读取最高256000字节，不得静默只取前段并声称全片观察。JSON 仍走原 API 响应大小限制。
- 既有资源界限不变：**48张源拼图、1400个扫描格、8 MiB图片数据、40M解码像素**，图片最多按主人设定输出12/24/48帧；扫描被限立即回报 `timeline_scan_complete=false` 与原因。
- 全局低清采样升级 **v9**；`lib/video-evidence-bundle.mjs` 同步认可 v9 和高于3000的官方索引数，同时限定 v9 的候选扫描 `<=1400`、已扫描源拼图 `<=48`、索引总数 `<=300000`，以及 `timeline_scan_complete=true` 时的各计数一致性。不放宽 v8 既有的3000索引边界；不把低清帧冒充解码原视频。
- 新版缓存不读老 v8 的算法输出。涉及 DSH Python 视觉缓存取 `PREVIEW_BOARD_VERSION`，无需再人工更新另一个版本常量。
