# 2.6.1 RC2 · 鱼鱼身份与 B站账号解耦：实施审计、迁移和安全契约

> **状态：本地实施并通过模拟测试；仍需 DSH Desktop + 真实 B站扫码/换号验收。** 不代表已正式发布。当前版本号保持 `2.6.1`。

## 1. 身份层次与目录

| 类型 | 位置 | 是否随 B站换号 | 数据承诺 |
|---|---|---|---|
| 鱼鱼稳定角色身份 | `character-identity.json` | **不变** | UUID；通用业务备份包含该文件，不包含账号密钥 |
| 当前登录 B站账号绑定 | `account-binding.json` | 更换 | UID、切换代次、复核状态；不存 Cookie、对话正文 |
| 当前 MCP 凭证 | `bili_credential.json` | 替换 | 原有 Python MCP 兼容路径；仅本机可读 |
| 待确认扫码 | `account-login-pending.json` | 暂存直至核验或取消 | 包含敏感 Cookie，禁止对外 API 返回、通用备份禁止纳入 |
| 历史账号凭证 | `accounts/<UID>/credential.json` | 隔离保留 | 仅本机加固保存，不能据此恢复旧号授权；可人工安全删除 |
| 平台私信与回执状态 | `accounts/<UID>/runtime/` | **按 B站 UID 隔离** | 私信 Agent、DM 去重、主人动作、评论互动及任务回访各自独立 |
| 鱼鱼本体记忆 | 根目录 `life-memory/`、`long-term-memory/`、人格、情绪等 | **保留** | 现有隐私和遗忘策略不变；不会把永久档案重新开放给模型 |
| 统一已接受待办 | `owner-todos.json` | 保留历史，新增带 `accountUid` | 已接收的旧账号任务保留，但不会被新账号自主调度或执行 |

依赖关系：`character-identity` ≠ `account-binding` ≠ `account-credential` ≠ `account-runtime`。不要通过 UID 变化重建鱼鱼角色人格或把所有生活数据迁到新账号目录。

## 2. 实际生产接线

1. 插件加载时创建或核验角色身份及账号绑定。首次升级旧装置仅记录当前凭证自报 UID（保持历史兼容）；本次起，扫码更换账号必须经真实远程验证。
2. 旧版根目录下的 `dm-autoreply-state.json`、`owner-dm-agent.json`、`owner-dm-actions.json`、`owner-comment-agent.json`、`comment-interact-state.json`、`owner-todo-followups.json` 安全迁移到原 UID 的 `runtime` 文件夹，保留旧状态，不混入新的 UID。已存在目标文件时不覆盖；残余源文件视为未决数据，不重新导入。
3. 扫码完成只创建 `account-login-pending.json`；状态立即进入 `login-staged`，后台外部行动冻结。主动取消则删除待确认凭证，旧账号不变。
4. 管理页与首次设置页都显示 UID，操作人明确确认后，向固定的官方 `api.bilibili.com/x/web-interface/nav` 在线验证 B站真实登录 UID。对比扫码凭证声称的 UID；不匹配、过期、网络错误时拒绝提交。
5. 核验通过后封存旧账号凭证，原子替换 MCP 的当前凭证，更新绑定代次，进入 `restart-required`。平台代码与旧 Python MCP 子进程不能继续使用旧账号上下文。
6. 重启 DSH 时基于当前已绑定 UID 选择独立平台运行账本，先保持 `review-required`。用户在「B站视频探索 → 鱼鱼的身份与 B站账号」或首次设置的 B站登录区域明确复核新账号外发许可后，再人工恢复活动。复核不等于开放未授权的公开写入能力。
7. 统一待办新增 `accountUid` 来源。原来没有账号归属的旧待办只在**首次升级绑定的原账号、第一次账号代次**下可自动候选；换号后仍能在管理界面看历史，但自动执行/完成回访不得复活。不同账号可持有相同源 Key 而不互相误判为重复。
8. 原有 `call` MCP 工具和独立值班 Agent 在待确认、凭证与绑定不一致、重启待完成、人工复核待完成时拒绝业务调用；独立私信轮询与日常动态也通过配置/执行门禁暂停。`bili_check_credential` 保留为诊断通道。

## 3. 旧数据和可恢复性

- **先在退出 DSH 后备份整个 `$DSH_HOME/bili-duty/` 的安全副本**，尤其 `life-memory`、`long-term-memory`、`owner-todos.json`、`accounts` 目录。完整本地备份含私密数据和凭证，**不要上传公开网盘、GitHub 或普通问题反馈**。
- 通用业务 JSON 备份现包括稳定的 `character-identity.json`，明确排除 Cookie/待确认凭证/私密账号运行账本。这类业务备份不能代替完整的加密、本机管理员备份。想跨设备恢复账号运行历史必须单独制定隐私协议。
- 一旦角色身份文件与账号绑定账本矛盾，启动应拒绝猜测身份并告警，不允许默默重生一个 UUID。若恢复到另一装置，需要针对当前绑定状态单独做人工恢复核验；不要删除警戒文件绕过校验。
- 已遗忘生活细节不随换号找回；历史永久归档和已发送回执仍为审计而存在，不应重新注入模型上下文。
- 新账户若被封或凭证无效，角色本体仍保留。换回旧号需重新扫码验证；不可把旧号的待发消息/不明回执直接视为新号可发送。

## 4. 当前实现范围与剩余风险

**已实现：** 单个当前账号安全重新绑定；稳定角色 ID；扫码暂存/取消、在线 UID 核验、重启/复核双重门禁；典型私信与回访账本按 UID 隔离；待办账号归属；简单备份与跨号拦截；管理中心状态/按钮。

**没有实现：** 多 B站账号同时运行；自动迁移粉丝、收藏和平台数据；在新账号补发旧账号动作；在同一进程热切换所有历史 Agent；可靠的跨设备加密私密数据导入；B站服务器在线接口不可用时的离线切号；全面重新签发旧白名单/社交发信权限（由新账号管理操作人逐项复核）。

**需真实测试的边界：** 已经在飞行中的异步平台操作、Electron/Windows 下 ACL 行为、平台实际 `nav` 返回值、旧装置残留的未枚举平台状态文件、跨账号保留的公开兴趣可能受到历史视频来源影响、平台单账号操作权限重新启用后是否符合运营预期。**自动化测试不能替代实机安全验收。**

## 5. 负面验收矩阵

- [ ] 从旧版升级，有原主人 DM、评论与未完成回访，原账号历史仍可读取；生命记忆和人格指纹不变。
- [ ] 只扫码新号不确认，旧凭证不被覆盖，所有自动社交和后台平台调用被冻结；取消则恢复旧账号正常操作。
- [ ] 新 Cookie 无效或官方 UID 与提交 UID 不一致，确认被拒绝且旧凭证仍在。
- [ ] 切换成功但未重启、或已重启但未人工复核，平台业务不能自动执行。
- [ ] 新账号私信去重、主人对话和回访历史是空的，而旧账号状态在原目录保持。
- [ ] 老待办无论是否 `pending`、`uncertain`、`running`，都不能在新账号自动重试；同一源 Key 在新账号可以新建独立任务。
- [ ] 切回旧账号，已被换号冻结的历史任务不能在不审查的情况下重新变成自动候选。
- [ ] 通用备份有 `character-identity.json`，没有 `accounts/<UID>/credential.json`、待确认 Cookie、原始私密 DM 运行状态。
- [ ] 已遗忘的痕迹没有从永久档案在新账号被复活；不同社交 UID 不共享私密往来。
- [ ] 全量 Node、Python、自检和 Windows DSH Desktop 上的扫码/取消/验证/换号/回滚测试。
