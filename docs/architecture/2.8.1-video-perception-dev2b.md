# 2.8.1-dev.2b：可选本机视觉模型管理与只读识图适配

> 2026-11-14；开发预览增量，基线为 **dev.2a（含 `AGENTS.md` 轻量交付规范修正）**，未发布 npm，未执行真实 Windows DSH/平台实机验证。

## 统一层归属与实际接线

`用户在「AI 模型 → 视频视觉模型 → 本地视觉」显式下载安装 → localhost Ollama 模型仓库 → 本机视觉自检 → 显式启用配置 → 原视频 Agent MCP 预览工具 → 原 B站视频快照 → 共享视觉调用额度 → 本机 /api/chat → 已标注低清/时间锚点的观察回执 → Life 原观察/记忆链路。`

- `lib/local-vision-model-manager.mjs`：固定白名单 `qwen3.5:4b` 与 `openbmb/minicpm-v4.7:1b`，只请求 `http://127.0.0.1:11434`，复用现有管理中心同源 POST 安全门禁。安装前用户确认；下载进度来自 Ollama 官方 `/api/pull`，取消仅中断当前请求；不获取 B站凭证、不访问私密记忆、不执行 Shell。模型由用户系统中的 Ollama 全局存储管理，**删除会影响其他应用，需第二次确认**。
- 安装与验证分离：`/api/tags` 可报告已下载，只有带一张合成图片的 `/api/chat` 能确认当前运行时的视觉能力。模型安装失败、Ollama 未启动、下载完成但视觉自检失败要在管理中心区分；MiniCPM-V 4.7 的 Ollama 下游兼容存在版本差异，不能认定已支持。
- `index.js`：管理状态/安装/取消/验证/启用/删除接口，新的 `independent_local` 视觉模式及固定模型 ID 配置。不能仅改通用配置跳过自检；旧配置、默认 DSH 模式不变。
- `lib/preview_vision.py`：`ollama` 为严格 `127.0.0.1:11434/api/chat` 路由，禁用系统代理和重定向，受原预览张数、B站固定 URL、每日模型调用次数以及本地缓存约束。**本地识图只产生简短观察，不为 Life 再投一次意愿，也不执行 B站写动作。**
- `vendor/bilibili-mcp/mcp_server.py`：新增 `independent_local` 原视频 Agent 只读分支。使用原 `public_read_reservation` 以及原 `analyze_preview()`，不改原写入与授权工具。识图失败按无画面处理，不会偷偷回退调用收费云端模型。

## Ollama 下载代理与硬件说明（dev.2b 补丁校正）

- **本地 Ollama 不需要注册为 DSH Provider**：插件直连 `127.0.0.1:11434`，并只在用户显式安装、完成图片识别自检并启用后切换视觉模式；Life 仍使用已有 DSH 模型。
- **仅列举 Windows 环境的本地网络代理方法**：下载可能需要合适的网络环境。请先完全退出后台 Ollama，再于独立 PowerShell 会话中执行 `$env:HTTPS_PROXY = "http://127.0.0.1:7890"`（`7890` 是常见端口，按实际端口修改），随后执行 `ollama serve` 并保持窗口运行。此环境变量只影响该窗口启动的 Ollama 子进程，不修改用户级或系统级环境变量；安装完成后本地识图不需要下载代理，但仍需 Ollama 正常运行。详见 [Ollama 官方 FAQ](https://docs.ollama.com/faq#how-do-i-use-ollama-behind-a-proxy)。插件不自动配置网络代理或导入代理证书。
- MiniCPM-V 4.7 **1B** 固定 `openbmb/minicpm-v4.7:1b`，下载量约 1.8GB，推荐至少 4GB 显存起试（非官方保证值）；Ollama 运行时仍可能缺少该模型所需支持。Qwen3.5 **4B** 为 `qwen3.5:4b`，下载量约 3.3～4.0GB，推荐 6～8GB 显存起试、优先 8GB。实际占用因量化版本、图像与上下文而变化。两款模型都不随插件打包。
- `/api/pull` 错误会保留末尾 DNS/超时/代理/证书信息并给出检查指引，避免以前被 URL 前半段截断；错误文字仅用于管理中心诊断，不对未核实的网络原因作确定归因。其 `completed` / `total` 按当前下载 blob 返回，**不是全模型进度**。MiniCPM-V 1B 的量化权重与视觉投影器为独立文件层，连续出现两次 100% 或进度重新开始并不代表重复下载；安装成功必须等待校验和 manifest 写入。

## 未实现及发布限制

1. **Ollama 必须由用户事先安装并启动。** 这轮的一键下载是“一键下载并验证所选模型”，不是无人值守安装 Ollama Runtime；不应与先前自管理 llama.cpp Embedding Runtime 混为一谈。
2. 模型下载由 Ollama Registry 管理。**当前只固定官方模型名称，不强行宣称已锁定上游模型 revision/SHA-256。** Ollama 负责 Registry 内容寻址与层校验；如正式版需要可重复构建，应进一步固定可信模型 manifest digest 和对应许可证快照。
3. 本轮视频 Agent 与 Life 「查看视频」只读入口均可调用本地 Ollama 预览识图；仍然使用 B站既有低清预览（通常 1–3 帧），**尚未实现**分镜镜头检测、全视频解码、复杂分镜拼图、真实音频事件分析及本地多帧优化。Life 的其他只读入口尚未全面切到此视觉模式。
4. 未测试 Ollama / GPU 兼容性、4GB/8GB 显存、真实 B站画面、长时运行、旧用户升级，不能作为产品级稳定性证明。MiniCPM-V 4.7 运行时不兼容时应提示停止、保留原 DSH 默认路线，不应盲目重试或另换模型。
5. 独立视觉能力不能自动启用：默认 `reuse_video_model` 不改变；启用需要用户再次确认。删除已选中本地模型时，清除选中状态并关闭视频识图开关，而不是把未来识图悄悄切回云端。

## 首批安全审计补充

- 通用设置 API 不得启用 `independent_local` 或绕过专属 `/local-vision/select` 偷换本地模型 ID；选择必须重新执行带合成红色方块的真实图片推理自检，而非仅检查模型下载或非空输出。
- 模型正在下载时不得并发自检或删除；未启动 Ollama 时安装返回错误而不是虚假成功。
- 本地模式可在 Life 「查看视频」读取和原视频 Agent 的 MCP `bili_preview_vision` 中使用；识图回执失败仍不得声称看到画面。
- 本轮未自动安装 Ollama 运行时；运行时一键安装需要另行验证跨平台安装来源与签名。

## dev.2b 图片自检：大肥鱼原图 + 用户人工验收（2026-11-14，替换前一版未使用的自检补丁）

- 固定测试图片改为 `lib/assets/local-vision-selftest-dafeiyu.png`（用户提供的大肥鱼角色原图）。管理中心通过 `GET /api/bili-duty/local-vision/selftest-image` 展示该原始 PNG，Ollama `/api/chat` 的 `messages[].images` 使用同一文件生成的 base64。状态接口只返回图片路径和自检记录，避免每次轮询携带大图片。
- 自检提示词改为**开放式描述大肥鱼人物外观、头发、服饰、配饰与姿态**。保留 `think:false`，不再指定 `options.num_predict`；不截断 `message.content`。模型服务本身的上下文、响应超时和资源限制仍适用，并不代表真正无限生成。
- 自检成功接收非空 `message.content` 时只形成 `awaiting_review` 状态，不自动合格；通过同源管理中心的 `POST /local-vision/review` 提交 `{model,reviewId,accepted}`，只有当次结果、同一模型、已安装且服务可用时才接受。用户认可记为 `approved`，拒绝记为 `rejected`。每次重测清除旧认可；重启服务后需重新识图和认可。
- `POST /local-vision/select` 不再替用户自动做语义判断，也不能绕过人工认可；通用配置接口仍禁止直接设置本地 Provider。只有请求失败、无法加载视觉组件或没有可见最终文字属于技术错误且禁止确认；返回不准确的描述由用户自行判断，不依赖固定关键词。
- 模型完整最终回复仅在已授权管理中心用 `textContent` 展示；不展示 `message.thinking`。图片来源为用户提供的项目素材，不复制第三方开源代码，原第三方项目声明沿用。
- 未在用户 Windows Ollama 上执行真实 GPU/视频识别验收，此项仍是开发预览；人工作出单图识别认可不等于视频理解能力已被全面验证。
