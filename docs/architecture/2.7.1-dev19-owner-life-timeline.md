# 2.7.1-dev.19 · 真实生活时间线用户视角收口

## 问题与原则

以前 `buildLifeTimeline` 同时投影公开评论与 `LifeAgentEvents` 的匿名可信发送回执。一次评论成功会出现「平台发送事务回执已核验」和「回复评论」两张卡，且视频进程、只读动作、反思也混有内部实施说明。管理页不应是调试面板。

**用户视角统一归 `lib/life-timeline.mjs`**：保留有事实依据的行动本身，不展示内部回执签名、结算和技术诊断。调试信息仍由原账本及 Life 诊断 API 管理；不因隐藏 UI 卡片删除或修改其记录。

## 生产数据流

`原视频/公开评论/情绪账本 + 当前账号 LifeAgentEvents` → `buildLifeTimeline` → `/api/bili-duty/life-timeline` → `management-console.js` 用户生活卡片。

- **评论去重**：仅当 `comment_reply` / `video_comment` 的已核验动作与同种类有效公开评论时间相距不超过三分钟，才优先展示带正文、对象和链接的评论；超出窗口或类型不符时保留简短互动摘要，不凭回执推断评论正文。
- **其他写入**：已核验私信、分享、动态、点赞、关注等若没有详细公共记录，可显示简短动作描述，不提供私信内容、目标 UID 或匿名技术引用。
- **只读、反思、视频、情绪**：展示自然语言叙述，不暴露进程退出码、证据源类型、调试用语和内核处理状态；看元数据仍不自称看完、听完。
- **不纳入**：模型提议、影子决策、平台受理但未证实、失败或未知发送。

## 唯一归属及安全边界

- `lib/life-agent-events.mjs` 继续管理跨重启可信事件与续行；`lib/life-willingness.mjs` 和渠道适配器负责原授权、发送、核验及防重；本轮不改变数据模型和行为授权。
- 用户看到的简化摘要不构成新的核验证据。隐藏技术行后底层回执仍可用于诊断、不重复发送和恢复。
- 三分钟近邻仅用于**用户界面的去重**，不用于原事务关联或事实结算；不可以把相邻但不同评论的内容写回账本。
- `/life-timeline` 仍只返回当前账号已核实的生活事实与公开评论；不能从隐私域补私信正文。

## 验收与限制

Node 测试检查与真实用户样例同秒的评论去重、跨种类不误合并、无正文回退、失败/影子严格排除、用户可读文案和时间顺序。Windows/B站真实浏览器回归尚需安装验证。
