# 2.8.3 · 视频视觉证据补看与深浅记忆收口计划（分阶段开发中）

> **定位：计划中的 2.8.3 开发范围，待 2.8.2 正式发布与当前 Windows/DSH 门禁完成后实施。** 本文不是当前生产能力、现成路由、已完成迁移或发布日期承诺。原定 2.9.0 的角色认知成长顺延至 2.8.3 视觉和记忆基础稳固之后。

## 目标与边界

把“已看过”“有可用画面记忆”“有足够证据回答当前问题”区分开。Life 无论**刚看完、同轮聊天、十分钟后、跨轮或隔天**，只要在正常聊天/主动探索中出现**具体、真实的证据不足需求**，都可按自主意愿考虑有限补看。补看**不是按天触发**，也不是一提 BV、缓存未命中或模型输出为空就自动抓取视频。24 小时重复全局识图保护继续防止无理由重看；必要补看走受限例外，不自动放松权限或 B站读取预算。

2.8.3-dev.2 已新增可迁移业务目录和受控深层详情内核（生产写入默认关闭），真实视频深层自动入库、自然回忆和即时补看仍待后续批次。

2.8.2 已有分镜/局部可信回执、同调用全局 AI 短摘要、新增局部后的视频 Agent 无工具文字整合、有限画面笔记、BV 当前清晰记忆精确查找和局部时间窗新证据检查。**尚未实现**随时证据不足的跨轮触发链，也没有可按需展开完整已观察细节的深层记忆。

## P0 · 能力和数据边界先行

1. 全面盘点当前 LifeMemoryGateway、普通聊天与公开互动上下文、视频证据验证、遗忘/账号切换/备份/缓存、24h 防重、Episode 与工具来源；复用唯一 Life 调度和已有事实/授权门禁，禁止第二套隐形 AI 主体。
2. 规定“证据充分性”投影：`not-watched / observed-no-summary / summary-insufficient / summary-sufficient / detail-faded / unavailable / unknown` 仅作为候选状态，不在未核实情况下把模型主观自信当作充分性证明；确认问题类型、当前可见摘要、时间锚点与已知覆盖范围。
3. 明确是否包含可访问的历史原始视觉结果及其有效期；**禁止从永久审计档案恢复已遗忘内容**。现有证明已看过但无描述的旧经历保持真实，必要时可作为补看候选，不自动追溯虚构旧摘要。

## P1 · 即时证据不足 → Life 自主有界补看

- **入口不限日期**：当前聊天、主人询问、与朋友正常交流、视频探索续行/再次遇到该 BV 都要通过统一、受权限过滤的 Life 候选入口。外部问句仅提供需求，不等于授权读取或指令；若只是再次看到标题、摘要已足够或 Life 不愿意，直接复用/拒绝/延期。
- **首选复用**：按当前账号和可衰减记忆检索已有可信摘要、允许访问的细节与合法缓存；不能仅因缓存失效就开启重复识图。
- **明确理由和目标**：由 Life 自行选择 `reuse / ask-clarify / focus / limited-overview-repair / defer / refuse`，记录摘要缺失或具体待验证画面、原证据覆盖以及期望新增的信息；理由必须可追溯到真实需求，不接受标题/模型提示注入伪造新需求。
- **受控绕过 24h 防重**：只对这次已确认的不足目标建立一次性有限许可；原账号、同 BV、真实时间窗、平台读取共享预算、并发锁、失败退避、单轮帧数/字节和新增采样校验必须全部保留。重复失败只计成本不写成功记忆；已被完整覆盖且没有新的观察问题时拒绝。
- **成功才合并**：新画面取得可信回执后更新当前仍可访问的记忆，并依 2.8.2 的无工具视频模型整合生成新版短摘要；失败保留原不确定性。明确“历史笔记缺失补全”和“有新问题的局部补充”的不同诊断，避免同 BV 成本反复消耗。

## P2 · 视频视觉浅／深双层存储与渐进回忆

- 浅层：当前 Life 记忆的有界 AI 自然语言摘要、视频/BV 及可见性和来源索引；与现有 `clear → fuzzy → trace → forgotten` 同生命周期。
- 深层：**仅保存实际取得**的全局分镜、局部识图详细文字、时间窗/帧锚点、模型不确定性和冲突/遗漏标签，挂在同一可衰减 `memoryId` 下；不是第二个事实库，也不假装已经看完未采样的画面。默认不长期保存 JPEG、视频、整段字幕、模型原文或私密材料。
- 抽取：现有视觉模型仍负责真实观察；成功局部深入后才使用现有**视频 Agent 模型**执行无工具文字整理。整合时只能读取当前可访问的全局与局部证据，避免跨轮补看时从不可访问的旧细节“拼出”虚假全貌。不能仅用一次模糊摘要替代源锚点。
- 读：普通对话和神经回忆场先找浅层；问题要求具体画面才通过 Gateway 限额展开当前允许的深层片段；Embedding 可选，未就绪时 Life 保留普通回忆，神经场语义框保持禁用。
- 删：衰减至 fuzzy/trace/forgotten、账号切换、权限撤销、删除、回滚和备份恢复必须同步处理详情、索引及缓存；不可由永久档案反向回填。失败按关闭访问处理，日志只给脱敏状态、次数、来源类型，不公开模型原文。
- 统一设计不仅覆盖视频：视频先作为端到端范例，之后复用通用层支持其他**有合法保存依据**的重信息（如对话和已核实行动）；非视频大规模迁移独立评审容量与隐私。

## P3 · 可观察性和发布验收

- 诊断区分：现有记忆复用、缓存命中、首次全局观察、已有摘要不足的局部补看、历史旧记录缺少笔记的补齐、失败后重试、因去重/预算/遗忘拒绝；每次要能回答“为什么再次看、增加了什么证据、是否真实调用模型、是否写入可衰减记忆”。不得把调试观察写为正式观看。
- UI 浅层默认，按需打开深层；访问拒绝/细节衰减应清楚说明原因。生活列表在**确属同一真实 Episode 的资料核验 + 可信画面回执**时合并为自然经历；没有画面回执时展示已记录的自主停止/模型阻断原因；未知原因不猜测。行为树和底层诊断仍保留原始独立动作、真实时序和失败回执，绝不靠同一时间戳、标题或 BV 虚构因果。
- 单元/整合测试必须覆盖当前聊天与跨轮聊天、24h 例外、摘要缺失/足够、缓存命中、同时间窗重看、账号与公私隔离、遗忘、注入、模型失败、预算/限流/并发/重启、备份恢复、回滚、Windows Ollama/DSH 实机。
- 每个功能改动先**静态扫描全部现行 Node/Python 测试**与契约断言、修复明显冲突；云端只跑定向测试；最终完整 `run-tests.ps1 -Mode full` 和实机验收由维护者进行。
