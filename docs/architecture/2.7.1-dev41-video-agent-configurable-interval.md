# dev.41：视频 Agent 最短启动间隔可配置

## 目标

把原先写死的 20 分钟视频 Agent 启动间隔变成用户可配置的最短间隔，同时保留 20 分钟硬下限。该设置控制的是**相邻真实视频子进程启动之间的最短时间**，不是定时器，也不是 Life 模型考虑频率。

## 配置契约

- 配置键：`videoAgentMinIntervalMinutes`。
- 默认：`20` 分钟；范围：`20～1440` 分钟（整数）。旧配置缺少该键时按 20 分钟运行，不执行额外迁移或重置。
- 管理入口：`Life 自主生活 → 鱼鱼的生活 → 视频 Agent 启动间隔`，位于普通设置区，不属于开发者诊断。
- 保存：复用 `life-agent/settings-v2` 版本化预览／确认接口。该键加入设置 revision，避免基于过期配置保存。
- 旧 `/config` 通用表单与 Agent-facing `bili_config` 不能直接更改该键；必须通过 Life 设置确认流程。

## 执行语义

- `lifePacePolicy()` 读取配置值；无效、缺失或低于 20 的运行时值 fail-safe 回退为 20。
- `lifeVideoGate()` 仍从当前账号的 `recentVideoRounds`／`lastVideoAt` 读取真实启动时间，并按配置的分钟数计算 `cooldownUntil`；运行状态也以同一 `videoGate.cooling` 判定，避免手动轮次虽被启动门禁拦截、却未显示冷却状态。
- 自动 Life 能力准入、执行前二次技术核验和管理中心手动启动继续调用同一个 `lifeVideoGate()`；手动启动不绕过冷却。
- 手动启动仍不计入 Life 模型每日决策额度。冷却只阻止新的视频子进程，不阻止 Life 对已结束视频回执进行只读考虑。
- 调高间隔会立即按上次真实启动时间重新计算剩余冷却；调低间隔不会删除或改写历史启动记录。
- 该值不改变 Life 是否唤醒、模型是否选择视频探索、视频 Agent 是否选片／发表评论，以及任何点赞、收藏、关注或私信授权。间隔到期也不保证会启动。
