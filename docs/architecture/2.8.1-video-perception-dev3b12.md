# 2.8.1-dev.3b.12：Life 自主视频阅读、成长与真实视觉 Debug

## 现行调用与边界

- 新视频 `bili_life_consider_video` 和已核实时间的 `bili_video_revisit_moment` 复用 `runLifeChosenVideoRead`，由统一 Life 模型选择略看、深看、补看、延期或拒绝；主人显式看视频和 Debug 不冒充自主。
- `executeWatchVideo` 获得可信公开资料后，由 `buildVideoExplorationEvent` 创建可衰减的公开视频经历，通过 `lifeMemoryCoordinator.recordEvents` 分别投影到经历库、反思候选和兴趣证据账本。之前构造器忽略 `autonomousSelected` 传参，现在补上并对 `bili-life` 做来源限制，同时保存带时区的真实时间，避免兴趣证据错归为旧日记录。
- 这不能证明情绪变化或人格成长。只有经原有反思审查、跨日兴趣多来源证据与独立人格账本记录才能在 UI 归因中展示。视频完整帧、第三方评论原文、模型不确定猜测不写入长期人生记忆。跨日语义模糊补看和社交自动接线仍未实现。

## 图片 Debug 的精确来源

1. Python 自适应采样在实际解码后才取得 `frames`（送给模型的分镜拼图）；重点复查额外保留 `debug_moments`（取自同一轮原采样 `moments` 的 384×216 JPEG）。不另联网重绘、不用在线搜索替代素材。
2. 调试资源独立写入 `vision-perception-captures/<128-bit-random-id>/`，每张图片最多 600 KiB，最多 4 张分镜或 12 张焦点 JPEG，仅固定文件名，记录原始采样时间，限期 30 分钟。重启后下次捕获清除过期项，运行期间另由宿主计时清理。
3. `preview_vision.py`/`vision_dsh.py` 只返回不可推断路径的临时调试 ID/资源清单；`executeWatchVideo` 将其从模型可见的 `visual` 回执中移除，单独供本机 Debug 的 `job.images` 和 `lastLife.images` 使用。
4. 受保护的只读接口只对回环地址、同源管理中心、同一已验证账号及正在保留的调试收据有效；不接收任意磁盘路径、外部 URL 或新视频资源地址。响应不缓存。
5. 用户明确点击「开始只读视频感知验收」时，原工具可带 `capture_for_debug`，绕过旧的文字识图缓存，确保取得本次实际分镜素材；正常 Life 查询仍可命中原缓存。没有可验证的原图时显示缺失，不凭采样时间生成示意图。

## 发布限制

Python/Node 离线模拟无法替代 Windows DSH 实际读 MP4、Ollama、Whisper 与 B站账号验收。只有完成与本版本对应的实机取帧、模型实际图片输入、显示及过期/跨账号隔离检查后才能进入 RC。
