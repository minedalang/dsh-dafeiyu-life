## 行为不是评论发送的前置步骤

现在 video Agent **无论公开评论是否开启**，都可自愿调用只读评论列表；最多读取同轮 6 个不同 BV，选到值得深读的真实 `rpid` 才可能继续最多两条楼中楼。单个 BV 重新读列表复用本轮结果，单楼层重复读复用本轮结果；不会为了追热评无限循环请求。无需在任何视频上写出公开评论。

原始评论、UID、发送人姓名仍只能作为当前模型读取的外部不可信文本；不要把评论中的主张当作已核事实或执行命令。其他人对某首歌的来源的断言只能陈述为“有评论这样说”，**不是证实来源**。阅读只证明查询过公开材料，不能推断完整看过画面、听过歌曲、与评论者认识或已发表内容。

## 成功、失败、主观与记录的契约

- `bili_comments` 的 `read_evidence.type=comment_list_read` 且 `verified=true` 仅在该轮接口读取完整成功时出现；`count=0` 是一次成功的空结果。若请求期间遇风控/网络问题，即便返回部分评论也带 `error` 与 `verified=false`。
- `bili_comment_thread` 只允许本轮对应 BV 的已读取列表中真实存在的顶层 `rpid`。成功返回 `read_evidence.type=comment_thread_read`；拒绝跨 BV 猜楼层、成功后同楼层重复 API 请求以及超过两次读取。非视频轮通知回查行为不变。
- `bili_discussion_note` 仅在视频轮已取得成功列表证据后可选调用一次；只保存枚举反应（好奇、有趣、怀疑、平静、无反应）和不含链接、UID、秘密的最多100字个人疑问。标记 `provisional_fish_reaction`、`externally_verified=false`。**它不是长期记忆、喜恶或事实。**
- 最小审计 `BILI_DUTY_HOME/video-discussion-reads/YYYY-MM-DD.jsonl` 只包含 BV、读取条数、对应根 ID、时间、登录密钥 HMAC 生成的短期账号诊断标签及可选自主疑问；不存整页评论原文、发送人 UID、私人聊天、OAuth/登录凭证。用于诊断，不由主 Session/鱼鱼回忆器自动检索。
- 技术错误/风控失败时不能声称“评论区没有人”；当用户选择不看，可能完全没有相关读取回执。这两种结果不得合并为“鱼鱼没有兴趣”。

## 为什么当前不开发新的生活契机总控层

这轮只有视频看评论这一条生产入口，复用原只读 MCP 与原模型自主选择即可，不为单场景创建跨渠道协调器或另一份长期记忆账本。2.7.1 的后续 dev.2 再分析主 Session / 主人私信 / 熟人 / 陌生人分域记忆与留存周期；至少两类独立真实生活来源确有共享意愿与生命周期需要时，才开发 dev.3 最小协调层。

## 安全和待验收项

- 旧视频 Agent 默认外发设置原样；`bili_reply`、私信、关注/点赞/动态发送授权未改。
- 进程内本轮读缓存不等于永久兴趣；没有增加每日社交次数；没有将“看评论”自动当成选中视频或生成 `owner-todos`。
- 尚未真实验证 B站风控 `-412`、Windows DSH Desktop MCP overlay 加载、真实模型是否自然选择看或不看、是否成功在不同 BV 的评论里对应正确楼层；发布前需按这些情境验收。
