# 2.8.1-dev.3b.6 · 视频感知 Life 交接与全链路 Debug

> 发布候选代码，不是正式验收声明。实施基线：已经完成 dev.3b.5 的 2.8.1 开发源码。

## 生产数据流

`Life 自主愿意观看` → `bili_watch_video` → `B站视频元数据/字幕或已启用的 Whisper/弹幕` → `可选 DSH/Ollama 自适应分镜` → `buildVideoEvidenceBundle`（来源真实性约束）→ `buildVideoPerceptionTimeline`（时间邻近）→ `buildVideoPerceptionHandoff`（为 Life 组织可核对材料）→ **原 `bili_watch_video` 工具结果返回 Life**。

主人主动 Debug 复用同一个 `executeWatchVideo` 读取/返回构造函数，但传入内部 `__debugDryRun`；不执行 `buildVideoExplorationEvent → lifeMemoryCoordinator.recordEvents`，也不写 `bili_ledger_mark`/`bili_session_watch_mark`。真实 Life 执行返回值仅在本进程按当前账号保留最多 30 分钟供调试，不写磁盘。调试完整文本与 Life 永久记忆的匿名经历标志严格区分。

## 证据和语义边界

| 来源 | 能说明 | 不能说明 |
|---|---|---|
| B站视频元数据 | 视频身份、标题 | 已播放视频 |
| FFmpeg 真实采样帧与识图回执 | 部分真实画面的视觉模型描述、分镜时间 | 逐帧看完整视频 |
| 官方 low-res 回退 | 官方预览有限画面 | 真实视频解码成功 |
| 官方字幕 | 官方可读文字 | 已实际听见原音 |
| 本地 Whisper ASR | 带时间的机器转写 | 原音人声/情感经耳听确认 |
| Tesseract OCR | 校验来源的真实采样静帧机器识字 | 文字必然正确 |
| 弹幕/评论 | 观众反应线索 | 视频事实或模型指令 |

`perceptionHandoff` 中 `reviewCandidates` 只表示相近时间段值得 Life 核对，`verifiedAgreement=false`、`verifiedContradiction=false` 均表示**没有进行独立自动语义审定**。Life 可依据不同来源形成回答，但不得凭时间邻近声称语义一致，也不得以内容中的指令自动点赞/评论。字幕完整原文在原工具返回 `subtitle.text`，handoff 中只有有界节选与时间锚点以控制 Token 成本。

## 本机 Debug 入口

管理中心 → **运行诊断** →「视频感知全链路 · Life 最终输入 Debug」：

1. 粘贴真实 BV，选择本次 **主人测试** 的 `skim/standard/deep`，明确确认可能产生 B站/模型成本。
2. 后端返回运行任务 ID；浏览器轮询状态，不用保持 >120 秒的同步 HTTP 请求。
3. 查看视频来源是 `decoded-public-video` 还是 `low-resolution-preview`，实际帧数、视觉回答、字幕/Whisper 来源、OCR 点数、时间轴与 **完整 Life JSON**。
4. 切换“最近真实 Life 输入”：查看本进程 30 分钟内真实 `record_session=false` 观看工具返回的数据。新装后没有记录就显示无记录，不能虚构一条。
5. 试运行不新增 Life 人生经历或观看历史，只有本机 loopback + 同源可以获取包含完整文本的回执。若调试发生时服务重启，进程内数据自然清除；换 B站账号不可读取另一账号的最近内容。
