# DSH 2.7.1-dev.37 · Life 自主行动统一归属与真实回执（未发布）

## 问题与现有真相

`dev.36` 的 Universal Episode 可以承接多步 Life 探索，但原系统仍有独立的 OwnerTodo、反思、待办回访、DM、评论专业 Agent 和已被 Life 审核的主动写入。**把所有专业 Agent 合并成一个任意调用的中央大模型会失去执行门禁，不是本次方案。**

## 本次实际实现

| 入口 | 行动提议 / 决策者 | 原权限及唯一事实源 | Episode 归属 / 状态 |
|---|---|---|---|
| Life Planner | 主 Life 模型在当轮可信菜单中决定 | 原待办、兴趣意愿、反思、账号门禁 | 主动 Life、`planner`；原读回成功后记一步 |
| 自主视频 Agent | Life 委派，专业视频 Agent 自主选工具，写前再过 Life | 已核验 BV / 原平台独立回执 | `video-agent`；真实写回成功才登记；未知冻结 |
| DM/评论回复 | 收到消息后原专业回复 Agent + Life 意愿审批 | 原渠道、关系、反骚扰、平台事务回执 | `dm`/`comment`；**每条不同平台 ID 独立去重**；无回执不算步骤 |
| 主人已接受的只读待办 | Life 或主人触发原待办执行器 | `owner-todos` `done` 与 `completedAt` | 统一源 `todo:<id>`；主人/主动不同枚举；同回执不双计 |
| 完成后回访 | 独立到期检查，Life 意愿决定是否联系 | 原回访队列 + 原 DM/评论发送事务 | 确认发出后回原待办 Episode；未知不补发 |
| 自主反思 | Life 选择或原独立反思定时器 | 原反思候选及成功提交批次 | 批次真实处理生成匿名回执；同一批次只记一步 |
| 其他已核验社交/动态 | 现有 Life 意愿 + 原发送权限 | 原专业生产回执 | 原有生命事件；部分仅有生产方确认，暂不能冒充精确平台读回 |

新增 `lib/life-action-attribution.mjs` **只有 `verified`、`unknown`、`notSent` 等记录接口，无发送方法，也不决定 Life 意愿**。调用它之前，原执行者必须已经得到稳定的可信凭证和当前账号。回执格式和权限不是由 Episode 发明。`owner` 为白名单 `life/owner/reactive`，渠道也是白名单枚举；不保存原 UID、BV、消息内容、私信地址、姓名或提示词。Episode 原摘要仅有不可逆的账号绑定摘要、步骤结果和允许枚举。

同一成功平台回执在全账号 Episode 范围内幂等；即使 Life Planner 与原待办回调都看到 `done`，也不会重复计算。发生写结果未知时，只有存在原来源活跃片段才冻结；不创建虚假的“已完成”片段、不发重试。未核实的操作未必产生 Episode 步骤，不能以“未录入”等同“没有发生”，需回原平台事务核对。

**自动连续性仍需原合法目标：**历史 Episode 不是新的调度权限。 `resume_episode` 仍仅对真实有效的视频探索意愿开放；非视频优先续行沿原已到期待办、公开机会，主人回复及社交回访仍有独立触发条件。这部分尚未成为通用无限后续工作流；不会为了凑 3–5 步而反复评论陌生人。

## 用户关切的主评论

- `bili_comment_consideration` 仍只是模型考虑记录；不会发送主评论。
- 自主原创主评论仍需 `autoComment` 授权、内容来源核验、Life 意愿、公开写入安全门禁与独立平台核验；本次改造**没有提高评论频率或强制发布**。
- dev.37 加固的是“模型选择 vs 实际发送”的回执归属，不代表已经证明真实 B站能成功发表评论。请结合原 `video-comment-summary` 的 `reviewed/wanted/proposed/approved/blocked/verified` 查看实际阻断点。

## 离线与实机验收分离

1. 离线验证：单次批准、多条平台回执、重复回执、失效账号、主人/被动社交来源分离、未知冻结、不制造虚假 Episode、待办回访正确接入原待办源；`npm run check:life-architecture`。
2. 实机验证：Windows Desktop 同一账号连续运行；真实首页选片与 2–5 步自然续行；对真实已发表的主评论、楼中楼回复、私信使用**原平台事务与读回**核对 Episode，不因没有评论就通过；跨账号切换和撤权；72 小时重复/空转率与真实成长因果。

仍保持 `releaseReady:false`，不合并 `main`，不 Tag，不发布。没有自动打开任何新社交权限。
