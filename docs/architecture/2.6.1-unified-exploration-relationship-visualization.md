# 2.6.1 RC2：统一连续探索与关系可视化（发布前增量）

## 生产接线与约束

可信已接受的只读 `search_videos`（主人、白名单或普通社交来源） → `executeOwnerTodo` 使用现有搜索工具取不超过三条真实 BV 候选 → 统一 `ownerTodos.add()` 持久化 `parentTodoId`、原始 `origin`、源身份与幂等 `sourceKey` → `AutonomousPlanner` 在同轮立即调用 `considerChildrenCore` → 每次独立模型决策、重新校验意愿与待办状态 → 执行/延期/放弃/沉默。`owner-ai-watch:` 旧子待办兼容读取，新子待办记录使用 `explore-watch:`。单轮最多三次、30 秒；仍计入每日 AI 决策额度，不绕过时段、只读工具和平台权限。

`todo-lineage.mjs` 统一解析显式 `parentTodoId` 与旧前缀；任何 UID、来源消息不一致的子任务组停止连续考虑，不可以凭单一父 ID 将不同人的请求混合执行。搜索若未产生子候选，普通来源仍保留原有单任务回访资格；若已产生子候选，则等待真实子任务终态再考虑一次汇总回访。完成回访仍由 `owner-todo-followup` 根据真实原请求核实合并，原评论/私信权限与 `sent/uncertain` 不重试保护不变。

## 关系权重及页面

`SocialRelationshipIndex.preferenceHint(uid)` 返回无权限含义的熟悉度与阶段；`rankAcceptedTodos` 形成 `relationshipContribution`（熟悉度 × 0.42）、`identityContribution`（已有来源起点）、`recencyContribution` 和 `waitingContribution`（防饥饿）。这些信息与总参考优先值由 `/owner-todos/page` **只读**投影到管理页，不写回任务账本，不增加 AI 调用；执行前 `DualContextAgency` 仍可拒绝或延期。数字只代表候选优先顺序的辅助参考，不能推断真实好感度或任务强制履约。

「逐渐熟悉的人」在桌面双列、手机单列；简要模式保留昵称/UID、关系阶段、熟悉度、跨天互动和最近活动。展开查看往来方向、活动新近程度、关系阶段、权限边界、记忆衰减参考周期及谨慎的互动印象。现有关系索引**仅有 UID 和互动元数据**，并不包含足以可信刻画性格的言语证据，因此不生成肯定式人格标签。若未来有经严格隐私筛选的、明确来源证据，可在统一社交投影中单独设计低敏、可撤销的印象，不得从私信正文或永久审计存档推断陌生人画像。

界面新增统一彩色可辨按钮、页面顶边细彩条、暗色/移动端对比度与折叠状态。保持全部原控件 ID、HTTP 路由、用户配置及低频设置不变。README 只给简短功能说明，详细本次变化留 CHANGELOG 和 Release Notes。

## 回归矩阵

- 主人旧 `owner-ai-watch` 与普通用户 `explore-watch` 子任务共用同轮自主决策；每日预算消耗与自主跳过；来源不一致阻止继续。
- 普通用户原消息源 UID / messageId 保留，三个子任务不产生三条强制外发；合并仍要二次校验原请求来源。
- 熟悉度、角色起点、新近度和等待补偿在只读分页展示；数值不改变实际权限和持久任务。
- 双列/单列、折叠、夜间样式、回访按钮与上一页下一页对比度；不主动查询无限昵称或未观察用户。
