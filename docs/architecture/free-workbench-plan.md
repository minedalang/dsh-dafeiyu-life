> **最新产品决议（源码候选）：** 维护者已选择方案 C，取消互斥的全局使用模式，默认推荐自主生活与 B站接入，记忆独立于平台准入；保留安全代际与原数据。后续 dev.24 按 [统一能力架构实施方案](2.8.3-dev24-unified-capabilities-plan.md) 收口。以下原双模式接线内容是历史设计，不再作为目标产品规格。

## 1. 2.8.3：原记忆基座模式（历史设计）

只提供自主生活（默认）和记忆基座两种预设，复用原有具体开关。旧用户升级保留原模式、配置和 Session。记忆基座保留原人格、消息历史、其他插件以及原有能力授权；不主动注入插件人格、改变表达方式或接管生活调度。独立核对宿主挂载、自动记忆提示、消息合并、后台活动、主动联系人、经历同步和已有权限入口，逐项验收后才启用模式。关闭介入不等于删除记忆或授予新权限。现有按需工具和用户已授权活动应继续可用。切换须显式确认且可恢复。

### 已确定的产品与内部名称（候选 UI 已接线）

- `autonomous-life`：**自主生活模式**（原完整生活模式），保留原自主生活与记忆能力，旧用户仍默认此模式。
- `memory-foundation`：**记忆基座模式**（原自由协作模式），副标题「记忆与能力基座：保留长期记忆、联想、人格历史和按需工具，不主动接管生活或改变主 Session 表达」。不是无记忆人格、不是总开关；不自动授予其他 Agent 私密记忆读取或 B站权限。独立首次设置、跨类别检索及其他 Agent 的实际宿主授权仍待验收，不承诺尚未实现的跨插件共享。
- dev.24 收口候选已接入主人确认与重启生效的模式配置，统一采用清晰内部枚举 `autonomous-life` / `memory-foundation`；旧开发枚举不再接受，缺省仍为自主生活；无模式字段的正式旧用户不需要迁移。

## 2. 分类记忆：同一身份库，不混淆事实和经历

当前分类：浏览、学习、创作、工具使用、其他经历。明确自主记录来源，原事实与真实观察不变；先私密本地回忆、后逐步验证跨种类联想。若未来接入关系网络，双端来源必须可区分，不能把自述升格为已核验观察。其他记忆插件可独立共存，不自动导入或合并。保持原有备份和衰减契约，避免长篇网页、技能脚本或未验证权限进入记忆。

## 3. 自由工作台：优先 2.9.x 的首个技能管理里程碑

不新建第三方插件注册、事件总线、浏览器或独立执行引擎。先探测宿主当前实际可用的工具、工作区和技能目录（路径及接口须由实际宿主验证）。鱼鱼自主选择学习目标，可以阅读说明、整理步骤、尝试已授权的低风险操作、记录真实结果和改进技能。技能管理采用宿主支持的文件形式（如实际支持 SKILL.md 时使用），避免另建一套执行体系。

| 工作台功能 | 设计 |
|---|---|
| 能力清单 | 显示工具名称、用途、可用/缺失/需授权、来源；不自动获取额外权限 |
| 学习记录 | 复用 `learning` 和 `browsing` 自主记忆，区分阅读、练习、成功验证和失败 |
| 技能卡片 | 名称、目标、版本、依赖工具、权限需求、验证记录、来源、标签、启用状态 |
| 技能文档 | 在实际授权工作区保存步骤与注意事项，与记忆摘要分离；不自动执行网页指令 |
| 练习验证 | 优先只读或隔离操作；失败真实记录，禁止把未执行操作标成掌握 |
| 维护 | 自主提出修改；支持查看、版本比较、禁用和删除；权限撤销时技能不可运行 |

例：鱼鱼想学浏览器。先检查已有浏览器工具；有权限就阅读公开文档并练习网页导航，记下学习摘要，在工作台形成技能草稿，经过验证才标记可用。没有浏览器工具，就标为缺少能力并可向主人提出申请；不凭记忆、技能文档或网页内容安装插件、改变系统权限、绕过确认。发送、发布、购买、删除等有副作用操作仍遵循原宿主及主人授权。

### 宿主接线契约（第七批取代前六批的固定模式）

1. 唯一模式事实源为既有主人确认的宿主配置；旧配置无模式字段保持 autonomous-life。不得由模型工具、导入文档、未信任网页或记忆选择模式。宿主须验证持久配置与当前授权，旧宿主退出后新进程激活并递增代际，并同步调用 `refreshSessionMount()`；出错不得偷偷回退至 autonomous-life 并恢复自主活动。
2. `createLongTermMemory` 新的可信注入 `getSessionIntegration()` 返回 `{mode:'autonomous-life'|'memory-foundation',revision:非负安全整数}`。旧宿主不传参数，默认 autonomous-life/0。异常策略或无效值拒绝挂载。旧回调检查当前绑定、策略、代际，不能靠切回旧模式继续读取。记忆基座挂载不注册人格、多气泡、情绪、自动上下文或待办提示；显式工具复用原接口与数据。记忆基座中的事实写入及新待办仍需要本次挂载后可识别的主人消息；插件/内部消息不可作为新依据。真实宿主事件来源需要进一步核验。
3. 暂停后台不是停止插件进程或抹去开关：宿主须在原调度、事件快唤醒、主动联系、经历同步和消息发送的实际入口复核有效模式，停止新自主任务，处理在途读取、模型调用和待确认写入；不得撤销已经完成的外部操作，未知外发必须冻结。保留已授权的显式只读/生活工具和原待办门禁。恢复完整生活必须重新核验权限且不重复执行积压事项。原配置和数据不改写。
4. 当前完整源码中 `index.js` 向原记忆挂载和 `createMainSessionBridge` 传入同一 `getSessionIntegration`，缺省 autonomous-life/0，由持久宿主策略提供。`session-integration-policy.mjs` 统一校验；桥接层禁止协作模式自动收集（包括强制补写）、同步（包括手动强制汇报）、主动联系、短暂停顿、情绪分享、私信历史读取及注入；旧观察器及等待中的读取/意愿复核代际。已交给宿主的成功注入正常结算，原队列/身份/权限不清空；未知结果的跨模式恢复仍须在宿主切换事务中验收。
5. 当前重启事务、UI、独立本地记忆及显式跨类别召回已接线，实机核验仍须覆盖所有后台与平台入口。备份恢复不自动切换模式；跨类别关联不得把私密自主记录提升为公共核验证据。即时热切换及第三方共享未宣称实现；无 B站账号的可选模型检索/凝练已接线，须独立验证及真实模型验收。

### 记忆基座的活动可观测性边界

dev.24 管理界面按实际生效模式投影，不在记忆基座显示 Life 自主行动树。当前只展示已有记忆工具挂载、长期记忆计数、最近检索状态；无完整原 Session 活动事件流。后续工作台若新增活动树，应使用受授权的真实工具生命周期与执行回执，区分计划、进行中、成功、失败、未知及自述，不扫描任意会话或将旧 Life 轨迹冒充工作行为；仍复用统一记忆与权限。
