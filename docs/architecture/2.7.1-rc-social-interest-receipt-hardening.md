# 2.7.1-dev.7 · RC 社交兴趣接线与主动视频私信事务加固

> **状态：已完成离线代码集成；仍未完成正式 Life 社交决策权迁移，不能封 RC。**
>
> 变更仅以 `DSH-2.7.1-dev7-RC-organic-life-full-source.zip` 为补丁基线。没有新建兴趣、记忆或人格账本，也没有新增用户外发权限。

## 一、从真实兴趣到社交表达

1. 鱼鱼的公开视频自主选片继续写入**现有** `life-memory/interests.json`，旧账号、匿名历史、主人指定核心偏好不因升级而被“证实为喜欢”。
2. `scopedInterestOpportunityEvidence(stateDir, trustedLifeAccountTag())` 只选当前已核验账号，要求**至少 3 条自主选片、横跨至少 2 天**，并返回 `interest-milestone`。失败只取消兴趣线索，不取消本轮正常对话。
3. `projectLifeSocialInterests` 再严格约束证据来源、数目（最多三项）、主题字符、阶段与长度，不携带 BV、UID、好友私信、评论原文或角色档案。兴趣是“可能想继续探索”，不是观看、听音、喜欢或与别人有共同兴趣的事实证明。
4. `SocialContextAssembler.message` 只对已核验互动者按条附加 `publicInterestEvidence`；遇隐私拒绝请求、未验证发送方或读取异常均不注入。`InteractionBatcher` **完整模式和精简模式**都读取这条证据，并继续从**同一 Life Voice**取得当前人格/情绪/关系语境；模型仍可选择沉默。
5. 此机制只影响**目前旧回复处理器调用模型时的参考**，并不把 `socialDecisionOwner` 改为 `life`；新兴趣线索不能授权联系其他人、私信、评论或 @。

## 二、所有旧社交外发入口归属复核

`legacySocialWrite` 是主人私信回执、视频兴趣分享、待办回访等多个入口的共享外发适配器；过去它只取得 `socialHandoffFence` 旧操作占位，没有直接复核 `socialDecisionOwnership.route()`。

现在它在占位前、以及真正调用写入适配器前均检查**当前账号 + 渠道旧 owner**。失败返回 `ok:false,no_retry:true`，不触发平台写入；占位与跨进程隔离仍由原 `SocialHandoffFence` 管理。此变更避免后续接管时出现旧发送旁路，但不能替代对所有 Python 和主人 Agent 外发的最终逐路径审核。

## 三、视频兴趣推荐私信加入原跨进程发送事务

原 `social-intentions.json` 提前预约草稿只能保护它自己的进程/文件，不能替代共享 `SocialSendTransaction` 对同一来源的跨进程防重复写入。现在在原白名单、平台授权、冷却、事实校验之后，真正调用 `bili_send_message` 前：

- 验证账号绑定和 `social-intent:*` 稳定来源；以 `video-recommendation:${uid}:${eventId}` 入**现有匿名哈希发送事务**（原文/UID/平台回执不落明文事务文件）。
- 必须取得平台 DM 真实回执 ID (`extractBiliDmReceiptId`) 才能确认完成。`success:true` 本身不是足够的成功证据。
- 网络错误、回执缺失、中断都视为不确定；同一稳定来源不允许自动重试，必须人工核查平台真实发送结果。
- 不更改 `SocialIntentEngine` 原有草稿、发送意愿、好友限额、授权或 `sent` 状态语义；也不因此允许 Life 提前向好友发私信。
