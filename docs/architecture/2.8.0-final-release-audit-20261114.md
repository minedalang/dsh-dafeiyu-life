1. **全量 Node 失败仍未完成归因与收口。** 逐条建立 `旧断言已失效 / 真实回归 / 环境不稳定 / 历史遗留` 记录；对应修复和测试迁移后，最终在 Node 22 / Python 3.11 的 GitHub Actions 上完整通过。
2. **Windows / DSH / Headless 实机。** 验证启动、主 Session 绑定、旧配置迁移、Embedding 安装运行索引区分、管理页窄屏/暗色、SSE 断线及 4 秒对账、日志 BAT 生成的 `diagnostic-coverage.json`。
3. **受控 B站平台端到端。** 只读观察、评论/私信/动态自主决定、授权和撤权、拒联、账号切换、限流与超时、平台受理/真实可见回执分离、未知发送冻结与重启不重复；在取得明确授权的测试账号上完成。
4. **72 小时长期运行。** 核对视频 Agent 委派、原创主评论意愿与回执、自然私信续行、快速检查、网络退避、CPU/模型调用、轮转日志和缺失诊断。观察「不行动」同样重要。
5. **2.7.x 老用户数据迁移/回滚。** 停机冷备份、迁移预览、账号与 UID 隔离、记忆/待办/关系与发送账本、遗忘内容不会复活；失败时可从备份安全回滚。
6. **发布流程。** 现有 `.github/workflows/release.yml` **只创建 GitHub Release 和各平台 tarball，不执行 `npm publish`**。稳定版 Tag 还要求版本字段精确匹配并且打在已合并 `main` 的提交上。本轮同时加强了稳定版的 README/Release Notes 预览文字检测：原先脚本只匹配旧文案，可能漏掉当前 `dev.16` 的实际提示。不能把 Tag 推送误认为 npm/DSHMarket 已同步发布。
