## dev.3a.2：自主选择观看深度 + 官方预览时间窗复查

本增量不执行“只要看视频就必须识图”的强制规则。最终自主权协议分成两个独立选择：

1. **是否了解视频**：Life 可以不看、休息、延期；主页/社交线索/视频 Agent 的候选列表不是强迫阅读的任务。
2. **选择了解深度**：已经决定看后，Life 可选 `skim`（元数据、字幕、讨论）、`standard`（自主请求视觉预览）、`deep`（自主请求预览和后续时间窗复查），且每步可放弃。无字幕仅作为可能需要画面的线索，不能自动提升深度。

原 `visionDecision()` 的“无字幕必须识图”被退役，`bili_watch_video` 提供显式 `view_depth`（默认为略看；旧的明确 `visual_question` 兼容为普通视觉请求）；Life 自主待办的模型选择可直接携带 `viewDepth`，执行器仅按当轮选择执行，不能二次强制调用。对非视频 TODO 不开放视觉深度参数。

`bili_preview_vision` 可在确有进一步观察意愿时传入 `focus_start_seconds` 和 `focus_end_seconds`，二者必须同时指定，且时间范围在 0～12 小时内、时长 3～120 秒。不带参数时继续执行已有的最多三帧全片官方低清预览。局部复查仅从现有 B站官方 videoshot 时间索引筛选窗口内帧，固定白名单/资源大小/重定向限制不变；没有窗口内官方预览时返回失败，不合成也不编造画面。局部缓存采用精确起止毫秒后缀与独立采样版本，不能跨窗口误命中。独立 DSH 子会话必须返回同一窗口的图片工具回执才能视为成功，Ollama 在本机进行有限视觉分析。

### 证据及验收

- 新采样策略 `focus-window+local-thumbnail-difference` 版本 3，保留时间窗毫秒范围、被采样帧时间、候选数与去重统计；**不代表完整视频解码、实际播放器观看或音轨理解**。

# 2.8.1-dev.3a.1：自适应预览缩略图采样（首批实现）

> 2026-11-14 开发增量。基于已应用的 dev.2c Patch。仍是只读低清图片，不是解码、观看或完整理解视频。本阶段没有改正式 npm 版本号或实际在 B站发消息。

## 完成范围

以前按照活动峰值/时间分布直接获取最多三张预览快照，可能三张来自相同画面。现在：

1. 仍用 B站官方 `/x/player/videoshot` 的时间索引（JSON / `.bin`）；沿用受限图片域名、资源大小、重定向、防目录穿越和视频 BV 校验。
2. 根据既有高能/时间主索引，只在**原本必须下载的官方拼图内部**扩展最多 12 个候选，不访问其他拼图，也不增加完整视频下载。
3. 本地 Pillow 将候选缩成 24×24 RGB 缩略图，计算低开销平均绝对像素差；以原活动/时间候选优先、差异与时序兼顾，保留 1～3 张视觉不同的快照。图片相同时只需要一张。阈值只是减重启发式，不等同真实镜头边界。
4. 返回按时间顺序排列的秒级时间锚点；回执记录 `sampling.strategy`、`sampler_version=2`、候选数量、实际选择数量与来源拼图数。debug 下单独写入素材索引，证据 bundle 只接收经过上限钳制的数字，不保存图像字节。
5. 无论 DSH 独立只读视觉子会话还是 Ollama，本轮视觉分析只接收选择后的最多 3 张图；历史算法缓存不再直接复用，避免把旧描述错当成新采样结果。

## 不包含

- 不是 PySceneDetect 式真实镜头分割：没加载全视频，也无法确认未在播放器快照中出现的动作。
- 不提取音轨；既有字幕与 ASR 仍有独立证据类型，不与画面混同。
- 不增加模型调用频率、公开评论、点赞或私信权限。
- 没有新引入 `dsh-video-storyboard` / `dsh-see-now` 代码；只是以其思想为参考独立编写的缩略图差异去重。
