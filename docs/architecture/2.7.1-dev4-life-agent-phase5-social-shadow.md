# 2.7.1-dev.4 Phase 5（第一段）：授权社交上下文与只读影子决策

> **已接入生产代码，未开放真实社交决策交接。** 这是 Phase 4 上的受控增量。Linux 离线测试不等于 Windows、真实模型、B站或跨进程发送验收。版本仍为 `2.7.1-dev.4`。

## 统一层归属及新增层理由

| 项目 | 现有唯一来源 | 本阶段接线 | 非职责/限制 |
|---|---|---|---|
| 入站消息核验、私信/评论游标 | `dm-autoreply`、`comment-interact` + `SocialInteractionCoordinator` | `index.js` 原 `onIncoming` 在成功记录后，生成原短期匿名生活事件 ID | 新层**不**自行读取 B站、不保存新收件箱、不控制已读游标 |
| 当前账号与联系人角色 | `accountBinding` + `SocialPolicyGate.actor` | 仅当前 16 hex 账号范围，好友普通私信与已核验的公开评论 | 不读取主人专属 DM、陌生人私信；人物熟悉度**不是**发送权 |
| 意愿与同一人格 | 原 `AutonomousPlanner` + `lifeVoiceContext` | 自主选择 `consider_social` 后，才可在**单独手动 opt-in**下查看验证过的短文本，并调用原模型作一次分类影子判断 | 不是新生活心智、不新增定时器；模型只能返回 `reply/defer/silent` 的枚举，不能作工具调用或外发草稿 |
| 平台发送权限与真实回执 | Phase 4 `SocialDecisionOwnership` + 原回复器、安全闸及执行回执 | 原旧回复器生成结果可与影子类别作内存对照 | 所有 `off/shadow/active` 仍由 **legacy** 唯一决定及发送。没有跨进程 handoff，模型输出不能夺取所有权 |
| 短期隐私生命周期 | 原 DM 保留期是 14 天（独立源） | 新增 `lib/life-social-shadow.mjs`：独立**进程内** 10 分钟最多 80 条、每条最多 420 字的临时阅读缓存，关闭授权清空，切号不可见 | 无磁盘写入、无 UID/聊天内容的管理诊断；不替代原私信清理、更不写人物画像/记忆/任务 |

为什么允许新层：原 `life-agent-events` 只能保留匿名事件，**不能**承担短期私密原文读取；原 `SocialContextAssembler` 服务真实社交回答，直接复用其全部会话上下文会扩大 Life Agent 的授权。本层专管只读、按事件的临时隔离，生产同时接入 DM 与评论，UI 与模型回调均复用同一 API，没有第二份事实或发送账本。

## 实际流程及安全门禁

1. 默认 `lifeAgentSocialContextOptIn=false`，无论 Life Agent `shadow/active` 都不能读取正文。用户必须在管理中心单独选“允许只读影子对照”，保存时会再次确认；`off`、总开关关闭及账号冻结时自动关闭读取。
2. 原成功核验的消息先由 `SocialInteractionCoordinator.record` 入账，随后产生 Life Agent 匿名唤醒。**只有这次成功回执**和合法角色才允许把最短必要的文本暂存进程内。原事件 ID 与账号作用域必须一致；非法来源/旧记录/缺失用户身份不允许预览。
3. 第一次自主模型调用仍只见到匿名事件。**只有当模型选择已有 `consider_social` ID**，并且该事件的临时内容仍有效，才考虑第二次模型调用。第二次调用在原自主调度**每日次数**内预先计数，额度不足只保存 `social-shadow-quota`，不额外调用；不另造模型池。
4. 第二次模型提示标明外部原文不可信，只请求 `reply/defer/silent` 分类。执行后复核当前账号、授权和事件有效期；被撤销则丢弃输出。分类结果在原 7 天匿名时间线只保存**结果码**，不保存原文、对方 UID、草稿、模型解释或事实主张。
5. 原 DM/评论回复器继续独占所有权与原发送门禁。其生成结果可与同一源事件按临时哈希匹配；管理中心展示内存短时统计（暂存数、两边选择数、可配对数和类别差异数）。匹配不到只说明无法对账，不代表真实收到/发送与否。

**隐私风险**：开启后所选文本确实会进入配置的模型调用，可能消耗模型服务额度；它只在本插件端不落磁盘，不保证第三方模型服务不会留存请求。**不应视为零数据外传**。关闭会清空本进程临时缓存，但不能撤回已经发往模型服务的请求。模型请求期间切号/撤权会拒绝采纳其输出。测试不使用真实模型。

## 跨入口及回归矩阵

| 场景 | 必须满足 |
|---|---|
| 朋友普通私信已验证 | 开启 opt-in 后且事件在十分钟内，按本账号事件 ID 只读；不附带聊天历史；模型即使选 `reply` 也不发送 |
| 陌生人与主人私信 | 不缓存、不能通过匿名 ID 反查；原主人 DM Agent 权限不变 |
| 公开评论及 @ | 已核验原来源且身份有效才能暂存；动态来源仍由旧 `dynamicVerified` 判真；不能产生评论发送权限 |
| account A → B / 关闭授权 / 冻结 | 当前账号上下文失效；已有模型异步输出不得被记为鱼鱼已决定或发送成功 |
| 超过十分钟 / 无可用事件 | 预览失败，无第二模型调用或补读旧私信；短期统计自动收敛 |
| 原回复器 vs Life Agent | 分类仅可短期对账；原评论/DM 唯一决策发送链继续存在，跨进程 handoff 未开始 |
| Token 消耗与隐私 | 最多每次 `consider_social` 一次额外已计数模型调用；真实费用、延迟和对话质量仍需进一步测量 |
| 旧配置及备份 | 旧配置读取时默认 `false`；不改变用户数据 schema、便携备份/冷快照内容及恢复冻结。原配置切换可回滚。 |

### 管理中心可见但暂不要求真实 B站验收

「鱼鱼想做的事 → 自主待办调度设置 → Life Agent → Phase 5 社交上下文影子对照」默认关闭。开启后可查看短时类别对照数量。若真实收件少、鱼鱼选择沉默、没有可用账号/授权、或额度耗尽，统计可以为零，不代表代码必定失败。用户不必为了产生样本而给陌生人发消息。

正式社交接管必须继续设计**跨进程原子决策所有权、旧收件游标/发送事务幂等、未知回执冻结、崩溃恢复、单渠道灰度/撤回**，完成跨进程故障注入并在用户明确授权的安全目标上进行真实发送验收后才考虑打开。当前没有社交 handoff 的任何开关。其他主动分享、回访、主 Session、Python 视频 Agent 的对外写入并不在本次 shadow 对照范围内。
