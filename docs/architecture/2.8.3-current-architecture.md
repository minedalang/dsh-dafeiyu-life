# 大肥鱼 2.8.3 · 当前系统设计

本页是 2.8.3 功能范围的当前入口。源代码版本以 package.json 为准，发布状态以独立渠道及验收记录为准。旧 dev 文档是历史快照。

## 统一 Life 及执行约束

一个角色、一个 Life 调度所有者；机会、意愿、已接受任务和真实执行结果分别记录。`index.js` 负责接线，`lib/autonomous-planner.mjs`、`lib/life-willingness.mjs` 决策，`lib/interaction-scheduler.mjs` 与原平台执行层共享预算、账号代际、拒联及去重。成功必须有真实平台回执，未知发送结果不能盲重发。主人私信定向150/30秒，普通哨兵与自适应检查不变。新装建议不等于外发许可，旧缺键保守、换号授权重新核验。

## Agent 工具运行时（dev.52）

dev.52：主 Session 31 个原只读入口（26 个 B站/宿主及5个记忆/待办/观察工具）与社交15、后台 Episode 8共用注册及执行网关；仍由原适配器及绑定范围核验。评论模型选中的热评及评论者投稿不再经过第二次意愿投票，分别复核真实入站来源、当前账号、active、隐私及原平台预算。不扩大任何写入、私密披露或主动联系权限。注册路由不是独立能力数量，宿主循环仍独立。 见[完整工具清单](life-tool-inventory.md)。

生产私信（主人、好友、陌生人）与评论的 `interaction-batch.mjs` 共享 `life-agent-read-runtime.mjs` 的工具描述、实时菜单和每项6轮/8次工具调用/每次4种预算。原模型根据回执选择后续工具，不按渠道设固定步骤；精确分镜需要已核验清单，分享和公开评论仍由原生产加载器校验目标、账号和权限。累计交付证据不受单次四种请求裁剪；除记忆工具外已消费能力退出本轮菜单。记忆可按不同规范化参数最多读取3次，每次计入调用预算并保留单次证据（最多1200字符）和结果状态，所有既有视觉证据需继续有效；主人独立拒绝披露时清除全部读取材料。未终结或越界拒绝外发。工具成功不代表同意披露或行动完成。

后台 Planner 的现有 Episode 续行已接入社交只读运行时的参数防重与原公开活体视觉记忆网关。模型可自主选择 `recall_public_experience`，每次最多3条词，同次续行至多2个不同检索，且保留下一次决策的局部预算、原最多4次子决策及每日额度；无命中、不可用及累计证据交回同一模型。历史证据只保留在本次内存，读取、交付和决策后复核活体证据及账号；不算新观看、Episode 业务步骤或写许可。主 Session 继续使用原宿主 Agent；Video Agent、后台 Planner 的视觉/写入等专业路径、反思及历史 owner-dm 专业循环尚未全面迁移。同一分享视频 Episode 的当前有效延期观察意愿由原 Planner 继续传给子决策，不复制私信或身份、不强制执行。工具写入、跨轮任意工作流仍待接线；dev.51 主人原分享视频回聊见下。不增加账本、调度器、模型身份或授权。

社交15种只读能力和后台六种已接线 Episode 只读路由共用 `registeredLifeRead` / `executeRegisteredLifeRead`：回忆、精确 BV 资料、作者投稿、首页推荐、评论者投稿及公开讨论。相同工具族仍保留各场景的权限、具体目标及原参数协议；只有当前动态合法菜单才进入执行，不从注册表自动开放能力。社交按批、后台按单个选择复用原 `executeChosenLifeRead`。后台执行前后复核有效会话、账号、Life 开关、Episode 原来源及状态、当前菜单精确候选、相关能力和原活体记忆。失效的结果（含异常）不进入账本、不触发本次额外续行。原平台/记忆执行器仍独立核验真实回执。`life-read-scope-changed` 为失效读取阻断，不代表工具成功或鱼鱼拒绝。统一的是上述只读调用契约，不是全场景同一个物理模型循环；通用任意参数、统一注意力、跨轮恢复和通用主人回聊仍待接线；本批视频路径见下。

dev.50 在原六种后台非视觉读取之外接通 `observe_video` 与 `focus_video`；工具说明由相同注册目录投影，仍仅能选择当前已核验 BV 和原可信全局观察中的片段候选。使用原租约、专业采样、预算和回执；模型菜单建立时保存原契机的原始字段快照，模型返回及每次 I/O 前后复核，休息/延期也不得落到已替换契机。视觉资源等待后及专业感知器记忆/相册写入入口使用同一 `isCurrent` 检查。已开始的物理 I/O 或已提交的有效事务不强制撤销。原资源调度器默认一个模型槽；账号持久标签之外增加原绑定运行代际，获准至开始回调间再检查。原宿主互动模型返回复核代际和会话，失效响应不供下游决策，不冒充未开始调用。此处仍不是单一全局模型循环或任意工作流暂停恢复；dev.51 仅接通以下主人原分享视频回聊路径，其他社交写工具仍待接线。

### dev.51 原主人分享 → 真实观察 → 自主联系

唯一决策者仍为原 Planner。只在正常 Life 轮次（非社交快唤醒、非专用待办/契机轮次）提供一个最近的主人直传视频来源：24 小时内、原分享具有 `observe_video` 延期意愿、原 `friend-shared-bili-link:<id>` Episode 有同 BV 的真实采样步骤、原活体 Gateway 仍有对应清晰公开视觉证据。用真实 Episode 判定已观察，用 Gateway 判定当前仍可用的记忆（不以同 BV 历史缓存证明已观察）；有界采样描述是模型观察而非独立事实。只提供公开摘要，草稿不进入 Life 决策账本；可跳过，不强制看完/回聊，也不转待办。

现有主动联系、主人私信沉默续聊和主人完成回访授权须同时明确启用，其他 Life、账号、DM、记忆和联系时段/额度仍生效。三项旧授权的交集用于保守准入，不改变旧默认。原 `talk_to_owner` 候选区分主 Session 与 B站主人私信。模型自然表达（5–180字）与意愿一次选择；复用原 `LifeWillingness` 一次性封装（`followup` 精确来源、收件人、文本），不再调用模型。通过原私信探针核实链接的原消息哈希；后来任何主人消息（包括非文字）使旧话题不再自动续接，无法重新找到原消息也不发。占用同一个主人联系账本，发送等待后重新读取收件箱，MCP 调用前再检查账号代际、权限、原来源、活体记忆与凭据期限。原社交发送事务冻结不确定结果；只有平台实际消息键确认才能记为 `owner-chat-confirmed` 并向原 Episode 投影，不以主 Session 的入队回执替代。已提交外部操作不保证可撤销；没有新账本、优先级或额外发送权。该路径只支持这个视频观察场景，非通用工作流恢复。

## 观察、记忆与成长

真实视频事件 → 核验观察与时间码 → 浅层经历 + 有界深层视觉附件 → 当前活体网关 → 合法检索/实际交付 → 自主选择、反思或原文采用 → 有证据的认识/联想/有限强化。永久档案是管理与备份数据，不进入日常 AI。容量3200（组内观察计入），优先淘汰遗忘占位、兼顾重要度/证据/时间；遗忘撤销深层与向量。新记录不从历史档案恢复。长期记忆与分类自述独立，私密域不进入公开社交/联想。

`life-memory-gateway.mjs` 是活体证据边界，`memory-retriever.mjs` 管理词法/本地向量/有界候选，`life-reflection.mjs` 与 `life-memory-associations.mjs` 验证独立认识和关系；图谱是投影，不是第二事实库。完整 BV 严格匹配，`visual_query` 反查画面，`detail_bvid` 读取现有附件不联网；新补看是独立真实观察。当前有界强化只覆盖已核验公开即时联想、深层反思有效续答及主 Session 已提交回复的原文采用。每条每日一次、累计最多20；非引用释义、其他普通渠道不普遍强化。自动反思成功最多恢复同域两条暂停候选，各一次补救、12小时退避。七日变动仅真实计数，不补历史。

## 能力与模型

B站、自主生活、人格、自动记忆、经历桥独立配置，保存重启按代际生效，旧在途按回执结算；本地记忆可无 B站使用。模型实际验证和能力门禁独立。无工具调用优先直接模型路由；后台 Headless overlay 禁用宿主已知会话持久化/投影，禁止续用正常聊天，不触碰全局配置或历史 Session。实际宿主兼容性需实测。

## 存储与诊断

V2 只迁移 Whisper/Embedding 大模型，核心 Python/uv、Life 数据和临时缓存不随大型模型迁移，Ollama 独立。原件保留、校验后切换；仅回收本次独占创建、未发布且确认失败的临时目录。旧 V1 仅兼容维护，整盘冷备份不属于本版。业务备份、记忆备份、完整诊断分别管理；自动业务备份先核验同角色文件才轮换最近两日。业务恢复以 `data-backup.mjs` 的分类策略为唯一入口：先验原始格式、完整性、角色及当前设置，生成分组差异与记忆聚合统计；确认时重新计算 revision，保存恢复前备份，再用原配置校验和 persistCfg 写回。人格兴趣、规则、记忆反思、读取检测频率、视频偏好及诊断参数可选恢复；文字模型必须具有当前 Headless 连接回执，Whisper 需当前缓存和运行环境；生活方案沿用原 planner 与当前准入。旧环境路径、视觉验收状态、账号授权、主 Session 绑定、历史任务和数据库保持当前；独立记忆入口仅修复有精确活体父记忆及撤销账本证明的缺失深层附件，同角色完整业务备份可作为来源。不支持缺失核心账本的灾难恢复，不能凭历史备份区分意外丢失与主动遗忘。失败保留保护备份并尝试回滚。SQLite 一致性快照不等于跨库原子快照。实时诊断记录插件实际报告的版本与主人定向检查的非身份聚合状态；无实际加载版本/实时状态证据时不把旧副本当当前版本。

### dev.38 运行总控、日志与分享视频

- 顶部自主生活开关与生活方案共用 `lifeAgentMode`/`autonomousPlannerEnabled`；保留原节奏，暂停自动人生反思，不影响显式手动回忆/反思和独立互动回复。互动回复开关暂停后台私信（含主人优先检测）、评论及 @ 回复；现有各渠道授权保持，重新开启不产生新授权。插件内手动私信、评论回复也受此暂停，独立原创主评论不因这个开关直接授予或撤销授权；共享 Life 发送通道暂停期间不出站。已提交平台请求仍按真实回执收口，未知结果不能自动重试。
- 日志页提供固定四个本机日志的有界分类摘要、错误筛选及 JSON 导出（每文件最多 8 MiB，最多 20,000 条导出；不含原始正文）。完整错误溯源使用现有 `tools/导出B站日志.bat`，日报 Markdown 及内部归档保留。日志分类不是完整错误审计，缺失/轮转/超限明确展示。
- 神经回忆场仅保留六类节点筛选，情绪依据活体证据；桌面画布/容器高度 1.5 倍，窄屏适配。
- 主 Session 已有 `bili_watch_video`（standard/deep 依能力）；主人/授权好友私信经 `shared_link` 真实元数据核验后可在同一轮自主选择 `shared_video`，仅对已验证同账号同联系人目标，复用共享读预算、视觉租约、标准感知。只交付实际验证的代表画面和/或字幕文字，非完整播放。历史画面仍可经现有记忆工具按需回忆，陌生人/评论仅保留原受限菜单。真实宿主工具注册、视觉及平台外发需短时验收。

### dev.39 自愿读取与主人交互收口

角色自主读取以模型明确选择为依据，执行前后复核当前范围；自动记忆/待办上下文改为能力提示，社交生产读取采用按需模式。管理维护不经角色意愿投票。主人私信可选择当前账号真实观察清单、按证据保存当前主人明确事实，复用原身份记忆及额度；缓存清单不含图片字节。保留现有授权和意愿执行门禁。业务恢复字段级选择（依赖组合原子化），运行日志事件归并并提供安全诊断分类。旧备份格式不变。完整图片发送、全渠道工具对等及网页完整诊断包仍待实现；真实宿主验收未完成。详见 [交互场景与工具能力指南](../interaction-tools.md)。

### dev.40 主人观察图片与待办

### dev.45 私信自主延期探索（第一批）

生产 `interaction-batch` 模型可在准确 `deferredExplorationCandidates` 内自主选择 `read_link` 或受信 `observe_video`，区别于具体承诺的 `suggestedTodo`。原 `life-shared-bili-links` 账本添加可选、有限的 `deferredExploration` 目标与时间，复用同一账号锁；不保存私信正文、原始 URL、模型话术，不另建任务/记忆/发送账本。入账前核验真实当前来信、候选、账号代际、同联系人角色、现有共享链接权限和视频 Episode；失败同模型修订而非固定回复。原 planner 在动态候选视图提供目标，不新增执行器、唤醒、发送或强制优先级。公开资料读取成功清除 read_link 意愿；observe_video 仅在原分享 Episode 尚无真实观察且仍可继续时投影，原核验/冷却/暂停/放弃生效。陌生人只能选择原获准公开链接读取。已完成探索后联系主人的新专属 DM 路由、非链接工具延期及完整工具自然性尚未接通，具体设计见[交互工具指南](../interaction-tools.md)。

### dev.44 分享视频跨轮感知

### dev.43 社交待办回执与探索候选

同一社交 Life 模型负责完整语义理解、自愿接受或拒绝与自然回复。准确本轮 BV 是程序核验的来源锚点，不是意图分类器；无真实来源、未接受或权限拒绝不能入账。结构化接受未持久化须交回同一模型有限修订，主人来信无回执回复须声明是否承诺本轮未来只读行动；原事实保护仍在，不声称可独立验证所有自然语言语义。原账号待办账本与 Life 调度不变。未结束同主题兴趣探索只保留原延续候选，不因阶段变化或短期冷却结束重复搜索。真实模型、Windows 和管理页三类库存仍待实机。
