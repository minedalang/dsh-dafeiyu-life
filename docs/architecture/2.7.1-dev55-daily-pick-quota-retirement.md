# 2.7.1-dev.55 · 历史每日选片额度退休（开发预览）

## 现场证据与根因

用户在 2026-11-10 的两轮视频报告里观察到：当日累计入选可能超过 50，Agent 自行把「额度满」当原因，只调了一次 `bili_home_recommendations`，不查 `bili_video_info` 或字幕，10 条候选只凭标题记为跳过。**尚未获得机器上的完整判重表/原始调度日志，不能核实确切当日入选条数。**

源码显示：`index.js` 的 `runDuty` 已不在 `perDay` 上拦截，`promptFor` 的现代说明也使用每轮软参考目标。但旧 `prompts/duty.md` 中「每天最多挑几条」「超过全天额度不再选」仍以最高优先级被复制进 `$DSH_HOME/bili-duty/duty.md` 并注入模型；`ensureCharter` 为保护用户改动会保留本地旧版。两套规则冲突，是足以解释现场行为的直接缺陷。

## 本次变更 · 唯一归属

| 链路 | 处理 | 不改变什么 |
|---|---|---|
| Life 选择 `browse_home` / 视频能力 | 移除 `reportLevel=off` 时每日一次委派的隐藏门禁 | 现有 Life 模型预算、账号及视频冷却 |
| `promptFor` 读取 `duty.md` | `normalizeRetiredDailyPickCharter` 只移除确认过的旧版每日选片额度句，随后追加 `VIDEO_PICK_POLICY` 消除其余冲突 | 不写回用户家目录，保留个性化章程 |
| 视频子 Agent 读取首页/搜索 BV | 旧“额度满/不明，只读标题”的 skip 允许重新详情/字幕取证 | 已真正读过、已入选、已评论的判重规则不变 |
| `bili_ledger_mark` / 日报 `### BV` | 继续记录事实，`countPickedToday` 仍供本轮增量和管理状态 | 不将历史入选数作为上限、不伪造已读证据 |
| `picksThisRound` / `perDay` / `pickPerRound` | 废止旧每日配额计算；保留旧函数签名和已保存配置的兼容 | 每轮柔性 `videoAgentReadTargetPerRound`、`videoAgentPickTargetPerRound` 不变 |
| 评论/点赞/收藏/关注/动态 | **完全不变**，仍需独立权限、额度和真实回执 | 不赋予 Video Agent 新的发送能力 |

入口 → Life Planner 候选 → 原视频 Agent → MCP 首页/搜索/真实内容读取 → `seen.md` 与报告 → 同账号 Life 事件。视频读取预算仍属于受控平台读取层；平台写权限归各自原适配器及 Life 写入门禁。没有新的统一层或第二事实账本。

## 验收边界

- 旧章程 `每天最多挑` 的句子不得在最终视频指令中继续生效。关闭日报不再限制每天只能启动一次视频 Agent；轮次仍有间隔及预算。
- 今日入选 50、100、未知时都不得因此停止 `bili_video_info`、字幕或入选。该行为由真实视频 Agent 自主决定，仍允许 0 条入选。
- “因额度只看标题”的历史跳过行不是已阅读证据；已发表过评论的 BV 仍禁止自动重发。
- 测试仅验证本地代码和提示词契约；真实 Windows DSH、B站、下一个自然轮次及旧家目录兼容仍待主人实机验收。`releaseReady:false`。
