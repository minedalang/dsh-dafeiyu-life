# 2.7.1-dev.3 · 三阶段统一执行协议（增量实现，尚待实机验收）

> 本文对应「视觉执行链 → 只读动作收尾 → 对外写入协调」的一次合并增量补丁。**统一执行并不意味着统一授权**，不会赋予新外发权限，也不是平台端 exactly-once 保证。版本不升、不发布。

## 第一性原则：决策、授权、预约、平台回执、经历事实是五件不同的事

1. 鱼鱼自主选择是否行动，不能代替用户授权；用户授权也不自动触发行动。
2. 同一操作的并发需要一个可验证的动作身份：**账号范围 + 操作类型 + 规范化目标**。纯只读取得资料不会证明鱼鱼已看完视频或听过音轨。
3. 只读动作完成时允许记录实际取得的内容；写操作必须更谨慎：网络超时不代表未发送，不能靠重试探测成功。
4. 真正的写入成功，必须有平台回执（评论 rpid、私信 msg_key，或关注状态的真实回查）；否则冻结并留待人工核查。
5. 已有私信/评论/关注授权、冷却、额度、审批、人工确认和安全提示不因新协调器而放宽。原账本仍拥有业务决策权。

## 第一阶段：视觉抓帧与模型理解分开

`bili_preview_vision` 的“抓取低清帧”通过 Python `public_read_reservation('bili_preview_frames', BV)` 预约；这段只涵盖 `preview_vision.analyze_preview(... enabled=False, return_frames=True)` 的网络抓帧。

**没有**在整个视觉 MCP 工具、独立 DSH 子模型或字幕缺失时的外层回退流程上加一把大锁：子进程可能递归调用视频工具，外层持有同一锁会造成自阻塞。原视觉开关、帧数、额度和安全模型约束不变。`frames_returned` / `model_description_returned` 仍是低清/待核实证据，不构成完整观看、真实听歌的经历。

## 第二阶段：可审计的公共读取和账号读取

Node `readToolAction` 与 Python `read_action_gate.read_tool_action` 复用相同动作身份、原子目录预约和锁回执。旧有搜索、视频详情、作者投稿、作者关注关系、评论列表、楼中楼、弹幕、字幕继续有效。

本轮新增（在工具可审计、目标可稳定编码的范围内）：抓预览帧、UP 主资料、热门视频、热词、每周热门、排行榜、收藏夹列表及内容、当前账号首页推荐、未读消息、回复通知、@/点赞通知。涉及登录账号的读取显式标为 `account`，不能并入公共域。正常子进程复用仅限严格匹配同一父进程及正在执行的动作。

**明确没有宣称完成**：`bili_crawl` 这类组合读写/聚合工具、ASR、付费模型调用、视觉智能体嵌套执行、全部平台 API；其执行语义与额外额度必须分别审计。任何工具返回都不能直接充当待办完成/发布成功的证据。

## 第三阶段：在实际网络发送前做跨进程写入冻结

新增 `vendor/bilibili-mcp/outbound_action_gate.py`，由现有业务安全门禁完成授权/内容/额度审核后，在真正网络边缘 `outbound_reservation` 领取持久预约。当前接入范围：

- 视频顶层/楼中楼评论（含 @ 和带图评论）；
- 私信发送（原自动和主人手动路径共用相同基础发送器）；
- 动态评论（仅原已授权人工入口，**不是开放动态自动发布**）；
- 关注、取关（包含已授权的手动路径）。

协调键基于当前**已验证账号**、动作类别、具体目标与内容摘要，持久化文件内只保留 hash、时间和执行状态，不保存私信正文、Cookie、Token 或收件人原始 UID。相同发送在同一天禁止重复；如果平台结果未知，稳定冻结标记跨天保留，不因超时、异常、进程退出就自动释放。获得可核实回执时先持久化回执，再解除未知冻结标记，保留同日去重锁。账号切换期间不允许把旧账号结果标记为新账号成功。

管理中心「运行诊断 → 对外动作预约与未知回执」提供当前账号的脱敏只读诊断，不提供一键重发/解除锁。锁文件遗留可能需要查阅平台真实记录后进行人工维护，不可把技术冻结冒充“鱼鱼不愿意”。

**未覆盖的写入**：其他非上述五类的网络副作用（如动态发布、点赞收藏、数据管理工具等）继续保留各自业务门禁，不能理解为全部平台写入统一协调。当前“有平台回执”只证明 API 返回了可核查的 ID 或回查状态，不保证公开页面立即可见。跨服务、平台自身重复投递无法由本地目录独自保证 exactly-once。

## 验收顺序

1. **离线快测（现在需要 Windows 用户验收）**：先运行 `node --test test/v271-dev3-three-phase-execution.test.mjs` 与 `python -m unittest discover -s test -p test_v271_three_phase_outbound_gate.py -v`；分别要求 5/5 和 10/10，无真实 B站操作。随后 `node selfcheck.mjs`，并核对插件 Python MCP 安全版本。
2. **真实只读验收（需要 Windows DSH 与 B站）**：在原授权下查看字幕/弹幕/热门、低清图，核对没有相同操作并发双取及错误“完整观看”表述；遇权限禁用不能开启替代渠道绕过。
3. **真实写入验收（需要用户另行明确允许）**：分别选择可控的测试目标，先确认额度和授权，再由主人单独触发一条评论/私信/关注；对照平台回执和管理中心脱敏状态。不允许为模拟超时而故意在真实账号上并发发送，或直接解除未知回执锁。
4. `dev.3` 完整验收并核对老用户存档后，再决定是否进入 `dev.4`。本补丁不修改发布版本、不创建 Tag、不发布 npm。
