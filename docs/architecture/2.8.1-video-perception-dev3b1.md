# 2.8.1-dev.3b.1 · 多模态时间轴第一阶段 + DSH 模型能力助手 + Ollama 快捷启动

> **开发增量而非正式 Release。** 基线为 dev.3a.4；真实 Windows / B站 / DSH 第三方 Provider / Ollama 端到端尚未验收。没有实现独立 OCR、音轨逐秒 ASR 或严格音画语义核对。

## 自主深度不变

Life 自主决定看不看；`skim` 不调用画面模型，`standard` 上限12时刻，`deep` 由用户卡片设12/24/48上限。调用和停止仍由鱼鱼决定；弹幕热度只帮助确定候选时间窗口，不是内容事实、意愿或提示词。

## 字幕与分镜时间轴第一阶段

1. `bili_subtitle` 对官方字幕返回体 `body[].from/to` 秒进行**显式**时间归一化，附加有界 `timed_segments`（按全字幕轨均匀保留最多160项、单条180字符），同时保留兼容的 `segments` 数量与 `text`。原接口未提供时间的 ASR 不能伪造时间戳。
2. `lib/video-evidence-bundle.mjs` 只将真实字幕/ASR、画面采样、识图、弹幕/评论回执分别入证据。新增对字幕 `timed_segments` 的起止点收录；依旧不保留第三方正文。
3. `lib/video-perception-timeline.mjs` 是**只读、临时**投影：根据正式证据包的采样时刻生成最多48个锚点，最多各带2条附近字幕摘录，仅标注 `time-proximity-only`（时间邻接），**绝不推断画面内容与字幕一致**。如没有已核实画面时间点，字幕可独立生成有限锚点；如 ASR 无时间戳，则只声明存在未定位转写，不混到画面时刻。
4. Life `bili_watch_video` 返回新增 `perceptionTimeline`，它不是新的事实数据库、不写入长期记忆、不赋予平台写权限。`sourceAvailability` 明确保留 `ocr:not-observed`、`originalAudio:not-listened`；已有视觉和字幕回执仍区分高低清、采样与全视频。
5. 修正 `bili_watch_video` 字幕结果的 JSON 解析位置，避免可用字幕被误当缺失而触发额外 ASR；ASR 原始纯文本仍兼容，但错误提示不能变成成功转写。

**尚未完成：** 逐帧 OCR 的独立可信提取、对视频音轨进行新的定时 ASR、字幕与图像语义交叉验证、完整连续剧情理解。后续 dev.3b.2 应先做结构化 OCR/ASR 证据，dev.3b.3 做疑点驱动音画核对；不能在本阶段宣称这些能力已存在。

## DSH 第三方 Provider 图片 / 思考能力

根据 [DSH 官方模型设置文档](https://deepseek-harness.github.io/deepseek-harness/en/guide/providers)，自定义 `llm-pi-ai` 模型能在 DSH Settings → Models → Customized settings → Model options 编辑 Input types 和 Reasoning levels。若当前构建没有入口，则可在所使用的 Profile `cordis.patch.yml` 原有 Provider 对应模型条目中合并类似片段：

```yaml
# 只合并到现有 llm-pi-ai > config > providers > <你的provider> > models 中
- id: gpt-6-luna
  input: [text, image]
  reasoningEfforts:
    off:
    low: low
    medium: medium
    high: high
    xhigh: xhigh
    max: max
```

管理中心的“根据当前模型生成片段／复制片段”只生成当前填写的模型 ID 的**模型级**示例代码，不修改 Profile，不复制密钥，不自动切换 Provider、不证明中转站具备视觉能力。`off` 不发送思考参数，不保证上游真正关闭推理；仅保留上游实际支持的等级。修改后新建 Session，并进行统一大肥鱼原图验收。

`gpt-6-luna` 可作为支持该模型的第三方中转站上的低成本候选，但**官方 API 定价并不等于中转站定价**；应核实图片输入、API 协议、计费与隐私策略。不同 DeepSeek 模型与通道成本也不同，不能简单断言系列所有型号更贵。

## Windows 端 Ollama 启动

本地模型区新增“在 PowerShell 启动 Ollama”：只有用户显式点击并确认，管理后台才会使用固定不可编辑命令启动独立可见 PowerShell 窗口执行已安装的 `ollama.exe serve`。此按钮不会下载安装、不会改系统或会话网络代理、不会暗中切换云模型；返回 `opened` 仅代表窗口启动成功，并非服务可用的证明。用户须检查窗口状态并刷新。若托盘 Ollama 已运行，不再重复启动。该接口要求本机回环 IP 和管理中心同源请求，其他操作系统拒绝。安装入口仍为 https://ollama.com/download 。
