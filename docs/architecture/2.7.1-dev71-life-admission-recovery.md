# 2.7.1-dev.71 · Life 授权事务恢复与诊断（开发预览，未发布）

## 本轮日志结论

11 月 11 日 16:05 的最新日志中，两条不同用户的动态评论在模型调用记录为 `completed` 后，都遇到 `life-choice-review-required`。两条通知均没有 `generatedReply` 持久草稿、没有发送尝试，也没有平台发送回执。

该错误不是模型拒绝，也不是 B 站拒绝发送。它来自 `lib/life-willingness-admission.mjs` 的账号级持久准入：已有授权记录超过 10 分钟，但系统无法安全确认它是否已经跨过最终执行边界，于是拒绝新的 Life 许可。由于准入按账号作用域共享，一条未结算授权可能连带阻断不同用户的评论、私信和视频主评论。

dev.70 的 `life-willingness.mjs` 在过期时会删除内存中的 proof，但未同步结算持久账本；旧账本又没有 `used` 字段，因此系统无法判断过期授权是否曾被发送器消费。原本用于防止重复外发的 fail-closed 保护因此退化为长期账号级锁。旧日志包未导出原始授权账本，无法从该包确定究竟是哪一笔旧动作留下了 claim；不能凭空断言它是某一条评论或私信造成的。

## dev.71 修复

1. **持久消费标记。** `approve()` 写入 `used:false`；最终 `verify()` 通过后，`markUsed()` 在持久账本中写入 `used:true`。视频评论的预审只检查证明，不提前标记消费；最终 Python 写入授权前才标记。
2. **安全过期规则。** 过期 `approved && used===false` 可安全释放，因为没有任何最终执行器获得过消费许可；`used===true` 或旧版缺少 `used` 字段的状态仍保留 `life-choice-review-required`，必须核查平台事务后离线恢复。过期 `considering` 仍须确认原进程已退出。
3. **证明生命周期结算。** 过期且未执行的内存 proof 在被删除前先调用持久 `settle(not-sent)`。已消费的 proof 不会被当作未发送自动释放。
4. **发送路径兜底。** DM、动态/视频评论、主人待办回访和视频分享的发送函数均使用统一 settler：所有提前退出结算 `not-sent`；平台调用抛错结算 `uncertain`；只有真实发送回执才结算 `verified`。事件级 `social-send-transaction` 仍负责未知结果冻结和防重；Life 准入结算不构成平台发送成功。
5. **诊断归因。** `life-choice-review-required` 记为 `life_authorization_review_required`，表达校验失败单独记录，只有真实模型调用失败才显示 `ai_generation_error`。主评论桥保留安全的具体 defer reason；主评论轮次日志分别显示审阅尝试、已完成审阅、自主延期、技术阻断与具体原因；管理页显示当前 Life 准入状态。
6. **旧账本离线恢复。** 新增 `tools/life-willingness-offline-recovery.mjs`，提供只读检查和显式批量恢复。工具不联系模型/B站、不重放动作、不读取消息正文。

## 当前旧 dev.70 账本的一次性恢复

dev.70 写入的批准记录没有 `used` 字段，dev.71 会将其解释为“状态未知”，不会擅自自动释放。若管理页显示“Life 授权账本需要离线复核”，按以下步骤操作：

1. 关闭所有 DSH Desktop、后台进程和其他使用同一数据目录的 DSH 实例。
2. 先在 B 站核对最近可能发出的评论/私信及其他写入；如果有结果未知的事务，不要把它当作未发送。
3. 在 dev.71 源码目录执行只读检查：

   ```powershell
   node tools/life-willingness-offline-recovery.mjs --data-dir "C:\Users\dalang\.dsh\bili-duty\accounts\3747574597028931\runtime" --inspect
   ```

4. 确认所有 claim 的 `ownerProcessAlive` 均为 `false`，并且已经核对所有可能未知的平台事务后，才执行：

   ```powershell
   node tools/life-willingness-offline-recovery.mjs --data-dir "C:\Users\dalang\.dsh\bili-duty\accounts\3747574597028931\runtime" --recover --confirm-all-stopped --confirm-platform-reviewed
   ```

5. 恢复工具只删除该账号 runtime 目录中的 Life 准入 claim，不清除评论通知、发送事务、额度、记忆或生活事件。然后重新启动 DSH，让原有轮询与 Life 自主意愿流程重新工作。

如果检查显示 `ownerProcessAlive:true`，不要强行恢复；说明仍有进程持有准入记录，先确认并关闭对应 DSH 实例。不要手工删除 `life-willingness-admission.json`。

## 安全边界与未验收项

- 过期未消费 proof 的释放只表示该次本地许可没有跨过最终执行校验；不自动发送、不自动补发历史通知。
- 已消费或旧版未知 proof 仍要求离线核对；不以“没有成功回执”推断“肯定没有发送”。
- 发送权限、B站实际额度、账号身份、评论来源核验、未知结果冻结和去重机制不变。
- 本轮授权、社交恢复专项测试通过；完整 Node/Python 全仓测试与 Windows Desktop/B站端到端行为仍需继续验收。
