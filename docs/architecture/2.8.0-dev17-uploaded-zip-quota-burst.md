# dev.17 · 用户最新 ZIP 基线：自然气泡、主人额度与互动节奏方案

**基线**：用户新上传的 `dsh-bili-scroll-plus2.zip`，其中 `package.json=2.8.0-dev.17`，且代码已部分包含上轮修复。不能假设上一份增量补丁完整适用；本轮 Patch 只相对此 ZIP 解出的原文件。

## 回复、逐气泡发送、可选续想

`lib/message-burst.mjs` 保持单轮表达 1–3 气泡、未知发送停止、逐条可信回执及新来信中断的执行契约。本次仅修改模型向导，让模型先根据当前来信、最近确认回复与可信历史构思完整内容，再辨识自然的独立语义点，最后返回 `messages` 数组；私信和主人私信使用统一数组输出指令。不是固定切标点、不是每次至少两条，也不会强制执行额外模型续想。

## 主人不受普通 DM 每日额度限制

`index.js` 的普通自动 DM 配额入口仍可调整 `dmReplyPerDay`，但独立主人 Agent 不消费该配额。为兼容降级/回退路径，`lib/dm-autoreply.mjs` 在当前账号核验及明确配置的 `ownerUid` 下，将主人视为授权的专用联系人，跳过普通每日上限且其成功气泡不再计入 `sentAt` 普通额度账本。**不改变**全局调度、单轮节流、账号校验、拒联、发送授权、未知结果冻结或平台保护。旧 `sentAt` 历史累计记录未标记 UID，无法安全地逆向扣除主人数量；升级后新数据才遵守新的分类。

## 互动额度方案双向同步

`lib/quota-preset.mjs` 定义六项数值方案及全部额度编辑字段；`index.js` 保存可检查的 `quotaPreset=gentle|natural|active|custom` 状态。以前的配置没有可靠的方案身份，因此新字段默认为 `custom`，**不根据仅六项相同就伪称用户已经选择过方案**。选择方案把对应数值写入界面，保存时校验数值与方案一致。手工修改任一额度，前端立即转 `custom`；其他写入路径更改额度而没有指定方案时，后端也使状态转 `custom`。服务端拒绝伪造或与实际参数不符的方案。单纯读取、选择卡片但没保存，不修改原运行时配置；卡片不授予外发权限。

## 验收范围与风险

离线测试覆盖方案校验/状态持久化契约、后端其他路径调整额度后变为自定义、主人额度回退路径、模型三阶段指令和逐气泡顺序。真实 Windows DSH、B站服务端限流、多人同时发信、跨日运行、旧用户配置迁移仍须在用户环境验收。无 npm 发布/正式 Tag。
