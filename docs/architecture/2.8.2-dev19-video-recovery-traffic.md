# 2.8.2-dev.19 · 真实视频恢复与视觉流量透明化

## 事实源与职责

- 行为主体：**Life** 或主人既有只读试运行显式指定 `standard/deep`；负责取源的 `adaptive_video.py` 仅实现相同意愿已允许的时间窗口，不扩大兴趣/复查意图，不改变外发授权和账号隔离。
- 唯一可用视频源：`_playurl` 从 B站官方 API 得到的本次 HTTPS DURL/DASH。DASH 恢复重新核对同一 BV/CID，并沿用公网固定 IP、TLS 原始主机名、重定向、Range、ETag/长度与本地 FFmpeg 边界；从不将媒体网址交给模型或 FFmpeg 自主联网。
- 网络恢复：DURL 在用户单视频上限内允许完整下载，按每 1 MiB 约 1 秒设置传输时间阈值（50 MiB = 50 秒，握手另有 8 秒网络等待上限）；完整下载超时/可恢复断连先尝试 MP4 索引 Range。只有 Range 未获支持、网络中断或有效索引缺失才可重新请求同 BV/CID 的 DASH SIDX。平台限流、疑似篡改、错误身份或耗尽预算不准换轨重试。
- 总额：本轮原视频实际收取的响应体字节，包括失败下载与探针，计入单视频网络预算。下载失败不能把消耗数清零。剩余预算不足时显式失败，不能用新的 50 MiB 配额继续。完整下载、稀疏读取受 170 秒本地视频处理窗口和 DSH 上层超时共同约束，保留本地离线 FFmpeg 限制。
- 低清兜底：现有 `preview_vision.py` 从播放器 `videoshot` 的 JPEG 精灵图和 JSON/pvdata 时间索引获取低分辨率缩略格；规则分层/画面差异筛选、重组分镜。没有 FFmpeg 从低清视频中取帧；每格一般远低于最低视频解码画质，B站所提供的实际宽高为准。低清不登记原视频观看回执。

## 视频视觉实收流量账本

- 唯一计量源：Python `video_traffic.py` 的上下文局部计数、`stateDir/video-vision-traffic.sqlite3` 日/类型累加。`original` 包括完整媒体、Range/索引/DASH 1 字节探针，`preview` 是 videoshot 图片或时间二进制索引，`metadata` 是视频视觉读取内相关 API 响应体。失败和超预算读取的**实际已接收字节**同样记账。
- 同一 Python 感知调用按 `home` 作用域写入，约每 1 MiB 一次 SQLite 原子累加、完成时补齐尾数；并发进程由 SQLite 串行化写入。异常中断可能遗漏小于刷新阈值的尾数，统计不是网络驱动级抓包，不得显示为全部流量。
- 账本不保存任何个人识别值、BV、媒体 URL、口令、原始响应或视频内容；主 Session/ASR/评论/弹幕等其它网络请求以及旧版本历史未接线，管理中心必须标出范围，不以估算视频文件大小替代实收流量。
- 只读接口：本机同源 `/api/bili-duty/video-vision-traffic` 通过宿主 Python 读取受控 SQLite 聚合；当无法读取时返回 `ok:false`，前端显示「暂不可读」。这是计量视图，**不是额度授权或新的账号账本**。

## 验收门槛

1. 对 50 MiB MP4，下载在约 1 MiB/s 下允许约 50 秒传输，不再固定 25 秒。
2. MP4 整体下载中断后可用同源 Range 成功取得真实画面；Range 失败时仅在可恢复且剩余预算足够时访问同 BV/CID 官方 DASH，危险回执严禁重试。
3. 40 MiB 的失败整体下载加后续 10 MiB 分段只能使用 50 MiB 累计额度，绝不重新授予 50 MiB；若读不够则如实报告失败。
4. 今日和累计流量值可在「次数与额度」刷新；含失败下载+低清回退+API 字节；不展示签名 URL/BV 或私密信息；计量失败不导致视觉读取失败。
5. 用户 Windows/DSH 实测同一个公开 BV，确认视频画面来源为 `B站公开视频片段（离线解码）` 或如实低清，而非因伪造/旧错误归类而显示成功。需要普通/管理员 full 测试及实机检查后才可进入发布流程。
