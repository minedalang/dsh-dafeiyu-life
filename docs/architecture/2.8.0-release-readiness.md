# 2.8.0-dev.1 · 新生活系统功能审计与正式版发布门禁

> 审计基线：完整 `2.7.1-dev.77` 源码（以及此前已上传日志的审计结论）；本次仅对管理 UI、用户文档、版本声明进行定向修改。**判定：`releaseReady:false`，不可封正式 2.8.0。** 尚未在用户 Windows DSH、真实模型或 B站账户执行端到端验证；“有实现通路”不能等于“真实行为自然、可靠”。

## 版本策略

- **2.8.0 是合适的下一正式版本号**：统一 Life、关系三维度、记忆与活动可视化等均属于功能级升级；不建议继续以 2.7.1 补丁版描述产品变更。
- 当前合法发布物标记为 `2.8.0-dev.1`，不更新正式 npm Latest，不自动创建 v2.8.0 Tag，不把 Github Release 标成稳定版。必须通过下方 P0 门禁才能将 package/lock/文档最终写为 `2.8.0`。
- 2.7.0 仍是已知稳定版基线；最终需要现场确认 npm 与 DSHMarket 最新实际发布状态。

## 已上传实机日志的有限事实（2026-11-11 至 11-12）

对用户最近的 `bili-duty-logs-20261112-090103-253.zip` 做**只读解析**：其中 60 份 Life 决策轨迹（按记录日期为 11 月 11 日 57 份、11 月 12 日 3 份）。按 `execution-plan.kind` 统计，观察到 8 次自愿休息、7 次视频评论意愿、6 次视频 Agent 委派、5 次本地只读反馈、3 次其他已核验动作、2 次社交关注及 1 次分享视频意愿；另有 15 轮以 `no-actionable-options` 结束。多个结算结果属于不同类型行为，不能简单把 `verified` 计数说成 B站评论成功数量。

**在这 60 份决策轨迹的执行计划中，没有观察到明确的待办执行、访问视频作者主页或公开交往对象投稿行为。** 代码中虽存在相应工具/候选，现有观察不足以证明这些自然行为已稳定发生。尤其部分 video_comment 为 `not-sent`，不能拿 Life 模型批准代替平台成功。这一导出是滚动日志快照，不能据此断言更早的所有运行中从未发生。

## 本轮确认并修复的 UI 缺陷

1. **「鱼鱼想做」重复旧组件**：上一版在统一卡片下堆完整旧流程图、彩色口号、待办列表、来源日志和高级设置。新版本删除重复流程说明，保留真实操作和数据接口；待办管理、来源记录仅在同一操作区按需二选一查看，顶部主要呈现统一生活事项及可信来源。
2. **神经回忆场搜索框位置**：原输入框放在整个板块的说明文字与多行图例之前，距离 3D 图较远。新版本将同一真实搜索输入和绑定原封不动移动到图形正上方，普通/全屏共用，不新增一套搜索或额外模型调用。
3. **用户首页过度工程化**：README 改为新版本价值与视觉流程、特色、安装、边界和反馈入口；复杂 P0/P1 风险移至本审计及版本日志。稳定版状态真实标注。

这些都是**已在源码中实施并可离线验证**的调整；本轮没有更改 Life 模型决策、自然关系评分、私信或公开发送器，不引入 Vue，不主动发B站内容。

## 建议继续执行的修复与验收路线

**P0（正式发布前）**：先在用户 Windows 环境收集一次受控运行证据和匿名化设备/版本信息；构建旧版数据快照测试，验证原账号和遗忘/权限；用只读探针与受控授权场景分别观察 Life 真正选择、专业执行、平台核实，记录不行动的原因；执行至少 72h 值守和故障恢复。必要时修正实际日志定位的漏处理/错误结算，反复跑带账号隔离的回归。不得让自动化在不经授权的情况下真实外发。

**P1（2.8.0 稳定后）**：响应式全站 Vue 重构应留给下个正式版本；需要统一生命周期状态库、SSE 断线游标、组件级读写隔离和防重操作，不能在本次 RC 期混入。可进一步提升动态树演出和社交自然度，但不能凭视觉动画证明真实动作成功。

## 发布决策

**当前可交付的是 `2.8.0-dev.1`，`releaseReady:false`。** 适合有备份的开发测试与社区收集反馈；目前不具备诚实宣称“全部行为都能自然运行”的证据，也不具备正式版发布门禁。只有各项 P0 实证完成、失败清零或有批准的非阻断处置，且维护者明确同意发布，才能封 `2.8.0`。本审计不操作账号、不开放权限、不自动创建 Tag 或 npm 发布。
