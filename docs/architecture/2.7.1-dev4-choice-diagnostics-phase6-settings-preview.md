# 2.7.1-dev.4 · Life Agent 决策诊断收尾与 Phase 6 设置契约预览

**性质：已接线的 Phase 5 修复 + Phase 6 只读设置预览。尚未完成旧调度器替换、配置迁移或新版设置页面。版本不变，真实 Windows/B站/模型需要用户验收。**

## 统一层归属检查

`管理中心手动唤醒 / 既有一分钟检查 → AutonomousPlanner（唯一模型决策/每日额度） → 原只读待办、LifeOpportunities 与匿名 life-agent-events → 有效候选与授权检查 → 原 Life Voice 一次 → 模型或直接无候选诊断 → life-agent-events 有界匿名时间线 → 管理中心。`

- **唯一事实源**：待办仍来自 `owner-todos`，生活意愿仍来自 `LifeOpportunities`，账号从可信账户标签获取，视频额度来自原事件账本；本修复不另建记忆、待办、人格或发送权。
- **可复用的独立状态生命周期**：`lib/life-settings-projection.mjs` 只计算现有配置的只读视图，由 GET `/autonomous-planner` 返回，未来可供管理中心与配置迁移工具对照；它不是第二配置存储，也没有保存 API。
- **影响范围**：Life Agent 生活决策和 UI 诊断；不改 DM/评论旧决策所有者、不改原安全动作适配器，不允许发送 B站内容，不改账户隔离和冷快照。

## 新增真实诊断（不伪装意愿）

| 本轮条件 | 时间线枚举 | 是否调用模型 | 解读 |
| --- | --- | --- | --- |
| 有真正可选动作，模型明确返回 JSON `skip` | `voluntary-rest` | 是，计入原额度 | 鱼鱼本轮主动决定暂时不做 |
| 模型返回非 JSON、不受支持动作或不存在的目标 | `invalid-decision` | 是，计入原额度 | 技术/契约失败，不是自愿休息 |
| 只有人工/空档/视频结束事件，原候选均不可执行 | `no-actionable-options` | **否**，不消耗模型额度 | 候选不足，可能是视频 180 分钟、当日限额或能力不可用 |
| 模型调用或后续执行失败 | `model-or-execution-error` 或 `failed=true` | 失败调用仍计原额度 | 明确失败，原事件可以保持待考虑 |
| 升级前的 `skip / no-action-receipt` | 兼容旧格式 | 无法判断 | 不会把历史旧记录强行解释为主动休息 |

匿名生活时间线仅保存候选 **类别数量**、有限枚举 `blocker`，不持久化模型理由、原始提示词、UID、BV、私信内容或待办内容；依旧只保留七天有限诊断，不是长期人生记忆或真实平台回执。自动轮次的六小时仅线索冷却仍生效；手动唤醒不跳过视频启动 180 分钟/每日两次、旧权限或每日 AI 额度。

## Phase 6 新设置系统的只读映射（本轮已接入）

`projectLifeSettings(cfg)` 基于原配置 **只读** 返回 `schemaVersion:1, readOnly:true, migrationApplied:false`，供 UI 显示当前“生活模式、真实视频调度所有者、旧视频定时器状态、社交旧决策所有权、每日模型决策额度”。

- 映射 `masterEnabled`、`lifeAgentMode`、`peakValley`、`autonomousPlannerEnabled`、`autonomousPlannerDailyLimit`、`autonomousPlannerMinutes` 与独立的 `lifeAgentSocialContextOptIn`；不读私信正文、账号 UID 或凭证。
- `active` 当前只代表视频生活接管，不代表对 DM/评论拥有发送权。所有外发许可仍归原安全层和旧社交决定者。
- 本轮**不删除**上述旧字段，不改变任何旧开关、默认值、模型额度、时段、外发授权；新旧设置尚未真正迁移。
- 正式 Phase 6 将先输出旧配置 → 新配置差异与冲突报告，再进行冷快照与还原验证；禁止自动打开历史关闭的权限，禁止因为精简 UI 丢失权限边界或资源限制。

## 安全离线测试与验收

用 `node tools/dev4-choice-diagnostics-offline-acceptance.mjs` 在操作系统临时目录运行纯合成数据，检查：无候选免调用、合法主动休息、非法模型输出、模型故障保留事件、新设置只读且不提升权限。不会联网、读取正式 `bili-duty` 或发送消息。另执行 `node --test test/v271-dev4-life-agent-choice-diagnostics.test.mjs`。

需要用户 Windows 验收时：先通过离线模拟器，再更新插件、完全重启，在管理中心 `shadow` 模式点击一次手动唤醒。时间线应显示区分类别与当前候选数量；真实点击可能调用当前已配置的模型，可能触发原来已经授权的公开只读读取，并不强制鱼鱼探索。**历史五次休息无法回溯成哪种真实决定。**
