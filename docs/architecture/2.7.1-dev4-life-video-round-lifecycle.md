# 当前增量 · Life Agent 原视频轮次真实生命周期回执

> 生产接线更新，版本仍为 `2.7.1-dev.4`。已完成离线回归；尚未在用户的 Windows DSH Desktop 和真实 B站账号验收。

## 统一层归属检查

`Life Agent 手动/自动唤醒 → AutonomousPlanner → LifeCapabilities（原专业 Agent）→ index.js/runDuty（原唯一视频执行器） → 原平台观看/入选账本 + LifeAgentEvents 匿名轮次状态 → buildLifeTimeline → 管理中心`。

- **唯一选择者**：既有 `AutonomousPlanner`。没有新增生活定时器、模型、人格、意愿或权限层。
- **唯一专业执行者**：现有 `runDuty` 的 Headless 子进程。沿用原身份校验、总开关、视频额度、Overlay、评论/关注/发送安全策略。
- **唯一作品事实源**：原视频 `seen`/日报账本；新轮次状态不是视频观看、听歌、发布或成功外发的证明。
- **唯一轮次生命周期账本**：现有账号隔离的 `life-agent-events/<account-tag>.json` 的可选 `videoRounds` 字段（v1 向后兼容）。记录随机 12 字节十六进制轮次 ID、来源枚举、进程启动/退出时间、状态、可选进程退出码、来自原入选账本的**新增条数**（未知时为 null）；不写入 BV/UID/Cookie/对话内容。
- **现有管理接口**：`AutonomousPlanner.status().lifeEvents.recentVideoRounds` 和 `/life-timeline`；不增加可写的 HTTP 控制接口。
- **受影响渠道**：仅手动视频轮与 Life Agent 委派的视频轮，以及管理中心展示；DM/评论仍为旧回复器唯一生产决策者，不开放新社交外发。

## 可验证生命周期

1. `runDuty` 真正获得子进程有效 PID 后记一条 `started`；没有有效 PID，不能向 Life Agent 声称启动成功。若账本无法登记，只记脱敏诊断，不制造完成回执。
2. 真实子进程 `exit`：退出码 0 为 `completed`（**仅进程正常退出**）；非零为 `failed`；缺失退出码/子进程异常为 `interrupted`。退出码无法证明任何 BV 的观看或音频聆听。
3. 原 `seen` 账本中，**本轮开始时不存在而结束后明确 picked 的 BV** 可计作新增入选数；若读取不可靠，保持 `pickedCount:null`，不得虚构 0 或“已看完”。
4. `video-round-ended` 的生活唤醒只在 **同账号 + 正常退出 + 本轮有匿名轮次启动回执** 时产生；失败/中断不得冒充成功结束，也不自动重新委派。
5. 账号中途切换时，不把旧账号的结束回执写进新账号。旧账号未闭合轮次仍保持 `started`，超过 8 小时仅**只读投影**为 `unverified-interruption`，不自动释放锁、不追加成功、不重试。
6. `buildLifeTimeline` 将正常结束、失败和中断显示为**进程级事实**；保留原作品账本独立条目，不把“模型选择探索/读取标题/进程正常退出”改写为“观看完成”。旧轮次不自动回填。

## UI 与调试验收

更新重启后：设置 → 大肥鱼 → 鱼鱼的生活 → 重新核查真实状态，可查看本账号最近视频轮次的开始、完成、失败、未知中断和退出码。打开「大肥鱼的一天 · 真实生活时间线」会看到新产生的真实视频轮次结束事件；只有原 `seen` 账本有实际入选作品时才出现逐 BV 的记录。单次 `begin_exploration` 获取公开视频标题不产生视频轮次。

失败应先检查 `duty.log` 及原视频账本，不要强制解除读写预约。真实 B站仍可能风控/限流；该补丁不绕过已有冷却、模型额度、视频配额和账号复核。

## 安全回归矩阵

- 模型只读选择和启动回执分离；正常退出与看过视频分离；失败/未知状态不被覆盖。

- 决策、自动启动、手动启动、子进程失败和退出、真实时间线 / Debug 状态。
- 已授权既有专业能力不新增任何外发权限；Windows DSH Desktop 与 B站实机发送/观看待单独验收。
