# 2.8.0-dev.16：私信活跃轮询、渐进表达与 Life 休息设计

状态：**dev.16 代码实施 + Life 休息提案**。不能将本文中的休息策略当作已经实现的能力。代码仍未获得 Windows DSH / 真实 B站端到端验收。

## 1. 本轮已经实现的私信读取

- 全局 `get_sessions` 按 `dmWatchMinutes` 间隔读取一次，默认为新安装 2 分钟；旧配置不自动改写。`dm-poll-cursor` 依据会话更新时间、未读计数和历史读取游标选择最多 12 个深入读取对象。**平台已读 != 鱼鱼已处理**，详细来信仍由消息 ID 账本去重。无变化的已处理会话一般不重复详细读取，保留低频安全重扫。
- 活跃快通道独立于全局列表读取，默认仅对最近确认成功回复的会话在 180 秒内做定向 `fetch_session_msgs`，每次只有一个目标；至多保存两个活跃会话，以检查时序公平轮换。间隔可配置 10–60 秒，活跃期可配置 60–600 秒，可关闭。**快通道不等于 10 秒的实时推送**；受模型处理时间、网络状况、全局调度 5 秒 tick 与统一预算影响。
- 定向读取复用真正完整的私信接收与正常 Life/owner Agent 路径，**不是发送前 `probeOnly`**。不推进全局会话游标。平台消息 ID 去重、首次运行只建立收件基线、账号身份隔离、发送授权与真实回执继续有效。
- 定向网络错误须向统一退避层上报（不能被 `collectDmInbox` 吞掉），模型失败在活跃通道至少 60 秒冷却。对话一旦超出活跃窗口立即回到全局低频检查；账号改变则清空旧活跃列表。上层读取预算和平台 `-509` 冷却是硬边界。

## 2. 本轮已经实现的渐进表达

首轮所有私信共享以下非授权的输出片段：

```json
"continuation": {"intent": "none|maybe", "thoughtCue": "短暂的尚未展开的独立想法线索"}
```

`thoughtCue` 不是任务、记忆、关注授权或一次已经写好的回复。它在当前回合结束时过期，不触发定时器；不能与 5–360 分钟后的 `idleReconsider` 互换。

- 普通联系人：只有首轮 Life 已经选择 `reply`、只产生一条预写气泡、明确 `maybe` 和非空线索、且第一条取得平台回执时，才尝试一次工具禁用的轻量表达模型。拒绝、没有线索、模型错误、出站结果未知均不额外生成或发送。既有一次性预写 1–3 气泡兼容。
- 主人专属 Agent：只针对直接普通聊天 `reply`（不是搜索/点赞等任务后的反馈）且首条获回执、单条消息时，允许一次额外模型思考；也允许 `stop`，不强行多气泡。
- 任何第二条都必须经过原相同收件人、Life 意愿字节绑定及本轮受限扩展、账号权限、新来信检查、写入安全门禁、独立真实平台回执和不可重复发送保护。不得因为第二条获得新的关注/评论授权。
- 观察指标：首次模型单条比例、线索提供率、第二次调用率、有效新增信息比例、重复/矛盾气泡比例、被新来信取消比例、平均回复延迟与各类网络限流率。用户体验改善必须使用实机日志，而不是“代码允许生成第二条”代替。

## 3. 尚未实施：Life 精力 / 自然休息调度（需明确产品决策）

当前的 emotion 与 Life Voice 不等于一个可靠的、能统一驱动后台调度的能量系统。直接加随机“困倦率”会制造不稳定、错过重要消息及错误归因。

提议建一个**统一 Life Attention & Rest 调度层**，它不成为第二个决策 Agent，只对后台非紧急读取与自发活动提供资源门禁：

- **认知/关注预算**：分别观察社交注意力、浏览探索注意力；输入包括本地连续活跃时间、最近已证实的探索信息增量、近期模型耗费、自然生活意愿中的休息/兴趣，且不直接把“情绪低落”当作必须休眠的硬规则。
- **状态**：`engaged`（正在聊天/探索）、`available`（可接收新机会）、`resting`（暂不主动探索/低频轮询）、`sleeping`（大段休息，可配置上限）。允许 Life 自主选择休息与恢复；技术层只施加预算上限，不能向平台虚构“人睡着了”的叙述。
- **分域自主**：`social_attention` 与 `exploration_attention` 可不同步。鱼鱼可能不想主动读私信，但仍愿意看公开视频；反之亦然。主人写入权限、已受理行动以及外发回执核验不自动随休息获得新授权。
- **温和退避**：全局收件箱没有活跃聊天、没有新来信、且 Life 选择休息时，默认可从 2 分钟逐步延长到 5、15、30 分钟；有新来信或恢复意愿则回到 2 分钟。最大休息跨度应可配置；**没有消息推送能力时，不可能一边彻底停轮询一边保证即时发现新私信**。
- **不触发模型**：绝大多数 tick 根据有时限的已有意愿和本地资源观察，无额外模型调用；仅在原 Life 决策时带入可选休息选项。不能专门为了“我现在累不累”每分钟调用一次模型。
- **安全/礼貌例外**：待核验外发、账号风险、主人优先消息、已确认约定应有独立安全维护节奏；但未获得平台实时推送的前提下，主人新来信也可能延迟到下一次列表扫描。不能承诺不存在这种延迟。
- **保底与可追溯**：任何休息均设最大时长与原因代码，允许手动唤醒，统计跳过的网络请求、节省的模型调用、回复延迟与异常漏处理，避免把网络故障当“鱼鱼选择睡觉”。

**不允许**通过模糊“疲劳分”直接取消主人已经明确授权并接受的行动，或因休息跳过账号隔离、平台回执与未知送达核验。

## 4. 本轮验收路径与保留风险

- `node --test test/v280-dev16-fast-dm-progressive.test.mjs`：纯本地模拟可验证少调用、追加回执、防重复、快通道选择/边界。
- `run-tests.bat`：当前版本核心，`run-tests.bat full`：含遗留测试的完整发布门槛。必须区分二者。
- Windows DSH 实机：确认新开关保存、两分钟全局列表 + 10 秒活跃定向读取的 HTTP 次数；验证主人额外思考不会误发旧话题、网络失联不会发送第二条；在 B站限流恢复/账号切换后没有重发。
- 上述休息策略仅是可讨论设计，**未改写**现在的 Life 全域调度或轮询退避默认行为。
