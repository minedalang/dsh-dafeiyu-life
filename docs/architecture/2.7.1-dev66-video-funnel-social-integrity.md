## 具体执行合同

1. `videoAgentReadTargetPerRound` 是本轮**内容证据探索目标**：尽量取得真实字幕/非空评论等读取证据，首页不足时允许安全关键词搜索；仍允许自主休息和因额度、网络、内容不足而停止，但提示词要求如实记录原因。
2. `videoAgentPickTargetPerRound` 是本轮**择优目标**，既非最高只许挑选的硬上限，也不是评论配额；真实热度门槛及同账号判重照旧。
3. Python `tool()` 只对有已创建 24 位随机轮次 ID 的七类视频工具生成受限 JSONL 诊断；日志只写允许的字段。工具异常也计入错误，但不能改变工具本身的结果。每条结果独立更新，不读取或保存具体内容文本。其父进程在该轮退出时读取精确轮次文件、汇总计数，并删除该临时文件；未读到文件记作「未知」，不能假装零次调用。
4. 原 `LifeAgentEvents.recordVideoRoundFinish()` 保存**匿名计数**，在管理卡片的现有视频委派区域显示。日报开启时在当日日报末尾追加一段真实工具漏斗及有限公开 BV 链接/状态。仍遵循日报关闭、账号隔离与缺失证据边界。
5. 「内容证据」仅意味着成功取得至少一条真实字幕/非空评论/有效转写内容，不表示真实观看全片、音频理解或模型的认知判断。候选未取得内容证据不等于被模型“讨厌”。热度不达标由真实详情数值和用户当前阈值计算，类别可能交叉；精确原因未知时不填想象的理由。
6. `classifyVideoCommentRound()` 中只要有未被更强平台回执覆盖的 `reviewRejected`，本轮总况保留 `comment-review-rejected`，不再因另一条视频产生 `pass` 就归为“模型不评论”。每个独立回复的真实发送规则不改。
7. `mcpIntegrity` 诊断及“备份旧文件后安装受审版本”采用与运行期 `assertSecureMcp` 一致的受审列表，新增 `vision_fallback_evidence.py` 和 `outbound_action_gate.py`。仍由用户明确在管理中心确认操作，不会静默覆盖或跳过安全检查；不得自动补发此前未处理的事件。
