# 2.8.1-dev.3b.19 · DSH 视觉路由一致性与分阶段图片验收

## 目标与边界

本增量解决两类可定位问题：

1. 管理页将默认模型继承值填入视觉 Provider/模型下拉框，却用原始空的 `visionModelProvider` / `visionModelId` 比较是否保存，导致默认继承路由被误报为“未保存”。
2. 普通 Headless 文字连接成功、模型定义声明 `input: image`，都不能证明固定图片块经过 DSH 附件桥接并被第三方视觉模型理解。此前验收界面没有将这些阶段分开呈现。

本版不更换模型、不写入 API Key、不自动修改 DSH `cordis.patch.yml`、不增加 B站写工具或 Life 外发权限。用户当前的 `muze-gpt / gpt-6-luna` 只是目标路由示例；运行时仍读取用户已经保存的配置，不硬编码该 Provider 或模型 ID。

## 视觉路由唯一优先级

运行时统一由 `lib/vision-model-route.mjs` 解析：

| 字段 | 优先级 |
|---|---|
| Provider | `visionModelProvider` → `pluginDefaultModelProvider` → DSH 当前宿主 Provider |
| Model | `visionModelId` → `pluginDefaultModelId` → DSH 当前宿主模型 |
| Reasoning effort | `visionReasoningEffort` → `videoReasoningEffort` |

`index.js` 的 Headless 验证门禁、视觉安全 overlay 和 `dshVisionReview.getRoute()` 共用此解析结果。这样，展示的模型、通过 Headless 文字验证的模型、实际启动的图片验收模型不会各自采用不同的回退顺序。

管理页没有直接导入 Node 模块，而是以相同优先级计算表单的有效路由。保存状态比较有效 Provider、模型和思考深度，而不是比较“空字段”与“已填充的继承值”。当用户改变默认模型时，现有表单应用规则仍然生效。

## Headless 模型能力声明

`lib/headless-model-sync.mjs` 在只读状态接口中增加白名单元数据：

- Provider 的 API 协议。
- Base URL 主机（不返回 URL 查询参数、凭据或完整路径）。
- 模型 `input` 声明中是否包含 `image`。
- `reasoningEfforts` 声明及档位名称。
- 源配置与 Headless 目标配置各自的声明，以及是否同步。

DSH 已注册模型如果目录接口提供相同元数据，也会显示；若目录没有提供，状态为“未提供声明”，不会推断为不支持。

这些是**配置声明**，不是实际能力证明。文字连接验证仍然只证明无工具 Headless 文本请求成功。图片实测继续由唯一的固定原图人工验收面板负责。

## 固定图片验收的五个阶段

| 阶段 | 可以证明什么 | 不能证明什么 |
|---|---|---|
| ① 实际模型路由 | 当前 Provider、模型、协议、Base URL 主机、思考深度；Headless 文字验证是否通过 | 不证明图片能力 |
| ② MCP 图片工具 | 固定 PNG 的 SHA-256、字节数、MIME、图片块数量与 MCP 侧 ImageContent 回执一致 | 不证明 DSH 已把图片附件成功交给模型 |
| ③ DSH 图片附件桥接 | 显示为“插件无法独立观测” | 插件没有 DSH 内部附件传递的独立可信回执，不会伪造绿色成功 |
| ④ DSH / Provider 请求 | DSH 子进程成功结束，或按安全类别标记启动、网络、限流、模型路由、图片输入、HTTP 参数/负载错误 | 不读取或展示第三方中转站私有请求正文、响应正文、密钥或原始 stderr |
| ⑤ 模型最终回答 | 是否有可供主人查看的最终文字；由主人认可或否决 | 模型返回文字不自动等于看懂图片，仍须人工核对 |

MCP 侧固定图片证明现在绑定：

- SHA-256：`a041e0a1ffc95fe91c13d9acc6c48b8a37ddae15a8de910d9ee35975d0ff5c3b`
- PNG 字节数：`515908`
- MIME：`image/png`
- 图片块数：`1`

这张图只用于只读验收，不访问 B站、不触发 Life 行动、不授予任何平台写权限。插件只能证明 MCP 返回了固定图片块；若 DSH 内部桥接或第三方中转站丢弃了图片，需根据最终回答与外部服务日志继续定位，不能把 MCP 回执误说成模型侧图片送达回执。

## 主要实现位置

- `lib/vision-model-route.mjs`：视觉路由优先级的唯一运行时解析器。
- `index.js`：Headless 视觉选择、overlay、图片验收 route 元数据。
- `lib/headless-model-sync.mjs`：安全读取协议、Base URL 主机、图片输入与思考档位声明。
- `lib/dsh-vision-review.mjs`：将分阶段诊断绑定到当前完整路由；路由变化后旧结果失效。
- `lib/vision_dsh.py`：验证固定图片回执，返回安全阶段状态和上游错误分类。
- `vendor/bilibili-mcp/mcp_server.py`：固定图片工具返回 ImageContent 时写入一次性、受限的图片证明。
- `lib/management-console.html` / `lib/management-console.js`：分别展示模型声明、Headless 文字验证、图片阶段与人工结果。

## 测试与未完成验收

新增 `test/v281-dev3b19-headless-vision-route.test.mjs` 与 `test/test_vision_dsh.py` 专项覆盖：

- 视觉独立路由、插件默认继承和宿主当前模型回退顺序。
- Headless 源/目标模型能力元数据和 Base URL 安全显示。
- 同一 Provider/模型同步、文字验证及路由指纹绑定。
- MCP 图片证明正确、缺失和不匹配。
- 第三方 Provider 请求参数/负载错误的安全分类。
- 模型回答等待人工认可，路由变化使旧验收失效。

离线测试不等于真实模型验收。仍需在用户 Windows DSH 环境使用现有 `muze-gpt / gpt-6-luna` 实际执行图片验收，查看五阶段状态与最终回答；如果第③阶段仍不可观测，必须结合 DSH/中转站可提供的日志继续确认。不得仅凭 `input: image` 或文字连接通过就宣布视觉闭环完成。

**架构接线未变**：没有新增业务 Agent、数据账本、平台工具或权限层；本版只是统一视觉路由解析、扩展本地只读能力状态并提高固定图片验收可观测性。
