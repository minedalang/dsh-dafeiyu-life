# Life Agent / Python MCP：跨语言只读预约的嵌套身份核验

当前增量保持 `2.7.1-dev.4`，不开放社交外发权，不改变账号绑定、原读取预算、契机状态文件或真实生活时间线。

## 问题与证据边界

用户手动考虑选择了合法 `begin_exploration`，`bili_video_info` 返回 `metadata-read-busy`，并标记 `origin=response-validation`。这只能证明**调用结果中包含预约拒绝**，不能从此单条日志断定是其他实例抢锁还是合法嵌套的自我拒绝。原内置调用链：Node `readActionGate.run` 先预约同一 BV；Python `_gate_read` 再次检查目录。Python 过去要求锁记录 PID 必须等于自己 `os.getppid()`。Windows Python 启动链经过启动器时，合法内置调用可能不是 Node 的直接子进程，造成无平台请求的 `reservation-held`。

## 唯一职责与信任边界

| 层 | 唯一事实／职责 | 新增内容 |
|---|---|---|
| Node 平台读适配 `index.js` | 唯一内置 MCP 启动及账号作用域 | 每次插件进程初始化随机生成一次 256 位只读适配凭据，仅交给内置 MCP 子进程环境，不写磁盘与日志；支持先占位待办的早期锁 |
| `read-action-execution-gate.mjs` | 原跨进程预约账本，唯一动作键与回执 | 在原 `entry.json` 上增加 HMAC 身份证明，不写原 token，也不改变 v1 读取兼容或写回状态 |
| Python `read_action_gate.py` | 独立 Python 与嵌套 Python 的共同预约核验 | 对新锁要求 HMAC 一致、同账号、同动作、执行中、原进程仍存活；旧锁无 HMAC 仍只允许严格直接父进程；跨进程和死锁保守拒绝 |
| Python `mcp_server.py` / JS metadata / Life trace | 原错误类别与脱敏记录 | 拒绝时返回有限 `reservationReason` 枚举，Life 调试显示具体原因，不保存目标 BV、账号 UID、Cookie 或原始错误 |

**未放松：** 独立 Python 视频 Agent **不能**因为设置 `BILI_JS_MCP_ADAPTER=1` 就复用别人的预约；token 缺失或伪造不能通过，非匹配 BV/账号/进程状态不能通过。旧中断锁不会自动清除，真实调用结果不明不自动重做。MCP 重启不会重新授予已有旧事件的执行权。

## 协议与兼容

Node 生成 `BILI_JS_READ_GATE_TOKEN`（64 个十六进制字符），但只通过内置 MCP 子进程环境传递。磁盘写 `adapterProof=HMAC_SHA256(token, reservationId)`，不写 token。Python 核验 HMAC、源锁的 `id/operation/scopeHash/state=executing/pid 存活`；因有独立凭据证明，不再需要“同一进程必须是直接父进程”。旧锁不存在 `adapterProof` 时仍要求 `pid==os.getppid()`。

`reservationReason` 枚举：`adapter-proof-mismatch`、`legacy-parent-mismatch`、`owner-not-running`、`record-invalid`、`other-reservation`；仅用于诊断，不是授权、平台回执或真实 B站错误码。原 `metadata-read-busy` 和读取预算保持不变。

## 实际触发与验收

- 更新插件与内置 MCP 副本，重启宿主；自定义 MCP 如存在冲突，必须走原人工备份复核流程。
- 先运行管理中心「诊断一次真实视频资料读取（不调用模型）」仅一次，再查看 Life 决策全过程；若成功，表明单条当前账号 BV 的只读元数据核验已通过，但**不等于看过视频**。
- 若仍失败，检查 `origin`、`layer`、`reservationReason`，并配合「平台读取预约与中断核查」的 `active/interrupted`，区分历史残留与进程校验失败。**不要直接清理仍在运行的锁。**
- `record-invalid/other-reservation` 不说明可以强行解锁；若账号切换或真正锁残留，仍需停机、核验原回执并按原流程人工恢复。
- 离线覆盖正常嵌套、额外 Python 进程层、伪造 token、禁用 adapter、旧锁兼容、账号隔离、保密和原限流契约；Windows 原版 `run-tests.bat`、真实 MCP 与 B站 API 仍须用户实机验收。
- **dev.7 Windows 夹具修正（不改变生产接线）：** `test/v271-dev4-life-nested-read-identity.test.mjs` 使用 `fileURLToPath()` 而非文件 URL 的 `.pathname`，确保 Windows 盘符和含空格路径能进入 `PYTHONPATH`；原有 `PYTHONPATH` 用操作系统分隔符拼接。`run-tests.ps1` 将这项双 Python 子进程核验列为早期必测，失败时不把后续批次标记为通过。该修复不修改锁协议、凭据、社交授权或事实回执；Windows 实机仍需复测。
