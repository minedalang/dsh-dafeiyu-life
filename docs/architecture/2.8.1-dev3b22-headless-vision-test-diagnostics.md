## 3. 图片验收时序

1. 用户保存实际 DSH 视觉路由，确认 Headless 已同步、相应模型文字请求已通过。管理页以最新 `dsh-vision/status` 而非本地旧卡片状态决定按钮可用性；异步旧响应丢弃。
2. 点击人工固定图片实测，先检查原 PNG 字节大小、SHA256、PNG 文件头、受限 MCP 服务器声明及 Python 运行依赖。
3. 启动**独立** stdio MCP 会话，工具目录必须只有 `bili_vision_selftest`；实际调用后验证返回唯一 PNG ImageContent 和 nonce 证明。失败则不启动 DSH，安全分类为 `mcp_preflight_failed`；成功仅记为「MCP 独立工具就绪」。
4. 继续原 `vision_dsh.py` 受限 DSH 会话，传入固定图片工具和严格 overlay，不开放 B站其他工具；会话前置证明不能替代 DSH 自己调用并写出的 nonce 回执。
5. 即使子进程非零退出/超时，也首先读取会话自己生成的 nonce 回执。可确认的是回执中的固定图像、状态及耗时分类；不能确认 DSH 内部图片附件是否已成功交付第三方 Provider。
6. DSH 返回非空 `VISION_TEST_RESULT:` 时在本次会话展示原始模型回答供**用户本人**判断。用户确认后才短时认可；切换模型/路由、重启进程则失效。

## 4. 脱敏诊断与日志导出

- 状态文件：DSH 本地数据目录 `bili-duty/dsh-vision-selftest-last-run.json`，只保留最后一次记录；按临时文件+原子重命名更新，使用权限 `0600`，拒绝状态文件符号链接和超大旧文件。历史格式 `schema:1`。
- 只允许 `at`、`status`、受限字符的 `provider` / `model`、不可逆短路由哈希、`diagnosticCode` 以及 `preflight` / `mcpImage` / `attachmentBridge` / `providerApi` / `modelAnswer` 的有限状态。
- 不持久化 `reviewId`、完整模型回答、PNG/Base64、原始 stderr、HTTP 请求/响应正文、URL/query、API Key/headers 或视频与账号私密线索。
- 日志导出工具只将字段白名单中的脱敏摘要写进 `_diagnostics/`；不复制原状态文件。已保存的上次诊断可能指向**旧路由**，不能充当当前路由验证或人工认可。

## 5. UI 和移动端

- 左侧 Desktop、右侧 Headless 各模型行使用稳定的 Provider+Model 标识，在 `synced` 时绘制柔和虚线；聚焦行高亮。滚动/高度变化时重新计算 SVG 路径，≤850px 不画交叉线，改用文字说明。
- 真实状态与对应连线分离：连线只说明同源同步关系；文字通过、图片通过必须另读后端事实，不用线条颜色替代验证结果。
- 删除重复的第三方视觉 YAML 配置助手，保留原安全的 Headless 专属能力补充弹窗；仅对用户手动确认的未声明能力补充，不写 Desktop。
- 手机端只读；实际同步、模型验证、能力写入及人工验收仍由桌面端操作。
