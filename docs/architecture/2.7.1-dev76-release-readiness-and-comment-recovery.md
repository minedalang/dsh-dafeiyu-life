# 2.7.1-dev.76 · 安全跨轮评论回访、统一看板与 RC 发布审计

> 审查基线：2.7.1-dev.75 完整交付包。该报告判断的是当前 dev.76 源码和给定日志，**不是**已部署 Windows 的结果。发布判定：**`releaseReady:false`**。不得擅自合并 main、打稳定 Tag 或发送真实 B站评论。

## 一、主评论机会丢失：源码根因与修复边界

旧链路 `bili_ledger_mark` 只有 `recorded_selection` 为 true 才会自动请求一次 Life 评论考虑。首次入选已经存入 `video-actions.sqlite3` 后，即使 `_round_comment_evidence` 不足、Life model/provider 不可用或轮次中断，下轮也不会再次触发；同时 `explainCommentSelection` 强制旧 BV 拒绝。这不是鱼鱼选择不评论。

### 新契约

1. 仍用原账号 `video-actions.sqlite3`，新表 `video_comment_reviews(account,bvid,state,updated_at_ms)`，不新建私密信息库、不存正文和 Life 提示。
2. 精确新入选时仅写 `pending`；Life 明确 `pass` 写 `passed`，返回有效 `want` 即写 `approved`。一旦已经批准，之后发送层可能发起外部写入，**不能因尚无已确认回执就再次自动复审**。平台回执由原 `comment_receipts` 和写入事务继续核查。
3. `video-owned-ledger-read.py` 只读报告状态及原可信入选毫秒时间；从旧版升级的状态缺失或历史时间为 0 的记录不推断为 `pending`。
4. `recoverableCommentCandidates` 仅在当前账号成功读取本地原账本、入选不超过 24 小时、状态 `pending`、无评论回执时返回，每轮最多 2 项提示给 Video Agent 自由决定是否重新访问。若重新访问，必须在**本轮**调用原视频阅读工具取得 `_round_comment_evidence`，再请求 Life 重新判断。对非本账号、过期、已发、已跳过、已批准及未知状态均拒绝。
5. 宿主 `explainCommentSelection` 只在当前轮持有同账号状态与原历史 `pending` 证明时解除“旧视频”阻挡；仍拒绝账号变化、工具读取失败和不匹配的轮次。**选择恢复不等于发送批准**；最终仍通过原 Life proof、用户开关、平台额度、防重及读回核验。
6. 自愿 `pass` 不被改变；已授权但未发送、发送结果未知或旧版未能完整复核的记录**不会自动恢复**，应让维护者停机核对事务。不会遍历旧共享 Markdown 自动发送，也不会重放旧评论草稿。

### 尚需实机观察

Video Agent 可以选择不回访这两项提示；这是恢复一次“考虑机会”，而非保证评论会发出。实际能否重新获得字幕/评论区证据仍取决于 B站接口、模型和本地工具。首次运行需备份旧 `video-actions.sqlite3`，一旦 Python MCP 与已安装受审版本不一致，按原安全诊断人工备份并修复后重启。

## 二、「鱼鱼想做」及行动树

- 顶部 `life-plan-hub` 从已有 `/life-opportunities` 和 `/owner-todos` 读取真实来源：线索、持续探索意愿和已接受待办进入同一种生活事项卡片；可筛选类别，显示阶段与下一步。旧任务编辑、原证据详情在折叠区保留，零新写入 API。**不会因为摘要看起来相近，就将两条不同来源合并为同一个事实，也不宣称某条线索必然引发某个待办。**
- 行动树从 `/life-agent/decision-traces` 的真实 `execution-plan`/`action-start` 选择行为，从 `action-result`/`execution-result` 结算。增加候选、模型选择、执行、核验四阶段说明；没有 `execution-plan` 的候选不能被高亮为已执行。`not-sent` 单独标记；`verified` 只表示该类动作有回执，不推出“完整观看音画”。
- 普通页面不展示匿名 UID、平台正文或原模型提示；专业诊断保留技术信息。低动态偏好下停止闪烁。

## 四、阻断发布的 P0 项

- **真实平台/宿主端到端未验收**：不能在隔离沙盒中完成 Windows DSH Headless、真实模型回执和 B站发言读回。
- **跨日成长因果未证实**：不能拿模型自述、候选计数或静态单测替代实际未来选择差异。
- **72 小时稳定性及故障恢复未验收**：包括授权撤销、账号切换、历史账本、未知外发冻结、重复轮询和平台限流。
- **UI 尚无真实 Chromium/Windows 截图验收**：本机浏览器启动受阻，不代表界面真正美观、可用与无溢出。
- **历史 dev.75 的既有测试失败没有全部解决**：离线专项零新增失败不能推断全库绿灯。正式发布仍需逐项处理所有有效失败并完成安全基线对照。

**本次代码补丁解决了可明确复现的评论机会恢复缺陷及 UI 结构问题；没有证据可以合理宣布整个 2.7.1 满足 RC 或正式版条件。**
