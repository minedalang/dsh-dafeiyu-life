# 2.7.1-dev.3 · 私密好友关系如何影响鱼鱼自己的生活（第一条真实接线）

> **不是自主好友回访、私人记忆自动搜索或关系语义画像的全部实现。** 本增量只将「私密域已证明的、最近多日明确表达的好友兴趣」与「鱼鱼自己的本账号公开兴趣候选」做精确交集，让鱼鱼同一轮 `AutonomousPlanner` 模型可以自主决定是否继续**已经有权探索的公开主题**。不从私密域创建公开查询目标，不创办回访工单，不自动私信。

## 统一层归属与实际调用

| 环节 | 唯一事实源 | 本增量 |
|---|---|---|
| 好友兴趣的明示与时序纠错 | 现有 `friend-learning.mjs` | 新记录在**事件准备时**绑定 `discussionAccountTag`；原有缺归属标签的历史记录不作自主生活依据。读取时按当前账号严格筛选。原兴趣/推荐旧逻辑兼容。 |
| 亲密度 | 原 `SocialRelationshipIndex` | 只作为附加门槛：`familiar/friend`、至少 3 个真实互动日、有双向互动、最近 30 天；白名单本身不计亲密度。不建立新关系库，不授予外发权。 |
| 私密域可用于个人生活的内容 | `createPrivateLifeAffinity` 只读投影 | 要求当前账号内**跨至少两天的好友私信**明确喜欢同一主题、近期重复且未被后续明确纠正；仅与鱼鱼自己的 `interest-milestone` 公开主题完全匹配。只返回原公开候选匿名 `cueId` 和模糊关系阶段，不返回私信文字、UID、姓名、私密主题、事件 ID。 |
| 意愿与执行 | 原 `AutonomousPlanner` | 在原有**一次** Life Voice 模型调用中增加至多 3 条匿名共享兴趣提示；模型可以忽略、沉默、继续原本可执行的只读公开探索；没有第二次 AI 分类或专属调度器。 |
| 公开查询 | 原 `LifeOpportunities` + B站只读接口 | 仍只搜索鱼鱼自己已核实的公开兴趣主题，绝不直接用模型编写的自由文本或私密好友话题构造搜索词。平台回执和账号校验不变。 |
| 管理中心 | 原「人生记忆 → 自主生活」 | 只显示**提供的**交集组数和匿名来源可用性；不声称模型必定采纳，也不展示好友信息。好友资料损坏显示读取失败，不伪称鱼鱼无兴趣。 |

## 为什么不直接做“关系越深越应该私信”

亲密度决定可参考多少可信关系信息，**不决定发送许可、联系频率或模型一定要找人聊天**。本阶段完全没有增加发送行动。旧版已核实的停止联系、退订、冷却和真实回执独立生效。即使模型自行产生关怀意愿，也不能绕过它们。更深的人际叙事必须先设计可撤回的、精确 UID／账号／私密域来源及用途授权，不能把 DM 原文、私密人物回忆作为公开搜索输入。

## 数据流和升级兼容

1. 白名单好友通过真实 B站 DM 明确表示对某个主题的当前喜好，原 `prepareFriendInterestObservation` 在**消息发生时**附当前账号匿名标签；原 `SocialInteractionCoordinator` 将这个标签通过原有待补偿 outbox 保留，避免晚写入时被赋予其他账号。`recordPreparedFriendInterest` 与既有账本一起落盘，未另起档案。
2. 当前账号已有鱼鱼自主选片、跨日至少 3 个 BV 的 `interest-milestone`，才能成为原自主规划器 `lifeCues`。
3. 自主调度时读取最多 50 位白名单好友；需要同账号、最近 30 天、私信跨日重复喜欢、熟悉阶段加真实双向互动、无新近相反自述等门槛。只计算已存在的公开兴趣候选交集，不新建外部查询候选，也不读取历史未标账号的私密资料。
4. 同一模型输入只增加最多 3 条 `sharedInterestAffinity`，含对应公开候选 ID 和`familiar-or-friend` 粗阶段；不得由它产生联系授权或人格判断。模型如果继续探索，后续执行仍从原公开主题发起 B站真实只读搜索，成功才入账。
5. 好友清除兴趣、白名单移除、兴趣新近纠正、账号切换或数据超时，下一轮即时失去交集。**已经发生的真实公开搜索回执不会被伪造或删除**，但本增量不会再把失效的私密偏好作为新的意愿参考。

## 仍未完成与风险

- 原 `SocialRelationshipIndex` 是既有关系元数据索引，本增量未重建为完整的逐账号关系索引；因此要求**额外的当前账号跨日私信偏好证据**作为硬门槛，不能仅依据关系阶段推断不同账号的熟悉程度。
- 现阶段不能从自由叙事的私人共同经历语义上推断喜好；只处理**明确、可纠错、已归属账号的好友兴趣与鱼鱼已公开核实的兴趣交集**。缺数据时宁可没有提示。
- 本轮只证明“可把关系信息作为自主决策输入并仍执行真实公开工具”的代码闭环；**真实模型是否因这项提示改变选择**，要在 Windows DSH/B站实机中比较有/无交集的轮次，不能靠一次模型回执声称有因果性。管理中心展示“提供参考”，不展示内部推理；如同一轮真实完成相交主题的公开搜索，调度历史会记录 `affinityMatched`，它只证明**选择的主题与参考相交**，不证明这是模型行动的因果原因。
- 私人关系驱动的合法对外联系、回访授权与完整共同经历纠错，仍需要独立开发和实机验收；不能把本轮自动化测试当成完成。

## 实机验收

- 更新并重启插件，先确定 B站账号绑定状态正常；确保后台私信、白名单与自主调度原开关和限额有效。
- 在不同日期由白名单熟悉朋友**真实、明确**通过私信表达相同兴趣，且与鱼鱼自己已有证据的公开多日选片兴趣主题完全相同。升级前无账号标签的记录**不会追认**；不应人为写入“我喜欢”测试数据冒充真实来源。
- 「管理中心 → 人生记忆 → 自主生活」刷新，检查“可信熟悉好友共同兴趣参考 N 组”，只读刷新不消耗 AI，不显示 UID、私信内容。没有满足全部条件则应显示 0 而非猜测。
- 有真实参考时，可以显式提醒鱼鱼自主考虑；允许沉默。如果她选择公开探索，原 `verified-search-results` 回执与公开主题一致才算成功。不能以参考组数证明她实际使用了该信息。
- 切换账号、清除该好友兴趣或明确表达不再喜欢后，下一次读取参考必须消失；主动私信/评论权限不变。
