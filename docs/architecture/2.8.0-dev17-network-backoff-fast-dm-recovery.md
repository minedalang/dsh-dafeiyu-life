# 2.8.0-dev.17：网络恢复、快通道接线与主人私信上下文锚定

本文件记录基于 `2.8.0-dev.16` 上传源码与 2026-11-14 运行日志的修复。它是开发预览增量，不代表 Windows、B站真实 API 或长期运行验收已经完成。

## 1. 网络退避事故复盘

11 月 14 日日志记录评论通知读取在 11:24:07、11:26:24、11:31:33、11:41:45、12:01:57 多次出现 DNS／连接错误。当前退避数组原为 `2 / 5 / 10 / 20 / 40` 分钟，因此 12:01:57 的第五次失败将 `replies` 与 `mentions` 的下一次允许检查写为 12:41:57。

12:15:02 的“取消退避”日志明确指向 Life 模型错误退避；它没有清理 `interaction-network-backoff.json` 中的评论与 @ 网络状态。普通网络退避只有真正发起轮询并成功后才会被清除，因而网络恢复后仍可能等到持久化 `nextAt`，形成恢复死区。

### 修复

- 普通 DNS／连接错误的退避调整为 `2 / 5 / 5 / 5 / 5` 分钟，五次后仍每 5 分钟允许一次只读恢复探测；B站 `-509`／HTTP 429 的 rate-limit 阶梯不变。
- 管理中心增加独立的「恢复网络监听」操作。
- 旧版 v1 网络状态首次升级读取时立即允许一次探测；该手动操作只清除 `category=network` 的 `dm / replies / mentions` 状态，并要求每个渠道的 `nextAt` 与页面读取值精确匹配（CAS）。
- `rate-limit`、共享读取预算、账号切换围栏、发送冷却和写入授权均不可通过该按钮解除。
- 清除后不主动调用 B站接口；后台在下一次调度 tick 按原轮询节奏执行。

## 2. 快速私信轮询真实断点

运行快照在 `dmActivePollSeconds=10`、`activeCount=1` 的情况下显示 `dmFast.checks=0`、`lastFastAt=0`。源码核对发现 `index.js` 构造 `createInteractionScheduler()` 时只传递了 `dm.poll`，没有传递 `dmAutoreply.nextFastUid()`；同时 wrapper 忽略了调度器传来的 `{fastUid}`，所以调度器不能选出活跃会话，也不能执行定向读取。

### 修复

- 生产 adapter 现在暴露 `nextFastUid` 和 `status`。
- `poll({fastUid})` 将目标 UID 传给原 `dmAutoreply.poll({fastUid})`，仍共用原账号校验、读取预算、锁、去重与回复回执。
- 普通全量扫描才执行主人沉默续聊检查；10 秒定向扫描不额外触发该流程。
- 定向读取失败仍进入同一私信网络退避；模型失败仍使用模型冷却，不会每 10 秒重复调用模型。

## 3. 截图中的回复是否错用了上下文

日志和本地账本可确认：12:16:09 在 `BV1MaWv6rEo3` 下成功发表一条原创顶层评论，RPID `323903108256`，正文与截图中鱼鱼引用的评论完全一致；当日视频观察账本也记录了标题「臭肥鱼害我把情书交给辅导员了！【人和肥鱼03】」。所以 12:24 对“最近发了什么有趣的评论”的回答有同账号、同日、真实评论回执支撑，不是把他人的评论当成自己的，也不是编造评论。

但截图中 12:26 对「还是得是你」的回应“猜错那么多次”更像从更早的猜饭话题借用了笑点，未紧贴上一条助手回复。短期历史本身属于同一主人会话，并不代表记忆串号；问题是短反馈时模型没有足够强的“最近一轮优先”提示。

### 修复

主人 DM prompt 对每条有效短期历史提供精确的 UTC 时间戳，同时明确提供上一条已确认助手回复的时间与主人本条消息的时间。**不按 90 分钟或其他固定间隔硬切历史**：昨天的话题仍可由主人自然接续。对“哈哈／还是得是你”等短反馈，要求优先理解本条消息与紧邻回复的语义联系，避免无关的旧猜谜突然串入；时间是判断线索而非对话结束证明。旧原文继续遵守原 14 天和 8 条提示词预算等限制，超过该范围的经历按原统一记忆检索处理。

原始完整模型 prompt 未被运行日志持久保存，因此不能声称已逐 token 复原当时的上下文；本修复通过 prompt 契约回归验证，不记录或额外持久化主人私信原文。

## 4. 本轮 4 个测试失败的原因

- `公开成功评论回执支持日期筛选…`：测试夹具使用没有时区的 `2026-11-06 12:41:35`，再与 UTC cutoff 比较。Windows 本机时区不同会改变 `Date.parse()` 结果。夹具改为明确 `-08:00` 偏移并调整 cutoff，产品时间过滤规则不变。
- 三个架构契约测试：图表逻辑路径使用 `/`，但 Windows `path.join()` 生成 `\`；`overrides` 查找键没有规范化，导致 Windows 测试注入的损坏图表没有真正被检查。现在统一规范化逻辑路径，并加强项目根目录边界判断。
