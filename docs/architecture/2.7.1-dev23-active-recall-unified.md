# 2.7.1-dev.23 · AI 主导的跨渠道主动回忆（生产接线，非发布验收）

> 当前事实：这次改的是**模型何时、以什么查询词寻找记忆**的接口，没有迁移记忆库，也没有引入第三方 Embedding、向量数据库、第二个角色模型或平台写入工具。完整 `full` 模式和部分专业 Agent 仍保留旧装配方式，不能把渐进接线描述为全系统完成。

## 1. 统一层归属检查（先核查后改动）

| 入口 | 复用统一层 / 唯一事实源 | 新增场景信息 | 隐私与权限 | 回归 |
| --- | --- | --- | --- | --- |
| 主人私信 `owner-dm-agent.mjs` | `memoryRetriever.ownerSearch/ownerDetail`；本人历史评论 `recent-comments` 成功回执 | AI 决定 `memory_search/public_comments` 与 `queries` | 需已认证主人、当前登录账号；`memory_detail` 只能展开本轮已检索 ID；无新写权限 | 无预检索、无词阻断、可衰减副本、跨日回执 |
| 普通私信/评论 `interaction-batch.mjs` | `SocialContextAssembler` → `memoryRetriever.socialContext`（主人私信私域由现有策略限定） | `contextRequests` + `recallQueries` 最多三组 | 一条消息的 UID/渠道作用域；空查询词或读取失败拒绝续推；未知身份不读 | 原文弱相关/模型词精准匹配、fail closed、隐私隔离 |
| 主人公开评论 `comment-social-ai.mjs` | `searchVerifiedPublicComments` 唯一 `seen.md` / 月归档账本 | `recallQueries`、当前视频/当前账号范围 | 仅当前已认证主人、当前账号、发送回执；额外轮仅可修改 chat 文本 | 多词、BV、换号/时间门禁、不触发新动作 |
| 受信好友公开评论（trusted） | `SocialContextAssembler.message` → 公开安全 `memoryRetriever.socialContext` | AI 在 `chat` 中提出 `recallQueries` | 本 UID 公开互动和鱼鱼批准公开记忆，不能查询主人私人记忆或其他人的私信；不写出新授权 | friend 查询、隐私拒绝、二轮不得改变行动 |

模型的查询词**是待检索线索，不是事实，也不是授权**。模型不得提供身份、账号路径、档案作用域、UID 或忘记保护开关。统一 `active-recall-contract.mjs` 只负责限制 3 组短语、去重和危险输入，不能替代 `SocialPolicyGate`、`MemoryRetriever` 或账本。后者在**实际读取时**再次按原权限、时效、遗忘及账号门禁确认。

## 2. 时序与成本

- 默认精简社交：先有小型场景上下文、统一 Life Voice（人格/情绪只取一次）、同 UID 近期对话；模型普通回复不读长期记忆。若需回忆，第一轮输出 `contextRequests:['memory']` + `recallQueries:[...]`，宿主调用原 `SocialContextAssembler` 读取当前仍记得的副本，第二轮做最终回复或沉默，最多一次额外模型请求。其它 `todo/portrait/meme` 仍使用原有类别请求，不是模型任意 SQL/路径工具。
- 主人私信：保留正常近期真实行动摘要（执行回执）和非记忆 Life 状态；**不执行文本正则预检索**。模型可按需用 `memory_search` / `public_comments`（搜索词由模型生成）、`memory_detail`（本轮已检索 ID）或 `recent_actions`；原最多四步，重复查询阻止。没有词时不回退整段用户原话；没有可靠证据必须承认未找到。
- 公开可信评论：第一轮意图/意愿决策仅做一次。只有 `chat` 可以申请回忆，回忆轮只能修订文本，不许重选点赞、评论、待办或社交意愿。`public_comments` 成功回执只证实曾被平台受理，**不保证当前仍可公开可见**。
- 多关键词召回：模型可分别提出具体名称、同义表述、上文指代的已知实体。长期记忆做当前库的本地词汇评分；情节只读当前可回忆、已衰减的情节副本；本人公开评论在**一次**主账本扫描中对多词做 OR / 去重排序。不是完整语义向量检索，专有名词替换与未建索引的经历仍可能漏检。禁止扫描永久遗忘归档。
- 可靠性：模型未给词、无授权或回忆读取异常时不继续使用半成品答复；未命中则明确标注 `not-found`，不能从未命中推论“从未发生”。日志仅保留请求类别和计数，不保留私信正文、查询词或记忆内容。

## 3. 当前覆盖边界和未完成项

| 场景 | dev.23 是否模型主导按需回忆 | 备注 |
| --- | --- | --- |
| 主人私信 | 是 | 有多步只读工具与真实活动回执摘要，具体模型选择需实测 |
| 默认 compact 的普通私信/评论 | 是 | 精简批次依 `contextRequests + recallQueries`；继续尊重原回忆权限 |
| 主人公开可信评论 | 是（公开成功回执） | 只可修正 chat；不可用主人私有记忆 |
| 受信好友公开可信评论 | 是（公开安全记忆） | 同 UID 公开互动、公开批准记忆；无主人的历史自评查询权 |
| 传统 `interactionContextMode=full` | **否（保留兼容）** | 仍会预装配当前作用域的记忆/画像，用户若要求完全按需应选择默认 compact；未来单独评估迁移 |
| 主 Session / 独立视频 Agent / 自主分享 / 回访 / 个别专业 Agent | **未整体迁移** | 各自现有检索和证据路径不变；先做跨入口召回率与行为对照再统一 |

**未验收：** Windows DSH Desktop、真实 B站平台、真实模型执行回忆请求的比例与自然度、双账号冷热切换、72 小时自主生活、被遗忘记忆确实无法被召回、跨日人格成长因果、Recall@k/语义同义词覆盖、跨平台。`releaseReady: false`，不得宣称 Life 1.0 已完成。

## 4. 可观察验收入口

- 主人私信问“那次是怎么回事？”并紧接上文提到“海边散步”；预期模型可能发 `memory_search(queries=['海边散步',...])`，只有这时访问仍可回忆的副本；若模型选择直接回答，不应存在规则触发的搜索。
- 普通好友问“之前那场电子音乐会呢”，精简模式应先由模型请求 `memory + recallQueries`，再只读取该 UID 可见的安全记忆。记录聚合类别和命中/失败，**不**记录关键词正文。
- 主人公开评论问鱼鱼过去的妙评：模型可从确认的本账号公开评论账本读到跨日原文；好友不能使用主人专属账本接口；对任何公开聊天记忆只能在原发送事务权限下对外发送。
- 各测试使用本地 fake 模型和副本，不代表真实模型必然产生检索意图；验收须对隐含指代、同义词、低信息量对话测量召回/误触发率和成本。
