# ADR · 2.7.1-dev.4 统一 Life Agent：以事件驱动取代场景规定的生活流程（设计决定）

> 状态：**方案 C 已选型，完整目标仍在规划；dev.4 第一阶段已实施并待实机验收**。讨论基线：2026-11-05 的 `2.7.1-dev.3` 三阶段执行与诊断源码。已接入范围请以 [第一阶段生产说明](./2.7.1-dev4-life-agent-phase1.md) 为准；本文其余跨平台、多步、社交与成长链路仍是未来目标。
>
> 核心选择：**方案 C —— 单一平台无关 Life Agent + 事件驱动/轻量唤醒 + 按需多步规划 + 分层记忆成长 + 已有安全执行协议**。允许重构乃至替换旧生活流程，**不要求保留固定时间刷视频作为生活主驱动**。

## 1. 为什么改：目标是连续的生活，而非越来越多的脚本

现有 `AutonomousPlanner` 已有真实生活线索、跨轮意愿、账号归属、只读动作与模型预算；`LifeMemoryGateway`、Life Voice、情绪、关系、统一待办、平台事实与外发回执也已存在。但生活入口仍由多个定时器和场景驱动：视频轮、社交回复、反思、待办、探索各自决定什么时候叫醒模型。新增“私信聊得投机→关注”或“作品欣赏→关注”若都靠专用流程，会无限膨胀，阻碍跨场景、跨平台成长。

目标不是自动多做事，也不是每隔几分钟让模型自言自语；目标是**真实相遇/记忆/兴趣/责任→自主形成或放下目标→选用允许的能力→核实实际结果→影响下一次选择**。沉默、休息、推迟、改变主意都是合法结果。

## 2. 方案对照与决定

| 方案 | 架构 | 连续记忆/成长 | 自由度 | 费用风险 | 结论 |
| --- | --- | --- | --- | --- | --- |
| A. 原场景 + Agent 决策增强 | 旧视频/社交/定时流程继续定义生活 | 经历分散、成长依赖场景覆盖 | 中低 | 低 | 不作为最终架构；迁移期兼容 |
| B. 常驻连续思考 Agent | 每隔几分钟调用大模型，长链持续自反思 | 可能反复写入无新证据的“感受” | 高 | 极高 | 不采用 |
| **C. 事件驱动单一 Life Agent** | 无模型事件汇聚，按需决策，短链执行，持久意愿，证据成长 | **同一人格/记忆/关系/目标来源，跨轮延续** | **高** | **可预算控制** | **采用** |
| D. 多 Agent 各自决策 | 视频、社交、记忆、探索 Agent 各有计划 | 易重复记忆、冲突目标和跨域泄露 | 高 | 高 | 专业工具可保留，禁止第二套生活主体 |

方案 C 不保证“模型有意识”或总能做出好决定；它提供可观察、可审计的自主选择与连续成长机制。专家执行器可在单次任务内被调用，但不能各自产生独立的“鱼鱼人格/人生”。

## 3. 目标职责与唯一来源

- **Life Agent（唯一生活决策主体）**：接受经过隐私过滤的事件/到期目标/生活状态；决定 `ignore | rest | reflect | pursue | defer | abandon`，在允许的能力集合中选择下一步；在有预算和证据时可以跨轮继续。不能直接改授权、伪造回执或凭模型生成 UID/BV 当作已核实对象。
- **低成本事件总线/唤醒器（确定性，不调用模型）**：去重、优先级、过期、合并、冷却、安静时段、每天/每目标 Token 预算；没有新线索时不唤醒。时钟是检查到期目标和节律的机会，**不是刷视频指令**。事件来自消息、评论、真实视频资料、记忆变化、待办到期、平台回执等；不可把未验证的外部文本作为系统命令。
- **统一生活/认知**：Life Voice 与原情绪/人格为唯一装配；Life Memory/检索、人物关系与兴趣、已接受待办、dev.3 自主意愿为唯一相应事实源。**不新增第二套记忆库、人格数据库、社交画像或承诺账本**。长期记忆应有来源、可信度、隐私域、可纠错/遗忘、衰减和实际行为证据；将一次动作的技术日志与值得记住的生活经历分开。
- **能力目录/平台适配器**：平台无关的能力语义，如 `search_public_content`、`inspect_creator`、`read_discussion`、`follow_creator`、`reply_message`；B站当前适配器提供实际工具。将来抖音只增加合规可用的能力实现、身份映射与平台授权，不再复制 Life Agent；平台能力缺失时 Agent 必须放弃或改选其他允许的行动。
- **执行与安全**：dev.3 的只读预约、写入持久冻结、账号绑定、权限/额度、平台真实回执继续是硬门禁。意愿≠许可，模型文字≠事实，平台未知回执≠可重试。私密聊天信息不能自动转成公开搜索或跨平台传播；不同平台身份不能仅凭昵称合并。

## 4. 生命周期（目标行为）

1. **观察**：外部事件和内部到期意愿进入轻量队列；保留来源 ID、账号/隐私域、时间、可信度、最短必要摘要，不默认长期保存原文。
2. **过滤**：本地确定性规则消重/合并；高价值、真实新信息、到期承诺或合理生活节律才有候选唤醒。普通通知可合批；空闲时完全不调用模型。
3. **自主判断**：按需检索相关事实和最多必要的长期记忆；复用统一人格、情绪、关系、兴趣和待办；输出结构化意愿与下一步，允许休息/沉默/放下。
4. **执行**：能力目录选工具，执行前再次检查身份/权限/预算/作用域；工具结果与真实回执写入原事实/执行账本。高风险外发绝不自动重试未知结果。
5. **反馈与成长**：将真实发生且有意义的经历形成候选记忆；按既有反思/遗忘机制更新兴趣、人物认识和目标。对人物认识的纠错需要可追溯证据；不能把“看过标题”写成“看完视频”。
6. **跨轮继续**：意愿可延期、修改、主动放弃；已接受的主人待办不可被自由意愿静默覆盖。下一次醒来只携带相关摘要与检索结果，不重复塞入整段历史。

### 场景示例（不是硬编码触发器）

鱼鱼与某人私信交流→发现共同兴趣→可以先继续聊天、读取其公开主页、暂时不做事，或在授权后提出关注→验证平台 UID、关系状态与回执→有证据地更新对这个人的认识。**没有“聊得开心就关注”的固定规则**。观看作品时同样可以自然形成关注、进一步了解、换主题或放下的意愿。

## 5. Token 预算：先给上限，再量化实测

以下仅为**算例，不是现有系统测量值，也不是费用承诺**。模型不同，输入/输出单价不同；实际账单还取决于缓存、工具回合和记忆检索。

- 计算口径：`日 Token ≈ Σ(每次决策输入+输出) + Σ(工具后续规划输入+输出) + Σ(成长反思输入+输出)`。纯本地过滤、定时检查、平台 API 请求本身不计入 LLM Token（但可能有其他 API 成本）。
- **建议试运行配置**：每日最多 10 次独立 Life Agent 模型决策（每次假设 1500 输入 + 300 输出）；最多 6 次工具后续规划（1000+200）；每日最多 1 次增量成长反思（2500+500）。算例合计 `10×1800 + 6×1200 + 1×3000 = 28,200 Token/日`，约 `846,000 Token/30 天`。实际事件少时可以远低于此；与现有调用重叠时应复用而非额外叠加。
- **不推荐的常驻轮询算例**：每 5 分钟一次模型调用，每次 2000 输入 + 400 输出，则 `288×2400 = 691,200 Token/日`，尚未包含工具和反思，约为上述算例的 **24.5 倍**。
- 当前源码的 `AutonomousPlanner` 默认设置有**30 分钟最小间隔、每日 24 次上限**，但无候选会跳过，**24 是上限，不代表每天实际花费 24 次**。dev.4 需要统计原有视频/社交/自主规划/反思实际 Token 基线，再对比迁移后增量，不能把新方案的算例与旧方案的配置上限当作实测费用对比。
- **费用护栏**：模型调用前预约全局日额度和单目标额度；按需检索，不全量注入记忆；同源事件批量汇聚；工具结果摘要而非全文回灌；最多 2–3 步连续自主规划，超出转为持久意愿等待下轮；低优先级成长反思延迟/合批；超过预算优雅停止且不影响收消息和已承诺任务。
- **放行条件**：同等真实事件回放下，统计旧系统与新系统的模型调用次数、输入/输出 Token、工具次数、记忆召回质量、重复外发和错误事实。建议先以“总 Token 不超过现有基线的 1.5 倍”为首轮目标阈值，**不是无条件保证**；若达不到，优先优化唤醒、上下文和模型路由，再决定是否接受增加成本。用户可修改预算目标。

## 6. 如何重构旧系统（允许替换生活驱动）

| 现有成果 | dev.4 处理 | 原因 |
| --- | --- | --- |
| 固定视频轮 / 定时刷视频 | **替换为 Life Agent 自选探索**；旧入口先影子运行/可回滚，最终不再是主驱动 | 让生活目的先于视频动作 |
| 收件箱轮询、评论/私信接收 | **保留为感知基础设施**；可向 Agent 提交事件 | 不能因为 Agent 休息而漏消息 |
| 现有评论/私信自然回复链 | **逐步统一意愿与目标选择**；原线程连续性/限额/发送器复用 | 不让多个决策主体重复发送；仍可低延迟响应 |
| 原 `AutonomousPlanner` | **迁移/演进为 Life Agent 核心**，不平行再建第二套计划员 | 复用已接受待办、跨轮意愿和模型额度 |
| Life Memory、Life Voice、情绪、兴趣、关系 | **复用且增强证据回馈** | 记忆成长只有一个事实与人格来源 |
| dev.3 共享读取、写入冻结、回执、授权 | **保留为不可绕过的执行底座** | 自由意愿不等于越权执行 |
| B站视频 Agent/视觉/ASR 等 | **作为能力适配器/专家执行器**，不是另一个独立生活主体 | 避免多个鱼鱼与嵌套锁死 |

迁移步骤：①事件源/成本/回执基线采样→②只读影子决策（不执行外发）→③只读真实探索并比对事实→④分流接入已有社交决策，严格防止双入口执行→⑤经明确授权和可控目标验收外发→⑥逐步关闭旧“时间到了必须刷”的主驱动，保留回滚开关。不得在一个版本里无回滚地删除老用户的记忆/待办/权限配置。

## 7. 验收指标与用户可感知结果

- **自由**：同一真实事件可以选择行动、延后、放下或沉默；没有固定时间刷视频的强制性；没有新事件时模型可以零调用。
- **成长**：能从有证据的真实经历形成可追溯记忆，后续在合法范围内被召回并影响选择；纠错、遗忘、隐私域和账号切换可测试。
- **连续**：跨轮/重启仍能继续自己选的目标，也能主动改变主意；主人已接受的待办不会被遗忘。
- **安全**：授权撤回立即生效；未知外发结果冻结；跨账号/跨平台身份与私密域隔离；工具输出不具有指令权限。
- **成本**：对照实际模型用量账本评估，报告每次唤醒、每类任务、每天的输入/输出 Token 与费用（若价格已知）；超预算会优雅停止。
- **真实环境**：Windows + DSH + B站只读/模型实测由用户验收；真实外发必须另经用户明确同意测试对象和范围，不能用离线模拟冒充已验收。
