# 2.8.3-dev.3｜模型与依赖下载安装跨平台审计

> 结论：**代码提供多平台路径 ≠ 三平台全功能实机已通过。** 本轮只调整 Python **存储迁移**为 uv/pip 缓存迁移，不触发任何 Python 依赖重新安装，其他安装器保留现状。审计基于 dev.3 当前代码、无网络的定向测试和上游公开文档；不声称已经在 macOS/Windows/Linux 所有架构下载、安装并真实推理。

## 范围与证据等级

- **静态兼容**：在源代码中存在平台分支、对应工件和异常处理；可在本机用模拟调用测到，不能证明下载资源实际存在或本机安装成功。
- **环境验证**：当前容器 Node 代码与无联网定向单测；不证明 macOS/Windows 真机、权限、Gatekeeper、GLIBC/CUDA、网络和系统包管理器。
- **实机验证**：需要对应平台真实安装/探测/推理成功后才记录。**当前三平台全量实机：均未形成这轮验收证据。**

## 本次修补的安全边界

1. 第 2 迁移项改名「Python 包管理缓存（uv / pip）」；没有 `高级重建`，不允许后台/CLI/API 新增重建请求。
2. `uv-cache` 与 `pip-cache` 迁移要求 DSH 完全退出、空目录预检、内容校验，完成后设置 `UV_CACHE_DIR` 和 `PIP_CACHE_DIR`。不迁移、不删除 `.venv`、`.venv-asr`、视觉环境、`uv-python`、`uv-tools`。
3. 对历史 dev.3 `rebuild` 数据指针**兼容读取**并保留安全回退。不能因为新页面取消模式就强行重写过去的指针，否则旧用户已建立的环境可能停止工作。
4. 模型迁移与 Life 迁移继续执行原有的身份核验、非法链接拒绝和遗忘保护，Ollama 仍由外部管理。

## 三平台必须补齐的实机验收（不能用模拟替代）

- **Windows x64 / Windows ARM64**：安装/恢复 uv 与主 MCP，Whisper CPU 转写、FFmpeg + ffprobe 视频解码、Embedding 运行时启动与一次检索、Ollama 图片模型真实回答；缓存分盘前后均测试，并验证权限、路径含空格中文、可回滚。
- **macOS Apple Silicon / Intel**：uv+Python 3.12、本机 MCP/二维码、PyAV/faster-whisper 模型下载及 CPU 转写、brew ffmpeg/ffprobe 解码、llama.cpp 二进制权限/启动、Ollama 模型图片回答；需要明确视觉 Python 环境目前没有一键修复能力，不能据此宣布全功能通过。
- **Linux x64 / arm64（至少 Ubuntu glibc）**：uv+Python、编译 wheel 与 glibc 限制、faster-whisper CPU、llama.cpp 运行时与模型、FFmpeg/ffprobe 和权限（无 polkit 时走手动安装）；核验图像/OCR 的 PATH、模型缓存软链接和部署方式。非 Ubuntu / musl / 特殊架构需要单独标注支持范围。
- **每个平台**：冷迁移预检 → 停机操作 → 重启实际模型加载 → SHA-256 源/目标比对 → 清理资格检查；没有完成真实转写/图片推理之前不得标注“成功迁移并运行”，不得清除旧模型。完整冷备份/恢复跨分区仍是后续发布阻断项。
