# 通用浅层／深层记忆与渐进式回忆 · 初步架构提案

> **状态：未来规划／待单独排期，未实施。** 本提案不是 2.8.2 开发需求、不是 2.9.0 已承诺功能、不是当前可用的 Deep Memory API。实施时必须根据最新 `AGENTS.md`、实际代码、迁移测试和主人决策重新评审。详细方案的技术选择、容量与阈值均为候选而非默认配置。

## 1. 目标与用户体验

鱼鱼面对一件过去的经历，先想起“发生过什么、与谁有关、自己当时做了什么、总体感受是什么”；只有新的问题确实需要具体画面、对话、观点或时间线时，才深入回忆已有细节；必要时再查看仍获授权的来源证据。**渐进式回忆不是强制增加多次模型调用，也不是伪装人类真正的意识或生理记忆。**

需要解决的不是单独的视频摘要存储，而是任意符合权限要求的 Life 经历——视频、与主人/朋友交谈、自主行动、情绪经历、活动和可信认知——在不同深度下如何保存、提取、修订及遗忘。

例：普通问“昨天看到什么了？”→ 取浅层经历；追问“那个人穿什么？”→ 当前主记忆仍清晰且有可访问的观察细节时才取相应片段；若当时未观察、详情已衰减或描述互相矛盾，应说明不知道，不能自动重看、通过永久档案回灌或编造确定事实。

## 2. 四组必须明确区分的概念

1. **记忆深度（浅／深／证据）**：决定一次回忆需要多少内容。浅层是默认索引和概要；深层是当前记忆挂载的有界细节；证据层是当前可访问、允许用于核实的引用，绝非永久原始内容库。
2. **记忆清晰度（`clear → fuzzy → trace → forgotten`）**：现有可衰减记忆的单调遗忘状态，与取用深度是两条正交轴。深入思考不能恢复已经被衰减或删除的具体细节。
3. **来源可靠性**：确认视频元数据、字幕/ASR、采样画面模型描述、第三方弹幕评论和平台行动回执的事实边界。视觉模型说过什么不等于经独立证实；意愿不等于完成。
4. **隐私与授权**：主人/好友私密交流与公开作品不得因主题相似或向量近邻被合并；关联到同一经历也不产生跨账号或公开发言许可。

## 3. 候选数据模型（设计，不是已落地 schema）

### 3.1 主记忆：保留现有 LifeMemoryGateway 的唯一事实权威

```json
{
  "memoryId": "opaque-existing-episode-id",
  "kind": "watch | conversation | action | ...",
  "scope": "current-account-and-privacy-domain",
  "stage": "clear",
  "summary": "我经历了什么、我记得的大概内容",
  "salience": "existing-importance-policy",
  "observedAt": "verified-event-time",
  "sourceRefs": ["opaque-verified-reference"],
  "detailAvailability": "available | no-detail | faded | unverified"
}
```

这是**候选读取投影**，不是要求直接用它覆盖现在的 `episodic.json`。`memoryId` 只能指向当前仍存活的可衰减主记忆；BV 号、UID、标题、时间邻近和向量相似性都不能替代唯一主记忆归属。

### 3.2 深层细节：同一生命周期的附属内容，不是第二事实库

```json
{
  "parentMemoryId": "opaque-existing-episode-id",
  "detailVersion": 1,
  "fragments": [
    {"segmentId":"opaque-fragment-id", "kind":"observed-scene | verified-message | ...",
     "timeAnchor":"optional-verified-timepoint", "content":"bounded-derived-detail",
     "sourceRef":"opaque-receipt-ref", "confidence":"model-observation"}
  ]
}
```

建议物理分离以避免普通检索一次取出全部细节，但深层文件必须服从 Gateway 读/删规则。候选片段带时间锚点、来源类型、冲突标记和内容覆盖缺口；只保存**真实已获得**且当前允许保留的内容，不永久囤积视频帧、音频、完整字幕、私密聊天或敏感凭据。不存在细节时不能让模型补写虚构片段。

单条主记忆可能有零至多个深层片段，按实际证据价值决定是否存；不预先要求每件小事都有长篇摘要。对不同 Episode 可进行物理重复数据去重，但访问必须按当前有效的每一条主记忆单独授权和衰减；不能借其他 Episode 解锁已遗忘内容。

### 3.3 来源/证据：仅是门禁后的引用

每条片段只引用当前允许调用的来源标识、真实执行轮次和证据类型。单 BV 多次观察必须具有不同记忆 ID/执行 ID；若观察区间重叠可展示来源冲突和版本，但不能推断采样帧之间的连续画面已经看过。第三方评论只是他人言论，不能升级成视频真实内容。

## 4. 自然渐进式回忆协议

1. **想起**：普通词法/Embedding 仅检索可访问的浅层摘要；返回 `memoryId`、摘要、阶段与已知覆盖状态。不能仅凭详情内的私密词汇把主记忆暴露到公开检索。
2. **细想**：Life 或主人确实提出细节需求，按当前主记忆 ID 与具体问题进行二次、**有界**片段选择；每次重新检查账号、领域、对象 UID、记忆清晰度和所需来源，返回对应片段而非原始整份文件。
3. **核实**：仅当事实争议/安全需求确有必要，且原证据还在、当前允许访问时，进一步获取独立来源；离线读细节与重新联网观察/触发外部动作严格分离，不能因为检索不到细节就自动取帧。
4. **结束**：浅层足以回答就结束；没有细节或细节矛盾，正常告知模糊/不确定，绝不为了表现得聪明而补造事实，也不要求无意义的多轮 AI 内部调用。

候选接口（名称仅示例）：`recallSummary(query, scope)`、`expandMemory(memoryId, question, scope)`、`verifyMemoryEvidence(memoryId, sourceRef, scope)`；其中后两项**目前不存在**。未来必须通过 Gateway，不能暴露文件路径、BV 直接读或绕过 `SocialContextAssembler` 进行权限提升。

## 5. 深度与衰减的联动

- `clear`：主记忆可正常召回；深层细节只在当前仍存在且授权时可读；可选比主摘要更早减少细节数量，但不改变主记忆既有时钟含义。
- `fuzzy`：按现有单调遗忘规则退化为模糊印象；深层具体内容、索引项、关联指针和可被外部检索的缓存需要随主记忆一并清理。
- `trace`：只剩可允许的抽象痕迹，无深层可取内容。
- `forgotten` 或删除/逐出：深层数据/索引/投影不可被正常召回，永久审计档案仅受现有后台管理/备份规则约束，绝不可成为运行时补偿来源。

**清理必须是真实的数据清理，而不只是隐藏按钮。** 清理失败应安全拒绝详情读取并留匿名诊断。备份/恢复、进程崩溃、并发写入、向量索引/缓存应纳入同一衰减联动验收，不能意外恢复过期明文。缓存仅承载当前授权的副本，不产生更长的存活期。回忆本身是否能强化记忆需要独立策略与经验证据，不能默认每次访问就延寿。

## 6. 账户、隐私、授权和安全

- 访问键由 **当前账号作用域 + 主记忆 ID + 隐私域/角色/对象 + 细节片段 ID** 组成；不要只凭 BV、用户名、同名视频标题或近似时间做主键。
- 同一主人会话/好友私信可用的详情不等于公开评论可引用的事实；公开表达依然经过原独立许可、敏感内容过滤与真实平台回执门禁。
- 原始视频描述、字幕、评论、私信和模型输出都属于不可信输入。详情是数据、不是工具指令，不得含可执行注入或通过模型让系统取消删除。
- 永久事件审计保持“运行时不可回忆”；一切内容和所需来源都先经过现有可衰减 Gate 检查。权限撤销、切号、遗忘和主体关闭应即时失效。
- 不存密码/Token/可复用会话 Cookie；管理中心默认只显示浅层，深层点击后才按明确读权限拉取，日志只记录类型/状态/计数。

## 7. 与现有实现的兼容及迁移策略

当前 `life-memory-gateway.mjs` 所谓 *Two-layer life memory* 是**永久写入审计档案 + 可衰减日常副本**，并非本提案的浅／深两层。不得把新详情藏在 archive 里或建立独立于 Gateway 的新事实库。

未来先增可选引用字段和只读适配层；默认返回 `no-detail`；既有 `episodic.json`、记忆条目 ID、旧反思和主 Session 工作方式保持不变。只允许在来源仍明确、作用域可核验、当前清晰且实际仍存的详情上渐进迁移；**不从历史永久档案回填已遗忘细节，不猜旧账号，不为补齐详情重下载私人材料**。回滚时旧版本必须能忽略新的可选字段，不能损坏原有数据。

索引仅覆盖浅层，深层不默认加入 Embedding；已扩展的片段属于临时、受限的输入，需复用 2.8.2 上下文完整性报告，说明哪些片段实际送达模型、哪些因预算未注入。

### 7.1 2.8.2 之后：AI 摘要与视频视觉细节保留（新增待评审需求）

- **当前 2.8.2 不增加模型调用**：有限画面笔记只从当次可信视觉模型回答中按规则截取，不代表完整画面语义。技术重复观察防护改为 24 小时，和普通记忆衰减互不替代。
- **后续可选 AI 总结**：在已有可信视觉输出中，按账号与明确预算调用一次摘要模型，分别生成适合日常回忆的浅层摘要与有时间锚点、证据来源、置信边界的深层结构化片段。模型的总结是衍生解释，不能从未观察的视频部分编造事件；新增模型调用的成本及回执要可见。
- **保存“已观察到的完整视觉信息”而非原始完整视频**：保留实际可验证接收的细粒度场景描述、帧/窗口与时间锚点、遗漏和冲突记录；不把没有采样的时间段冒充已经看完，也不默认永久存储 JPEG、整段视频、完整模型原始响应或受限私人材料。实际接收内容应尽可能完整入深层片段，不能只剩当前少量截断笔记。
- **分层与遗忘联动**：浅层继续由 LifeMemoryGateway 管理；深层附属片段不得单独绕过账号、主记忆 ID、可见角色和 `clear → fuzzy → trace → forgotten`；历史永久档案不能被模型拿来恢复已经遗忘的信息。
- **检索策略**：BV/具体作品标识只用于当前仍清晰的经历精准定位；普通回答先浅层回忆，确需问细节再展开深层，不应因为摘要没命中就自动再次识图。

## 8. 建议实施阶段（全部待独立立项）

- **阶段 A · 协议评审**：枚举现有记忆类型、账号/隐私/衰减/备份路径；明确字段、退出机制、并发事务和容量上界；建立单独模拟数据集。
- **阶段 B · 最小只读原型**：选已获得明确来源的公开视频经历做主记录→详细片段的存取与按需读取，不动现有记忆索引和 Life 决定权。
- **阶段 C · 跨类型推广**：受限迁移到普通经历/已验证动作/合规私人对话，验证索引与权限隔离；拒绝无来源或已遗忘数据。
- **阶段 D · 渐进回忆体验**：Life 自选深度、主人追问、神经回忆场浅层默认+按需展开、深层失败提示。
- **阶段 E · 长期验收**：单调遗忘、跨进程竞态、重启恢复、回滚、内存/磁盘预算、脱敏/注入隔离、旧用户迁移及 Windows/DSH 实机。

## 9. 必须先决策的开放问题

1. 清晰期内的“深层细节更早淡化”是固定时间、信息价值驱动，还是主人可配置？不要擅自设置频繁整理任务。
2. 多 Episode 共享同一条视频片段时，如何实现物理去重又不让一条已遗忘的经历从另一条不相关路径复活？
3. 主人指定永久保留/自主删除、行政备份、缓存与正常运行时遗忘怎样协调？
4. 深层详情的成本上界与隐私域、原文保留政策由谁审批？旧来源缺账号标签时，默认拒绝，不强行迁移。
5. 是否允许 Life 为更强回忆主动调用额外模型，以及如何展示其开销和失败？

## 10. 2.8.2 允许的唯一提前适配

2.8.2 继续原路线：**视频证据追溯、真实感知覆盖、共享读预算/退避诊断、Life 意愿全过程解释、11 类上下文完整性整改**。可以保留“现有可衰减主记忆 ID + 已核验来源类型/观察时间 + 账号作用域”的轻量只读投影，为未来添加深层详情提供稳定适配点。

**明确不做**：建立新的深层文件或索引、拆分所有主记忆、生成通用深层摘要、自动二次召回、调整记忆衰减率、重建旧视频详情、神经回忆场深层面板或角色关系成长。此处的 `memoryId` 不代表新详情可用，更不代表目前能够“想起”从未保存过的内容。
