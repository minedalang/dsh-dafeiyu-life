# 2.8.1 私信转发原动态：两步自愿只读闭环

**源码基线**：`2.8.1-dev.3b.33.14`；**本次候选**：`2.8.1-dev.3b.33.15`。本文件仅描述真实源码与离线回归，不宣称 Windows 实机成功。

## 从日志与源码识别的缺口

20:31 导出的 Life 决策轨迹中 `inspect_related_content` 可作为候选，但本次日志未见实际执行的记录；脱敏诊断未包含私信正文，不能反推主人发出的精确动态内容。生产代码可从 B站转发动态对象 `item.orig` 提取经平台核验的原动态 ID，并创建 `reposted-original` 待读节点，但私信模型完成 `shared_link` 读取后只拿到外层摘要，不能立即看见可选 `shared_original`，导致外层附言容易被误解成原帖本身。

## 实现

1. 当前 B站账号和真实发件人通过私信接入门禁后，安全链接仅以类型化引用入库；Life 是否读取外层 `shared_link` 是第一次独立意愿。
2. 外层 `bili_dynamic_info` 真正成功，当前账号的同一账本里才能生成 `reposted-original` 子节点。仅当原动态引用唯一、合法、同账号、同发件人、时效内且未冻结，交给下一次**同一私信模型**的 `shared_original` 只读菜单。用户文本、外层附言和模型回复不得制造原动态 ID。
3. Life 第二次独立选择 `shared_original` 才能触发原帖只读；如果原帖已有真实核验回执则复用，不再重复发平台请求。若原帖读取失败、缺失或限流，模型只收到不能声称已读的提示。
4. 单轮最多两次按需读取；第三次请求及越权请求均 fail closed，不外发不完整草稿。回复、收藏、点赞、关注等写入仍需原授权和独立回执。
5. 原来 5 分钟普通 DM 列表、60 秒活跃检查、持久化 `-509` 退避、账号隔离、未知发送保护不变；客户端本地预算禁止时，不能误记原帖已读，也不能伪造平台失败。

## 定向验收

`test/v281-dev3b33-dm-reposted-original-continuity.test.mjs`：覆盖原帖候选唯一性、真实平台 ID、同账号隔离、Life 两次自由阅读与直接拒绝、越权菜单禁止、歧义拒绝、限流未读统计及宿主安全门禁。

**未验收**：Windows 生产真实转发 API 返回 `orig`、原帖图像模型识别、实际私信发送及用户是否在自由选择中愿意读取。日志缺少原始 DM 证据时不能宣称用户的那一条动态已经被鱼鱼真实读到。
