# 2.8.1-dev.3b.21 — 全站设置保存体验与跨场景契约复审

> 开发候选；基线 `2.8.1-dev.3b.20`。本次获准审计所有列出的场景，但不以「自然度」为理由扩大平台外发授权或跨用户私密记忆披露。下文区分**源码存在的能力**、**本次实际修改**、**仍需实机验证**。

## 1. 上版 Headless 是否解决第三方图片输入问题？

- **已实现**：`headless-model-sync.mjs` 保留 Desktop 明确声明的 `input` / `reasoningEfforts`；缺失时仅支持经用户确认的 Headless 专用补充，不会静默修改 Desktop/global/API Key。来源与目标是 Provider 级同步，同一 Provider 多个模型在同一张卡内展示；同步不等于已通过连接验证。
- **已实现**：`vision_dsh.py` 在退出码非零或超时时优先取 nonce 绑定的 MCP 固定图片回执；`management-console.js` 核对有效视觉模型路由及 `visionMode` 未保存状态。
- **未解决／不应谎称**：`exit=1` 仍可能是 Headless profile、MCP 工具、附件桥接、第三方代理的图片格式/凭据/调用失败。Desktop Session 能识图不代表受限 Headless Session 能识图。插件无法独立观察 DSH 内部附件桥接或第三方模型真实收到的图片字节。
- **本次修复**：`vision_dsh.py` 不再把 stderr 中普通的 “MCP ...” 字样就归类为 MCP 启动故障，新增安全的 Provider 401/403/密钥权限诊断；无 MCP 回执且子进程失败时，上游 API 状态标记为 `not_confirmed`，不会误报已经证明上游失败。
- **下一次 Windows 验收**：同一个实际 `Provider / Model / Profile` 先检查文字 Headless 验证，再执行固定图片检测。记录脱敏的 `diagnosticCode`、`mcpImage.status`、`providerApi.status`、`modelAnswer.status`，不要提供密钥或私密请求正文。若仍 `headless_exit_unknown`，需要 DSH 侧可安全观察的独立回执，而不是自动扩大图片声明。

## 2. 全站设置保存 UX

源码原先有几十个互相独立的「保存」按钮：模型、视频、评论、好友、社交、快速设置、轮询、记忆、额度等，长页面编辑后容易忘记底部动作。

本次 `management-console.html/js` 新增统一浮动保存提醒：

1. 用户编辑具有真实保存事务的设置表单时，底部始终显示未保存状态。与历史每页单独的保存端点复用；不会自动提交。
2. 保存栏的「保存本组设置」仅在确定**唯一归属保存按钮**时执行那个按钮，否则只引导定位；不能把私信授权、公开视频权限和模型路由拼成一次跨域批量 POST。多组待保存显示数量。
3. 只有**实际产生成功写入请求**、原保存流程未抛异常时清除该组提醒。预览请求不算保存；取消确认不会清除。按钮触发的是已存在的验证、确认、保存逻辑。
4. 内部页签跳转若存在未保存编辑，必须选择取消或明确放弃；浏览器离开时出现原生未保存提示。手机版原有只读限制保持。
5. 不在 localStorage 或日志中保存表单草稿（可能包括权限与提示词）。某些仅供查询、诊断、上传或临时动作的输入不显示错误的「待保存」。

**限制**：尚无真实 Windows DOM 自动化测试覆盖整个管理中心；新逻辑已进行语法和静态守护回归，动态保存行为须在 DSH 页面实际手动验收。不要用静态契约测试冒充完整交互测试。默认优先使用显式保存，尤其是账号、授权、私信、公开写入等有副作用的设置。

## 4. 不在此增量擅自做的事

- **不**自动为任意第三方模型声称支持图片或所有思考深度；所有 Headless 专属声明由用户确认，最终以真实测试而非标识为准。
- **不**把分散的 B站流控来源全部合并成一个可清零计时器；这会绕过平台风控。只允许未来增加透明的只读聚合状态。
- **不**为了“真人自然”固定最小评论、最低关注、自动公开回忆或让主人已授权即强制发送。
- **不**扩大记忆留存、跨账号可披露范围，不改变既有好感阈值、好友白名单默认权限或未知回执自动重发。

## 5. 版本与验收门禁

此版交付实装的保存 UX、图片错误分类准确性、旧 Python AST 测试夹具所需 `closing` 注入以及跨场景代码审计，不称六个大系统全部重构；对需要 2.8.2 机制设计的内容以源码级审计和后续验收清单交付。正式发布需要全量回归与 Windows DSH / B站 / 第三方视觉端到端证明。
