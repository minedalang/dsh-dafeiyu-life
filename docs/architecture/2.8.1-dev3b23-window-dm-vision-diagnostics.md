- 日志中曾出现 `api.vc.bilibili.com code=-509`（11 月 15 日多次），但当前导出 `interaction-network-backoff.json` 的 `lanes` 为空，不能把该联系人没有回复直接归因于当下退避。
- `lib/vision_dsh.py` 的 `headless_exit_unknown` 仅是 DSH 子进程非零退出、诊断模式没有命中已知签名；没有 MCP nonce 图片回执时，Provider 请求和附件桥接都不可确认。**独立 MCP 预检不是 DSH 会话内调用成功的证明**。当前不能认定 `gpt-6-luna` 或 Headless 一定不支持图片输入。
- Node `spawn` 的主要视频/视觉路径使用 `windowsHide:true`；Python 的 DSH/FFmpeg 使用 `CREATE_NO_WINDOW` 与 `SW_HIDE`。黑窗可能来自外部启动器或宿主子进程，这些现存隐藏参数不能证明所有下游窗口都被隐藏。当前 ZIP 缺少当时进程父子链与窗口创建事件，不能定位单一进程。

## 本次安全增量

1. 新增 `person.lastInboundOutcome = {at,inboundAt,status,reason}`，枚举包含 `model-skip/model-close/model-defer/delivered/send-unknown/send-blocked/model-failed/model-invalid/safety-blocked/approval-pending/permission-denied`。该状态复用已有 DM 事务数据库文件，仅说明**最后一个已处理入站轮次**，不代表平台未读已清零、历史已回复或发送成功。未经处理的网络失败仍无入站结果；不补算旧记录。
2. 原 `tools/导出B站日志.bat` 的 Python 安全摘要新增 `_diagnostics/dm-inbound-outcomes.json`，仅保存通过白名单的数值、状态和基于账号+UID 的短摘要联系键；没有原始消息、提示词、私信 UID 明文、错误 stderr 或 API Key。完整主日志 ZIP 仍可能包含私人历史，上传前应私密处理。
3. Windows 运行 `tools/抓取窗口与私信视觉诊断.bat 202573574 90`，在采集的 90 秒内主动复现“观察视频画面”黑窗，获得 `dafeiyu-window-diagnostics-*.zip`，它包含 `process-ancestry.json`、`dsh-vision-last-run.json` 与该联系人的无正文状态摘要。进程采样每 1.5 秒，短于采样间隔的弹窗可能遗漏；它不包含命令行与实际窗口句柄，故不能当成操作系统级确定证据。也可不填 UID，只采集黑窗/DSH 诊断。
4. 完成复现后运行原 `tools/导出B站日志.bat --no-pause` 并提供新 ZIP（仅私下提供）。若 `dm-inbound-outcomes.json` 空，先确认当前新版插件**确实运行并处理过新的入站轮次**，不可通过重启强制重发旧已处理私信。

### 诊断启动器编码热修（dev.3b.23 工具修订）

Windows CMD 在中文或 UTF-8 代码页不匹配时可能误解 UTF-8 BAT 内嵌中文脚本路径。推荐使用 `tools/capture-window-dm-vision.bat 202573574 90`，它与对应 `.ps1` 均只使用 ASCII 内容和文件名。原 `tools/抓取窗口与私信视觉诊断.bat` 仍可调用同一 ASCII 入口，原中文 PS1 添加 UTF-8 BOM 以便 PowerShell 5.1 直接读取。本补丁只修复诊断器调用，并不改变 DSH、视频 FFmpeg 或私信业务逻辑。
