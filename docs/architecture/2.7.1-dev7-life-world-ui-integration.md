## 实际接线图

见 [生产 Mermaid](./diagrams/2.7.1-dev7-life-world-live.mmd)。上层只有**一个**普通 Life Planner。当前人格、情绪与角色声音已经由 `getLifeVoice`/`getLifeState` 参与 Life 决策；已接受待办由 `getTodos` + `rankAcceptedTodos` 参与候选选择；关系参考只用于排序/意愿；利益和经历作为**可丢弃**线索进入模型。

`index.js` 的 `getLifeWorldEvidence` 先调用现有的 `selectionInterests`；根据当前待办/契机生成检索词后，只在主记忆允许时调用 `lifeMemory.recall({domain:'bili-explore',kinds:['watch'],reinforce:false})`。后者内部先按真实身份域/遗忘门禁过滤再检索；`projectLifeWorldEvidence` 二次过滤，保留 `stage=clear` 且有效 BV 的公开探索元数据。模型不能把主题列表当作已经观看，更不能把笔记文字当作系统指令。**不读取私信、陌生人身份、永久档案，不调用平台发送 API。** 查询为空或任意依赖出错，沿用原普通决策和行动权限。

真实视频 Agent、平台执行回执、独立额度/冷却、意愿重检、待办更改、模型分类预算继续是原实现。普通 Life 决策本身仍可能选择休息或延期，模型无法直接更改人格。

## 成长闭环：已接线与尚未证明

1. 真实 B站探索/评论/关系行为 → 原平台回执与 `LifeMemoryCoordinator` 投影 → 原 `LifeMemoryGateway` 可衰减的经历。失败、未知发送、未经核验的感觉不能成为经历。
2. 原 `lifeReflection` 按当前仍可访问的证据生成候选；本地验证后才可能将观察提交给原 `personalityEvolution` 或 `life-interests`。成长记录的“证据次数”是观察摘要，并不是模型倾向或人格改变已经影响下一次**实际选择**的因果证明。
3. 后续普通 Life 决策读取人格语境、模拟情绪、已接受待办、关系排序、当前兴趣、公开仍可回忆经历。相关性检索没有命中就不注入记忆；刻意不从审计备份绕过遗忘。
4. 本版尚缺“同一真实回执 → 有效成长改变 → 不同日期后续选择”的完整、可复核因果对照与现场数据。因而 `releaseReady:false`，界面不显示虚假的“成长完成”。

- dev.7 UI 导航修复：`lib/management-console.js` 的 `tabNames` 注册 `life-agent`，和已有 `data-tab`、`panel-life-agent`、`loaders["life-agent"]` 保持一致；既允许左侧入口点击，也允许 `?tab=life-agent` 直达。此项只涉及页面路由，不影响后端 Life 调度、权限或外发。

## 新 UI 与旧系统清理

- 新 `panel-life-agent`：生活总体状态、记忆/待办/兴趣/人格/社交 owner 状态卡、跨页真实入口、V2 生活档位及手动唤醒、专家诊断与无发送社交交接演练。
- 旧 `panel-todos` 的重复旧版计划器参数编辑表单、旧推荐按钮和无效的 legacy 模式选择器已经**从 DOM 移除**；旧 `panel-life` 的重复节奏设置已移动到新 Life 页；TODO 仍保留真正的待办和回访设置，人生记忆页保留原记忆/兴趣数据界面。任何旧 URL 深链仍由现有 `data-open-tab` 访问原目标。
- **不删** `autonomousPlanner*` 历史配置字段、旧账本、备份字段、发送事务、平台采集器、权限开关和迁移/恢复路径。它们或是新 Life 的原有单一状态源，或是回滚及核对所必需。未经过升级/回滚证据，不以“旧字段”为由直接物理删除。
- 开发者影子社交授权独立按钮、独立确认；保存待办回访设置不会偷偷刷新或开启它。
- 全部总览数据由 `GET /api/bili-duty/life-agent/integration-status` 实时只读汇总。某一个下游坏掉时不会掩盖其他服务；不创建新账本，也不因页面加载而消耗模型/平台调用额度。页面不会展示私信正文或私人内容。

## 当前未完成项与不可跳过的门禁

- `social-decision-ownership.mjs` 的实际生产回复 owner **仍是 `legacy`**：真实私信、评论、@、回访及主人专属路径需要单通道原子排空、Life 生产执行器、未知发送回执复核和逐渠道带回滚验收。此前 dev.6 的无发送演练不等于正式接管。**本版不能宣称单一 Life 社交决策权已经完成。**
- 需要长时间运行采样证明兴趣/人格/关系变化真的影响后续选择，且能纠错、遗忘、停止与回滚；本版做的是安全可观察的读链，不是“记忆自动驱动人格”的伪闭环。
- 需要 Windows 的 `run-tests.bat`、真实账户和不同账户切换、B站 API 限流/异常回执、备份恢复、UI 夜间/窄屏和多日稳定性验收。没有新平台外发许可，也没有实际修改主人已保存的权限。
