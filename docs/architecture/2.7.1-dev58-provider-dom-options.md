# dev.58 · AI 模型管理界面 Provider 下拉 DOM 修复

## 问题和根因

在 dev.57 `lib/management-console.js` 的 `renderModelDropdowns` 中，`const options=[option(...)]` 创建一次 `<option>` 列表，紧接着反复 `setSelect(default, options, ...)` 和 `setSelect(eightRoutes, options, ...)`。真实 DOM 的 `Node.replaceChildren(...nodes)` 将节点从旧父节点**移动**到新父节点，不会复制。导致前一个 `<select>` 的选项被搬空，通常只剩最后一个检索模型 Provider 下拉框有选项。旧假 DOM 测试直接替换 `children` 数组，没有模拟所有权转移，因此误判为全部正常。

## 正确数据归属与本次修改

| 项目 | 唯一职责 | dev.58 的动作 |
| --- | --- | --- |
| Provider 与模型真实注册/发现 | `index.js` 与原 `headless-model/status`、`lib/model-catalog.mjs` | 不变；不创建虚假 Provider、密钥或注册结果 |
| 当前配置／旧配置 | 原 `/config` 及可读的宿主当前选中标识 | 不变；仍标注无法枚举的条目为未验证 |
| 页面 `<option>` DOM 对象 | 管理台 `lib/management-console.js` | 每个 `<select>` 用独立 `providerOptions()` 实例 |
| Life 意愿、模型路由、失败退避、发送权 | 原统一层和技术授权层 | 不变；前端修复不增加 AI 调用和外发权限 |

### 影响范围

“默认 Provider”及视频、后台互动、每日动态、主人私信、人生反思、视觉、梗知识、AI 记忆检索八项 Provider。已选模型、独立调整和默认模型同步功能按原来规则运作。无数据迁移、无新增网络 API、无持久状态；不修改现有 Mermaid 架构接线（本次只改 DOM 视图）。
