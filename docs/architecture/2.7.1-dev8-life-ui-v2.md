# 2.7.1-dev.8 · Life UI v2 卡片与自主社交管理（开发预览）

## 边界与归属

- 本次仅调整现有管理中心的表现层、已有配置表单映射及旧版人工社交审批入口；不新建 Life 意愿决策者、视频 Agent 或社交发送器。
- 保留原管理中心的顶部横导航组、`data-tab`/`panel-` 稳定锚点及管理 API。窄屏为顶部单行水平滚动；不增加侧栏或底栏。
- 鱼鱼此刻展示的真实时间线来自已保存的执行记录。重复内部状态、调试提示和跨栏目快捷入口置于默认折叠的诊断区，不冒充鱼鱼经历。
- 经历与记忆使用角色素材 `/api/bili-duty/life-character.png`、新首页与分区卡片，仍消费原人生记忆、兴趣和经历来源。角色仅是 UI 展示，不是事件证据。
- 自主生活的「开启 / 暂停 / 仅观察」和「安静 / 自然 / 活跃 / 自定义」以卡片呈现，底层原 `life-v2-mode` 与 `life-v2-pace` 控件继续用于 API；点击方案不会隐式保存。

## 自主社交与授权边界

- 视频兴趣推荐新增自由分享（预设每日额度上限 100）、关闭、50–1000 范围自定三种方案；100 是上限而非预期每日发送数。后台 `socialOutreachDailyLimit` 原本已支持高额度，原来的 3 仅是卡片预设。
- **历史已保存额度及所有授权保持原样**，打开或浏览新版设置不改变外发权。新启用自主推荐须明确保存及现有服务端授权确认。
- 取消普通自主社交的「仅草稿、等主人审核」方案及管理页面的逐条发送/放弃按钮。发送由 Life 的意愿契约及账号、收件人许可、冷却、防重、平台回执共同决定。
- 服务端拒绝自主社交 `send`、`dismiss` 和手动 `authorizeDraft`。视频推荐引擎在生产视频模式也拒绝 `send({automatic:false})`，避免旧页面或旧脚本绕过 UI。
- 旧版严格暗号审批记录只读；服务端拒绝批准、拒绝、恢复的 POST。禁止新配置打开旧版 `dmApprovalEnabled`；历史为 true 时不自动放宽，必须显式切换为新的自主交流方案并保存。
- 动态创作仍是独立的草稿与人工审核产品能力，不受普通自主社交审批取消影响。
- 主人 Agent 的**显式工具命令权限**与普通自主社交的逐条审核属不同契约：本次没有重写 owner DM / owner todo 工具协议。若未来要全面废除主人直发指定正文的历史能力，必须作为单独的业务权限迁移评审、验收和测试，不能伪装成 UI 改造。该边界待产品决策进一步确认。

## 新旧兼容与验证

- `management-console.html/js` 的原控件 ID、已有表单读取函数与存储字段不变；白名单编辑仍存储在原 friendDirectory 中，不能直接信任页面里的昵称或 UID。
- 新卡片与动画兼容 `prefers-reduced-motion`；手机和桌面无横向页面滚动。所有截图均来自静态页面渲染，不包含平台真实数据。
- RC 阻断项仍包括 Windows 实机、真实 B站发送/回执、旧配置迁移、跨进程持久机会池、长期记忆成长因果；`releaseReady=false`。
