# 2.6.2 · B站后台只读保护与多彩生活管理中心（dev）

## 目标和不变量

本版本将原拟 2.6.2 和 2.6.3 合并。保留 2.6.1 角色/账号独立、人生记忆隐私衰减、统一已接受待办与发送许可；不引入新模型调用、P6 主动续聊、账号跨号外发或额外写授权。

## 真实生产接线

```text
已核验当前 B站账号 → accountBinding.runtimeDir()
  ├─ bili-read-budget.json（本地小时窗口、分钟窗口、平台退避）
  │    ├─ lib/dm.mjs listSessions/fetchMsgs → 真实请求前 acquire
  │    ├─ index.js 主进程只读 MCP 调用 → guard
  │    └─ 公开昵称读取 → acquire
  └─ dm-poll-cursor.json（只有会话 UID/lastTs/unread/时间；不记录正文）
       └─ dm-inbox collectDmInbox → shouldRead → onRead(暂存)
            └─ dm-autoreply 持久状态 → onScanSettled → cursor.commit
```

两个账本均在当前已核验的平台账号专属目录；A→B 账号切换不会复用彼此请求额度或会话游标。`bili-read-budget` 对每一次网络尝试扣预算，即使网络失败也算；默认 30 次/分钟、450 次/小时，限流、验证码/平台拒绝时短期退避且跨重启持久；这些不是平台公开保证安全的阈值。会话读取最多 12 个、无变化的一般约 30 分钟复查，保留未读会话短周期复查。旧消息是否处理由原有私信幂等账本判断；若读取失败游标不提交。

**尚未覆盖：** 独立 Headless Python 视频进程、其他插件和部分未封装的直接请求。因此这里是“已接入主进程只读接口的合并预算”，不是全平台、全进程、外发与只读的统一官方额度。未来若需要进一步扩展，应使用独立跨进程调度服务和共享限额原子操作，不能谎称这次已经完成。

## UI 信息架构与隐私

`management-console.html` 为原有 `life-todo-section` 整块换到新的 `panel-todos`，而不是复制控件：旧 ID、事件处理、待办状态历史、回访入口和设置仍复用；旧 `life` 标签专注人生经历、记忆、反思和兴趣。`management-console.js` 为 `todos` 配置真实 loader，不再在打开记忆页时自动加载待办。

`panel-life` 新增“记忆花园”与四种浏览筛选；结果来自现有 `/main-session/memory`，不读取永久封存档案、不推导私密人格。`panel-personality` 使用五项有主题色的特质卡，显示阶段、证据数和详情入口；颜色进度仅示意证据积累，不等于 AI 人格量表真值。轮询页从 `interactionScheduler.status()` 读取本地限额及冷却状态，无新增网络查询。浅色、暗色、键盘焦点与窄屏布局专门适配，交互 IDs 未变化。

## 兼容与失败处理

- 首次安装没有新请求账本时创建空账本，不追溯旧 B站请求。账本已存在但损坏则暂停后台读取，避免重置退避状态；不得手动删除来绕过限额。
- DM 游标只记录最小化的会话元数据，最多保留约 2500 项。不存私信正文；旧的去重/回执账本不作迁移。升级前已有私信依然由旧基线和消息 ID 去重保护。
- 客户端导航保留旧书签兼容；所有原待办和记忆控制项只保留一个 DOM 实例，避免双重绑定；无新表迁移。
- 已接入只读预算耗尽的任务延迟到下一轮，不等于已经执行。写操作的独立权限、幂等与真实回执不得自动重试。
