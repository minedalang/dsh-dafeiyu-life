# 2.8.0-dev.10 · 跨场景自主意愿与并发外发协议（开发预览）

> 基于 dev.9 独立复审的代码修复；**不是**真实 Windows DSH/B站在线验收。继承 [dev.9 统一行动协议](2.8.0-unified-life-action-protocol.md)，本轮重点补齐沉默、候选证据与社交回复路径。

## 入口 → 共用层 → 事实源 → 状态与边界

| 来源 | 首次意愿主体 | 共用层 | 外发事务与可信回执 | 不得发生 |
| --- | --- | --- | --- | --- |
| Life 已核实视频 Episode | Episode 原模型已选 | `LifeWillingness.adoptVideoDecisionQueued` → `LifeContinuationWriteExecutor` | 原 Python 自主视频工具 / 同 BV 独立回读 | 在队列中丢弃选择、再投票或重发未知结果 |
| 公开视频普通回复 | 原社交模型 | `adoptSocialDecisionQueued` | `socialSendTransaction` + B站真实 rpid | 使用情绪公式否决已选文本 |
| 可信主人/好友公开评论回复 | `interpretTrustedSocial` 的首次模型 | **同一** `adoptSocialDecisionQueued`、单次文本与源评论绑定证明 | `socialSendTransaction` / 原 `bili_reply_manual` 受控适配器 | 绕过共用意愿证明、重复回复 |
| 普通私信回复 | 原私信模型 | `adoptSocialDecisionQueued` | 原 DM 事务与回执 | 将私人正文暴露到其他渠道的仲裁窗口 |
| 可信评论邀请/普通聊天 | `interpretTrustedSocial` | 一次模型同时决定**行动**和**表达** | 仅 `replyDecision=allow` 才能申请上述公开回复证明 | 把 `refuse` 变 `allow`、自动模板代说话 |

## 统一自主决定，不等于一条全能发送器

- `decision=allow/defer/refuse` 为本轮**行动意愿**；`replyDecision=allow/defer/refuse` 为**公开表达意愿**。一个模型可以拒绝视频邀请但选择礼貌回答，也可以既拒绝行动又沉默。普通 `chat` 如果拒绝或延期，回复必为空，不向平台发送；旧模型没有填写 `replyDecision` 时仅用安全回复做有限兼容。第二轮只读公开回忆**只能修改回复内容**，不能更换意愿或动作。
- 统一层只管理候选、一次性意愿凭据、短期账号内仲裁及结算。原 DM、评论、视频专业执行器负责权限、真实平台调用、配额、去重、身份复核和送达核验。用户明确的主 Session 操作仍属人工明确授权，不伪装自主选择。
- 多渠道候选在约 140ms 窗口内合并时，各自提供**限长公开证据摘要**，包括已验证视频上下文、候选公开回复文字；**混合私信和公开视频时不携带 DM 正文**。仲裁只能选择某个已提供的候选，不可修改原 BV、UID 或发送内容。
- 账号级单次准入采用 `LifeWillingness` 的原**有界 FIFO**。视频已选动作现在与私信/评论同样排队取得密封证明，不再因另一频道正在发送就立即按模型拒绝结算。队列满、等待超时、账户变化属于**系统阻断/延期**，不是鱼鱼主动不想做。没有把跨进程持久化意愿自动重放引入本版。
- 等待期间以及最终发送前重新核验账号、原 Episode、权限、额度与目标；**这是安全检查，不是第二次模型意愿投票**。撤权或切号而未尝试外发，结算 `not-sent`，不能误报为已向 B站发送但回执未知。
- 已进入平台调用但结果未知时保留原发送事务冻结，严禁在崩溃恢复后根据原模型意愿直接重发。一次性证明不持久化恢复为可重用外发权。

## 离线验收与遗留边界

- 新增 13 项测试位于 `test/v280-dev10-cross-scene-intent.test.mjs`，覆盖聊天沉默、行动与表达分离、可信社交邀请、自主点赞等待、账号切换、排队撤权、公开证据合并、DM 证据不跨渠道泄露、未经平台尝试不得标为未知送达、原模型的**表达意愿**不得被系统成功模板替换；若后续取得新的真实执行事实，则允许原专业生成器提供对应结果措辞，不重新投票。
- 代码锚点：`lib/comment-social-ai.mjs` 的 `parseTrustedSocialDecision`；`lib/owner-comment-agent.mjs` 的 `mayReply`；`lib/life-willingness.mjs` 的 `candidateEvidence` 与 `adoptVideoDecisionQueued`；`lib/life-continuation-write.mjs` 的 `authorization-changed-after-queue`；`index.js` 的可信评论 `adoptSocialDecisionQueued`。
- **未覆盖**：Windows DSH 的真实账号交替、网络故障与重启期间的长期压力；并发跨进程持久排队（原机制仍是进程内短队列，原持久防重准入单独发挥作用）；旧主 Session 的人工明确指令不被改写为自主凭据；原版遗留的 Node/Python 历史失败不因本次修复自动视为解决。

**发布原则：** dev.10 仍仅开发预览，不修改用户现有外发授权默认值，不向 B站真实发送，不创建 npm Tag 或正式 2.8.0 发布。
