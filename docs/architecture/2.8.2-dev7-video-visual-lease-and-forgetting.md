# 2.8.2-dev.7 · 视频完整取帧互斥与遗忘边界

> 开发版增量。Windows 全量、真实 DSH 双进程和 B站 CDN/视觉模型验收均未完成；不属于正式发布。

## 统一层归属

- **意愿主体**：Life 保留是否看、看多深、是否停止的唯一选择。互斥只管已选择动作的执行，不投票、不替模型改变意愿。
- **记忆事实来源**：`LifeMemoryGateway.videoEvidenceTrace()` 才能判断当前账号可衰减记忆是否仍清晰。`LifeOpportunities.visualReads` 和历史 Episode 回执只在 **30 分钟短期执行防重窗口**内生效；旧回执不再永久阻止视频重新观察。仍然不读取永久审计档案或已模糊/遗忘内容。
- **共享执行协调**：复用 `life-planner-atomic.mjs` 的原子目录所有权机制。新增只有当前账号+精确 BV 派生的哈希只读取帧锁，不包含标题、UID、模型文本、视频画面，也不构成第二套记忆/调度/限流。
- **介入入口**：`bili_life_consider_video` 自愿 `standard/deep` 取帧，以及 `AutonomousPlanner` 的 Episode `observe_video`。后者持锁至 `recordLifeVideoVisual` 的可信回执落盘；前者在持锁期间完成 `executeWatchVideo` 的既有记忆及跨入口回执尝试。主人明确指定的普通观看、独立局部时间窗口补看仍按原门禁执行，不被误视为无理由自主重复完整采样。
- **失败语义**：另一进程已持锁 -> `video-visual-busy`，非 Life 休息/拒绝。坏锁/身份不明 -> `video-visual-lease-review-required`，不能假装观察成功。进程确认死亡时，旧只读取帧锁以原子重命名、二次核对身份后恢复；不能按时间判断正在运行的进程死亡。
- **安全界限**：不更改认证、平台只读预算、-509 退避、评论点赞权限、授权、外发、主动局部补看，不添加第二个视频记忆仓库，也不在本版实施未来浅深分层记忆工程。

## 本批不保证

仍无法依靠单一旧版回执证明视觉描述一定写进记忆。若视觉执行成功但所有持久化回执都失败，30 分钟后仍可能重新执行；必须在未来改进端到端写入确认并在 Windows 实机检查。独立主人观看和显式时间窗补看不属于本批自动抑制范围。网络文件系统不保证本地原子目录语义。
