# 2.7.0 社交管理页信息架构（现行 UI）

本轮**只改变管理页的信息组织和入口**，不新增后端接口、状态字段或 B站外发权限。

## 信息归属与唯一保存源

- **社交互动**是用户的第一入口：日常交互快速入口位于首屏，授权主人、主动推荐、主人私信 Agent、主人公开评论和已停用旧能力按任务归类折叠。折叠是纯展示行为，不改变存储或后台运行状态。
- **最近评论**仍是公开评论的唯一配置与保存位置（`comments-configuration`、`comments-settings-save`），以及发送回执、记录查询的位置。社交页按钮只执行跳转，不复制 `commentAtEnabled` 等字段；直接定位到「被 @ 邀请」，其后紧接原保存按钮。
- **后台私信**是私信监听、陌生人申请、回复额度的唯一配置和记录页。社交页只提供直达对应设置的入口。
- **好友关系**页展示自然增长的关系；社交页的名册只负责显式操作授权。亲密程度不产生权限。
- **运行诊断**仍是未回复原因的诊断来源，不添加第二套日志。

## 导航安全与体验

通过同一套 `data-open-tab` / `data-open-settings` 导航，切换页面并展开目标 `<details>` 的祖先分组，异步记录加载结束后再校正滚动位置。未完成首次引导时仍遵循原有的页面限制。手机查看模式保留原本的只读权限。

新的折叠分组和快捷入口只在 HTML/CSS/JS 层实现，不影响 `Life Voice Context`、统一社交意愿层、`SocialPolicyGate`、额度、冷却或真实发送回执。
