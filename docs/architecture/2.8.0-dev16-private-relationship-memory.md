# 2.8.0-dev.16 私信经历、私密反思与跨渠道熟人理解（开发接线）

## 事实源、阶段与生命周期

真实入站主人 DM、好友 DM（以及经既有开关确认的主人主 Session）在原渠道身份、事件 ID、权限校验之后，调用 `preparePrivateLifeEvent`。该函数仅识别低敏、有限的共同交流主题、明确关系边界与偏好等类别；**不存储私信原文、确切作品名、联系方式、昵称或未核实的人物事实**。不符合安全规则的事件不进入记忆。鱼鱼自己确认过的主人 DM 表达仍走 `preparePrivateSelfExperience`，不将拟发草稿当成已发生。

事件经原 `SocialInteractionCoordinator` / `LifeMemoryCoordinator` 持久补偿链投影到 `LifeMemoryGateway` 中的 `private-social` **可衰减情节**。主题来自对方的真实陈述，不等于验证了过去确曾一起做某件事。新的事件摘要带当前登录 B站账号的 HMAC 式匿名 `accountTag`；账号与 UID 共同限制新式公开关系理解。旧版没有账号标记的私密事件仍可遵循其原私有读取范围，但**不能自动迁移成公开评论可用的关系上下文**。同一消息 ID 在不同账号下不复用私密记忆键。

`LifeReflection` 只读取仍存活的同一私密域候选；普通领悟仍需要真实认知与行为影响，低频且有主题证据的 `shared-experience` 可只记下“对方提起的共同话题”，不编造未来行为。反思结果仍写入原 `private-insights.json`，按人隔离，**不直接加入公开长期记忆或人格**。它不是自动归档每一句聊天，也不保证历史未保存的私信原话可以再生。私密认识的删除、撤回与长期生命周期仍应由原私密存储治理进一步核验，不能把一次模型成功当成永久真实事实。

## 跨渠道只读理解与表达范围

通过原 `SocialPolicyGate` 确认的主人或好友公开评论，`SocialContextAssembler` 在 compact 路径首次附上一份来自**当前账号 + 同一 UID + 未遗忘私密情节**的短关系线索，无需额外主模型调用。模型主动请求记忆查询时，仍复用现有词法／可选本地 Embedding 和原记忆检索模型，再让原主模型续答；没有必要每条评论固定二次思考。公开安全记忆和 `privateUnderstandingContext` **严格分字段**，私下经历不是可公开引用的证据。

原评论单条回复和主人/好友可信评论路径均有明确公开场合提示及附加的输出文本风险阻断；风险时可以静默或保留通知，绝不合成一个“代言式”回复。代码检查只能识别明显提及私信来源、旧私下谈话等泄露句式，**不可能单靠正则保证所有语义级间接泄露都被识别**。真实外发仍经过原 Life 意愿、精确正文、权限、冷却、幂等与 B站回执。关系亲密不自动产生发送许可或自动打招呼。

## 验收与诊断边界

- 用已核验真实好友 DM 的非敏感“共同讨论视频／音乐”等例子，检查可衰减 `private-social` 生成，而原文不出现于归档或反思输入。
- 同 UID 不同账号、同账号不同 UID、陌生人、旧无账号标记和隐私守卫均不得将私密记忆混入公开理解。删除或遗忘后不可从索引、候选或反思来源复活。
- 模型仅在首次上下文不足时请求定向回忆；私密回忆不得成为公开引用。测试普通评论和可信评论，冒称私聊事实时不得发送；自然熟悉的轻松语气可保留。
- 本轮为代码／离线回归。历史缺失的私信内容不会补造，Windows DSH、B站真实账号切换、敏感语义披露和长期反思成长尚需实机与人工验收。
