# 2.7.1-dev.11 · 多源自主生活与 1000 条统一公开评论容量（未发布）

## 1. 实际生产接线

- 生命周期：现有 `AutonomousPlanner` 接收时间、兴趣、记忆、只读待办、真实视频轮、社交信号；新增 `LifeFriendInitiatives` 根据**当前账号标记**的真实双向好友互动记录生成匿名候选。无视频时仍可选 `review_friend`、`reach_out_friend` 或 `skip`，不是重新开启视频定时器。
- 候选合同：只向 Planner 传入匿名 id、关系阶段、距上次互动小时数和当前是否具备渠道授权。持久日志仅存哈希、状态和重考虑时间，不记录 UID/消息内容；账号隔离使用既有可信账号标签。旧无账号标签互动**不能直接作为新主动私信授权**，须待新记录形成有效双向关系。
- 出站私信：必须单独将 `lifeProactiveFriendDmEnabled` 从默认关闭显式开启，且满足首次账号/模型验证、明确的白名单 `dm=true`、真实双向互动、原收件人拒绝/冷却检查、当前账号一致与 Life 主动选择。生成短消息后再做事实核验，调用原 `lifeDmWithReceipt → lifeSocialWrite → socialSendTransaction`，禁止重复外发或因结果不确定自动重试。**没有逐条主人审批**，但管理员决定是否赋予该渠道权限。
- 评论容量：`commentDailyLimit=1000` 为新用户默认的**全部公开评论共同自然日发送尝试容量**；`commentReplyPerDay=1000` 为额外的后台滚动 24 小时容量。视频顶层、视频楼中楼、视频 @、带图评论、动态评论及动态回复调用 Python `_reserve_comment_quota()`，共用 `public-comment-quota.sqlite3` 原子账本。模型是否愿意发评论、频控、同用户防重复、平台风控均独立。已经保存的老用户低上限原样保留，须在「次数与额度」明确选择/保存 1000 方案方可提高。
- 日常生活预算：安静/自然/活跃档继续影响自主 Life 思考机会，不得将后台思考每日 12/40/100 次理解为私信/评论回复数；已经受控接管的社交意愿不消耗后台自发思考额度。工具调用与平台写入须经过原验证。

## 2. 行为边界及尚未完成项

- `getRelationships()` 在当前账号作用域下只认可本版及以后带账户标签的真实关系证据。老用户看到的关系画像可以保留旧汇总，但这不构成主动发私信的授权证据。
- 在读取证据/权限变化/模型异常时跳过外发。已预留且发送结果未知时标记 `uncertain` 并冻结该候选；不通过重试来猜结果。
- 1000 是容量、不是 KPI 或发送目标；大量评论可能触发 B站官方限流，模型可能自然选择一条也不发。未新增绕过验证码、风控或平台限制手段。
- 新增的是可再生成的**熟人候选账本**，并非跨所有渠道的永久共享队列。完整的跨渠道竞争、跨进程重启续行、Windows Desktop、真实 B站、72 小时运行与跨日成长因果仍是正式 RC 门禁。

## 3. 验收和回滚

- 运行 Node `test/v271-dev11-friend-origin-life.test.mjs`：无视频候选仍能思考熟人、已授权能在模拟中产生一次发送、未经授权禁止外发、账户切换隔离、发送未知不自动重试。
- 运行 Python 共享额度测试：1000 次总容量按尝试占用；手动动态评论和自动动态回复都要进入同一额度。不以测试中的 mock 发送冒充真实 B站回执。
- 运行 `node --test`、Python unittest、`node selfcheck.mjs` 和 `npm pack --dry-run`。Windows B站需要在授权账号上从仅只读测试开始，进行受控单次实发与回执检查，完成旧配置升级和退出时状态复核。
- 关闭 `lifeProactiveFriendDmEnabled` 可阻断新的主动外发；保留历史事务防重记录。回滚前停止所有实例并备份，禁止删除未知外发事务日志以“清空额度”。
