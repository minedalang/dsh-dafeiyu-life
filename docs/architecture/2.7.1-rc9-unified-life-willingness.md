# 2.7.1-dev.7 · P0 统一 Life 意愿生产接线（RC9，未发布）

> **当前实际代码，不是未来能力宣称。** 本轮使用 RC8 完整源码作为 Patch 基线；版本仍是 `2.7.1-dev.7`，`releaseReady=false`。以下按可验收与仍阻断分开记录。

## 1. 决策与执行边界

- 新 `lib/life-willingness.mjs` 是**唯一新增的意愿契约**：在当前账号核验通过后，提供已知候选，让相同 Life 角色、当前人格/情绪/关系、兴趣、可回忆公开经历选择 `act / skip / defer`。模型只返回严谨 JSON，禁止凭模型结果授予平台权限。
- 它是一个**可复用入口，而不是第二套模型人格、消息发送器、记忆数据库或事件账本**。各生产触发器仍独立产生机会；目前**尚不是单一全局多候选调度队列**，不应混淆。
- `LifeWillingness.decide` 在原有 `autonomous-planner.json` 跨进程预算账本中预扣调用，类别为 `willingnessRuns`（日上限 80，所有类别共同日上限 288）；没有单独的额度数据库。账本损坏、配额耗尽、模型不可用时默认阻断**新自主外发**，不是允许旧系统绕过。
- `proof` 仅存在当前进程内存，绑定已核验账号、行动类别和十分钟有效期；发送前再次由原路由、权限、授权、跨进程事务与平台回执核验。重启/换号/到期或未知结果会让这个决定失效，不得据此重试。**原有主人手动明确指令不被当成自主选择。**
- 诊断复用 `life-decision-traces`，只写匿名来源摘要、候选数量、动作类别与结果，不写 UID、消息、原文或模型提示；管理中心现有 integration-status 增加 `willingness` 只读汇总。

## 2. 实际生产入口与结果

| 入口 | 当前 Life 统一意愿位置 | 执行工具/既有授权 | 可信结果与局限 |
| --- | --- | --- | --- |
| 私信收到消息 | `index.js` → `lifeWillingness.decide(dm_reply)` → `interactionBatcher.generate` | 原 DM 发送事务、冷却、owner proof；`dm-autoreply` 保留 proof | 真实发送回执后原 `SocialInteractionCoordinator` 投影；无效 Life 输出不自动标记“主动沉默” |
| 公开视频评论 / @ | `lifeWillingness.decide(comment_reply)` → 原评论内容生成 | 原评论区权限、来源/防重和发送门禁 | 真实 rpid 回执按原渠道记录；模型无意愿不发送 |
| 待办完成后自然回访 | `lifeWillingness.decide(followup)` → 原证据与话术模型 | 原待办完成、原请求人及回执门禁 | 未确认任务事实不能变成回访；自动回访不绕过 Life |
| 已选公开视频推荐私信 | 原视频分享引擎仅生成候选 → `decide(share_video)` | 朋友同意、共享 DM 发送事务、白名单与发送冷却 | Life 拒绝、失败或无 proof 时不得发送；推荐谁的候选仍由原引擎先提出 |
| 自主生活动态 | 原动态时钟只提供机会 → `decide(write_dynamic)` → 真实公开证据草稿 | 原 Python SQLite 动态额度和不确定回执冻结 | 默认可休息；生产不按 12 档固定风格轮转；API 接收不等于公开可见，Life 标记 `accepted-unverified` |
| 视频探索委派 | 原只读 Planner 先挑选 `use_capability`，再由统一意愿复核 `explore_video` | 原视频 Agent 委派、单日轮数/冷却、账号/权限/进程回执 | `delegated` 只代表启动；进程退出不等于实际视听；视频 Agent 内部自主点赞收藏关注**尚未逐动作由 Life 复核** |
| 评论→动态同步 | 原 Python `sync_to_dynamic` 自动发布被关闭 | 日后 Life 动态选题可参考**当前可回忆的本人公开回复** | **尚无**成功评论后按该源立即登记、单独评估的动态候选；保留普通动态机会，不凭空自动同步 |
| 主人主动问候 | 原主动召回发送保持暂停 | 保留原禁止骚扰/许可边界 | **尚未启用 Life 主动关心候选**，不能为了 RC 抢先解除暂停 |

**反向影响**：意愿所用 `lifeVoiceContext` 复用当前人格成长、情绪、关系；`getContext` 进一步读取原兴趣/仍可回忆公开视频元数据与原记忆网关过滤后的**鱼鱼本人公开发言**。成功外发和真实探索由原记忆、兴趣、关系、人格反思链路处理，**没有因 Life 意愿选择就直接增添人格分数**。因此能核验数据连接，但**无法凭离线代码声称已经形成跨 2–7 日可观察的因果人格成长**。

## 3. 安全与兼容

1. `owner` 一致性仍由 RC6 的持久化社交归属控制：新老用户均由 Life 管理真实 DM、评论归属，但原所有权交接、历史发送事务、授权原值、记忆半衰和备份机制保持不变。
2. 旧 `autonomous-planner.json` v1 可以增量增加 `willingnessRuns`；历史使用量 `runs` 不清零或免单。保持原文件格式版本，不静默升级另一套状态。
3. 自主动态依旧使用已有公开事实与隐私校验，绝不将聊天记录或视频标题当做完整观看/聆听证明。生活动态原人工发送接口不强迫走自主意愿；人工授权单列。
4. 意愿选择 `skip` 是正常沉默；**无效 JSON、未知候选、账本损坏、模型故障或账号变化不属于自主沉默**，不应自动处理尚待回复的可信事件。
5. 旧“评论工具自动同步动态”停用，以防止统一 Life 以外的自动写入旁路；原图文评论能力与评论回执不受影响。

## 4. RC 发布阻断（不能把代码接入误报为完成）

- **P0-A 未全部完成**：生产入口共用意愿模型和短凭证，但尚缺统一的**跨渠道多候选机会池**及竞争/跨渠道抑制；现有各路触发器仍独立唤醒。`consider_social` 仍有只读关注旧逻辑。
- **P0-B 部分完成**：动态独立时钟已降为机会发起器，真实发表必须先过 Life；评论直接同步被禁止，但需要真正的成功评论候选注册与自动反馈调度，不能长期禁用替代。
- **P0-C 部分完成**：DM、评论、分享、回访、动态、视频委派有 Life 契约；视频 Agent 内部自动**点赞/收藏/关注/取关及其他可写动作**仍未实现逐动作 Life 前置授权；主动主人关怀仍暂停。主人明确手动命令允许按手动授权执行。
- **P0-D 部分完成**：原成长数据回流和新意愿上下文读取均存在，但缺跨天因果回放及真实样本证据。平台“收到请求”不等于公开成功；下游投影需验证实际成功回执。
- Windows + Anaconda、实际 B站、真实模型、双账号旧数据升级、72 小时和随后 7 天观察全部尚未执行，**因此 `releaseReady=false`、不封 rc.1**。

`test/v271-rc9-unified-willingness.test.mjs` 覆盖错误模型/候选、账本损坏、跨账号、未知发送、时间过期、现有配额、匿名轨迹、公开经历变化与视频委派仅为启动；`test/v271-rc9-life-dynamic-intent.test.mjs` 覆盖动态选择休息/发帖/失效凭证/不确定发布/无素材沉默。原 DM、评论、分享、主人回访和 Life Planner 全套回归亦必须通过。
