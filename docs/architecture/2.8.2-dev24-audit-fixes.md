# 2.8.2-dev.24 · 关键缺陷修复与未闭合验收

## 修复生产缺陷

1. **P0 Windows DSH 视觉契约**：原 `vision_dsh.py` 已要求8个语义候选，但 `vision-host-owned-executor.mjs` 仍严格校验旧提示词。现在固定提示词两端逐字匹配，并用真实 Python 生产执行器产出的 prompt 进行 Node Host 验证，伪造追加命令仍被拒绝。只允许受限 MCP 只读工具。
2. **P1 候选解析**：最终回答以 `VISION_DESC:` 开始，后续最多8行独立的 `复查候选`。Python 只解析最后一个正式 `VISION_DESC` 之后的候选行；Node 仅将经本次官方预览采样的时间戳转化为候选，工具日志、虚构时间不能增加真实取帧。
3. **P1 视频全片覆盖**：扫描顺序改为全局锚点优先、跨选定源拼图轮询；命中1400格/8MiB/40M像素/48源拼图上限时以不完整回执暴露覆盖缺失，而非顺序扫描丢失视频尾部。preview 采样协议 v8；原视频 MP4/DASH 采样 v7 保持不变。
4. **P1 Life 兴趣和状态**：`life-voice-context` 统一表达层有当前人格、情绪、成长和关系，却不负责兴趣/记忆事实。实际看后续行中已注入现有同账号可回忆的公开兴趣/观看记忆及 Life 精力/好奇心；无必要时不读取，不附带私信记忆，未添加新持久化事实库。
5. **P1 超长候选**：最多14400秒（4小时）的已核验时间可参与复查建议，解析100分钟及以上的 `MMM:SS`。覆盖范围和 URL 必须仍由可信采样回执证明。
6. **P2 缓存与 Episode**：DSH 缓存按提示词协议版本失效，低清全局采样缓存按 v8 失效；局部完成回执保留精确时间数值与选择依据，不记录模型私密原文。

## 预算：不要混淆50 MiB与8 MiB

- `lib/adaptive_video.py`：12/24/48 帧对应媒体读取 24/50/100 MiB，预算限制原视频完整下载、DURL Range、官方 DASH SIDX/片段恢复。一次媒体读取已使用的字节需计入同轮分支恢复；不能每次换下载方式就重置额度。
- `lib/preview_vision.py`：第一轮官方 videoshot 源缩略拼图硬限制8 MiB / 48源拼图 / 1400候选格 / 40M解码像素；不由50 MiB替换。
- `autonomous-planner.mjs`：Life 看后真实局部复查按对应档位总额减去第一轮可记录的 `spriteBytes`，把剩余媒体预算传给受控原视频读取器；只扣准确可归属的项目，仍非整个插件的总流量上限。实际 CDN 传输、元数据/PBP、ASR、模型传图等不等于媒体预算值。
