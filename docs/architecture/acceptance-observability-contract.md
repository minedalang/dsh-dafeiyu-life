# 功能可验收性契约（适用于 2.7.1 及后续）

> 问题来源：功能存在并通过离线测试，但用户没有入口看到真实行为、未执行原因和实际结果。此类能力不得仅凭截图、文案、提示词或单元测试标为「已完成真实验收」。

## 新能力交付的七项证据

1. **入口**：用户明确知道在哪个页面观察，或如何通过授权的手动触发运行场景。没有额外外发权限时允许只读模拟或沙盒测试，但必须明确其不是平台实测。
2. **触发契机**：独立区分「没有运行轮次」「轮次运行但没有进入这个场景」「场景被选中」。未检测到工具调用不能推断鱼鱼主动拒绝。
3. **自主决策**：如果宣传“可自主选择”，需要能观察至少选择结果和受限原因信息。不能要求模型强迫执行来证明自主性，也不能暗示未经保存的心理动机。
4. **真实操作与回执**：成功、平台接受但未确认、失败、额度阻止、去重、跳过都要区分。浏览视频元数据不能当作观看画面；阅读公开评论不能当作发表评论。
5. **真实效果**：验收证明该结果进入了应该影响的后续决策链，而不是 UI 多了一个状态。没有跨轮影响的能力，应标注为“本轮临时信息”，不能冒充长期成长。
6. **隐私和权限**：数据按账号、UID、公共/私密域隔离，日志最小化，公开诊断不包含密钥、原始私信、评论者敏感标识。诊断入口不能扩大平台写权限。
7. **使用者的操作方法**：每轮交付包括“点击哪里 → 看什么字段 → 成功与失败分别是什么 → 哪些结论目前不能证实”，自动化测试、真机测试和人工体验必须分开列出。

## 2.7.1-dev.1 实际已做到 / 尚未做到

| 观察对象 | 已可验收 | 尚不能由本轮回执证明 |
| --- | --- | --- |
| 视频评论列表 | 哪个 BV、何时、读到多少条、成功/空结果/失败 | 没有工具调用时鱼鱼主动选择不看，以及未选择的原因 |
| 楼中楼 | 实际根评论 ID、阅读结果及条数 | AI 是否真正理解了观点，而非看到了文本 |
| 暂时感受/疑问 | 在成功读取后由鱼鱼调用工具记录的自述 | 外部事实真伪、持久兴趣、跨轮后续影响 |
| 视频轮与费用 | 宿主状态及视频模型用量页面有相应信息 | 精确归因到“评论区探索增加的 Token / 模型续推次数” |

对未实现的观察能力，应列为下一阶段任务，不可用占位进度条、伪造事件或人为固定回复代替。
