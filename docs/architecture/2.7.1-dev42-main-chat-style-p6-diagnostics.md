# dev.42 主 Session 自发表达与普通 DM P6-A 诊断

## 自发表达原则（修订）

- 撤销尚未交付的主人指定「肥鱼原味／俏皮碎碎念／温柔日常／清爽直说／自定义性格」卡片及 `mainChatStyleHint` 提示词注入；不新增第二套人格配置。
- 主 Session 继续复用现有 `lifeVoiceContext({scene:'main'})`：基础人设、角色背景、已认可成长经历、成长人格、当前情绪从各自真实状态读取。
- 管理中心只给出情绪与人格成长证据的入口，不把观察数据伪装成真实语言效果或可控性格评分。
- 对话是否自然、会不会主动聊天、能否发送多条物理消息，必须单独验收；不能仅靠提示词或单元测试宣称成功。
- 现有基础人设仍对表达有影响，其与动态情绪/成长间的相对作用尚未通过真实模型对照测试证明。

## 普通 DM P6-A 可观测性

1. `interaction-batch.mjs` 可产生 1–3 条 `messages`，`dm-autoreply.mjs` 逐条复核并发送。配置允许三条不保证 AI 会说三条。
2. 已核验主人 B站私信优先走 `ownerDmAgent.processMessages(ownerRows)`，不是普通 P6-A 的测试样本。
3. 脱敏诊断只保存 `at/status/proposed/planned/confirmed/reason`，不存 UID、消息正文、消息 ID、模型提示。
4. 对真实 B站普通私信测试时，先看 proposed/planned，再看 confirmed 与真实平台回执；主人私信不会进入同一统计。
5. P6-A 诊断的离线测试不代表 Windows/B站环境实机验证；微信通道暂不在此次交付范围内。

## 后续需要的真实模型对照验收

- 在明确授权的本地测试会话中，保持人格、基础人设和问题内容一致，分别设置不同的可信模拟情绪/成长证据进行对照；不得把模拟结果写入真实人生状态。
- 观察表达词汇、语速/句长、是否主动追问、是否选择结束话题、表达是否具体反映经历，而不是人为打“可爱分”。
- 分开记录：输入上下文是否包含情绪、是否包含成长、模型输出有无可观察差异、发送通道是否真正分成多条消息。
- 原始对话内容只在用户本机明确同意的测试域使用，报告默认脱敏；不靠模型自评证明人格已成长。
