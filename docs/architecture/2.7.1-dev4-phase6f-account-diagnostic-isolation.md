# 2.7.1-dev.4 · Phase 6f：自主调度诊断跨账号隔离（开发增量）

> 以已包含 Phase 6e/7e 的用户源码 ZIP 为唯一修改基线。该修复仅解决管理中心对自主调度最近决策的账号归属显示；**不代表**社交决策已交接、成长因果闭环已完成或 Windows/真实 B站已验收。

## 为什么需要这一轮

`lib/life-agent-events.mjs` 的匿名生活事件、视频委派与时间线已经按核验账号作用域存储。然而 `lib/autonomous-planner.mjs` 为兼容旧自主调度仍使用**全局** `autonomous-planner.json`，其中 `runs/lastAt` 属于共享模型额度和节流，而 `recent` 可能包含待办 ID、模型生成的生活理由、上次错误。旧管理状态 API 会把后者无区别返回，切换 B站账号时存在把旧账号决策内容显示给新账号的风险。

## 统一层归属与生产接线

| 入口 | 复用的统一层 | 唯一状态源 | 本次变化 | 权限/隐私边界 | 回归 |
| --- | --- | --- | --- | --- | --- |
| Planner 自动轮、手动考虑、同轮子待办、两次模型对照 | 原 `AutonomousPlanner` | 原 `$DSH_HOME/bili-duty/autonomous-planner.json` | 新增可选 `accountTag` 给每条新诊断、新增 `lastAccountTag` 标识全局最后结果的出处 | 作用域只能来自可信 `getLifeAccountTag()`；不从模型输出猜账号 | Phase 6f 跨账号切换测试 + 原 Planner 测试 |
| 管理中心 `/life-agent/status` → `AutonomousPlanner.status()` | 原 `status()` / `LifeExperienceReadiness` | 同一全局文件 + 已有按账号隔离的 `LifeAgentEvents` | 只向当前核验账号投影本账号 `recent/lastResult/lastError`，不反序列化另一账号原文到页面；无账号则拒绝投影敏感诊断 | 其他账号和**来源不明的旧记录**只能留在冷快照或原文件，不得猜测归属 | 旧文件兼容、只读状态不写盘、额度和活跃性一致性 |

## 数据与老用户兼容

- **没有另建配置或记忆文件**；保留原路径、`version:1`、所有旧字段以及过去 `recent` 条目。新写入条目增加可选作用域；同一份旧文件可以被原冷快照逐文件备份及恢复。
- 从旧版升级后，**没有可证明账号归属的历史诊断默认不再展示在当前账号的最近决策列表中**。并非删除：原文件里的旧历史仍保留，可经停机冷快照保存；不能凭软件升级推断旧记录属于现在的登录账号。
- 全局模型预算依旧共享，界面上的调用次数和字符累计属于全局合计，不应误写成当前账号私有 Token 使用量；`recent` 与 `lastResult/lastError` 则只投影当前账号。全局 `lastResult` 被另一个账号覆盖后，当前账号可能显示空值，但其带来源的近期 `recent` 仍可查看。
- 若当前登录账号在模型运行中变化，仍使用**决策开始时**捕获的作用域标记记录，不能把旧账号的结果标给新账号。原 Life Agent 事件结算、执行前身份复核、外发安全门禁保持不变。
- 这一轮只负责**管理诊断投影**，不迁移真实长期记忆、关系、任务或权限；不声称解决全模块、全路径的跨账号审计。

## 可验收行为

1. 在隔离测试目录或已冷备份的 Windows 测试配置中，让账号 A 产生一条自主决策理由，切换到账号 B 后刷新管理中心：「最近自主调度决策」中不应出现 A 的任务标识或理由。
2. 在 B 产生自己的决策后，切回 A：A 的已标记近期诊断仍在（除非因原 24 条滚动保留限制被淘汰）。A/B 的每日模型调用计数不能因切号归零。
3. 若升级前只有无账号来源的旧诊断，页面不应将其冒认为新账号的经历；原 JSON 保持可备份，真实人生记忆、待办和凭证不应被清空。
4. 可以运行 `node --test test/v271-dev4-life-agent-phase6f-account-diagnostics.test.mjs` 验证以上纯离线回归。此测试不用 B站账号、真实模型或外发。
