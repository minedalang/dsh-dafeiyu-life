## 具体错误解释与误报边界

`502 bad_response_status_code` 说明模型宿主请求收到中转/上游网关失败响应。即使有唯一请求 ID，也只能用于供应商排障，不能确定错误发生于哪个后端节点；不等于本地断网。`429` 为限流、`401/403` 为认证或访问拒绝、`ETIMEDOUT` 为超时、`ENOTFOUND` 为 DNS/连接问题。新诊断仅展示分类和正则截取的最小安全证据，不保存敏感 URL、原始 HTTP body、提示词或密钥。

退避从失败时起依次 5、15、30、60 分钟，连续失败时增加并封顶；重试到期不等于连接已经恢复。主人点“取消模型退避”需要二次确认，提交页面所见重试截止时间戳；后端在原账本锁内进行 CAS 比对。若模型正在执行、退避已过期、时间戳不匹配或状态不可写则拒绝。成功时不调 AI、不取消其他领域冷却；下次正常到期尝试仍可能再次失败。

## UI 模型目录缺失和真实 502 是两个问题

- **目录不可枚举**：曾保存的 Provider + 模型 ID，或宿主当前真实选中模型，允许显示为“仅历史／宿主选择，未验证”；用户能检查配置，但这不表示模型已成功连接。
- **中转站真实 502**：连接测试发出了模型请求，宿主返回了服务端网关错误；不是 Provider 下拉框为空的直接同一根因。只有 DSH 模型宿主或中转/上游恢复后才能通过真实连接测试；本地诊断与按钮不保证修复它。
