> **生产事实**：本版仍是 `2.7.1-dev.6` 未发布预览。**私信／评论的唯一正式决策者依然是 legacy**。Life Agent 只能接收匿名社交事件，按明确授权做 10 分钟内的短期只读影子分类；不存在 Life 正式社交发送器或自动所有权切换。此文档是当前实现，不是将来目标图。生产 Mermaid：[可编辑源码](./diagrams/2.7.1-life-b-social-handoff-live.mmd)。

## 真实交接前协议（当前只执行到演练阶段）

1. **预约旧渠道**：以账号伪名＋渠道在 `social-handoff-fence/lanes` 中创建原子目录及持久 `claim.json`。已存在目录即拒绝，不以超时自动释放。
2. **排空旧操作**：所有已接线的旧社交决策／发送在 `inflight` 中先登记、再检查预约；预约之后的新操作会拒绝。预约者必须确认所有在途操作为零；不完整或已崩溃记录按待人工复核处理。
3. **检查发送事务**：仅检查原 `social-send-transactions` 账号账本的 `confirmed/attempted/uncertain/incomplete` 汇总；任何发送中、未知回执、不完整事务都阻止演练通过。已确认历史发送不会被错误清除或重发。
4. **释放无发送演练**：正常演练只在未进入平台适配器的前提下释放本人预约。切号、崩溃或释放失败留下冻结，**必须停机人工核查**；不能以旧 PID 不在或超时为理由自动清除。
5. **尚未实现**：没有把原正式收件／回复路由切成 Life，也没有 Life 正式发送器、跨渠道 owner 状态迁移、灰度回滚事务。因此演练通过也只表示**本次**旧操作和逐消息事务检查没有发现阻塞，不能据此自动授予任何发送权。

## 逐渠道真实风险矩阵

| 路径 | 当前事实 | 2.7.1 后续必须补齐 |
| --- | --- | --- |
| 普通 DM | `dm-autoreply` 的模型决策和发送仍属旧处理器；已接入跨进程在途和逐事件事务 | Life 取得正式决策后，收件游标、源事件和发送事务必须共用唯一 owner 状态，确保同消息不重复处理 |
| 普通公开评论／@ | `comment-interact`、可信评论 Agent 等并存；部分路径共用逐事件事务 | 逐个审计所有 `bili_reply` 写入入口，保证原授权、冷却、事务、未知结果冻结无遗漏 |
| 主人专属 DM / 评论 | 独立的高权限原路径，不等于普通社交；有些发送走 `legacySocialWrite` 在途登记 | 必须明确选择保留主人专属工作域还是迁移至 Life，不能因接管普通社交而扩大权限 |
| 自主分享与待办回访 | 原独立意愿决策仍可经原发送门禁外发 | 要么纳入统一 Life 决策权，要么声明为单独工作域；不能在归属不清时开启新 owner |
| Python 视频 Agent 互动 | 仍有独立 MCP 写能力及其权限／平台回执 | 审计跨语言执行身份与唯一事务；Node 侧无发送演练**不证明** Python 写入已排空 |
| 影子对照 | 只有 10 分钟内临时分类，且仅限明确授权的内容 | 必须补跨日、跨进程、真实模型和受控账号的验收，不能用 5 个样本直接授权 |

## 管理中心操作与可观察性

- 路径：**鱼鱼的记忆 → 鱼鱼的生活 → 开发者：系统迁移与验收诊断**。展开后可分别点击「演练私信交接（不发送）」或「演练评论交接（不发送）」。**须先关闭 B站生活总开关、等待原有操作排空**，再点击并确认。
- 演练不触发真实社交事件、模型、B站读取或发送；不会改变 `lifeAgentMode`、旧回复器归属、好友权限、发送冷却或已确认平台回执。仅短暂写入并正常释放已有交接预约。
- 如果提示“旧操作在途”“发送事务待复核”“预约残留”或“账号变化”，先停止 DSH，再结合本地账本和真实平台回执复核。**不要重复点击试图清锁**，也不要直接删除数据目录。
- API 仅返回渠道、布尔状态、匿名计数与枚举原因；不会返回 UID、聊天正文、原始消息 ID、账号标签、凭据或模型输出。

## 验收与未覆盖边界

- Node 定向验证：同账号排空、跨账号隔离、在途旧发送阻止、确认历史事务不误判、未知结果不重发、异常预约冻结、用户显式操作与版本一致性。
- Windows：在 DSH Desktop 本地同源页面点击两个演练按钮，观察按钮确认和结果、确认没有真实外发；检查暂停与切号情形。此项**尚未实机验收**。
- 真实平台：须另用明确授权的测试收件人与评论目标进行端到端验证，包含旧版停机、在途排空、重启、重复来源和未知发送回执；本包没有开启这些写入实验。
- **下一步开发**：正式 Life 社交决策器和账号＋渠道＋源事件的原子 owner 状态；所有写入入口清单完成后再分渠道灰度切换。当前 Phase 6 / 7 / 8 仍未完成，不发布正式 2.7.1。
