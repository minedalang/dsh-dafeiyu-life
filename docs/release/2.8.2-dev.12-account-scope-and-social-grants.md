# 2.8.2-dev.12 · 本地账号来源连续性与社交授权隔离（开发候选）

> 基线：`2.8.2-dev.11`。仅为同一份现有 Life 的账号作用域治理，**不提供多个 Life 记忆档案、运行切换或跨机器云同步**。不新增平台外发能力或读配额。

## 事实来源与责任边界

- Life 仍由既有 `character-identity.json` 的稳定角色 ID 标识；B站 UID 是当前外部账号，Cookie 是可轮换登录凭据，不是新的鱼鱼身份。
- `lib/account-binding.mjs` 的核验与换号冻结继续决定账号是否有权运行，不能凭匿名来源标签或管理中心文本越过验证。
- `lib/account-life-scope.mjs` 在当前 UID **确实核验成功**后，以 UID 绑定首次可信的匿名 Cookie 来源标签，在 `$DSH_HOME/bili-duty/accounts/<uid>/life-account-scope.json` 安全持久化。同 UID 重新登录继续使用首次标签；A→B→A 恢复同一 UID 的已有标签。已有源事件和遗忘状态不被重写；先前已经失配的未知来源不会靠相似性合并。
- `lib/account-social-grants.mjs` 将好友名册、私信/公开外发相关选项的**有效权限**按当前 UID 从 `accounts/<uid>/social-grants.json` 读取。旧全局配置仅用于当前已确定的原账号首次升级一次性导入；其他 UID 空名单、外发关闭，必须主人明确在配置页再次保存。
- 初装未登录时，允许在设置界面暂填联系人信息，但仅作草稿；绑定新 UID 后**不会自动把登录前的联系人草稿作为授权**。账号冻结时配置接口拒绝写入受信授权。
- 冷恢复标志存在时不将旧配置自动导入社交授权。恢复后继续遵循原账号复核机制，结果未知的外发绝不自动重发。

## 使用与撤销路径

1. 正常使用当前账号：管理中心读取当前账号的有效好友/社交配置；首次升级原账号维持已有设置，不自动向好友发送通知。
2. 切换到新账号：按照旧换号流程完成登录、重启和确认；新账号联系人列表及主动外发选项默认关闭。使用者重新核实列表并手动保存才创建该 UID 的授权文件。
3. 回到旧账号：重新履行原账号的复核门禁，已保存的旧 UID 授权才可在当前账号范围内重新有效。历史相识不表示旧朋友能认出新账号。
4. 撤销：在当前账号的管理中心清空名单／关闭相应开关并明确保存。不得通过换 UID 或更换 Cookie 绕过现有社交执行门禁。

## 兼容性、安全与剩余限制

- `social-grants.json` 和来源标识均是原账号管理的附属作用域文件，**不是第二个人格或记忆库**；不允许按其他 UID 读取，也不允许用侧车文件授权真实外发。
- 损坏、符号链接、UID 不匹配等可疑文件直接报错，不擅自重建或自动放宽权限；来源创建使用竞争安全策略，Windows/受限文件系统仍需实机验证。
- 初次生成侧车文件仍会沿用当时的可信来源标签；**首次可信使用之前已有的换 Cookie 历史账本可能已失联**，此批不猜测合并，不可承诺旧记忆 100% 无缝恢复。
- 现有**本地业务备份**并不保证携带 `accounts/<uid>` 侧车及全部账号私密记录；不要把本次改进宣传成跨机器搬运或完整档案备份能力。冷状态快照和可携带业务备份的作用、权限与恢复机制不同，务必遵循原有恢复门禁。
- 未来的多记忆档案管理器（UUID、昵称、目录、独占运行、离线移交及可能的云端服务）全文归档在 [`../architecture/future-local-multi-life-profile-management.md`](../architecture/future-local-multi-life-profile-management.md)，**本批只归档，不实施**。
- 额外核对历史测试：反思流程原本已经拒绝在空证据或全是 `partial` 证据时更新情绪；旧测试误用零证据期待成功。现将该回归覆盖零证据拒绝、截断拒绝、完整证据允许，未改动生产反思逻辑。

## 定向验收与正式发布门禁

- 新增测试涵盖：Cookie 轮换、A→B→A、账本损坏及符号链接、旧好友授权保留、新 UID 默认关闭、显式再授权、切号冻结、未登录设置草稿、冷恢复阻止旧授权导入，以及真实管理中心 GET/POST 路由。
- 保留所有既有账号绑定、Life 记忆与机会、社交权限/收据、管理中心开放生态预告页相关的定向回归；新增测试登记 `test/governance/catalog.json`。
- **无实机结论**：本机环境的 Windows 普通/管理员全量测试、真实 DSH B站 A→B→A、Cookie 轮换及冷恢复端到端、完整备份恢复、异常退出、目标操作平台回执、网络恢复仍由维护者验收。任何未解释的安全失败阻断正式发布。
