## 反思连续 10 次 0 条的结论边界

**仅凭“评估 18 条，长期认识 0；人格候选 0，采纳 0”，不能认定服务端逻辑坏了。** 当前对模型成功返回的无有效领悟会正常结束整批，不会反复对同一批重试；如果手动触发 10 次但仍显示同一累计统计，可能是反复查看既有统计而非 10 次重新评估相同候选。`personalityEnabled=false` 时人格候选 0 属于预期；即便开启，证据和跨日期条件仍可能拒绝候选。

本版补充出数、过滤和保存阶段诊断；**没有用户真实反思模型原始回执与候选状态日志，无法断言那 18 条为何都没有可保存的结论。** 不应通过减弱质量/隐私门槛让面板好看。

## 发布顺序（不能跳步）

1. 在 Windows DSH Desktop 完成上述真实环境测试并备份必要的数据。
2. 运行 `run-tests.bat`、`node selfcheck.mjs`、`npm pack --dry-run --json`，确保 npm 包不包含历史开发说明和私密运行文件。
3. 审查并提交 2.6.0 源码，然后在发布分支的对应提交上创建 `v2.6.0` tag；GitHub Actions 会打包 npm 可安装的 `.tgz` 并创建 GitHub Release。**推送 dev 分支本身不会发布正式版**。
4. 检查 Release 资产 SHA-256，然后单独执行 npm 发布 / 插件市场同步步骤（如果渠道尚未自动更新）。
5. 分别核对命令行、DSHMarket 插件和 DSHMarket 网站显示的实际版本，再宣布正式可用。
