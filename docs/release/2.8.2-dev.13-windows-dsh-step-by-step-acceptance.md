## 0. 测试前：确认源码/DSH、备份，避免误向真人发送

1. 暂时退出 DSH Desktop（避免修改正在被插件写入的数据），在 Windows 项目目录打开 **PowerShell**：

   ```powershell
   cd 'G:\WorkSpace\WorkspacePython\dsh-bili-scroll-plus2'
   git status --short
   node -p "require('./package.json').version"
   ```

   应显示 `2.8.2-dev.12`。如果不是，先停止；请勿对未知基线执行 patch。`git status` 如有未提交修改，先保存并核查。

2. 把 `PATCH_2.8.2-dev.13_AFTER_CORRECTED_dev12_VISUAL_RECEIPT_TEST_FIXES.patch` 放到根目录，执行：

   ```powershell
   $patch = '.\PATCH_2.8.2-dev.13_AFTER_CORRECTED_dev12_VISUAL_RECEIPT_TEST_FIXES.patch'
   git apply --check $patch
   if ($LASTEXITCODE -ne 0) { throw '基线不匹配，停止应用！' }
   git apply $patch
   if ($LASTEXITCODE -ne 0) { throw '补丁应用失败，停止！' }
   git diff --check
   node -p "require('./package.json').version"
   ```

   应显示 `2.8.2-dev.13`。如果 `git apply --check` 出错，**不要执行 `--reject`、`reset --hard` 或删除记忆**；保存 Git 报错与当前 `git status --short`。

3. 在 DSH Desktop 原有大肥鱼管理中心打开**「数据备份」**，按本机已有方式创建备份并确认备份结果成功。注意业务备份不等于整个 DSH Profile 全量快照；凭据和隐私资料请本机离线单独安全保管。不要将 Cookie、对方 UID、私信全文上传给任何测试者。
4. 确认 DSH 插件实际加载的是 dev.13。**项目文件夹版本显示 dev.13 不代表 DSH 已安装 dev.13**；从 DSH 插件信息或管理中心版本状态核对，若显示旧版本先重启/按 DSH 官方插件更新流程装入本次源码。没有核实前停止实机测试。

## 3. 不用真人账号就能完成的“视频观察日志检查工具”

本批新增了一个**可以直接运行、不会访问 B站、不会调用模型、不会改动记忆**的脚本：`scripts/audit-282-observation.py`。

将你在 DSH 导出的日志 ZIP 放在一个你自己知道的目录。例如放在「下载」：

```powershell
python '.\scripts\audit-282-observation.py' "$env:USERPROFILE\Downloads\bili-duty-logs-20261119-132258-356.zip"
```

把命令末尾改成你实际文件路径。输出会展示：Life 决策条数、Life 自己选择画面次数、可信视觉回执次数、模型失败和技术阻断分类。**不会输出真实 BV、UID、聊天正文或 Cookie**。

**如何判断：**

- 旧 `vision-events` 日期很老，但「当前决策记录中可信画面回执次数」大于 0：说明旧事件日志不是最新视觉事实来源，**不能说鱼鱼完全没看画面**。
- 「Life 选择实际看画面」大于 0，但「核验画面回执」为 0，且出现 `visual-read-receipt-unavailable`：检查本批修复是否已安装并查看新版诊断。
- 「Life 选择实际看画面」为 0：当前窗口内可能没选看；**不等于一定有 Bug**，要看模型是否故障、视觉开关和候选门禁。
- 「模型调用失败」大于 0：先排查 DSH/Headless 模型与代理连接；不是鱼鱼主动休息。

这是**离线统计工具**，不是强制 Life 取帧工具。该 ZIP 不必发送给我原始内容，可只反馈这份脚本的汇总输出。

## 4. 第一个真实 DSH 视频测试：手动只读取帧（不检查鱼鱼意愿）

**费用与联网提示：** 下面操作会产生真实 B站只读请求，也可能调用视觉模型产生费用。必须已完成第 1 节外发关闭，且是自己明确允许用于测试的公开视频；不要选私人视频。

1. 启动 DSH Desktop，打开大肥鱼管理中心，从左侧点 **「AI 模型」**。展开 **「视频画面识别／视觉模型」**，确认已配置模型、已打开自主视频画面观察开关（若关闭则这次只读视觉测试会被拒绝），必要时使用该区域的模型“测试连接”按钮。确认成功后再继续；**不要为了看一个测试结果打开任何外发权限**。
2. 左侧点 **「视频探索」**。在 **「🎬 自主视频画面观察」** 栏确认开关；第一次可以选**“均衡档”**，点击 **「保存视频感知方案」**。
3. 左侧点 **「运行诊断」**。页面顶部展开 **「视频感知只读验收」**（源码中对应 `video-perception-final-debug`）。
4. 在 **「BV 视频号」** 输入一个可公开访问、没有地区/付费限制的测试 BV；选择 **「正常了解」**（不是“略看 · 不识图”），点 **「开始只读视频感知验收」** **一次**。
5. 观察进度条完成，展开 **「视觉模型实际回执 · 来源、时间与描述」**，再看 **「真实分镜拼图与高清局部复查」** 和 **「OCR 结果与可信时间轴」**。
6. 预期：有实际 JPEG、帧来源和时间标记，模型描述与这些实际图片相符；如果字幕/音频不可用，应明确显示不可用，**不能冒充识别到音频**。如果没有 JPEG 或视觉回执报错，则标记失败，保存脱敏诊断。
7. 可点 **「查看最近真实 Life 输入」**：**不要把本次主人手动测试的成功，误当成 Life 已自主观看**。这两类证据必须分别检查。不要重复点击同一 BV 消耗额度。

## 5. 第二个 DSH 视频测试：检查 Life 是否自己选看画面

1. 保持第 1 节所有外发禁用。打开左侧 **「运行诊断」**，找到折叠项 **「🎬 视频 Agent · 手动诊断与运行证据」**，展开。
2. **先点**「重新核查真实状态（零模型调用）」，仔细读它报告的账号、Life、视觉、模型门禁及最近委派状态。
3. 如果页面明确显示模型/账号/权限阻断，先排查该原因，**不要继续狂点测试运行**。
4. 在确认没有实际外发权限、账号和视觉模型就绪后，**只点击一次**「手动触发一轮真实视频 Agent」。这个按钮会启动真实视频 Agent；它**不会强迫鱼鱼看画面**，因此完成一轮也不等于取帧成功。
5. 点同页 **「刷新决策记录」**，查看「鱼鱼的决策全过程」：
   - `observe_video` /“看画面”动作不存在：本轮没有自主选择视觉，不认定 Bug。
   - 选中了画面，但只有 `visual-read-unverified`：没有可信视觉回执，查失败详情和视觉模型/取帧依赖。
   - 选中了画面，出现 `visual-read-receipt-unavailable`：怀疑回执写入或账号/并发保护问题，需发送脱敏决策分类。
   - 明确显示 `visual-read-verified`：这是该轮真实视觉证据；还要查看对应的视觉记忆/持续性。
6. 去 **「🧠 鱼的记忆」** 搜索本轮公开测试视频的主题（可使用标题的非敏感部分），核对是否存在真实经历。**记忆记录为空**也可能是未写入、隐私/衰减过滤或未发生观察，不要靠猜测修改数据。
7. 正常重启 DSH 后再回忆这份**仍清晰、已写入**的经历。若数据丢失，保留匿名回执状态和重启时间，不要修改 `episodic.json` 或备份造数据。

## 6. 专门检查“快速设置不会隐式开权”（你之前不知道怎么做的那一项）

前提：第 1 节已经保存了**关闭**的 A～H 选项。

1. 在管理中心 **「社交互动」**、**「视频探索」**、**「动态创作」**、**「最近评论」**、**「后台私信」**各页面确认一次对应设置为关闭（可以用手机拍这些**不含个人信息**的页面作为对照）。
2. 点击 **「🚀 快速设置」**；只浏览页面，**不要**点任何「确认保存……」按钮。
3. 点击另一个页面，例如 **「大肥鱼的家」**，然后浏览器刷新（F5）。
4. 回到前面五个页面，重新读取/刷新配置；检查 A～H 依然关闭。
5. 全部保持原值即通过：**“打开或浏览快速设置”没有隐式恢复之前关闭的外发授权**。
6. 如果某一个开关重新打开，即失败。先重新关闭并保存，再记录【原值】【意外新值】【页面】【浏览器时间】【是否有重启】；停止进一步真实平台测试。

**注意：** 如你希望测试“保存快速设置里的生活参数会不会开权”，也可以在其**明确提示不会发平台消息**的生活参数区域修改一个无害值并保存，再重复 A～H 检查；不建议在生产账号上改变任何社交授权复现 Bug。

## 7. Windows quick / full 与管理员补测

将以上专项与 DSH 安全只读操作完成后，退出所有仍在运行的测试窗口，普通 PowerShell 先运行 quick：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\run-tests.ps1' -Mode quick
```

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\run-tests.ps1' -Mode full
```

等待命令**彻底结束**，再关闭本次进程。接着右键 Windows PowerShell → **以管理员身份运行**，进入相同项目目录，单独执行 `-Mode full`，用于补测因符号链接权限不足而 SKIP 的安全测试。**两份 full 禁止并行运行**。

如果 full 有 FAIL 或安全 SKIP，**不能发布正式版**。日志汇总会列出 `%TEMP%` 的 `dsh-bili-scroll-plus-tests-*.log` 和 `dsh-bili-scroll-plus-details-*/step-*.tap.log`。反馈时请复制**失败测试名字、`error`/`actual`/`expected`/调用栈附近几十行**，先删掉 Cookie、token、私信、真实 UID 和隐私路径；不要直接上传未经检查的整个临时 Profile。
