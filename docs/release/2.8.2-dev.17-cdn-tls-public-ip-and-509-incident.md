## 视频 CDN 安全实现

1. `adaptive_video.py` 的候选媒体 URL 仍只能由官方 `api.bilibili.com/x/player/playurl` 返回，经 `https`、`*.bilivideo.com`、`/upgcxcode/`、媒体格式、无用户信息、无片段锚点校验；不信任网页 Query、AI 输出或第三方重定向 URL。
2. 官方 CDN 允许 `:443` 和 **1024–65535** 高位端口上的 HTTPS；1–1023 除 `443` 仍禁止。这不是给任意地址开放网络：仅适用于上述合法 CDN 媒体地址。
3. 禁用从环境继承的 HTTP(S) 代理，解析并拒绝任何非公网 IP；连接**实际固定使用已验证公网 IP**，TLS 的 SNI 与证书校验仍采用原 CDN hostname，避免 DNS 检查后重新解析发生变更。重定向每一跳仍须重新满足 CDN 白名单及公网连接条件；网络超时、字节/Range、下载总量及 FFmpeg 本地解码预算均保持原要求。
4. 如所在网络只能通过代理访问，或 CDN 实际返回其他媒体地址/保留端口，安全拒绝后仍降级低清分镜；不会悄悄关闭证书校验，也不提供“任意 URL 测试”入口。

## -509 复盘实现

- **已有账本继续单一事实源**：`bili-read-budget.json` 的每分钟/每小时计数、会话列表间隔、DM/社交通道限流退避与账户隔离不变。
- 每次已接入门禁的读取派发，额外计入按 5 分钟分桶的匿名端点分类汇总，保留最近 48 小时，不保存 URL、正文、目标 UID、登录信息或请求参数。
- `noteError` 实际识别限流时，原子保存该时刻的脱敏限流类别（例如 `bili-509`）以及**限流前 15/60 分钟**的派发总量和按端点分类明细，至多留最近 16 次限流事件；即使一小时实时预算历史随后清除仍可复盘。
- 管理中心 **「消息感知」→「后台读取保护」** 显示最新现场快照；升级前的旧 -509 无法倒推回填。没有发生新 -509 时清晰显示暂无新记录。
- 没有为了测试人为触发 B站 509，不修改发送上限或擅自重试已知平台失败。

## 统一层边界与验收

视频源属于现有只读视觉工具；平台账号只读节奏属于现有 `BiliReadBudget`。未增设另一个调度器/账号状态/事实库，不涉及 Life 自主意愿、私人记忆或外发权限；**架构接线未变**。本地 Python TLS 连接校验是实现安全加固而非跨层新节点。

开发环境仅执行相关 Python/Node 定向测试、既有静态门禁、自检和独立 Git Patch 回放；Windows 普通/管理员全量测试、真实 CDN 与真实 DSH 仍待维护者实际操作。若视频仍然低清，反馈脱敏的 `adaptive_fallback.reason/authorityDetail/rejectedTrack`、取帧诊断（不上传签名 URL）；若再次 509，反馈消息感知页的 15m/60m 计数和最近错误时间，不需要私信正文。
