# 2.8.2-dev.35 · 私信/局部视频收口复核

## 审计依据与结论边界

基于11月20日脱敏运行日志，`get_sessions` 于17:29返回业务限流码`-509`；同一时段还存在视频元信息、字幕及其他接口读取，无法仅凭一次失败认定30分钟无未读兜底是限流原因。因此保持私信未读哨兵约5分钟、会话一致性核对30分钟及原有共享请求预算/持久退避。**这次没有调整 B站读取频率，也没有实时操作平台。**

Life 日志曾有选择并启动`focus_video`的记录，但没有足够的窗口成功证据；另有两次空`focusCandidates`异常，因此把运行不崩溃与每窗口可观测失败作为本次 P0 修复。此版本不能宣称真实 B站/Windows 下的端到端局部视频观察已成功。

## 本次代码变更

- `lib/interaction-scheduler.mjs`：`ok:false` 不再清除私信列表 pending；失败回执标为 error，有可识别的 `-509` 时纳入已有持久化限流退避；异步哨兵/详情结果需要同账号才允许更新持久化状态；跨账号的晚到响应也不得污染另一账号的网络退避状态。30分钟一致性间隔和5分钟哨兵未改。
- `lib/life-continuation.mjs` / `lib/autonomous-planner.mjs`：只有当前 Episode 与观察的 BV 可信匹配且候选为数组时才构造 Life 局部选择菜单，消除 null `focusCandidates` 异常；真实复查拒绝时写有界失败 trace；帧超额不计为成功窗口。
- `lib/video-focus-review.mjs`：验证真实解码帧的时刻必须在可信窗口内且升序、网络字节字段为有效整数并在授权预算内。视觉模型文字不会转成可执行时间点或真实视频来源证明。
- 回归新增 `test/v282-dev35-dm-focus-closure.test.mjs`，覆盖未读兜底、重复调度、限流退避、账号切换、Life 空观察、局部来源/时刻/字节验证。
