# 2.8.2-dev.30 · 视频感知收口与安全说明（开发候选，非发布放行）

## 背景与归属

- Life 意愿仍属于现有 Life willingness；本批仅让看后独立自主意愿在真实生产入口中支持多个可信候选。没有引入新的发送者、社交权限、账本或自行选择未经核验网址的模型工具。
- 全局视频证据由原有 B站 videoshot 时间线和视觉回执提供；局部只允许选择在可信全局时间线上实际出现的时间锚点。多窗口共享现有每次 Episode 三档预算，读取侧同时检查帐号、视频 BV、窗长、帧数、网络字节和来源。
- 「次数与额度」的流量统计来自 HTTP 响应体计数，属于已发生的观测值，不是新增可重置的每日流量额度；每次视频感知 24/50/100 MiB 执行预算仍分别受限，不能因为显示今天使用量为 0 而放宽取帧。

## 本次行为变化

1. 多窗口从“每个窗口预先扣除整档最大帧数”改为执行后依据可信回执中实际帧数扣减。新一轮局部复查的剩余 `frame_budget_limit` 传递到 MCP/DSH/FFmpeg 控制链，不能仅由 UI 显示剩余额度。
2. 原视频局部 FFmpeg 解码采样目标为最高 640×360（约 360p），保持源宽高比，低清源不被强行放大；不宣称请求到的视频流必定为 360p，也不代表观看了全部画面。调试图为独立帧；视觉模型实际收到的局部素材是由采样帧组成的拼图。
3. 主人只读全链路 Debug 先取得可信全局观察，再让真实 Life 独立决定是否继续；若愿意，Life 可一次选择多个可信时刻。分段取帧、视觉证据验证、累计额度和拒绝/失败记录均分别展示；调试入口不写入真实 Life 经历，也不外发 B站内容。
4. AI 模型页移除「旧版主人 Agent 模型（兼容配置）」编辑区；保留原配置与底层兼容读取，避免升级造成旧用户行为变化。
5. 恢复之前 dev.28/dev.29 交付包中意外遗漏的 `tools/导出B站日志.bat`，保留既有脱敏导出语义。
