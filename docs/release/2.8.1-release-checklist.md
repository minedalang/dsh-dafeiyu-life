## 发布操作（只有阻断项关闭后才能执行）

1. 核对 `git diff` 与 `package.json`/`package-lock.json` 的 2.8.1 版本号一致，删除开发/试验后缀，发布说明与归档导航同步。
2. 在干净 Git 工作区执行完整本地 Windows 测试及 DSH 实机验证；保留安全证据（不导出私信正文、API Key、图片或配置内容）。
3. 评审后 Commit/Push/Tag/Release；如通过 GitHub 插件安装，需要确认目标分支/Tag 真正指向相同构建。
4. 如另行发布 npm/市场，核对上架包名称、版本号、完整依赖、发布平台状态，再更新用户文档。不要把 `dev` Git 推送称作已正式上架。
