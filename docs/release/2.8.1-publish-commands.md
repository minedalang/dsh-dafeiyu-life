## 3. 合入 main 后再创建稳定 Tag

正式版 Release workflow 要求 **`v2.8.1` 的提交已经合入 `origin/main`**。先通过 PR 将测试通过的 `dev` 提交合并进 `main`，确认 CI 通过，然后：

```powershell
git switch main
git pull --ff-only origin main
git status --short
node -p "require('./package.json').version"
git tag --list v2.8.1
```

必须确认工作树干净、版本严格等于 `2.8.1`、`v2.8.1` 尚不存在、已合并的提交就是你最终验收的源码，然后：

```powershell
git tag -a v2.8.1 -m "大肥鱼 2.8.1 正式版"
git push origin v2.8.1
```

推送 Tag 会触发 GitHub Actions **自动创建 GitHub Release 和各平台 `.tgz` 附件**；**不会自动发布 npm**。请在 Actions 中确认 Release job 全绿，并核对附件与 `SHA256SUMS.txt`，不能在失败时直接补发 npm。

## 4. npm 正式发布（需要 npm 包维护权限）

```powershell
npm whoami --registry=https://registry.npmjs.org/
npm view dsh-dafeiyu-life version --registry=https://registry.npmjs.org/
npm view dsh-dafeiyu-life@2.8.1 version --registry=https://registry.npmjs.org/
npm pack --dry-run --ignore-scripts
npm publish --dry-run --ignore-scripts --access public --registry=https://registry.npmjs.org/
```

`npm view dsh-dafeiyu-life@2.8.1` **若已经返回 2.8.1，说明该版本不可重复发布，应停止**。仅在 Github release 全绿、npm 版本尚未使用、dry-run 清单正确、当前 main 源码为刚才的 Tag 提交时，执行：

```powershell
npm publish --ignore-scripts --access public --registry=https://registry.npmjs.org/
npm view dsh-dafeiyu-life@2.8.1 version --registry=https://registry.npmjs.org/
npm view dsh-dafeiyu-life dist-tags --json --registry=https://registry.npmjs.org/
```

如未登录，使用 `npm login --registry=https://registry.npmjs.org/` 并按当前 npm 的 MFA/权限流程完成。不要将 token 或 `.npmrc` 放进仓库。
