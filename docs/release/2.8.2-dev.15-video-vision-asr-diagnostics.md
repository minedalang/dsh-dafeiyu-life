# 2.8.2-dev.15：视觉／语音并行与 CDN 安全拒绝诊断

> 状态：开发候选；仅离线验收。用户提供的 BV 页面链接是 `/video/BV...`，不是 B站 playurl API 返回的签名原视频 CDN 地址。本批没有获得用户当时的原视频签名 URL，因此不能断言哪个具体 CDN URL 格式应获准。

## 统一层归属与安全边界

- **自主意愿事实源：** Life 先选 `skim`、`standard` 或 `deep`；只有原 `visionDecision` 许可且独立视觉模式就绪才启动视觉。字幕有无不改变该意愿；默认略看仍不识图。
- **视觉与语音：** 两个既有只读工具调用，在已经授权的标准／深入观察中并发开始。共享读取预算与模型能力限制继续由既有工具门禁检查；没有新增网络 API、Token、外发权限或记忆库。
- **最终事实：** `buildVideoEvidenceBundle` 和 Life Episode 的可信回执、账号归属、记忆遗忘边界原样保留。并发完成不代表真正观看成功。慢 Whisper 不阻止已经授权的独立视觉调用启动，但最终视频交接仍等待读取汇总，可能仍耗时较长。
- **视觉源：** `adaptive_video.py` 只验证官方 playurl 的真实媒体地址，不接受用户传入网页 URL 作为 CDN 源。不放宽 HTTPS、域名、路径、默认拒绝显式端口、重定向、Range、预算和离线 FFmpeg 门禁。拒绝时仅输出固定枚举，不包含域名、签名或查询值。

## 本批修复

1. 视觉先于 Whisper 结束也能独立获得真实模型回执；此前 ASR 必须完成才能启动视觉，现改为当轮明确选择后并发。仍尊重当前账号和 Life 视觉互斥租约。
2. `lib/asr.py` 使用本地单调时钟记录下载、模型加载、切片、推理、回执与总耗时。Whisper 分段迭代是惰性的，推理计时覆盖真正消费返回片段的过程，最多读取 2500 条，不把巨大迭代器全部转成列表。所有数据仅为非负整型毫秒。
3. `bili_transcribe_safe` 对时间字段做有限白名单及范围校验，旧版无时间字段的回执仍兼容。管理中心仅展示计时，不推断真实语言质量。
4. 原视频降级回执的 `authorityDetail` 仅有 `userinfo`、`explicit-port`、`url-fragment`、`malformed-authority`；`rejectedTrack` 仅有 `durl`、`dash`。诊断不回显任何 CDN Host、签名、路径或 Token。显式 `:443` 也暂时仍拒绝，避免未经证据批准扩大白名单。

## 仍需真实 Windows／DSH 验证

- 使用 `BV1Nxs26uE46` 比较关闭／开启 Whisper 的本轮实际 **总耗时**；开启时检查音轨下载 `audioDownloadMs`、加载 `modelLoadMs`、切片 `clipExtractionMs`、推理 `inferenceMs`，不能把管理中心阶段 2 的全部等待都叫作推理时间。
- 检查 `visualCompletedBeforeSpeech`、`visualMs` 和真实 `analyzed` 回执；如果两条工具调用因共享模型服务排队，墙钟加速可能有限，但视觉应已被提前提交。
- 若仍降级到 videoshot，记录 `reason`、`authorityDetail`、`rejectedTrack` 三个不含签名的字段。**只有经可信实际回执证实合法的特定 CDN 格式，才评估独立的安全兼容变更**。
- 对 `asr_timeout`、视觉回执登记、网络预算、账号切换和 Windows full／管理员符号链接安全 SKIP 单独复测。本批未声称修复全部历史 Windows full 失败。

架构接线未增加新权限或存储事实源；视觉调用执行时序调整，不引入新的调度器。
