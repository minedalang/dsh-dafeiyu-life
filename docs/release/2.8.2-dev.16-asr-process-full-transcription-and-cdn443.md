# 2.8.2-dev.16：ASR 外层长等待定位与完整语音转写恢复

> 开发候选；基线为 `2.8.2-dev.15`。不向 B站调用真实 API，不增加 Life 外发权限或独立记忆库。

## 用户现场证据与推断边界

- 用户对同一 BV 的真实只读结果：完整视频 1364 秒、视觉 10.5 秒、字幕／语音 308.5 秒、整轮 310.3 秒，视觉先于语音完成；Whisper 内部音频下载 6.6 秒、模型加载 5.1 秒、切片 0.3 秒、推理 5.1 秒，内部总计 17.1 秒。
- 现有测试回执不能证明额外约 291 秒准确归属于 MCP 入队、默认 executor、跨进程管道、调度还是返回；此前把它直接归因 Whisper 慢是错误的。本批取消共享 `asyncio.to_thread(subprocess.run)` 启动，改专用受限异步子进程，从代码上去掉共享线程池排队的可能，并在**外层工具、MCP 处理、子进程启动、进程+管道生命周期、Python ASR 内部**各自添加有界耗时。若实机仍慢，可根据外层差值继续定位，不冒称已经完全解释 291 秒。
- 本地脚本默认将完整音轨交给 faster-whisper，`coverage=full-audio-attempt`。对长视频也不再默认剪成头／中／尾三段，仍保留仅维护者环境变量 `BILI_ASR_LONG_VIDEO_MODE=sample` 作为可撤销的采样备选；无完整可信识别时不声称已听完、看完或准确转写。
- 旧 MCP 与 Node 总时限仍然存在（Python 子进程默认 360 秒，Node 工具请求 390 秒），超过限时返回技术失败而非伪造“全音轨已转写”，取消/超时尝试终止子进程及收回管道。**这不是任意长视频无限时转写的承诺**。
- B站原视频安全校验仅允许白名单 CDN、标准 HTTPS、原 `/upgcxcode/` 媒体路径与原有索引/Range/重定向/网络字节预算；标准显式端口 `:443` 等同 HTTPS 默认端口放行，其他端口、用户信息、fragment、可疑主机仍拒绝。用户日志只说明 `explicit-port`，没有原始数值，故 **:443 兼容不保证这个 BV 改为原视频取帧**；仍保留低清分镜、安全原因、轨道类别的明确回执。

## 统一层归属与恢复

- 自主选择仍由 Life 与现有 `visionDecision` 控制；ASR 只在原始 `cfg.transcribe` 明确开启、官方字幕不足时调用。非授权 `bili_transcribe_safe` 依然拒绝。
- 账号与内外发权限使用原有门禁；视觉已经获得的回执不因 ASR 失败伪造或扩大；最终多模态结果仍等待两个读取分支收敛。
- ASR 子进程只运行用户已经安装的 `.venv-asr/.../python` 与固定 `asr.py`，路径校验、超时与 stdout 容量限制原样保留。新增的统计不包含实际 BV、源网址、签名、Cookies、语音内容与 stderr 原文。
- 线程池改为独立 asyncio 子进程，属于既有 MCP 内部执行机制更新；未增加新的跨层入口、模型、服务或持久化事实源，四张 Life 总体接线图不增加节点。

## 发布状态

离线定向测试与补丁回放不等于 Windows DSH 正式验收。需要本机用同一 BV 核对 `subtitleToolMs`、`asrToolMs`、`asrMcpTimings` 与 Whisper Python 内部计时，以及 `coverage`、`visual.adaptive_fallback` 和新降级原因；普通/管理员 full、既有历史 FAIL 及符号链接 SKIP 未放行。
