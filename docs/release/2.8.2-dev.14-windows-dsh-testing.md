# 大肥鱼 Plus `2.8.2-dev.14` · Windows / DSH 实际验收教程

> 适合直接照做。**不用发送私信、评论或点赞**；“视频感知全链路 Debug”是主人主动的只读试运行，并不是鱼鱼自主观看。不需要访问私人视频。

## 一、先备份并确认源码版本

1. 关闭 DSH Desktop；不要删除或编辑数据目录、记忆、Cookie，也不要用 `git reset --hard` 清理工作区。
2. 普通 PowerShell 打开源码目录：

```powershell
cd 'G:\WorkSpace\WorkspacePython\dsh-bili-scroll-plus2'
git status --short
node -p "require('./package.json').version"
```

3. 应显示 `2.8.2-dev.13`（已经使用上一批补丁的前提下）。工作区若有未提交修改，请先保留并确认是否与本次补丁重叠。
4. 将本包 Git Patch 放到当前根目录后执行（可用 Tab 补全长文件名）：

```powershell
$patch = '.\PATCH_2.8.2-dev.14_AFTER_dev13_VIDEO_SOURCE_LONG_ASR.patch'
git apply --check $patch
```

5. **只有 `--check` 没有错误才执行：**

```powershell
git apply $patch
git diff --check
node -p "require('./package.json').version"
```

预期版本 `2.8.2-dev.14`。失败则停止；**不要**加 `--reject`、`--3way`、`reset --hard`，不要再次打同一补丁。保存 `git status --short` 和报错供排障。

以下命令从项目根目录执行，实际需要本地已有 Python/Node 及项目依赖：

```powershell
python -m unittest discover -s test -p 'test_v282_dev14_video_source_asr.py' -v
python -m unittest discover -s test -p 'test_adaptive_video_dev3a3.py' -v

node scripts/check-context-budget.mjs
node selfcheck.mjs

```

预期显示 Python `OK`、Node `fail 0`、治理/架构检查 `PASS/通过`。个别旧测试可能依赖 `Pillow`、FFmpeg；若提示 `SKIP` 或 `ImportError`，不能把跳过算成通过，应记录系统依赖。建议更新 Git 提交前继续执行：

```powershell

```

确认 quick 完全通过后，分别在**普通 PowerShell、管理员 PowerShell** 执行 `-Mode full`；不要同时运行。你的历史 Windows full 仍有失败和符号链接安全 SKIP，本批不能替你声明它们已经解决。失败保留 `step-*.tap.log`，先脱敏再上传。

## 三、DSH 第一次：只验证视觉模型与低清回退原因

1. 确认这份源码已被 DSH 实际加载；仅 `package.json` 是新版本不代表 DSH 插件运行版本更新。重启 DSH Desktop，在插件信息页核对来源/版本。若仍加载旧版，按你的 DSH 安装方式更新插件源码后重启，**不删除数据**。
2. 打开大肥鱼管理中心。点击左侧 **「AI 模型」**，找到 **「🎞️ 视频感知 · 解码和语音能力」**；确认 FFmpeg 显示已就绪。此测试可以先**取消勾选「启用视频语音识别」**，然后点击 **「保存视频语音识别设置」**；这样可以单独比较视觉速度。
3. 在同页确认本地视觉模型已启用且原来的“图片识别”测试成功。不要因此打开私信/评论/动态发布授权。
4. 进入左侧 **「运行诊断」**，展开顶端 **「🎞️ 视频感知全链路 · Life 最终输入 Debug」**。
5. 在 **「BV 视频号」** 输入你之前的公开测试视频 BV（也可用另一个可公开读取的 BV），将 **「本次主人测试深度」** 选为 **「正常了解」**，按 **「开始只读视频感知验收」** **一次**。
6. 结束后看卡片：**「图像来源」「原视频降级原因」「模型实际视觉回答」**；再展开 **「🖼️ 视觉模型实际回执 · 来源、时间与描述」**。

**预期 A：** 出现 `decoded-public-video`、真实 FFmpeg 采样时间和本地模型返回的视觉描述，说明此次路径支持原视频解码（不代表全部视频看完）。

**预期 B：** 出现 `low-resolution-preview` 和「原视频降级原因」，会给出诸如 `video_source_path_rejected` / `video_source_domain_rejected` / `dash_indexed_video_unavailable` 的明确分类。降级时仍可 `analyzed`，不算视觉模型错误。**保留原因分类和结果截图即可，千万不要粘贴带签名的原始 CDN URL、Cookie 或账号凭据。**

**预期 C：** 如果出现 `vision_unavailable`、`timeout`、FFmpeg 或网络预算错误，记录具体状态分类；不要连续多次请求以免触发平台风控。`unsafe_video_source` 不代表视频内容有害。

## 四、DSH 第二次：比较长视频 Whisper 抽样与耗时

1. 返回 **「AI 模型」→「🎞️ 视频感知 · 解码和语音能力」**，重新勾选 **「启用视频语音识别」**，保持 `small` 或你原本已经验收过的模型，点击 **「保存视频语音识别设置」**。
2. 回到 **「运行诊断」→「🎞️ 视频感知全链路 · Life 最终输入 Debug」**，用同一个约 22 分钟的公开视频 BV，选择 **「正常了解」**，点击只读验收按钮一次，记录从开始到结束的总耗时。
3. 展开 **「🎙️ B站字幕／Whisper 语音识别回执」**。若平台本身有字幕，可能直接使用官方字幕，不触发 Whisper；需要测试抽样时必须选择没有可用官方字幕的公开视频。
4. 若确实触发本地转写，查 `coverage`：长视频且 FFmpeg/ffprobe 已就绪时预期为 `representative-windows`；`sampleWindows` 约 3 个，时间分布在开头/中间/结尾。这里的文本只来自窗口，不是全文。
5. 查 **「本地模型实际视觉回答」**。ASR 的模式不应该把低清预览伪装成真实解码，也不应该使识图自动成功。如果图像来源仍是低清，按第三节的降级原因分析。
6. 比较第三节（ASR 关闭）与本节（ASR 抽样）的耗时；与之前 `dev.13` 整音轨实验相比若更快，只能说明当前设备/素材有改善，不能推算所有视频会快多少。

### 特殊情况与恢复

- 若 `coverage=full-audio-attempt`，可能是音轨不足 8 分钟、FFmpeg/ffprobe 在 ASR 的 Python 子进程 PATH 中不可见、探测/裁剪失败，或由维护者设置了 `BILI_ASR_LONG_VIDEO_MODE=full`。检查 **「AI 模型」** 页的 FFmpeg 状态与安装路径，记录现象，不要把“没有抽样”说成 Whisper 故障。
- 若 Whisper 仍长时间停在阶段 2：**下载整段音轨仍会耗时**，也可能是模型加载、音频切片或 CPU 推理；当前仍没有每一子阶段的准确耗时仪表。超过现有受控时限应有失败回执，不必在真实账号上反复重试。
- 结束后保持或恢复你自己原来的 **「启用视频语音识别」** 设置；本次不改动其他授权。
- 需要完整视频语音文字的高级用户，可以在真正启动 DSH 的父进程环境中设置 `BILI_ASR_LONG_VIDEO_MODE=full` 后重启，但它会恢复较长 CPU 时间；不要在产品中称抽样为全片理解。
