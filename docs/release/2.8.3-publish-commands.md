# 2.8.3 正式发布门禁与命令

本文件是维护者手动发布流程，不是发布证书。先在收口候选上通过[用例清单](2.8.3-release-checklist.md)。禁止跳过失败、自动提交或发布。

Windows 项目根目录，普通及管理员环境按清单分别执行 full，并保留完整日志：

```powershell
$ErrorActionPreference = 'Stop'
node -p "require('./package.json').version"
git status --short
git diff --check
if ($LASTEXITCODE -ne 0) { throw 'diff check failed' }
npm ci --ignore-scripts
if ($LASTEXITCODE -ne 0) { throw 'npm ci failed' }
foreach ($task in @('check:test-governance','check:context-budget','check:life-architecture','check:video-tool-contract')) {
  npm run $task
  if ($LASTEXITCODE -ne 0) { throw "$task failed" }
}
node selfcheck.mjs
if ($LASTEXITCODE -ne 0) { throw 'selfcheck failed' }
.\run-tests.ps1 -Mode full
if ($LASTEXITCODE -ne 0) { throw 'full failed' }
npm pack --dry-run --ignore-scripts
if ($LASTEXITCODE -ne 0) { throw 'pack failed' }
```

完成真实 DSH/平台、干净安装、2.8.2 及公开 dev.14 无损升级、备份恢复和分盘故障验收后，由维护者明确确认放行。再同步 package.json/package-lock.json 为 2.8.3、README 版本状态、CHANGELOG 正式版标题 `## [2.8.3] · 让经历成为记忆`、验收记录（只有全部门禁确实通过才将清单状态改为 `releaseReady:true`）。重复上方门禁及打包预检，审查变更，通过项目 PR/CI 合入正式分支。禁止直接用候选包作为稳定版。

Tag 与 package 版本须完全一致。确认正式提交及 CI 后，由维护者手动创建 `v2.8.3` Tag 并推送；等待 release 工作流通过，再核对 GitHub Release。npm 单独核对账号、权限、实际打包清单和 dist-tag，确认后方可 `npm publish --access public --tag latest`。DSHMarket 单独核对索引版本。任何阶段失败均停止，不自动 reset、强推或删除数据。历史发布操作参考 [2.8.2 发布命令](2.8.2-publish-commands.md)。
