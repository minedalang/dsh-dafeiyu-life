# 2.6.1 正式版发布核对清单（最新 RC2 账号解耦版基线）

> **发布闸门：** 本清单不代表真实 B站/Windows DSH 已验收。未通过实机确认时，只允许制作发布候选与运行本地测试，**不要推送正式 `v2.6.1` Tag 或执行 `npm publish`**。

## 1. 唯一发布基线与范围

- 源码来自 **`2.6.1 RC2 · 账号与记忆解耦版`**（之前包含连续探索、关系界面、全社交 AI 待办、音乐建议与自然回访修正），不是早期 dev.6/RC1。
- `package.json`、`package-lock.json`、`README.md`、`RELEASE_NOTES_v2.6.1.md` 及 Git Tag 版本对应 `2.6.1` / `v2.6.1`。
- 2.6.1 只新增一个当前 B站账号的受控换号，不实现多账号同时运行；不合入 P6 连发、沉默续聊、跨频道自发联系、开放式技能或外部视频 Skill。
- README 保持特色功能为主；详细变更在 CHANGELOG/Release Notes，RC2 技术历史已归档。

## 2. 本地自动化检查

- [ ] `node --version` >= 22；`npm --version` 正常。
- [ ] `git status --short` 干净，`git diff --check` 不报错；核对当前 commit 是预计发布的开发成果。
- [ ] `node --test` 全量通过（允许明确标记的跳过）。
- [ ] `python -m unittest discover -s test -p 'test_*.py'` 全量通过。
- [ ] `node selfcheck.mjs` 通过，且没有写入真实 `$DSH_HOME/bili-duty`。
- [ ] `npm pack --dry-run --ignore-scripts` 成功，核对包文件清单，排除凭证、Cookie、SQLite、私信原文、日志、私密档案。
- [ ] `npm pack --ignore-scripts` 生成可安装 `.tgz`，计算并记录 SHA-256；不把 GitHub Source code 压缩包误当安装包。

## 3. 真实 DSH Desktop / B站 必须验收

- [ ] Windows DSH Desktop（若提供 Mobile 入口也检查）加载、First Start、模型验证、管理页读写、重启有效。
- [ ] 完整关闭 DSH 并离线备份 `$DSH_HOME/bili-duty/`；历史记忆、人格、情绪、已接受待办和 UID 状态对比一致。
- [ ] 旧版升级后原 B站账号正确读取私信和回访状态，旧登录与关系没有意外失效。
- [ ] 新账号扫码**只暂存凭证**，可取消；在线 UID 不符/登录失效时原账号及 Cookie 不变。
- [ ] 确认换号后重启前业务被冻结；重启后人工复核新账号许可才能继续。
- [ ] 旧账号待办/私信/评论回执不串到新 UID；`sending`/`uncertain`/旧 `pending` 不自动重试；切回旧号仍需核验。
- [ ] 主人、好友、普通用户的已启用私信/评论自然提议能被原回复 AI 理解，可接受/延期/拒绝；艺人推荐不需 BV，分段消息和 UID 隔离正常。
- [ ] 连续探索父子任务至多本轮 3 项、遵守 AI 额度；一次原请求的完成回访不重复；私信/原评论外发有真实 API 回执且不会跨账号误发。
- [ ] 主人主动视频兴趣推荐在**明确授权后**能生成草稿并正确选择渠道；默认没有自动恢复旧发送授权。
- [ ] 人生记忆衰减、私密域隔离、遗忘不可逆，以及旧数据备份恢复与回滚正常；账号切换不能复活已遗忘的细节。
- [ ] 在 Windows 下核查文件访问权限和账号 `accounts/` 目录的敏感凭证保护；真实运行时的限流/认证失败会安全停止。

## 4. 发布顺序：dev → main → tag → GitHub → npm → DSHMarket

1. 在 `dev` 提交本轮发布资料修正，推送后开 PR `dev` → `main`，审核并合并。**不要直接从未合并的 dev Tag 正式版**。
2. `git fetch origin --tags`，切到 `main` 并 `git pull --ff-only origin main`，再次核对包版本、测试和最新提交；确认远端没有 `refs/tags/v2.6.1`。
3. 只有第 3 节实机验收完成，才创建并推送附注 Tag `v2.6.1`。现有 `.github/workflows/release.yml` 将自动生成 GitHub Release 与 `dsh-dafeiyu-life-2.6.1.tgz`/`SHA256SUMS.txt`。
4. 检查 Actions 结果、Release 附件和 SHA-256，以及 `RELEASE_NOTES_v2.6.1.md` 正文；若工作流失败，先排障，不要伪造已发布状态。
5. 在 npm 登录正确账号后执行 `npm view dsh-dafeiyu-life@2.6.1 version` 检查是否已存在；确认该版本尚不存在后才 `npm publish --access public`。npm 同版本通常不可重新发布，故上传前务必核对 `.tgz` 内容。
6. 单独确认 DSHMarket 版本显示与安装；GitHub Release、npm 包、市场同步不是同一步。
7. 版本发布后在真实客户端复查升级，不要为修复同一个版本重写历史 Tag；需修补时使用新的补丁版本。

## 5. 回退与事故响应

- 发布前确认离线备份可恢复；发生凭证、UID 或外发串号异常，立即停用插件与自动发信功能，保留完整日志和本地私密数据（禁止公开上传）。
- GitHub Tag 或 npm 发布不可作为可靠的可撤回操作：即使随后删掉 Release 或下架，也不能保证客户端未获取。**因此第 3 节必须先于正式发布。**
- 按 `docs/architecture/2.6.1-account-identity-switch.md` 的回滚流程恢复旧号，不能在换号后自行删除身份文件来绕过保护。
