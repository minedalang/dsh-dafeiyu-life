# 2.6.1 正式版发布核对清单

## 基线
- 本版本以交付的 `dsh-dev6-video-push-fixed-source.zip`（dev.6 精简调度 + 主动视频兴趣私信修复）作为**唯一**开发基线。
- 不合入未完成的 P6-A/B 多气泡/沉默续聊实验代码；P6-C/D、换号迁移和回访诊断留待后续。
- 发布资料 `RELEASE_NOTES_v2.6.1.md`、`README.md`、`CHANGELOG.md` 与 `package.json`/锁文件必须统一为 `2.6.1`。

## 本地检查
- `node --test`、`node selfcheck.mjs`、`npm pack --dry-run --ignore-scripts`。
- 可选 Python 模拟测试：`python -m unittest discover -s test -p 'test_*.py'`（不接真实平台时不得宣称线上能力已验证）。
- 使用最新 dev.6 源码做 `git apply --check`；用临时目录真正应用补丁并逐文件比对。

## 上线前人工实测（阻塞最终全面发布）
- Windows DSH Desktop 的插件加载、首次设置、模型真实验证、管理页保存与重启。
- **兴趣视频推荐**：新入选真实视频→白名单好友兴趣匹配→草稿生成；确认自动发送开关与平台回执；对旧升级配置不会突然发私信。
- B站主人私信、普通好友私信、UID 隔离、退订/限额、自然朋友无白名单写权限。
- 待办页提醒不强制执行、预计时间准确，异常恢复不会重复平台写入。
- 备份与升级：`$DSH_HOME/bili-duty/` 数据与记忆未被覆盖，回忆不会跨隐私域或从遗忘档案恢复。
- DSH Mobile 网关与插件市场 UI 显示符合实际版本。

## 发布顺序（先合并、后 tag）
1. 在 dev 分支应用补丁，提交中文 Commit 并推送。
2. 创建 PR `dev` → `main`，审查更改并**合并到 main**；本地 `git fetch origin` 后确认 `origin/main` 指向预期正式版提交。
3. 从 `main` 创建并推送 `v2.6.1` 标签（先检查是否已有同名 tag，不要直接重写远端标签）。
4. GitHub Actions release 工作流应使用该 tag 自动生成附件与 Release Notes；**本地打包并不意味着已经发布**。
5. 之后单独执行 npm 发布、检查 DSHMarket 同步；不得将三者混为同一步。
6. 正式版推广前核实实际市场显示的 `2.6.1`；如未上架，说明目前可用的是哪个渠道，切勿提前承诺。
