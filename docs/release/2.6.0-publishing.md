# 大肥鱼 v2.6.0 发布操作指南

> 在 Windows Git Bash / DSH Desktop 项目根目录执行；发布为真实外部操作，只有维护者本人执行。当前 Release 工作流仅创建 GitHub Release 与 `.tgz` / SHA-256 附件，**不会自动 `npm publish`**。

## 1. 最后一次检查与提交

```bash
git status --short
git diff --check
node -p "require('./package.json').name + '@' + require('./package.json').version"
cmd.exe /c run-tests.bat
npm pack --dry-run --ignore-scripts
```

预期包名版本：`dsh-dafeiyu-life@2.6.0`。核对 README、Release Notes、安装页面和私密备份；不要提交 `.tgz`、`.zip`、`.patch`、含密钥 `.npmrc` 或本机诊断文件。

```bash
git add README.md RELEASE_NOTES_v2.6.0.md docs/release/2.6.0-publishing.md
git commit -m "docs(release): highlight v2.6.0 features and finalize release notes"
git push origin dev
```

如果这是你尚未提交的完整正式版变更，应先按 `git status` 提交其他必要的已审核源码及版本文件；上面的 `git add` 只涵盖**本次文档增量**。

## 2. 在正式发布的分支确认版本

按仓库的发布策略，将已经测试的 `dev` 提交合入稳定发布分支（例如 `main`）；不要在尚未核对的旧提交打 Tag。如果正式发布分支是 `main`，可按你现有 PR/合并工作流进行合并，再执行：

```bash
git switch main
git pull --ff-only origin main
node -p "require('./package.json').version"
git status --short
git tag --list v2.6.0
```

**确认 `v2.6.0` 不存在、工作区干净、版本为 `2.6.0` 且测试通过后**：

```bash
git tag -a v2.6.0 -m "大肥鱼 2.6.0 正式版"
git push origin v2.6.0
```

标签推送会触发 `.github/workflows/release.yml`，它验证 Tag 与 `package.json` 一致、运行指定回归测试、执行 `npm pack --ignore-scripts`，并生成 GitHub Release、`.tgz` 和 `SHA256SUMS.txt`。在 GitHub 的 Actions 和 Releases 页面确认结果。**不要随意强推或覆盖已发布标签。**

## 3. 推送 npm 包（另行手动发布）

在要发布的同一源码提交上、项目根目录执行：

```bash
npm config get registry
npm whoami --registry=https://registry.npmjs.org/
npm view dsh-dafeiyu-life version --registry=https://registry.npmjs.org/
npm pack --dry-run --ignore-scripts
npm publish --dry-run --ignore-scripts --access public --registry=https://registry.npmjs.org/
```

如果 `npm whoami` 提示未登录，先执行 `npm login --registry=https://registry.npmjs.org/`，按浏览器/2FA 提示验证。**确认 npm 还没有 `2.6.0` 且 dry-run 文件清单正确**，才执行真正的发布：

```bash
npm publish --ignore-scripts --access public --registry=https://registry.npmjs.org/
```

也可以改为**从 GitHub Release 下载经核对的同一份 `.tgz`**，用 `npm publish ./dsh-dafeiyu-life-2.6.0.tgz --access public --registry=https://registry.npmjs.org/`，避免从另一套目录误发内容。发布需要对应 npm 包的发布权限与按 npm 当前策略完成的二次验证。切勿把密码或令牌写入仓库。

发布后核对：

```bash
npm view dsh-dafeiyu-life@2.6.0 version --registry=https://registry.npmjs.org/
npm view dsh-dafeiyu-life dist-tags --json --registry=https://registry.npmjs.org/
```

npm 同名包的**同一版本号不可重新发布覆盖**；若需修改，发布新的补丁版本（例如 `2.6.1`），而不是覆盖 `2.6.0`。

## 4. DSHMarket / 用户安装验证

- 在 DSH 内 `dshmarket` 搜索 `dsh-dafeiyu-life`，确认页面展示 `2.6.0`。
- 在 DSHMarket 网站搜索同名包，查看对应的安装入口及版本。
- 在一套干净 DSH Desktop 环境中按 README 命令安装，检查首次设置、插件启动、模型验证、关系列表、记忆与隐私边界。
- GitHub、npm、DSHMarket 不一定同步；市场未更新时先不要声称三处已全部发布。

## 5. Release 完成后

检查 GitHub Release 的标题、正文、包附件和 SHA-256，npm 版本、DSHMarket 版本及 README 的链接。保留版本来源记录；不要在未知回执时重复推包或重建已存在的 v2.6.0 标签。
