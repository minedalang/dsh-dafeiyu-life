# 2.6.2 封版／正式发布门禁

> 当前处于 `2.6.2-dev.1` 阶段。历史增量补丁的数量不等于 `dev.N` 次序；`dev.N` 仅在实际提交新的开发预发行版时递增。本文是操作清单，不是新增产品功能。

## 版本阶段与唯一真值

- `dev` 开发与测试：`package.json`、`package-lock.json`、README、CHANGELOG 和发行说明显示 `2.6.2-dev.1`（下一次需要发布开发版时递增 N）；不得提前发布同名 `2.6.2` 到 npm。
- 预览 Tag（按需）：`v2.6.2-dev.1`。GitHub Action 生成 prerelease，不能成为 Latest；如确需发布 npm 开发版，**人工**执行 `npm publish --tag next`，不得覆盖 `latest`。
- 正式封版：在 `dev` 通过全部检查后单独提交 `2.6.2`，**同时**改包版本、锁文件、README 当前版本文案、CHANGELOG 标题和 Release Notes 标题。经核对后合并到 `main`，再在 `main` 对应提交创建 `v2.6.2`。
- 正式 Tag 触发 GitHub Release 工作流；完成后经人工确认再执行 `npm publish --tag latest`。GitHub Release **不等于** npm/DSHMarket 已更新。
- Tag 必须与包版本完全相同；正式 Tag 必须指向 `main` 已包含的提交。禁止对未提交的本地文件打 Tag，禁止让 `dev` 预览覆盖稳定 Latest。

## 封版检查（不可用离线测试代替真机）

1. 确认 `git status --short` 无意外变更；`dev` 上最新代码和版本文件一致。先备份 `$DSH_HOME/bili-duty/`，避免修改或覆盖真实账号状态。
2. 运行 Windows `./run-tests.bat`（Node.js 全量、Python 全量、自检）及 `npm pack --dry-run --ignore-scripts`；检查 `.tgz` 文件清单没有个人 Cookie、数据账本、私信、日志、备份或测试缓存。
3. 在真实 DSH Desktop 验收：首次引导、新老用户配置兼容、旧数据恢复、B站账号切换与身份隔离、评论/@/私信权限和回执、待办与父子任务联动、回访说明原请求、无字幕视觉预算和事实一致性。
4. 检查 README 面向用户且简短；CHANGELOG 与 `RELEASE_NOTES_v2.6.2.md` 的已实现／未验证边界准确。架构变更应同步更新 `docs/architecture/` 说明和 Mermaid 图。
5. 实机未完成的项目要单独记录风险。决定是否仍可发布必须由维护者确认；失败时不能虚称“正式验收通过”。

## 参考 Git 命令（PowerShell，需先人工核实远端）

开发预览：

```powershell
git switch dev
git status --short
./run-tests.bat
npm pack --dry-run --ignore-scripts
# 若需要发布预览，先在 dev 提交并确认当前 package.json 为 2.6.2-dev.1
# git tag -a v2.6.2-dev.1 -m '2.6.2-dev.1 prerelease'
# git push origin v2.6.2-dev.1
```

正式封版（**不是立即执行的操作**）：

```powershell
# 在 dev 上修改 2.6.2 正式版本文件并跑完全部测试，提交后：
git switch main
git pull --ff-only origin main
git merge --no-ff dev
# 核对正式包版本、干净工作区、Release Notes 和真实验收记录
git tag -a v2.6.2 -m 'Release v2.6.2'
git push origin main
git push origin v2.6.2
# 等 GitHub Release CI 成功，且手动确认 npm 发行权限：
# npm publish --tag latest
```

**注意**：`git merge` 以及创建 Tag 都是会改变远端发布状态的操作，未经明确批准不得代执行；工作流目前仅自动制作 GitHub Release 及 `.tgz`，不会自动 npm 发布。
