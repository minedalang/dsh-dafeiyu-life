## 2. 修复边界

`lib/life-opportunities.mjs` 的原规则在 `recordVideoVisual` 接收真实取帧证明时，再次查询已清晰的视觉记忆，错误地把**本轮刚写入的记忆**当作早先的重复观察。入口的 `beginVideoObservation` / `hasVerifiedVideoVisual` 已在真实读取之前做历史防重和账号限制，因此应仅在**后置回执提交**时核对 Episode 已有账本，而不能再次以当前记忆拒绝同轮收据。修复保留：账户归属、可信来源、有效帧数、BV 匹配、同轮收据幂等、跨进程视觉租约和忘却边界。

`lib/autonomous-planner.mjs` 将真实冲突分类原样传入技术回执，避免一律掩盖为一般不可用。没有开启强制观看、没有放宽任何外发授权。

## 3. Windows 测试事实与仍需复测

用户上传的 quick：35 文件，第二批 4 个失败（原 `dev14-hybrid-memory-release` 的旧无账号假设），其余通过；另有系统符号链接权限引起的安全测试 SKIP。full：588 文件分 49 批，多个失败聚集在旧公开记忆/衰减/反思用例，以及 2.8.1 固定版本、旧页面文字、文档导航错误和模拟凭据不符合新格式。

本次仅在对应测试夹具补入**可信的当前账号标签**，并重写过时的固定版本断言；**不允许**生产环境把无来源的旧记忆默认视为当前账号的公开素材。文档导航修正了已经迁移到 `2.10.x` 的目标链接，首次设置测试改用可解析的**本地模拟凭据**而非损坏的字符串。

独立定向测试不等于 Windows full。用户提供的 full 测试存在若干未完全复现的剩余错误（包括 Windows 符号链接权限和潜在并发环境差异）；必须按本次测试教程在 Windows 重新运行，若失败仍需提供具体 `step-*.tap.log`（先脱敏），严禁删安全断言或把 SKIP 当 PASS。

## 4. 操作工具

- 只读、离线命令：`python scripts/audit-282-observation.py 'C:\path\to\bili-duty-logs.zip'`；不联网、不会操作运行态或公开发送。
- 测试工具：管理中心「运行诊断」 →「视频感知只读验收」，输入合法的公开视频 BV，选择“正常了解/深入探索”，点击「开始只读视频感知验收」，查看 JPEG 和回执。模型费用与 B站读取预算可能变化。
- 真正自主观察：管理中心「运行诊断」 →「视频 Agent · 手动诊断与运行证据」查看当前 Life 运行门禁、真实委派轨迹。**不要**把强制的只读调试结果当成 Life 自主观察。
- 每一步详细可执行操作见交付包 `TESTING_2.8.2-dev.13_一步一步实机验收.md`。

## 5. 已知限制

无法从现有诊断快照完整证明所有“为什么没有主动识图”的心理或内部模型因果；稀疏视频帧不代表看完整段视频。旧 `vision-events` 不包含全部新入口，离线审计只是读已导出的证据。Linux/macOS 的定向测试不能替代维护者真实 Windows + DSH + B站验证。
