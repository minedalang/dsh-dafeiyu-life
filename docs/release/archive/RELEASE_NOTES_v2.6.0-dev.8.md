# 大肥鱼 · DSH 生活系统 `2.6.0-dev.8`

## 这次更新解决什么

过去在「AI 模型 → Headless 模型同步与验证」中，列表主要显示自定义 Provider。用户在 DSH 中正常使用的官方 DeepSeek 等内置模型可能缺席；此外，插件升级或无关配置文件发生变更后，先前成功的 Headless 模型验证也可能被意外判为失效。

**dev.8 修复模型发现及验证状态保持机制，不改变 First Start 的安全门禁。**

## 新行为

- **内置模型可以直接验证**：从宿主当前注册的模型适配器中发现 Provider 和模型；通过真实、无工具的 Headless 连接测试后，才允许独立 Agent 使用。无需复制 API Key，也无需先把官方模型伪装成自定义 Provider。
- **自定义模型按需同步**：仍需比较 Desktop/Web 与 Headless 的有效 Provider 配置。存在差异时必须明确预览、确认、安全备份并同步；一致时直接验证。
- **验证结果按模型绑定**：保存 Provider、模型及其生效配置的指纹。无关 YAML 注释、其他插件或其他 Provider 的修改不再吊销全部验证结果；真正改变自定义模型路由时，旧验证立即失效。
- **旧记录有条件迁移**：仅在旧指纹仍有效、当前源/目标模型配置确实匹配时自动转成新记录。失效的旧记录不会被自动标记为验证通过。
- **界面更容易理解**：三步流程显示「检测模型 → 按需同步（官方跳过）→ 真实连接验证」，仍明确提醒“同步完成≠验证成功”。

## 安全和验证边界

- 所有用于独立 Agent 的 Provider/模型均需成功完成实际 Headless 探针。验证失败或没有确认注册的模型时不会放行。
- 不复制登录态、API Key、工具权限及任意自定义配置；手机端仍不开放模型配置和验证写操作。
- DSH 内置 Provider 的内部密钥或路由变更未必能通过公共注册目录静态发现；变更官方模型的真实连接配置后建议在管理页重新进行 Headless 连接验证。
- 测试中的模拟服务不能代替用户 DSH Desktop 的官方 DeepSeek 实机验证。

## 安装与升级

`dev` 分支用户更新插件后，进入管理中心的 AI 模型页。已经验证且有效的模型将继续显示“后台已验证”；官方内置模型如未验证，只需点击对应模型的验证按钮。只有检测到真正失效或无法安全迁移的配置时才需重新验证；自定义 Provider 只有配置确实不一致时才需要同步。

本版本是 `2.6.0-dev.8` 开发预览，**不是 2.6.0 正式版**。正式发布前仍需核查真实 DSH Desktop、B站互动、Android 管理中心及全部依赖安装。具体历史版本见 [CHANGELOG](CHANGELOG.md)。
