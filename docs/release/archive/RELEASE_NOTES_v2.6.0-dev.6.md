# 大肥鱼 2.6.0-dev.6（开发预览）｜动态评论回复与人生记忆适配

> 本版本是 `dev` 分支源码，不代表各发布渠道已经上架。未在真实 B站账号上执行公开评论验证；应先在测试环境核对评论区映射，再由主人明确授权操作。

## 新功能：动态评论独立通道

主 Session 提供两项工具：

1. `bili_dynamic_comment_context`：使用动态页面的完整数字 ID 查询真实动态详情，读取其 `basic.comment_type` 与评论区资源 ID，列出评论并可核对待回复的 `rpid/root`。只读。
2. `bili_dynamic_comment_manual`：当主人在当前对话明确要求回复时，用已核验的真实评论区发送一条文字或图文动态评论，保留平台回执，不确定则禁止重试。

视频仍走原来的 BV 工具。**动态 ID、评论区 oid、评论 rpid 不是同一个概念**，动态 ID 和 rpid 全程使用数字字符串，不能转换成 JavaScript `number`。暂不支持未知/不一致评论区、视频类型动态或未核验的转发动态写入；也不开放给自主生活域自动发言。

## 跨模块兼容与安全

- 已确认的公开评论才进入 `LifeMemoryCoordinator`，随后由 `LifeMemoryGateway` 写入可衰减生活经历，由 `LifeReflection` 记录反思候选；旧视频经历不改变格式。
- 动态引用明确标记 `contentType: dynamic`、`dynamicId`，不会伪造 BV；模糊后移除精确动态 ID、事件 key，遗忘后无法从永久档案、过期候选重新精确召回。
- 反思只取当前可衰减的正文证据，不接收候选文件中的原始动态 ID、第三方正文或历史归档作为额外依据。兴趣档案仍只基于真实观看证据，不把单条动态互动变成视频兴趣。
- 评论工具共用当前主人授权/总开关/B站登录门禁、公开评论日限额、持久化去重；回执不确定不重试。内置 First Start、DSH Mobile、Headless 等 dev.5 安全边界不变。
- 真实 B站接口、鉴权、风控与可见性仍受平台限制。自动化测试不能代替真实账号回执验收。

## 升级

`dev.5` 代码可按补丁升级至 `2.6.0-dev.6`，不迁移或重置原有用户数据；建议保留原先独立数据备份。升级后运行 `run-tests.bat` 并重新安装 dev 分支插件。阅读 [动态评论跨系统审计](docs/architecture/dynamic-comment-integration-v2.6.0-dev.6.md) 获取实现边界。

**与 dev.5 的关系：** 安卓查看模式、禁止手机远程写入、Headless 三步验证和首次启动强制门禁继续保持。体验推荐参数没有更新，继续沿用 dev.4 的推荐值版本。
