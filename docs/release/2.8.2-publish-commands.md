## 3. main 上创建唯一稳定 Tag

`release.yml` 要求 **Tag 精确匹配 package.json 版本且稳定 Tag 必须属于 origin/main 历史**。Pull Request 合并后：

```powershell
git switch main
git pull --ff-only origin main
if ($LASTEXITCODE -ne 0) { throw 'main 更新失败' }
if (git status --porcelain) { throw '工作区不干净，不打 Tag' }
if ((node -p "require('./package.json').version") -ne '2.8.2') { throw 'main 版本不是 2.8.2' }
git tag -l v2.8.2
git ls-remote --tags origin refs/tags/v2.8.2
# 上两条必须均没有已有 v2.8.2；不要覆盖已存在的 Tag
```

检查 GitHub Actions 的 `ci.yml` 已在 main 全绿、最终提交与本机全绿源码一致且远端无同名 Tag，再执行：

```powershell
git tag -a v2.8.2 -m "大肥鱼 2.8.2 · 视频感知体验优化"
git push origin v2.8.2
```

推送稳定 Tag 会触发 `.github/workflows/release.yml`：构建六平台包、运行测试、创建 GitHub Release 并生成 SHA256 校验文件。**它不会自动执行 npm publish**。必须等 Actions 的 release Job 通过，检查六份 `.tgz` 和 `SHA256SUMS.txt`，不能把推送成功当作已完成发布。


确认 dry-run 打包清单、发布账户、仓库提交与 GitHub Release 一致后，才执行真正的发布：


若需要 npm 登录或二次认证，遵循 npm 官方交互流程；不将 token、Cookie、`.npmrc` 等敏感文件放进 Git。发生权限/认证失败就停止，不要重复执行已可能成功的 publish。
