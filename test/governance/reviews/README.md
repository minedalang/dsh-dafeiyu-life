# 代码变化但不需要修改测试时的审查说明

PR CI 将比较本次修改的 `index.js`、`client.js`、`lib/`、`vendor/`、`prompts/` 与 `scripts/`。如果修改了这些生产文件，且没有同时修改任何 Node/Python 测试，就必须在本目录新增或更新 **非 README** 的 `YYYY-MM-DD-topic.md` 审查说明。

审查说明至少写出：修改的生产路径、运行 `npm run review:impacted-tests` 后核对了哪些现行测试、为什么不需要改测试、实际执行过的定向测试结果、哪些安全与 Windows 场景仍需复测。这个机制不自动认为未修改的旧断言正确；PR 代码审查仍需核对说明是否可信，禁止只填空话。

如果本次确实修改了测试，不要求重复写一份审查说明，但仍需完成测试影响核对。归档历史测试须额外通过 `catalog.json` 的退役理由与替代覆盖校验。
